# Claude Code as a lane host

Lanes that Claude Code starts in its own session. `.claude/AGENTS.md` owns loading, models, cache, and wiring; `.agents/transports/claude-cli.md` owns the Claude CLI as a bench; `.agents/platforms/` owns the host shell.

## Mechanics

| Question            | Claude Code                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Start               | The Agent tool for one unit or when the next step depends on the result, with a role from `.claude/agents/` as `subagent_type`; never `general-purpose`, `Plan`, `claude`, `fork`, or `Explore`. A Workflow for a fan-out of small units, a staged pipeline, or a loop, its nodes configured per `.claude/AGENTS.md` § Dispatch. `scout` for an exact bounded lookup, per `.agents/orchestration.md` § Routing.  |
| Continue            | Resume a custom subagent by its agent id through the installed tool's resume or message interface; a team teammate is not a custom subagent, so verify which one the installed version resumes. Recover an interrupted Workflow with `resumeFromRunId`; its journal replays the finished agents. A surviving transcript file is no continuation route, and a one-shot `Explore` or `Plan` agent cannot continue. |
| Wake versus deliver | A finished subagent, Workflow, or background command wakes the session with a notification.                                                                                                                                                                                                                                                                                                                      |
| Track               | The agent id, not its display name, and the parent session that can recover it. A Workflow's `scriptPath` and `runId`, recorded at launch; its journal writes only at agent start and result, so read its liveness from the newest subagent transcript. A background command's task id and output file.                                                                                                          |
| Background          | A foreground shell call is capped at 10 minutes. A background command runs to its own timeout, at most 2 hours, then stops. Run anything longer under `.agents/skills/orkestrel-dispatch/references/launch.md` § Launch ownership.                                                                                                                                                                               |
| Isolation           | Agents share the session's checkout; `isolation: worktree` gives one agent its own worktree.                                                                                                                                                                                                                                                                                                                     |
| Tools               | A role's frontmatter lists its tools, and the host can still withhold one: in-process roles in the desktop host ran with no shell although their charter listed one (2026-10-03), and the harness can refuse an in-process agent's file write.                                                                                                                                                                   |
| Limits              | At the account's usage limit, running agents and Workflow agents stop mid-run and keep the edits they made.                                                                                                                                                                                                                                                                                                      |
| Host effects        | Agents and Workflow nodes run inside the session's process and open no window (2026-10-21). An agent's shell can restart in the session root between calls (2026-10-17).                                                                                                                                                                                                                                         |
| Visibility          | Agent tool calls, Workflow runs, and background commands appear in the session the user watches, where the user can stop them; a CLI started from a shell shows only its command line, so run it as a capped command inside such a lane.                                                                                                                                                                         |
| Capability map      | `.agents/orchestration.md` § Roles, Claude column; `.claude/AGENTS.md` § Models owns the aliases.                                                                                                                                                                                                                                                                                                                |

## Quirks

- When independent review or a blind design round needs an agent, create it in a clean context on its assigned model; never `fork`, which inherits the session's model and context.
- When a unit needs continuation, start a named custom role, never a one-shot `Explore` or `Plan` agent.
- When a Workflow starts, record its `scriptPath` and `runId` before doing anything else. When a usage limit stops it (2026-10-21), launch no further lane, do independent hand work until the reset, then resume with `resumeFromRunId` rather than relaunching.
- When a usage limit stops a writing agent, relaunch it from the edits it left in its checkout (2026-10-15 and 2026-10-16).
- When an in-process unit must build, test, or run gates, confirm its shell first; otherwise give it edits only and run its command list through a lane that holds a shell.
- When an in-process agent must produce a report, check its tools first; when the harness refuses its file write, brief the agent to return the report as text, and the Orchestrator files it.
- When an agent works outside the session root, give it absolute paths, and check the root's `git status` for strays after it returns.
- When read-only fan-out runs on a host where child CLIs open windows, prefer in-process agents and Workflow nodes.
- When the Edit or Write tool must reproduce a literal Unicode escape in source (a backslash, the letter `u`, and four hexadecimal digits), write that backslash itself as a Unicode escape (code point 5C). The tools decode every such escape you type before matching or writing, so a typed escape for a backtick lands as a backtick (2026-10-27). Never fall back to a shell edit.
- When a command carries a program, keep it in a TypeScript file run by `node`: a heredoc, `node -e`, an `&&` chain, or a `${...}` argument trips the harness's approval classifier on a Windows host; a one-shot read-only check can run inline.
- When a `Remove-Item` runs on a Windows host, run it as its own short command with a relative path: the approval classifier blocks a command that pairs it with a path-like literal elsewhere, such as a `'\'` string. Verify with `git status`.
- When a claim about caching, resume, or team behavior matters, verify it against the installed version and the official [subagent documentation](https://code.claude.com/docs/en/sub-agents), [team limitations](https://code.claude.com/docs/en/agent-teams), and [prompt-cache documentation](https://code.claude.com/docs/en/prompt-caching).
