# T3 as a lane host

T3 hosts Claude, Codex, and Cursor lanes as app-owned child tasks of a thread, and runs top-level threads beside it. Each provider's own page adds its quirks; `.agents/platforms/` owns the host shell.

## Mechanics

| Question            | T3                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Start               | Read providers, models, options, and limits from `orchestrator_capabilities`. Use `delegate_task` for app-owned children, cross-provider work, requested model options, or worktree isolation. Create a top-level thread only when the user asks for one. A child task names its role and reads that role's charter first, or the brief inlines the charter's Do, Refuse, and Return lines, and the launch records the model and options actually applied beside the role. |
| Continue            | Send an ordinary continuation to the child's `childThreadId` through `t3_thread_send`: `queue` for a separate request turn, `auto` for a reply or idle continuation, `steer` only for an in-flight change. Send a continuation that changes scope, acceptance, or authorization as a pointer to its `<unit>-brief-<n>.md`; send a bare message only for an unchanged objective.                                                                                            |
| Wake versus deliver | An async child's completion wakes the parent thread with a notification. A queued turn can finish with no notice (2026-10-23).                                                                                                                                                                                                                                                                                                                                             |
| Track               | The full `taskId` the launch returns, the `childThreadId`, and the provider, model, and options actually applied. The `clientRequestId` is no lookup key. Thread ids change when the tool session changes, sometimes between launches.                                                                                                                                                                                                                                     |
| Background          | A child runs commands through its provider's shell. T3 stops an idle provider session's process tree about 30 minutes after its last turn (2026-10-15).                                                                                                                                                                                                                                                                                                                    |
| Isolation           | `shared` uses the parent's checkout; `worktree` creates one from the parent's local commit, without uncommitted edits.                                                                                                                                                                                                                                                                                                                                                     |
| Tools               | Codex children reach `t3_thread_send`, `t3_thread_read`, and `t3_thread_wait` (probed 2026-10-22).                                                                                                                                                                                                                                                                                                                                                                         |
| Limits              | A provider's usage limit acts as that provider's page states. T3 refuses delegation with `parent_not_active` while the parent thread is not active (2026-10-24); the Background row holds the idle stop.                                                                                                                                                                                                                                                                   |
| Host effects        | Each child's shell opened console windows on a Windows host; six concurrent children made it unusable (2026-10-21).                                                                                                                                                                                                                                                                                                                                                        |
| Visibility          | A `delegate_task` child appears in the T3 app, where the user can stop it; a CLI started from a child's shell is hidden (the user's ruling of 2026-10-19).                                                                                                                                                                                                                                                                                                                 |
| Capability map      | The Claude and Codex columns of `.agents/orchestration.md` § Roles; Cursor lanes are readers.                                                                                                                                                                                                                                                                                                                                                                              |

## Quirks

- When an independent review round starts, call `delegate_task` with a distinct `clientRequestId`, and reuse that id only to retry the same round's uncertain launch. Supply the original brief, prior findings, responses, and unresolved objections. Never continue a review round through `t3_thread_send`.
- When an ordinary follow-up starts, use a stable `clientRequestId` and retain the returned task id beside, never in place of, the original result. A completed task and a later turn in its child thread are distinct results.
- When a queued turn's result is needed and no notice came, read the durable result file or `task_status` with the full task id once.
- When a launch's reply is missing or ambiguous, inspect the recorded task before retrying. A timeout on a parent wait cancels no child work.
- When a lane must be interrupted and restarted, use `restart`; never use it as a resume. Create no ordinary top-level thread as a delegated lane.
- When a child would launch processes beside another, get the user's go-ahead until a quiet single-lane trial passes on that host.
- When a run must outlive the idle window, start it under `.agents/skills/orkestrel-dispatch/references/launch.md` § Launch ownership, or keep the session in its turn.
- When delegation is refused, record the refusal and whether a child was created, then use the permitted fallback with its actual model disclosed.
- When a Cursor lane launches, pass no model options; the registry refused `fastMode`, `reasoning_effort`, and `contextWindow` with "AI Model Not Found" (2026-10-21).
