# Harness mechanics

| Harness           | Launch                                                                                  | Own address                                       | Push channel                                                                                                                                                                                                       | Limits                                                                                                                                                                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T3 (any provider) | `delegate_task` with `isolation: "shared"`, `mode: "async"`, a stable `clientRequestId` | `parentThreadId` from `orchestrator_capabilities` | `t3_thread_send`: `queue` for a request (one turn per message, arrival order), `auto` for a reply or ruling, `steer` to change a running lane's instructions; `t3_thread_read` and `t3_thread_wait` to read a lane | a lane address embeds the Orchestrator's MCP session, which can change between launches: write each roster row from its launch result                                                                                                   |
| Claude Code       | the `Agent` tool, background by default                                                 | the agent id or name the launch returns           | the Orchestrator sends `SendMessage` to a running subagent; a subagent without a message tool uses the file channel and the Orchestrator relays                                                                    | the dispatch aliases `.claude/AGENTS.md` names                                                                                                                                                                                          |
| Codex             | native agents or the CLI (`.agents/transports/codex.md`); under T3, the T3 row          | the session id the launch returns                 | the native message and follow-up tools where the session exposes them; otherwise the T3 row when Codex runs under T3                                                                                               | `max_concurrent_threads_per_session` in `.codex/config.toml` caps native agents; the shell tool returns after its yield time and leaves the command running, so write output to a file and poll the process or resume the shell session |
| Cursor            | the CLI (`.agents/transports/cursor.md`)                                                | the session id the launch returns                 | none, so a Cursor lane holds no writer or runner lane                                                                                                                                                              | the routing `.agents/orchestration.md` § Routing gives Cursor                                                                                                                                                                           |

- Where the harness resumes an ended lane with its context, as T3 does, send the lane's fix unit to that lane; otherwise dispatch a successor brief carrying the lane's report and the fix scope.
- Under T3, retain the task id each send returns. A completion notice for a turn another lane started can miss the Orchestrator: after the last `FINAL` is sent, read the runner's `coord/results/closing-<k>.md` or its task status instead of waiting for the notice. Never brief the runner to wait inside a turn, which blocks every queued request.
- In every Codex brief, state how the lane waits on a long command: output to a file, then poll the process or resume the shell session.
