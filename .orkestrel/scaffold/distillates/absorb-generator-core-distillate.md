## Ownership model

- `content` means the plan claims the bytes. The type states: "`content` claims the bytes: audit compares them, and a write restores a missing file and replaces a stale one." `blueprintToConfigArtifacts` assigns it to `tsconfig.json`, `vite.config.ts`, `configs/browsers.ts`, every selected `SRC_MATRIX` and `APP_MATRIX` wrapper, both bin wrappers, `SHOWCASE_CONFIG_PATH`, and `SKILLS_CONFIG_PATH`. `blueprintToDocumentArtifacts` assigns it to `AGENTS.md`. `HydratedArtifact` is the host branch whose ownership is `content`; these compilers never construct that branch. A write that the type calls a restore is what `repair` is bound to: `Finding` says `repair` and `remove` re-derive every verdict and refuse a caller's audit that does not match. `src/core/types.ts:24`, `src/core/types.ts:413`, `src/core/types.ts:483`, `src/core/compilers.ts:932`, `src/core/compilers.ts:1512`.
- `presence` means the plan claims existence. The type states: "`presence` claims only that the file exists: audit compares existence, and a write restores an absent file and never touches present bytes." `blueprintToHostArtifacts` assigns `presence` and `origin: 'host'` to every selected `HOST_PATHS` entry, every seed guide, `CATALOG_AGENT_PATH`, and, unless `skills` is set, each target-skill bridge, sidecar, and pointer. `blueprintToTestArtifacts` assigns `presence` to `tests/distribution.test.ts`. The distribution remarks say a missing proof reports as drift and a package that replaced it with a better proof keeps that proof. Guide mirrors are described the same way on `Mirror`: "a guide mirror is presence-owned: repair restores one that is absent and never replaces one that is present." `WORKSPACE_OWNED_PATHS` names `.gitignore`, which is also a `HOST_PATHS` member, and says those bytes are copied when absent and never compared or replaced while present; the compiler still plans that path as `presence`. `src/core/types.ts:25`, `src/core/types.ts:348`, `src/core/constants.ts:238`, `src/core/compilers.ts:1224`, `src/core/compilers.ts:1353`, `src/core/compilers.ts:1614`.
- `birth` means the plan claims creation. The type states: "`birth` claims only the file's creation: audit never compares it and always reports it aligned, and a write creates it only while it is absent." `blueprintToSourceArtifacts` assigns it to every barrel and entry. `blueprintToTestArtifacts` assigns it to every tests artifact except the distribution proof. `blueprintToGuideArtifacts` assigns it to `guides/README.md`. `blueprintToDocumentArtifacts` assigns it to `README.md`. `blueprintToOrchestrationArtifacts` assigns it to `scripts/service.sh`. `blueprintToConfigArtifacts` assigns it to `JOURNEY_CONFIG_PATH` and to no other config. `Plan` states: "An artifact at `package.json` carries `birth` ownership because the compiler emits the manifest that way." `blueprintToManifest` says a repair that replaced the manifest would take the consumer's description, keywords, and added scripts. `src/core/types.ts:27`, `src/core/types.ts:448`, `src/core/compilers.ts:518`, `src/core/compilers.ts:1098`, `src/core/compilers.ts:1145`, `src/core/compilers.ts:1242`, `src/core/compilers.ts:1449`, `src/core/compilers.ts:1502`, `src/core/compilers.ts:1552`.
- `host` means the bytes are copied from this package's vendored data root. The type states: "`host` is byte-copied from this package's vendored data root." `blueprintToHostArtifacts` is the compiler that assigns `origin: 'host'`. A `HostArtifact` ownership is narrowed to `presence` or `birth` because the pure core face cannot read the vendored root; these compilers assign `presence` only. `pointer: true` tells hydration to derive bytes with `renderSkillPointer` rather than copy them. `applyOverrides` leaves a host-origin artifact untouched. `src/core/types.ts:13`, `src/core/types.ts:391`, `src/core/types.ts:394`, `src/core/compilers.ts:1609`, `src/core/compilers.ts:1667`.
- `template` means the text is filled from a frozen template definition. The type states: "`template` is filled from a frozen template definition." Every `blueprintToConfigArtifacts`, `blueprintToSourceArtifacts`, `blueprintToTestArtifacts`, `blueprintToGuideArtifacts`, `blueprintToDocumentArtifacts`, and `blueprintToOrchestrationArtifacts` artifact is assigned `origin: 'template'`. `fillTemplate` from `@orkestrel/template` fills the `{{…}}` slots listed above. `src/core/types.ts:14`, `src/core/compilers.ts:26`, `src/core/compilers.ts:933`.
- `computed` means the text is derived by this package's own combination logic. The type states: "`computed` is derived by this package's own combination logic." `ContentArtifact` allows `origin: 'template' | 'computed'`, and `PlanSummary.computed` counts that origin. No assignment `origin: 'computed'` appears in `compilers.ts`. `blueprintToManifest` returns the manifest string, and `replacePlanRanges` replaces the `content` of an existing `package.json` artifact that is not `origin: 'host'`. The artifact object for that path is not constructed in these four files; `Plan` still requires `birth` at `package.json`. `src/core/types.ts:14`, `src/core/types.ts:423`, `src/core/types.ts:448`, `src/core/types.ts:555`, `src/core/compilers.ts:534`, `src/core/compilers.ts:2126`.
