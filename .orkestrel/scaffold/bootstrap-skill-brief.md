## What the files must hold

### `references/inputs.md` — the affordance catalog

Keyed by what a person is asked for, never by a package's type union. One row per category, each
carrying: the default Bootstrap 5.3 affordance and its markup, the alternates and the density or
list size that earns each, the ladder rung, and the fixed state set. The categories: one line of
text; text over many lines; a secret; a number; a number in a bounded range; a date; a time; a date
and time; a color; one on/off answer; one of a few; one of many; one of many with an unlisted value
admitted; any of a few; any of many; a value picked from a searched list; files; an ordered set of
tags; a rating; a step in a sequence.

The fixed state set every affordance handles: rest, hover, focus-visible, disabled, locked,
invalid, busy, required, with help, and — where the value is a set — empty and full. Point the
data states (ideal, empty, loading, partial, error) at `bootstrap-reference.md` → The data states
rather than repeating them.

Carry these rules, each with its reason in one clause:

- Keep a read-only field on the same affordance as its editable form with `readonly` or
  `disabled` plus a transparent chrome combination declared once by name; never swap to
  `form-control-plaintext`, whose zero horizontal padding reflows the view against the edit.
- A native select cannot be read-only; a locked select is `disabled` and its value travels anyway.
- Give a chosen filter an accent variant rather than the neutral outline.
- A lone on/off box is one thing; a group of boxes holding a list is another; a radio group and a
  segmented `btn-check` group draw the same question and the list size decides.
- A hidden file input driven from a button, a card, or a dropzone keeps the input as the non-drag
  path.
- Where Bootstrap ships no component, name the APG pattern the hand-roll owes and route the
  build decision to `bootstrap-reference.md` → When not to hand-roll. Skeletons are shipped
  (`components.md` → Placeholder) and do not belong in that set.

### `references/inspection.md` — the instruments

Move the "Mechanical proof" block out of `SKILL.md` here and extend it. State each instrument as:
the property, the population it walks, the reading that settles it, the negative control drawn
from outside that population, and the coverage it does not have. No function name from any
package, no algorithm. The instruments: authored class in the shipped cascade with a population
floor; declared class combinations (each multi-utility chrome string declared once with its
invariant, and an undeclared combination fails — never a cancellation heuristic); style escapes (a
`style` attribute or a `<style>` element in the surface's own markup, read on a freshly mounted,
undriven tree, with the framework's own runtime styles and `v-show` named as exemptions); token
discipline (no literal color, every custom paint resolves through a token in each color mode);
custom rule doing a utility's job; composited contrast in both themes; one glyph one meaning.

Add the custom-CSS exception here and reference it from `SKILL.md` → When custom CSS is justified:
an authored rule is permitted without the developer's say-so only where an instrument in this
file reports the vendor cascade failing a stated bar, the rule cites that reading, and the rule is
written over tokens.
