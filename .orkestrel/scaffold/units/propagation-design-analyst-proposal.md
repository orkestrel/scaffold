# propagation-design — analyst proposal

## Answers

1. **The model.** Keep `Environment = 'core' | 'browser' | 'server'`. An environment fixes a host boundary; a surface adds a generated build or proof capability; an extension contributes a named implementation of an existing browser or styles surface. Browser remains represented by the environment selections. Styles, journey, and showcase become additional selections. Do not turn Vue or stylesheet names into environments. The existing environment union and independent axes are the starting contract. (`src/core/types.ts:4`, `src/core/types.ts:213`.) Paths in this proposal are scaffold-relative; `../veneer/` identifies the reference checkout.

   Put these proposed contracts in `src/core/types.ts`, with readonly members and collections:

   ```ts
   export type Surface = 'styles' | 'journey' | 'showcase'
   export type Axis = 'src' | 'app'

   export type Extension =
   	| {
   			readonly surface: 'browser'
   			readonly name: 'vue'
   			readonly axes: readonly Axis[]
   	  }
   	| {
   			readonly surface: 'styles'
   			readonly name: string
   	  }
   ```

   Add `Blueprint.surfaces: readonly Surface[]`, `Blueprint.extensions: readonly Extension[]`, and `Blueprint.themes: boolean`. Remove the duplicate `showcase` and `journey` booleans and update their consumers together. `themes` describes the optional styles subtarget; require the styles selection when it is true. Keep the other structural facts, including `conformance`, independent. The extension discriminant is `surface`; the browser branch's `axes` records independent `src/vue` and `app/vue` presence. An extension name is data for a template, never executable plugin code. This follows the named-discriminant, derived-state, readonly, and no-compatibility-shim laws. (`AGENTS.md:41`, `AGENTS.md:56`, `AGENTS.md:57`, `AGENTS.md:64`.)

   Add creation options `--surfaces styles,journey,showcase`, `--extensions browser:vue,styles:bootstrap,styles:tailwindcss`, and `--themes`. The Vue creation shorthand applies to the browser axes selected by `--src` and `--app`; the library contract can select its axes individually. Require at least one matching browser axis. Require `app/browser` for journey and showcase, and styles for a styles extension. Make surface selection explicit: `new --app browser` alone no longer implicitly selects journey. These are changes to the creation contract, which presently selects journey from the app axis and accepts no surface option. (`src/bin/CLI.ts:233`, `guides/scaffold.md:552`, `guides/scaffold.md:598`.)

   Extend `#derive` with exact-case, physically contained markers: `src/styles/index.scss`; `configs/app/vite.showcase.config.ts` or the physical `showcase/` directory; `configs/app/vite.journey.config.ts`; `src/vue/` and `app/vue/` independently; and a direct `src/<name>/` directory containing both `index.scss` and `sheet.ts` for a styles extension. Detect themes from `src/styles/themes/index.scss`. Exclude reserved names, including environment names, `bin`, `styles`, and `themes`; validate a portable lowercase name before using it in a path, script, alias, or export. Reject duplicate and case-colliding destinations. Sort selections deterministically. Keep `host.json` an inventory, and store no target selection. Existing derivation reads the target on each run. (`src/bin/CLI.ts:955`, `src/core/constants.ts:227`.)

   A marker that has been deleted cannot prove its former selection. In particular, deleting the journey wrapper removes the only journey marker specified by this brief. Report that recovery limit; do not infer selection from a stale script or invent a hidden registry. Also refuse a repair that would remove Vue tooling while an older target still contains `.vue` files under `app/browser`: require an explicit source migration to `app/vue`. The existing browser template installs Vue unconditionally, so separating that extension changes existing targets. (`src/core/compilers.ts:637`, `src/core/templates.ts:330`, `src/core/templates.ts:731`.)

## Proposal

**Surface.** Preserve host environments and add explicit styles, journey, and showcase selections. Styles owns publishing/build/proof machinery; journey owns application proof composition; showcase owns publication output composition. Keep themes a styles subtarget. The separation extends the independent environment axes without expanding the host union. (`src/core/types.ts:4`, `src/core/types.ts:185`.)

**Extension.** Represent an extension by its parent surface and name, with independent axes for a browser extension. Vue is the supported browser recipe; styles uses a validated name-driven recipe. Project, wrapper, script, export, and packaging generation share that recipe, while CSS framework implementation and conformance claims remain authored. This carries the reference's separate faces without importing its product policy into scaffold. (`../veneer/ROADMAP.md:48`, `../veneer/ROADMAP.md:117`.)

**Ownership.** Content-own generated configuration and hydrate shared host bytes to content ownership. Preserve birth-owned sources, setup, and variants. Keep pages build-owned and manifest changes region-scoped or explicit during adoption. This delivers repeatable restoration of the propagation files without pretending repair can reconstruct authored files or an erased selection. (`src/server/Materializer.ts:877`, `guides/scaffold.md:1171`, `src/core/compilers.ts:518`.)

**Derivation.** Rebuild the in-memory blueprint from exact-case, contained source/configuration markers on each invocation. Validate names before path or code interpolation. A registered extension's outputs follow its physically present axes; unrelated proof facts remain independent. No selection is persisted, and a missing final marker is an explicit recovery limit. (`src/bin/CLI.ts:955`, `src/core/types.ts:191`.)

**Proof.** Combine generalized vendored config assertions, meaningful seeded infrastructure proofs, real generated-consumer builds, repair/idempotence cases, and mutation controls. Test the generator's behavior and the application source; rebuild showcase outputs at publication. Treat release and adopter success as unverified until their named runs complete. (`.claude/rules/quality.md:29`, `.claude/rules/tests.md:329`, `../veneer/ROADMAP.md:70`.)

## Alternatives refused

- **Add styles and Vue to `Environment`.** Styles is a publishing/proof surface and Vue inherits browser boundaries; neither introduces another host. The existing host union and reference's separate wrappers support keeping those dimensions separate. (`src/core/types.ts:4`, `../veneer/ROADMAP.md:64`.)
- **Persist selections in `host.json`.** That file identifies vendored bytes; target selection is reconstructed from the tree. A persisted selection would introduce another authority. (`src/core/constants.ts:227`, `src/bin/CLI.ts:955`, `AGENTS.md:56`.)
- **Keep automatic Vue on every browser application.** That coupling cannot represent the requested base browser plus separate Vue extension and makes an extension-free application depend on Vue tooling. (`src/core/compilers.ts:637`, `src/core/constants.ts:599`.)
- **Copy Veneer's config proof unchanged.** It asserts a fixed factory set, fixed face names, and unconditional themes/present HTML. Those assertions do not apply to a core-only or arbitrary-name adopter. (`../veneer/tests/config.test.ts:105`, `../veneer/tests/config.test.ts:158`, `../veneer/tests/config.test.ts:249`, `../veneer/tests/config.test.ts:2363`.)
- **Use `overwrite` as a force update for presence ownership.** Effective ownership is decided during hydration, and genuine presence bytes remain retained. The proposed release needs canonical content claims, not a misleading force convention. (`src/server/Materializer.ts:764`, `src/core/helpers.ts:558`, `guides/scaffold.md:1138`.)
- **Make authored files content-owned to promise universal repair.** That would erase setup behavior and journey variants, contradicting their existing ownership and the explicit birth-owned wrapper requirement. (`guides/scaffold.md:1171`, `tmp/units/propagation-design-brief.md:32`.)
- **Keep `dist/showcase`, copy steps, or time stamps.** The requested artifact is a reproducible final-page digest at a root mode path; the reference computes the stamp after inlining and writes the final filename directly. (`../veneer/configs/app/vite.showcase.config.ts:41`, `../veneer/configs/helpers.ts:450`, `src/core/templates.ts:403`.)
- **Infer conformance or install Bootstrap/Tailwind from the extension name.** Conformance has its own proof marker, and Veneer's framework packages serve authored reference checks rather than published runtime dependencies. (`src/bin/CLI.ts:991`, `../veneer/ROADMAP.md:12`, `../veneer/ROADMAP.md:117`.)
- **Add a package-owned config escape leaf.** The existing permitted leaves and generated root factories can carry these decisions. Another leaf violates the configuration authority rule and leaves the repair gap in place. (`.claude/rules/workspace.md:64`.)
