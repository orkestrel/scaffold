## What the files must hold

### `SKILL.md`

Keep the journey laws, the refusal family, and the transport family. Add:

- **The families table.** A browser `integration.test.ts` declares which families it carries;
  the always-on proofs assert every declared family is present. Journey and refusal are always
  on; matrix where the surface ships more than one variant; statechart where the surface declares
  transitions a journey drives; transport where the surface persists or restarts; capture under
  the capture flag. "Options" means which families a surface declares, never a switch that
  changes what a declared family proves.
- **The `variant` run axis.** One value carries the theme and the viewport, read once at run
  start, choosing the capture destination, the matrix row, and the statechart run together. Never
  split them. The matrix family loops every declared variant inside one run by applying each
  variant's `apply` and viewport; the capture family renders one variant per run.
- **Statechart family**: required wherever a journey drives controls that carry state, offered
  where the surface is static; point at `statechart.md`.
- **Decision routing**: point at `decide.md`.
- **Styles**: point at `styles.md`; the perception laws stay here.
- **Accept** gains: the matrix per variant, the statechart outcome, the authored-class census and
  the escape reading on the mounted surface, and the written artifact.
- Route portfolio review to `orkestrel-polish-surface` as today.

### `references/layer.md`

Replace "Implement the signatures below…" with the import rule: import every journey helper from
`@orkestrel/test/browser`, and write one of your own only where that package publishes none for the
act, placed in the workspace's browser test setup module and named for the act. Keep the failure
voices table (extend it with the region, disclosure, perception, and value voices the package
publishes), the role vocabulary, the traversal contract, and the perception rules, re-pointed at
the published names. Correct the law "never let a helper take an element": journey verbs resolve
their own target and refuse an element; readers, fixture builders, and capture take one, and a
journey step never passes one to a verb.

### `references/captures.md`

Name `createPortfolio` and `place(state, element?)` as the hook; keep as suite assertions what the
package leaves to the suite: the always-on expansion-uniqueness proof over `expandCaptures`, the
placement set-equality against the registry in every run (an ordinary run never refuses an
unregistered state, because `place` returns before it checks), and the on-disk membership and
non-empty read-back under the flag. Keep the transient-state rule with `place` from inside the
one-shot listener.

### `references/statechart.md`

The contract: declare each transition with `StateTransition`, one `StateScenario` per transition
with arrange, act, assert; run the table with `executeScenarios` from `@orkestrel/test` against a
context the suite builds; drive `act` through the journey verbs where a person could, and through
the entity's own API only where the transition is the entity's, saying which. The harness a person
watches: mounted on the same table, a play control per transition, play-all, a state badge, an
event log, a `role="status"` announcer, the `STATECHART_ATTRIBUTES` on the stage element cycling
through `STATECHART_STATUSES`, a deep link for one transition and for play-all, and a demo step that
leaves the widget in its most legible state. The gate: mount the harness page, press play-all
through the journey verb, poll the status attribute, assert passed with zero failed. The harness
stays per repository; only the types, the runner, and the attribute names are published.

### `references/decide.md`

Route by what judges the claim. A claim a compiler, a linter, or a Node runner judges goes to the
`prove` tool with its project, its case, its control, and the stage the control breaks at, and its
receipt line is quoted. A claim a person's eye judges goes to a rendered artifact: one written text
file per variant under the workspace's `tmp/`, composed from `describeTree` and `describeFocus` of
the mounted surface, the resolved-style rows the matrix family read, the journal's steps and
output, and the capture filenames, named by the variant so a decision cites it, read in one call.
State the limit plainly: `prove` cannot serve a browser project today (name the two defects from
the finding), so never route a rendered question there. Name the statechart harness link as the
artifact for a look a person decides on.

### `references/styles.md`

Assert the resolved value, never the class list. Run every style assertion once per declared
variant, applying the attribute the surface actually reads (`data-bs-theme` on a Bootstrap
surface). Read contrast through the composited layers with `contrast` and focus chrome with
`readRing`, and carry a control that must read under the bar in the same run. Read the authored
class census as the difference between `readClasses` of the mounted surface and `readCascade`,
with a population floor and a control class the cascade lacks. Read escapes with `extractStyles`
on a freshly mounted, undriven surface, with the framework's runtime styles and `v-show` named as
exemptions. Read tokens with `token` and `rootToken` and compare values, never presence. Each
instrument names the property it proves by pointing at the bootstrap skill's `inspection.md`
