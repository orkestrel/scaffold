## Distillate

- Statechart sweep: pattern `statechart|StateScenario|runScenarios` over `*.ts,*.vue,*.md` in `elements mailbox veneer taverna terrain test probe`. Hits: 47 files in `elements` (contract, runner, 19 factory suites, 18 matching playground pages, harness, E2E gate, showcase guide, router, plus a few src/guide mentions); 12 files in `veneer` (contract, runner, seven component suites, `guides/showcase.md`, `vite.config.ts` comment, `ROADMAP.md`); zero in `mailbox`, `taverna`, `terrain`, `test`, `probe`. `NavPlaygroundPage.vue` and `TablePlaygroundPage.vue` exist and mount the harness but did not match the three strings.
- Elements contract: `StateTransition { name, from, event, to }` and `StateScenario { transition, arrange, act, assert }` in `setup.ts`; `runScenario` / `runScenarios(scenarios, build)` in `setupBrowser.ts` walk the closures and own no dispatch.
- Veneer uses the same type names and fields; `runScenarios(label, create, scenarios)` builds the `describe`/`it.each` block itself, `create` takes no scenario, and `settle`/`toggle` wait on Bootstrap lifecycle events after `instance.show`/`hide`.
- The playground harness adds wall-clock pauses, a visible state badge, a status live region, per-row pass/fail paint, `data-statechart-*` attributes, and hash deep-links that a `runScenario` table cannot show; the Vitest gate clicks `Play all` rather than setting `?autoplay=all`.
- The veneer rendered golden snapshots every showcase element’s resolved computed-style matrix in light and dark, catching token/`var()` resolution a declaration-text cascade snapshot misses.
- The inspector walks a parsed `ParentNode`, evaluates the frozen content-model registry (context/content/transparent/structure/attribute/interaction) plus computed-style presentation rules, and returns severity-ranked `Finding`s; elements and mailbox each dogfood it on their mounted pages.
- `prove` can target a browser Vitest project by path: `inferTestProject` maps `tests/src/browser/…` → `src:browser` and `tests/app/browser/…` → `app:browser` (`helpers.ts:534–539`); `RuntimeStage.#project` (`RuntimeStage.ts:504`) looks that name up with no browser exclusion. The claim test path must be `tests/src/browser/<file>.test.ts` or `tests/app/browser/<file>.test.ts`, and that project must be composed in the root config with the overlay plugin. Prerequisites (`probe.md:418–419`) only spell `tmp/probe/` → `probe` and `tests/src/<environment>/` → `src:<environment>`.
- `@orkestrel/test/browser` already publishes the journey, fixture, color/contrast, cascade, capture, journal, and constructed-event surfaces; it publishes none of the statechart contract, playground harness, inspector, rendered-matrix golden, `data-vn-*` switch proof, or `prove`.
- Mailbox/veneer style setups overlap `style`/`token`/`pixels`/`findRule` but return a boolean from `findRule`/`findKeyframes` and omit `contrast`/`readRing`/`readCascade`.
- Search for `?scenario=` / `?autoplay=` across the seven repos hits only `elements` (`StatechartHarness.vue`, `router.ts`, `guides/showcase.md`, and `playgrounds.test.ts` which clears the hash). No repository drives a Vitest browser test from that URL query.
- Capture portfolios and journals exist only in `test/src/browser/factories.ts`; no sibling imports them.
- `mailbox/guides/styles.md` and `composables.md` describe styling and composable contracts, not a test mechanism.
