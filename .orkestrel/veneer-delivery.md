## Reconciled decisions

The blind planner and analyst reports are in Veneer's tmp/units/veneer-delivery-planner-report.md and veneer-delivery-analyst-report.md. The root read both and their decision-bearing source. This is the single reconciliation; unit briefs close the contracts below rather than repeating a design round.

- Form retains terminal submit/answer. Add an immutable FormSubmission receipt with values and an AbortSignal, FormPreparationResult, pending, prepare(), accept(receipt), abort(receipt), and receipt-aware invalidate(name, message, receipt?). Receipt identity and per-field revisions reject stale completion/error writes. Accept only submitted enabled fields, including their absence, into baseline; leave later values and disabled-field baselines intact. Clear/destroy invalidate and abort pending work. Do not add a second document class, lifecycle mode, rejected/saved flags, or persistence policy. Abort replaces the analyst's cancel verb to follow lifecycle vocabulary and gives consumers a real cancellation signal.
- Native FormBinding owns native control projection, validity, neutral feedback/summary associations, focus and controlled submission. An admitted submit reads and prepares the existing Form, emits its receipt to the application and never acknowledges it. Initial authority is the supplied document. Missing controls preserve logical fields; native disabled/fieldset state excludes mounted controls; locked fields retain logical participation. Bootstrap classes belong to VeneerForm. The application owns persistence and navigation; a page-unload guard may be an explicit Veneer integration over document.dirty.
- Native TableBinding admits one row owner: a provided row renderer for model-owned data, or explicit keyed authored DOM enhancement for the retained column-sort outcome. A readTable projection reads declared header metadata and stable row keys. Both populations use the existing Table managers, retain nodes by key and have no second sorting/filter/selection store. The binding owns placement, native sort/select/details controls, cancellation before sort, focus and teardown. VeneerTable adds Bootstrap state classes and scope only.
- Drag gains a synchronous commit callback for model-owned moves. Require stable keys in that mode; the existing DOM-owned population does not need invented keys merely to retain its current operation. The proposal carries key, source/target hosts, before key, indexes and input origin. Veto precedes commit; verify the resulting keyed order before success. Keep existing move/end events rather than adding an unneeded parallel success API. Peer admission must respect the nearest Veneer scope. Board uses one shared commit callback and keyed renderer. Multi-item and external/file ingestion remain excluded.
- The showcase is one hash-addressed developer workbench with Examples before the complete reference. Use the real responsive offcanvas engine for navigation. Add local navigation search with clear/no-results, preserve stable hashes/inventory and theme choices. Board and Records are honest page-session examples; Settings demonstrates real acknowledged local persistence in IndexedDB. Do not add storage policy to every example merely to exercise a state. Board supports add/edit/move and empty columns; Records supports every applicable core manager and a reversible session bulk update. No fake backend or inert controls.
- Visual direction follows the planner's restrained Bootstrap-blue workbench, adaptive neutrals, system sans/monospace, clear hierarchy and bounded forms. Keep the existing named theme-pack work outside this campaign; redesigning the app does not require completing an unrelated theme library. Add DESIGN.md and UX-CONTRACT.md with runtime token ownership and narrow behavior. Use Bootstrap primitives for summaries/details/panels; new reusable CSS classes require an actual uncovered need.
- Semantic defaults remain element-local and limited to ordinary buttons, text-like inputs, textarea and select. Preserve Bootstrap Reboot for text and tables; cells/rows/compound forms remain class-driven. Utilities must remain composable with defaults. Admit explicit same-element component exclusions backed by the pinned class inventory and cascade tests; do not use classless-only admission that strips base treatment from a spacing utility. Do not infer any component from ancestors or nested semantics.
- enterprise-veneer is a concise procedural skill in Scaffold that loads enterprise-bootstrap and reads the installed Veneer/Form/Table guides and declarations before choosing APIs. It teaches ownership, composition and proof, without freezing an API-symbol tutorial. This resolves the discovered BASE_DEV_DEPENDENCIES fence restriction without extending the policy or installing Veneer in every target. No hidden prose API tutorial bypasses the import validator. Validate skill distribution and use the skill during the showcase implementation.
