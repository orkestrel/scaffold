# Routing ledger — which unit runs on which engine, and why

The contract routes objective, constraint-heavy, mechanical-precision work to GPT-5.6 Sol, and
API-shape, naming, and documentation-voice work to Opus 5. Routing a unit to the wrong engine without a
recorded deviation is a dispatch deviation, so the routing is written down before dispatch rather than
recalled at launch.

| Unit | Subject | Engine | Why |
| ---- | ------- | ------ | --- |
| S1 and its three fix rounds | `RuntimeStage.ts`, then the `Finding` discriminant | Sol, then Opus for rounds 2 and 3 | Rounds 1 and its first fix were process lifetime and cleanup ordering. Rounds 2 and 3 added a discriminant to a published type and rewrote contract prose, which is API shape. |
| S2 | `Probe.ts` — the deadline bounds the queue rather than the work | **Sol** | Concurrency, timer ordering, and what a budget actually covers. Constraint-heavy. |
| S3 | `LintStage.ts` — surviving the Oxlint child's death | **Opus, re-routed** | Was Sol on work class. Re-routed on a measured host constraint: the bench sandbox gives a Node-spawned-Node child no working stdio, so a bench unit cannot arm, drive, or observe the Oxlint child that is this unit's entire subject. It would produce false greens rather than failures. The native `implementer` runs outside that sandbox. |
| S4 | `TypeStage.ts` — the overlay outliving its inspection | **Sol** | Cleanup ordering and map lifetime. |
| S5 | `src/core/**` — the contract describing a package that does not exist | **Opus** | Documentation voice, plus a ruling on whether `Control.reason` is routed or removed. |
| S6 | `src/bin/main.ts` — the entry owning its shutdown | **Opus** | Where a lifecycle belongs on a published surface is an API-shape decision. |
| O9 | candidate-source overlay | To be split at design time | Its objective units go to Sol; its contract shape goes to Opus. |
| U4c | guide and parity | **Opus** | Documentation voice throughout. |

## A routing error caught before it cost a dispatch

The launch scripts for S3 through S6 were generated by copying S2's, which invokes
`codex exec --model gpt-5.6-sol`. That is correct for S3 and S4 and wrong for S5 and S6, whose briefs
name `implementer` — Claude Opus 5.

Deleted `tmp/codex/s5.sh` and `tmp/codex/s6.sh`. Those two dispatch through the harness's native Agent
mechanism with `subagent_type: implementer`, as fix rounds 2 and 3 did, per the native-first rule: never
route a model across a bridge when the running harness hosts it.

Recording it because copying a launch script is exactly how an engine assignment goes wrong silently —
the brief still says Opus, the script says Sol, and nothing reconciles the two at launch.
