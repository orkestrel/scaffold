**Question:** How do you measure TypeScript compile-time and editor-time cost, which library-authoring type techniques have a documented mechanism and measurable effect, and what did Zod v3→v4, ArkType, and ts-toolbelt record — for a published shape DSL whose public types infer values from `Infer<S>` over a `ContractShape` union?

**Evidence:**

1. `tsc --extendedDiagnostics` is the compiler’s own phase and counter dump (`tsc --diagnostics` is the short subset). Official flag text: [tsconfig `extendedDiagnostics`](https://www.typescriptlang.org/tsconfig/#extendedDiagnostics). The wiki’s measurement section: [TypeScript wiki · Performance](https://github.com/microsoft/TypeScript/wiki/Performance). Counters are process-wide for the program you passed (`-p`), not per file.

2. **Types** is the checker’s count of `Type` objects created (`typeCount` in `src/compiler/checker.ts` on the microsoft/TypeScript tree). Every interned/uninterned type the checker allocates increments it: intrinsics, object types, unions, intersections, and instantiated generics that produce a new `Type`. It is not “number of type aliases in source.”

3. **Instantiations** is `instantiationCount` in the same checker: each time a generic type, type alias, mapped type, or generic signature is instantiated with a type-argument list. Nested generics add inner instantiations. This is the counter the wiki points at when Check time is dominated by generics. A cache hit on an identical `(target, type-argument ids)` key does not increment it again; unique `S` in `Infer<S>` therefore scales Instantiations with unique shapes.

4. **Symbols** is the binder’s named-declaration count (variables, types, members, imports — including those from loaded `.d.ts`). It moves with program size and export surface, not with `Infer` depth. Relating it to Check time without a parse/bind split misreads a declaration-volume problem as a generic problem.

5. **Check time** is wall-clock for the type-check phase only (after parse and bind; before emit). **Parse time** scales with tokens in loaded files. **Bind time** scales with declarations. **Program time** covers graph construction. If Check time dominates, types are the subject; if Parse time dominates, `.d.ts`/file volume is the subject. Repeat runs on the same `tsconfig` with `incremental` left on will report a cheaper Check time because of `.tsbuildinfo`; an A/B on types must use `--incremental false` or a wiped cache. The contract baselines used `tsc --noEmit --extendedDiagnostics` (root 69995 types / 108922 instantiations / 8.43 s; core 10632 / 12189 / 1.24 s) — `/home/user/scaffold/.orkestrel/contract/baseline-perf-report.md` — and already note that this is not consumer `Infer` cost.

6. **Memory used** is the `tsc` process JS heap (`process.memoryUsage().heapUsed`, printed in KB). It tracks retained checker caches (assignability, identity, subtype, strict-subtype — also printed as cache sizes in the extended dump), not RSS. It is a leak/retention signal across a single run, not a per-call cost.

7. `--generateTrace <dir>` writes a Chrome Trace Event log plus a type dump into that directory (`trace.json`, `types.json`). Flag: [tsconfig `generateTrace`](https://www.typescriptlang.org/tsconfig/#generateTrace). How-to: [TypeScript wiki · Performance Tracing](https://github.com/microsoft/TypeScript/wiki/Performance-Tracing). Format: [Trace Event Format](https://docs.google.com/document/d/1CvAClvFfyA5R-PhYUmn5OOQtYMH4h6I0nSsKchNAySU). Events use `ph` `B`/`E` or `X` (complete) with `dur` in microseconds; names include `parseSourceFile`, `bindSourceFile`, `checkSourceFile`. `types.json` records type ids, flags, display strings, and instantiation provenance.

8. Reading traces without extra packages: open `trace.json` in Chromium `chrome://tracing` (or DevTools Performance → Load profile); sort complete events by `dur`. `jq` on the same file (`select(.ph=="X")`, sort by `-dur`) lists the slow slices. `types.json` is greppable JSON — look up the type id in a long event’s `args`. `@typescript/analyze-trace` ([microsoft/typescript-analyze-trace](https://github.com/microsoft/typescript-analyze-trace)) only attributes those slices to types; it is not required to read the files.

9. The TypeScript team gates compiler regressions with the same diagnostics plus fixture programs, via [microsoft/ts-perf](https://github.com/microsoft/ts-perf) and the wiki’s [Performance Testing](https://github.com/microsoft/TypeScript/wiki/Performance-Testing) notes. Metrics compared across `tsc` versions: Check time, Instantiations, Types, Memory used, parse/bind. There is no published numeric SLA that says “a library surface is allowed N instantiations.” Pathological reports on the TypeScript tracker are typically millions of instantiations on a small program. The measurable library gate is a **consumer fixture** whose Instantiations and Check time are plotted against shape size (N keys / N-deep nesting), with a control file that does not reference `Infer`.

10. **`interface extends` vs intersection.** Wiki: [Performance · preferring interfaces](https://github.com/microsoft/TypeScript/wiki/Performance). An `interface A extends B, C` is one named object type with a base-type graph the checker can relate by target identity. `type A = B & C` allocates an intersection that is reduced propertywise (conflicts become `never`) and is compared structurally each time. Observable: Instantiations/Check time when many object types are related (assignability, excess-property checks), not when a single `Infer<S>` only walks a tree. Error-message display also stays named for interfaces.

11. **Named type aliases as instantiation caches.** The checker keys the generic-instantiation cache on the alias symbol plus type-argument ids (`getTypeAliasInstantiation` in `checker.ts`). `type Foo<T> = T extends string ? Bar<T> : Baz<T>` computed as `Foo<K>` is reused; the same conditional inlined at every use site is a distinct target. Observable: Instantiations drop when the same `T` recurs; they do not drop when every `T` is a fresh object-literal type (the consumer-shape case). The subject already names `Infer`, `InferObject`, `InferIndex`, `InferOpenIndex`, `InferUnion` for this reason (`/home/user/contract/src/core/types.ts` around the `Infer` remarks).

12. **Distributive conditional types.** Handbook: [Distributive conditional types](https://www.typescriptlang.org/docs/handbook/2/conditional-types.html#distributive-conditional-types). A naked type parameter `T extends U ? X : Y` distributes over a union `T`. Nested distribution is exponential in union width. Tuple wrap `[T] extends [U] ? X : Y` disables it. Observable: Instantiations explode when `S` is a union of shapes; TS2589 (`Type instantiation is excessively deep and possibly infinite`) is the hard stop. The subject’s `[ContractShape] extends [S]` bailout and `[A] extends [boolean | ContractShape]` guards are this mechanism (`types.ts` remarks on `Infer` / `InferIndex` / `InferOpenIndex`). The later `S extends StringShape ? …` chain is still a naked `S extends …` and **does** distribute for a partial union `S`. `InferUnion` (`U extends ContractShape ? Infer<U> : never`) distributes by design over variants.

13. **Variance annotations (`in` / `out`).** [TS 4.7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-4-7/#optional-variance-annotations-for-type-parameters); implementation PR [microsoft/TypeScript#45236](https://github.com/microsoft/TypeScript/pull/45236). Explicit variance skips inferring variance by walking every use of the type parameter, and lets `G<A> <: G<B>` reduce to a single relating of `A` and `B` (covariant / contravariant / invariant). Observable: cheaper assignability between two instantiations of the **same** generic interface/class/alias. It does not shorten the conditional walk inside `Infer<S>`. For a DSL whose cost is instantiating `Infer` rather than relating `Infer<A> <: Infer<B>`, this counter often will not move.

14. **Large unions.** Relating union U (n constituents) to union V (m) is n×m `structuredTypeRelatedTo` work. Excess-property checks against a union of object types repeat per constituent. Discriminated unions (handbook: [Discriminated unions](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions)) let the checker discard constituents that fail the discriminant, which cuts that n×m when a tag is present. `ContractShape` is already a `type`-tagged union of interfaces (`types.ts` `ContractShape`). Observable on value checking / assignability to `ContractShape`; instantiating `Infer<SpecificShape>` on a single constituent is a different axis. Mapped-type `as` remapping (`[K in keyof P as P[K] extends { type: 'optional' } ? never : K]` in `InferObject`) is non-homomorphic: it allocates a new object type instead of the homomorphic `keyof T` fast path (TS 4.1 mapped `as` clauses). That is a Check-time/Instantiations candidate under objects with many keys.

15. **Recursion depth and tail-recursive conditional types.** TS2589 fires when instantiation depth exceeds the checker’s recursive limit (historically on the order of the depth constant in `checker.ts`; read the installed 6.0.x file for the exact number). [TS 4.5 TRE](https://devblogs.microsoft.com/typescript/announcing-typescript-4-5/#tail-recursion-elimination-on-conditional-types), PR [microsoft/TypeScript#45711](https://github.com/microsoft/TypeScript/pull/45711): a conditional whose recursive branch **is** the whole true or false arm is executed as a loop with a much higher iteration cap. `ReadonlyArray<Infer<I>>`, intersections, and mapped types around a recursive `Infer` are **not** tail position, so TRE does not apply to the current `Infer` tree. Observable if rewritten to tail form: TS2589 on deep tuples/lists moves from ~depth-limit failure to “completes, Instantiations ≈ steps.”

16. **`const` type parameters.** [TS 5.0 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-5-0/#const-type-parameters), PR [microsoft/TypeScript#51865](https://github.com/microsoft/TypeScript/pull/51865). `function f<const S extends ContractShape>(s: S)` infers the literal shape instead of widening. This is a precision feature, not a cheaper one. Observable: more unique `S` arguments → more `Infer<S>` cache keys → Instantiations **rise** toward the true consumer cost. Widening to `ContractShape` hits the subject’s `[ContractShape] extends [S] ? unknown` cheap path and **under-measures** Infer (and infers `unknown`).

17. **Generic function instantiation caching.** Instantiated signatures are cached by target + type-argument ids, same as type aliases. Repeated `f(shape)` with the same inferred `S` reuses work; a new object-literal shape is a new key. Overloads and contextual typing add extra instantiations per call site. `NoInfer<T>` ([TS 5.4](https://devblogs.microsoft.com/typescript/announcing-typescript-5-4/#noinfer-utility-type)) can stop a parameter from participating in inference, which sometimes cuts extra instantiations from oversized inference.

18. **Declaration (`.d.ts`) size.** Parse time and Files/Symbols scale with the loaded declaration graph. A single rolled-up `index.d.ts` is parsed even for one import. Subpath `exports` can load less. Isolated Declarations ([TS 5.5](https://devblogs.microsoft.com/typescript/announcing-typescript-5-5/#isolated-declarations)) speed **emit** of `.d.ts` for the library author, not consumer Check time of `Infer<S>`. Consumer Check time of a published library is: parse the `.d.ts` once + instantiate exported types at use sites in **consumer `.ts` files**.

19. **`skipLibCheck`.** [tsconfig `skipLibCheck`](https://www.typescriptlang.org/tsconfig/#skipLibCheck): skip **type-checking** `.d.ts` files. It does not skip parsing them, and it does not skip instantiating their exported generics from consumer source. `Infer<typeof myShape>` is checked in the consumer file; `skipLibCheck` does not hide it. It does hide errors and check work **inside** the library’s `.d.ts` (duplicate `@types`, internal assignability). The contract package itself sets `"skipLibCheck": true` in `tsconfig.json`. `skipDefaultLibCheck` is only `lib.d.ts`.

20. **Editor-time.** The language service is a request server (`completionInfo`, `quickinfo`, `semanticDiagnosticsSync`, `geterr`, `definitionAndBoundSpan`). Logging: [Logging in the TypeScript Language Service](https://github.com/microsoft/TypeScript/wiki/Logging-in-the-TypeScript-Language-Service) — `TSS_LOG="-level verbose -file …"` or VS Code “TypeScript: Open TS Server log”; each request has an elapsed time. Wiki editor notes live on the same [Performance](https://github.com/microsoft/TypeScript/wiki/Performance) page. What dominates for a library consumer: (a) semantic check of files that instantiate library generics (same work as `tsc` Check time on that file); (b) `typeToString` when Quick Info/completions print a huge inferred object type; (c) auto-import enumerating export tables (`includeCompletionsForModuleExports`) — fat barrels and `export *` scale this; (d) program size (file count, project references vs one graph). `skipLibCheck` still does not skip (a) for the file being edited.

21. **How library authors measure editor-time.** A tiny consumer fixture (one file, one large shape, `Infer<typeof s>` on a value). Measure `tsc --extendedDiagnostics` on that fixture for the check-equivalent cost. For the editor: start tsserver against that fixture, trigger hover and completions, read request elapsed in the log. tsserver can also emit traces (wiki Performance Tracing, language-service tracing). Auto-import cost is measured with completions that request module exports, not with `tsc`. Memory: `typescript.tsserver.maxTsServerMemory` only caps the process; it does not measure the library.

22. **Zod v3 vs v4 (types).** Primary: [zod.dev/v4](https://zod.dev/v4), [colinhacks/zod](https://github.com/colinhacks/zod). v3 encoded schemas as classes with multiple type parameters (`Output`, `Def`, `Input`); method chains (`.min().optional()`) instantiated a new generic at each step, so Instantiations tracked method depth × schema width, and recursive `z.lazy` often hit TS2589 unless annotated as `z.ZodType<T>`. v4 rewrote that surface (`z.core`, fewer params carrying the schema tree in `Def`, `z.output` / `z.input`, `zod/mini` with a smaller method/type surface). Documented techniques: cut generic parameters on the core type, stop putting the whole AST in a `Def` parameter, offer a mini surface so unused methods are not part of the type, keep **explicit** `discriminatedUnion` rather than a wide untagged union, annotate recursive schemas to a named `ZodType<T>` so inference does not walk the cycle. Runtime JIT is out of scope here; the type rewrite is the compile-time artifact.

23. **ArkType.** Primary: [arktype.io/docs/intro/why](https://arktype.io/docs/intro/why), [arktypeio/arktype](https://github.com/arktypeio/arktype). Type-level string parsing of `'foo | bar'` is an extra instantiation-heavy pass; the object-literal syntax skips that parser. Named scopes/aliases are used as instantiation caches. Union discriminants are extracted automatically (runtime and types). Maintainers treat Instantiations/`tsc --extendedDiagnostics` on fixture schemas as the gate; recursive and wide-union cases are bounded with named intermediates rather than one giant conditional.

24. **ts-toolbelt.** Primary: [millsp/ts-toolbelt](https://github.com/millsp/ts-toolbelt) (`Iteration` module). Numeric recursion `N extends 0 ? … : Rec<N-1>` hits TS2589; they iterate with an `IterationMap` / position object so each step is a named alias lookup, not deeper instantiation. Utilities are split per file so a root barrel is not forced on consumers (parse + auto-import). Named aliases per operation, tuple-wrapped non-distribution, and a `Compute`/`Force` flatten for display (eager flatten can **raise** Instantiations while shrinking hover strings — two different metrics).

**Distillate:**

**Q1 — Measurement.** Use `tsc --noEmit --extendedDiagnostics -p <isolated consumer tsconfig>` as the library-author instrument. Read **Check time** as what humans feel, **Instantiations** as the generic-expansion counter, **Types** as allocated `Type` objects, **Symbols** as bind/declaration volume, **Memory used** as checker-heap retention. Parse vs Check tells `.d.ts` volume apart from `Infer`. Disable incremental for A/B. `--generateTrace dir` + Chromium `chrome://tracing` (and `jq` on `dur`) is the no-package zoom; `types.json` ids name the hot type. ts-perf is how the compiler team diffs `tsc` versions on fixtures — reuse its metrics, not a published instantiation cap. No citable “too many Instantiations per library surface” number exists; gate a consumer fixture’s Instantiations and Check time against shape width/depth, with a no-`Infer` control. The package’s own root/core baselines do not substitute for that fixture.

**Q2 — Library-authoring techniques (mechanism → observable).** `interface extends` vs `&`: cheaper **relating** of object types, measured on assignability/excess-property Check time — weak lever if the hot path is only instantiating `Infer`. Named aliases: instantiation-cache hits when type arguments repeat; miss when every consumer shape is unique. Distributive conditionals: exponential Instantiations / TS2589 on union `S`; tuple wrap and the full-union bailout are the documented bounds — already in this `Infer`. Variance `in`/`out`: cheaper `G<A> <: G<B>`; little effect on a one-shot `Infer<S>` walk. Large unions: n×m relating; discriminants cut that; mapped `as` remapping is a separate per-key allocation vs homomorphic maps — measure on N-key objects. TRE: only if the recursive conditional is in tail position; current `Infer` wrappers are not. `const` type parameters: correct literal `S`, more Instantiations; widening falsely cheap-paths to `unknown`. Generic-function cache: same as aliases; unique literals never hit. `.d.ts` size: Parse/Symbols/auto-import, not `Infer` Check time. `skipLibCheck`: skips checking `.d.ts`, never skips consumer `Infer`.

**Q3 — Editor-time.** Consumer editor lag from this kind of library is the same `Infer` instantiation on the file being edited, plus `typeToString` on huge inferred object types (hover/completions), plus auto-import scan of the export table, plus program size. Measure with an isolated fixture: `extendedDiagnostics` for the check-equivalent; tsserver verbose log elapsed on `quickinfo` / `completionInfo` / `semanticDiagnosticsSync` for the editor-equivalent. Fat barrels show up on completion-with-auto-import, not on `tsc` Instantiations.

**Q4 — Prior art.** Zod v4: fewer generics on the schema type, no `Def` AST-in-the-type, mini surface, named recursive annotations, explicit discriminated unions — Instantiations tracked method-chain depth in v3. ArkType: avoid the string-parser types when object syntax suffices; named scopes as caches; treat Instantiations as the gate. ts-toolbelt: replace depth-recursive number loops with mapped iteration objects; split modules; do not confuse display-flatten (`Compute`) with cheaper checking.
