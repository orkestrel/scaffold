**Question:** What primary-source methodology, Node 22 instruments, V8 hot-path techniques, and Zod/Valibot/ArkType prior art apply to measuring a TypeScript validation library?

**Evidence:**

1. V8 compiles JS through Ignition (bytecode interpreter), Sparkplug (non-optimizing baseline compiler), Maglev (mid-tier optimizing JIT), then TurboFan (top-tier optimizing JIT). Sparkplug: https://v8.dev/blog/sparkplug — Maglev: https://v8.dev/blog/maglev — Ignition/TurboFan launch: https://v8.dev/blog/launching-ignition-and-turbofan
2. A microbenchmark that loops inside one function can compile via on-stack replacement (OSR), which is a different compilation entry than the call-and-return path a library actually serves. V8 documents OSR as a Sparkplug/TurboFan concern in the Sparkplug post (https://v8.dev/blog/sparkplug). Vyacheslav Egorov’s microbenchmark pitfalls: https://mrale.ph/blog/2012/12/15/microbenchmarks-fairy-tale.html
3. TurboFan dead-code-eliminates a body whose result is unused. Egorov’s rule is to keep a live sink; otherwise the bench times an empty optimized function (https://mrale.ph/blog/2012/12/15/microbenchmarks-fairy-tale.html). Google Benchmark’s `DoNotOptimize` is the same idea in C++ (https://github.com/google/benchmark/blob/main/docs/user_guide.md#preventing-optimization).
4. `--trace-opt` / `--trace-deopt` / `--trace-turbo` show when a function is optimized, deoptimized, and recompiled. V8 tracing docs: https://v8.dev/docs/trace — profiling: https://v8.dev/docs/profile
5. Type feedback and inline caches live on the isolate. Node’s `vm` module shares the process isolate; a new isolate requires a new process. Node `vm` docs: https://nodejs.org/docs/latest-v22.x/api/vm.html — V8 isolate model: https://v8.dev/docs/embed
6. Running two variants of the same source in one process can pollute a load/call site from monomorphic to polymorphic to megamorphic. Mathias Bynens (V8): https://mathiasbynens.be/notes/shapes-ics
7. `process.hrtime.bigint()` and `performance.now()` are wall-clock elapsed time, not CPU time. CPU time is `process.cpuUsage()` (`user` + `system`, microseconds). Node 22: https://nodejs.org/docs/latest-v22.x/api/process.html#processhrtimebigint — https://nodejs.org/docs/latest-v22.x/api/process.html#processcpuusagepreviousvalue — `perf_hooks`: https://nodejs.org/docs/latest-v22.x/api/perf_hooks.html
8. Allocation/retained size: `process.memoryUsage().heapUsed` after a forced GC (`node --expose-gc` then `globalThis.gc()`), `v8.getHeapStatistics()` / `v8.getHeapSpaceStatistics()` / `v8.getHeapCodeStatistics()`, `v8.writeHeapSnapshot()`. Node 22: https://nodejs.org/docs/latest-v22.x/api/process.html#processmemoryusage — https://nodejs.org/docs/latest-v22.x/api/v8.html
9. GC: `PerformanceObserver` with `type: 'gc'` (entry `detail.kind` / flags); `v8.GCProfiler` start/stop JSON; `--trace-gc` / `--trace-gc-nvp` / `--trace-gc-verbose`. Node 22: https://nodejs.org/docs/latest-v22.x/api/perf_hooks.html — https://nodejs.org/docs/latest-v22.x/api/v8.html#class-gcprofiler — V8 GC tracing: https://v8.dev/docs/trace
10. IC/deopt: `--trace-ic`, `--trace-maps`, `--trace-deopt`, `--log-ic`, `--allow-natives-syntax` with `%GetOptimizationStatus`, `%OptimizeFunctionOnNextCall`, `%PrepareFunctionForOptimization`, `%HasFastProperties`, `%DebugPrint`. V8: https://v8.dev/docs/trace — natives in `v8` source `src/runtime/runtime.h` (https://github.com/v8/v8/blob/main/src/runtime/runtime.h). `%GetOptimizationStatus` is a bitfield (`kOptimized`, `kTurboFanned`, `kInterpreted`, Maglev bits, deopt marks) defined with the runtime.
11. Import/startup: `performance.nodeTiming` (`nodeStart`, `v8Start`, `environment`, `bootstrapComplete`); `performance.mark`/`measure` around `await import(...)`; `node --cpu-prof` / `--heap-prof`; Node 22 module compile cache `module.enableCompileCache()`. Node 22: https://nodejs.org/docs/latest-v22.x/api/perf_hooks.html#performancenodetiming — https://nodejs.org/docs/latest-v22.x/api/module.html#moduleenablecompilecachecachedir. Fresh-process import is required because the ESM module map and isolate code cache persist in-process.
12. tinybench (used by Vitest bench; lockfile here pins `tinybench@2.9.0` via Vitest): configurable `warmupTime` / `warmupIterations`, then samples until `time`/`iterations`; default clock `performance.now()`; reports mean, sd, sem, moe/rme via Student’s t, min/max and high percentiles. It does not spawn processes, does not force GC, and by default times one call per sample (timer overhead dominates sub-microsecond bodies). https://github.com/tinylibs/tinybench — Vitest: https://vitest.dev/guide/features.html#benchmarking
13. mitata: warmup, optional `gc()` between runs, batched iterations so timer resolution does not dominate, a live sink against DCE, percentile table (min/avg/p75/p99/…), and on Linux optional hardware cycle counters. Package: https://www.npmjs.com/package/mitata
14. Hidden classes (V8 Maps): property insertion order produces distinct shapes; `{a then b}` is not `{b then a}`. Fast properties vs dictionary mode: https://v8.dev/blog/fast-properties — shapes and ICs: https://mathiasbynens.be/notes/shapes-ics
15. Load/Call ICs: monomorphic (one map/target) → polymorphic (a small map set; V8’s polymorphic cap is a handful of maps) → megamorphic/generic. A generic walker that does `value[key]` for many schemas at one site goes megamorphic; a per-schema compiled function keeps each `value.email`-style load monomorphic. Same posts as (14); optimization patterns: https://benediktmeurer.de/2016/10/31/javascript-optimization-patterns-part-1/
16. `delete obj.x` typically moves the object to dictionary (slow) mode; assigning `undefined` keeps the shape. https://v8.dev/blog/fast-properties
17. `Object.freeze` / `Object.seal` transition the object to a new integrity-level map (`JSObject::SetIntegrityLevel` in V8). Loads of data properties on frozen objects use the fast path in modern V8; freeze is not a load-speed win versus a same-shape mutable object. Freeze after an IC has seen the unfrozen map splits shapes and can deopt that site. Fast properties post: https://v8.dev/blog/fast-properties. Subject library freezes released empty sentinels and published schema (`/home/user/contract/src/core/ContractCompiler.ts:167-179`, `types.ts:1014-1015`).
18. A new closure allocates on creation. Compile-once closures over child plans amortize to zero per validate; per-input `return (v) => …` does not. V8 lazy parsing: https://v8.dev/blog/preparser. Subject: artifacts “close over the CHILD entries” at compile time (`ContractCompiler.ts:203-206`, `types.ts:1081-1083`).
19. Direct `fn(x)` is a CallIC TurboFan can inline. `fn.call` / `fn.apply` / `Reflect.apply` are extra calls; `Reflect.apply` also builds the arg list via `CreateListFromArrayLike`. Inlining lives in V8 `src/compiler/js-inlining.cc` (https://github.com/v8/v8/blob/main/src/compiler/js-inlining.cc). Subject hot path dispatches `WeakMap.prototype.get/set` through `INTRINSICS.apply` (`constants.ts:122-123,198-201`, `ContractCompiler.ts:605-608,968-970`).
20. `WeakMap.get/set` is an identity hash lookup (ephemeron table), not a property IC. Fast for “have I seen this object” when the object must not be mutated; slower than an in-object field or a packed-array index. Weak refs: https://v8.dev/features/weak-references. Subject uses WeakMap for shape→index and per-call object memos (`ContractCompiler.ts:196-201,589-608`).
21. Array element kinds (PACKED/HOLEY × SMI/DOUBLE/ELEMENTS, then dictionary) transition one way to more general kinds; holey/object kinds slow indexed loops. https://v8.dev/blog/elements-kinds
22. `a + b` builds ConsString ropes; flattening happens on indexing/`length` in some paths. Hot success guards that never build messages do not pay this; `audit`/`explain` path strings do. V8 string discussion in the one-byte/two-byte and concatenation work; see also elements/strings coverage in https://v8.dev/blog
23. try/catch is not an optimization killer under TurboFan (that was Crankshaft). A throw remains expensive (unwinding). A try around a path that does not throw has a small leftover cost. https://v8.dev/blog/launching-ignition-and-turbofan — Meurer optimization patterns: https://benediktmeurer.de/2016/10/31/javascript-optimization-patterns-part-1/. Subject uses try/finally on the tracked-guard object path (`ContractCompiler.ts:599-612`).
24. Rest/spread allocates; `fn(...arr)` and `arguments` inhibit the fixed-arity call path. Rest/spread: https://v8.dev/features/rest-parameters-spread. Subject oneOf uses an indexed loop; `unionOf` is applied with the guards array rather than spread (`ContractCompiler.ts:961-970`).
25. Accessor get is a call; a data property is a field load. `compiler.guard(v)` re-enters the getter every time; `const g = compiler.guard; g(v)` / a frozen bundle data property does not. Shapes/ICs: https://mathiasbynens.be/notes/shapes-ics. Subject: compiler members are getters; `contract` is a frozen six-member bundle of those artifacts (`types.ts:1091-1105`).
26. Simple `const {a} = obj` is loads; `{...rest}` allocates and copies. Object rest/spread: https://v8.dev/features/object-rest-spread
27. `for-of` on arrays goes through the iterator protocol (`next`); TurboFan has array-iterator fast paths, still typically behind `for (i; i < length; i++)` on PACKED arrays. Indexed vs iterator is the measurable split. Related V8 for-in work (different protocol): https://v8.dev/blog/fast-for-in
28. Class `#private` is a brand check plus a slot; on monomorphic `this` V8 stores privates in-object and access is close to a named field. A `WeakMap`-per-instance private pattern is a hash lookup. Class fields: https://v8.dev/features/class-fields. Subject `#` fields are compiler working state released after compile; compiled artifacts are not supposed to read them (`ContractCompiler.ts:203-206`, `types.ts:1077-1083`).
29. Zod 4 rewrite (docs at https://zod.dev/v4, source https://github.com/colinhacks/zod): new parser internals vs Zod 3’s recursive `._parse` + issue objects; `zod/mini` drops method-heavy schema instances; `discriminatedUnion` on a key remains the tagged-union fast path (already in Zod 3, kept in 4). Zod 4.5 is a follow-on line on that parser; this session did not re-read a 4.5 changelog.
30. Valibot (https://valibot.dev, https://github.com/fabian-hiller/valibot): one small function per schema combinator (tree-shaking, fewer schema-object methods); still an interpreter over those functions, not eval/codegen in core; `parser` / `safeParser` skip some error-formatting work on the success path. Comparison notes: https://valibot.dev/guides/comparison
31. ArkType (https://arktype.io, https://github.com/arktypeio/arktype): JIT-compiles type syntax to specialized validators; automatic discriminant extraction for unions; morphs compiled into that function. Intro/rationale: https://arktype.io/docs/intro/why
32. Same-domain public bench corpus (schema compile vs interpret, discriminated unions, allocation): https://github.com/moltar/typescript-runtime-type-benchmarks

**Distillate:**

**Q1 — trustworthy V8/Node microbenchmarks.** Warmup until `--trace-opt` shows TurboFan (or Maglev) and `--trace-deopt` stays quiet; then measure. Time the real call-and-return, not a giant inner loop that OSRs. Keep the result in a sink so TurboFan cannot delete the body. Treat mean as outlier-sensitive (GC pauses); report median or a high percentile plus CV (`sd/mean`) and discard a run whose CV is not small and stable across windows. Force-GC only between rounds, never inside the timed call, unless GC tax is the claim. One variant per Node process: `vm` is not an isolate. tinybench: warmup then `performance.now()` samples, t-interval, one call per sample unless you batch yourself. mitata: warmup, batching, DCE sink, percentiles, optional `gc()` and CPU cycles. Neither library gives you process isolation or formal steady-state change-point detection.

**Q2 — metric catalog (Node 22).** Elapsed ns: `process.hrtime.bigint()` (preferred over `performance.now()` for ns integers). CPU µs: `process.cpuUsage()`. Function timing helper: `perf_hooks.performance.timerify` + `PerformanceObserver`. Allocated/retained: `gc()` then `process.memoryUsage().heapUsed` delta; heap layout via `v8.getHeapStatistics` / `getHeapSpaceStatistics`; retained graph via `v8.writeHeapSnapshot()`. GC: `PerformanceObserver` `gc` entries, `v8.GCProfiler`, `--trace-gc-nvp`. IC/deopt: `--trace-ic` / `--trace-deopt` / `%GetOptimizationStatus` under `--allow-natives-syntax`. Startup: fresh process, `performance.nodeTiming` plus marks around `import()`, `--cpu-prof`, compile cache off if you are measuring cold import. Event-loop delay (`monitorEventLoopDelay`) only matters if the library yields; a pure CPU validator will not show it.

**Q3 — techniques vs this library’s hot paths.** The observable win is almost always “keep the validate call site monomorphic and allocation-free,” not freeze or `#private`. Per-schema compiled functions (what `ContractCompiler` already emits) exist so each property load/call IC sees few maps — a generic `value[key]` walker is the megamorphic case. Freeze stabilizes published graphs; it does not speed loads and it splits maps if the same IC also sees unfrozen clones. `delete` and dictionary mode belong on working objects, not on user values. Closures should be created at compile (already true for artifacts). `compiler.guard(v)` pays a getter each time; the frozen `contract` bundle’s `is` is a data property. `Reflect.apply(WeakMap.prototype.get, memo, [value])` on every object node (`#trackGuard`) is a measurable apply+hash versus a direct `memo.get(value)` or an indexed packed array. WeakMap identity memos are the right tool for cycles without mutating user objects; they are not free. try/catch/finally around hostile reads matters when it throws, not on the stable-data success path. Spread/iterator/`{...rest}` matter when they run per value; the oneOf indexed loop is the cheap shape. String ropes matter in `audit`/`explain`, not in a boolean guard that does not build paths. `#private` is compile-time working state once the artifact is closed-over arrays. Array element kinds matter for packed result/fault arrays the library allocates, not for arbitrary user arrays.

**Q4 — prior art.** Zod 4: rewritten interpreter, fewer allocations than Zod 3, mini build, explicit discriminated unions. Valibot: tiny combinator functions, success-path parsers, no codegen. ArkType: compile-to-function plus automatic union discriminants — the closest analogue to “compiler emits a frozen method bundle.” Cross-library numbers live in moltar’s runtime-type benchmarks, which must be read with Q1’s isolation/DCE/warmup caveats.
