## Ruling

Primary sources establish, without needing local measurement, that the installed `vite-plugin-dts` chain calls the project's own installed `typescript` in-process through `unplugin-dts` → `@volar/typescript`, and that TypeScript 7.0 ships no such in-process API until an unscheduled 7.1 (devblogs.microsoft.com/typescript/announcing-typescript-7-0, read 2026-09-06); this chain is the one the brief names as breaking, and no primary source found under this fetch budget shows the maintainers have closed that gap, so treat the "auto fallback" claim surfaced by search as unverified. `api-extractor` 7.59.0 also calls TypeScript in-process, but against its own bundled 5.9.3 dependency rather than the project's, so a bare `typescript` range bump on the project side does not by itself feed TypeScript 7 into `api-extractor`'s compiler — the risk there is only real if the owner points `typescriptCompilerFolder` at the project's own install. `rolldown-plugin-dts` 0.28.5 carries the cleanest default dependency footprint (no `typescript` in its own `dependencies`) and ships a documented, if labeled "experimental," `tsgo` generator mode for TypeScript 7, alongside a `tsc` mode for today, and a `dtsInput` option that can bundle pre-emitted `.d.ts` files the way `api-extractor`'s rollup does.

The open questions the Orchestrator must measure locally, because no primary source resolved them under this fetch budget: (1) whether TypeScript 7's native `tsc` supports `--declaration --emitDeclarationOnly` at release, which every chain in this matrix depends on somewhere upstream — secondary sources disagree with each other on this; (2) whether `api-extractor`'s `bundledPackages` config and its `import`/`import type` rollup rule can reproduce the exact `beforeWriteFile` rewrite the workspace uses today at `vite.server.config.ts:15-19`; (3) whether `rolldown-plugin-dts`'s Vite 8 integration (`build.lib`, which itself ships no built-in `.d.ts` option per `vite.dev/guide/build.html`, read 2026-09-06, confirmed for Vite 8.2.2) can reach the workspace's `rolldownOptions.external` boundary shape already used at `vite.core.config.ts:32-37`; and (4) whether `unplugin-dts`'s claimed TS 7 fallback exists and what it falls back to.
