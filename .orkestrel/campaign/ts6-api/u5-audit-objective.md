## Findings outside the claims

**F1. The reader's whole contract rests on one unmeasured assumption: that the parser's `start`/`end` are UTF-16 code-unit offsets. `tests/setupServer.ts:931-935,953`.**
`parameters`, `returns`, and `text` are all `source.slice(node.start, node.end)`. If the parser reports UTF-8 byte offsets, every slice is shifted by one byte for each multi-byte character earlier in the source. This repository has no precedent to inherit: `configs/helpers.ts:832` drives `parseSync` with a `Visitor` and reads node values, never spans. Every source in `tests/setupServer.test.ts:135-253` is ASCII, so the reader's tests cannot distinguish the two readings. The consequence is not uniformly loud: a shifted `text` produces a syntax error at transform or load, but a shifted `returns` produces a wrong string that compares unequal to `'UserConfig'` at `tests/src/core/templates.test.ts:537` — an empty finding, which is the vacuous pass that assertion exists to prevent. What right looks like: add one case to `tests/setupServer.test.ts` whose source carries a non-ASCII character before the declaration — an em dash in a leading comment, which this repository's prose style produces — and assert `text`, `parameters`, and `returns` for the declaration that follows it. That test is the control the reader currently lacks, and it costs four lines.
