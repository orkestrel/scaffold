## The owner's instruction

"I want us to stay on version 6.0.3 but I want us to get rid of the in-process JavaScript API that we depend on from typescript since it will not be in version 7. First provide a plan on how to get rid of the in-process JavaScript API that won't be in version 7 but still keeping all on 6.0.3."

## The constraint that shapes every answer

Every replacement must use only a surface that exists in both `typescript` 6.0.3 and 7.0.2, so the fleet can move to 7 later by changing one range. What both ship: the `tsc` command (`--noEmit -p`, `--pretty false` diagnostics, `--showConfig`, `--incremental --tsBuildInfoFile`, `--declaration --emitDeclarationOnly --outDir`), Node's `stripTypeScriptTypes`, oxlint's JS plugin surface, api-extractor's own bundled engine, and the runtime (`import()` of an installed package). What 6.0.3 has and 7 drops: every `import ts from 'typescript'` member the fleet calls (`createProgram`, `createSourceFile`, `forEachChild`, `transpileModule`, `createLanguageService`, `readConfigFile`/`parseJsonConfigFileContent`, `ts.sys`, `getPreEmitDiagnostics`, `flattenDiagnosticMessageText`, `canHaveModifiers`/`getModifiers`, the `SyntaxKind` walk), `tsserver`'s own protocol, and `unplugin-dts`'s `createProgram` emit. What 7 has and 6.0.3 lacks: `typescript/unstable/*` and the LSP server, so neither is available now. `@typescript/typescript6` is banned. A new npm package (`oxc-parser`) needs the owner's explicit request; name it only as an alternative.

## Decisions the plan must take, each with its rationale and its cost

1. **Probe's type stage on the `tsc` process.** The stage checks in-memory drafts today through a language-service overlay. With the `tsc` command the drafts must be on disk: write the case and the control to their revision paths beside the declared path (the runtime stage's own mechanism), generate a scratch `tsconfig.json` that `extends` the caller's project and adds the revision files, run `tsc --noEmit --pretty false -p <scratch>` with `--incremental --tsBuildInfoFile` under `tmp/probe/`, parse `file(line,col): error TSnnnn: message` lines into `Issue` records mapped back to the declared path, and read `Project.digest` from `tsc --showConfig` over a canonical serialization. Decide the deadline budget against the measured cold and warm costs, what `Toolchain.typescript` and the receipt read, how the scratch config keeps the project's `include`/`files` semantics, how a draft that imports a sibling draft resolves, what the stage does with the buildinfo across inspections and across claims, and how the boot control proves the instrument. Name what the published `probe` types stop importing.
2. **The generated distribution proof and `database/tests/setupServer.ts`.** Without a checker: the value-export walk becomes a runtime `import()` of the installed package reading `Object.keys`, and the type-level proof becomes `tsc --noEmit` over a generated consumer that imports each documented name (`import type` for types, a value reference for values); the three resolution drivers become three scratch `tsconfig.json` files. Decide what each site loses (the `SymbolFlags.Value` distinction, the alias resolution) and how the guide fences' type checks in `database` are expressed.
3. **The AST-shaped rules.** The vendored policy sweep's AST rules move to the oxlint `policy` plugin (`ROADMAP.md` names it), rewritten with `RuleTester` controls; the text- and path-shaped rules stay with no compiler; the registers get one home. For the generated-text lifts in `tests/guides.test.ts` and `tests/src/core/templates.test.ts` and for `lsp/tests/setupConformance.ts`'s import walk, only a text scan is available without a new dependency: decide the scan's shape against text scaffold itself writes and the formatter pins, and name `oxc-parser` as the alternative the owner would have to request.
4. **Fences.** `stripTypeScriptTypes({ mode: 'transform' })`; the `vm` CommonJS sites become scratch `.mjs` modules imported by `pathToFileURL`; `MINIMUM_NODE_VERSION` rises to `22.13.0`.
5. **Declarations.** `tsc` 6.0.3 emits, api-extractor rolls up with its own engine through a `declarationBundle` Vite plugin in the vendored `configs/helpers.ts` that keeps the per-face `core/index` → `@orkestrel/<pkg>` rewrite; `vite-plugin-dts` goes. Decide the api-extractor configuration shape (the core `types: ['node']` override, `typescriptCompilerFolder` pointing at the workspace's own 6.0.3 for the lib folder or left to the bundled engine) and the bump consequence (`import type` on external imports is a material declaration diff).
6. **Order.** `scaffold` first (vendored bytes, templates, seeds), `probe` second, then the fleet visit per package (re-pin scaffold and probe, `repair`, regenerate the proof in the same step, edit the package-owned `configs/src/vite.*.config.ts`, mirror refresh, gates, rebuild, diff, bump, publish in catalog layer order). `database` and `lsp` carry source work beyond the pair.
7. **What the proposal's TSDoc reader becomes.** `PROPOSAL.md` plans a TSDoc reader; under this constraint its control path is an oxlint JS plugin rule reading doc comments (`getJSDocComment`/`getAllComments`), never the compiler API. Name the sentence set that changes.
