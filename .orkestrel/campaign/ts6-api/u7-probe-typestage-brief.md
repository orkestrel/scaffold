## What is fixed

- **The mirror.** Per inspection the stage refreshes a mirror of the workspace under `<workspace>/tmp/type/<pid>/` by content digest (reuse the walk and digest map `RuntimeStage.#snapshot` runs), writes each `subject.files` draft and `subject.test` at its mirrored declared path (so a draft shadows the file it replaces and a draft importing a sibling draft resolves to the sibling draft), symlinks or resolves `node_modules` through the workspace (the mirror sits inside the workspace, so the walk up reaches it), writes one scratch `tsconfig.json` per selected project that `extends` the mirrored project file and re-roots `rootDir`, `include`, `files`, `paths`, `incremental`, and `tsBuildInfoFile` into the mirror (the measured shape is `instruments/mirror-scratch-tsconfig.json`), runs `tsc` per distinct selected project exactly as `#inspect` selects today, and deletes the mirror at teardown; the pid rule sweeps a stale one at boot. Nothing is written outside `tmp/`. `tmp/type/` rather than `tmp/probe/`, because the `probe` Vitest project collects `tmp/probe/**/*.test.ts`.
- **The spawn.** `process.execPath` with the workspace's `typescript/bin/tsc` JavaScript entry (a JavaScript entry on 6.0.3 and on 7.0.2), resolved through `resolveWorkspaceBinary(workspace, 'typescript', 'tsc')`: the helper gains a `command` parameter defaulting to the package name, because `typescript` publishes its binary under the key `tsc` and the helper's own `@example` records the throw. Spawn with `cwd` = the mirror root, so every printed path is mirror-relative, which equals workspace-relative. `destroy` terminates the running child (by process tree on Windows, per the portability rule). The event loop is free while the child runs, which closes the Oxlint `initialize` deadline the whole suite misses on a four-CPU host (the type warm no longer holds the loop); keep the destroyed-stage refusal at each candidate boundary.
- **The parser**, from `m3m4-report.md`: a diagnostic line is `path(line,col): error TSnnnn: message` on stdout, line and column 1-based, the column in UTF-16 code units (lower both to the 0-based UTF-16 coordinates `Issue.range` fixes; `end` equals `start`, the point the contract already admits); elaboration lines follow indented and join the message; a diagnostic whose path is the project file (TS1005 on malformed JSON, TS5023 on an unknown option, TS18002 with no inputs) and a line with no location prefix (`error TS5083`, `error TS5058`) are workspace faults (`origin: 'workspace'`, `code: 'malformed'`, `path: project`), never candidate issues; the exit code is not the verdict (2 on 6.0.3, 1 on 7.0.2) — the diagnostic lines are; text on stderr that is not a diagnostic (the 7 platform-package failure shape) is an instrument fault. The text is byte-identical across the majors, so one parser serves both.

Run it against the workspace project so writing drafts into the mirror never changes it. The value moves from today's; update every documented receipt example in `types.ts` and `guides/probe.md`.
