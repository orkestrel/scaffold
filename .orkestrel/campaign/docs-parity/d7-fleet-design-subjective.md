## Design

### Decision 1 — Publish the guide and scaffold first, behind one head-started pilot package

Run the whole per-package chain on **abort** against `--no-save` installs of the guide's and scaffold's packed tips, before the owner publishes anything; then publish `@orkestrel/guide@0.0.18` and scaffold's bump; then run every remaining package against the registry with no head start. A head start per checkout is the expensive shape at fleet scale: each one costs an install, a restore (`npm ci`), and a second full gate run, and every one of them goes stale the moment the guide's source moves — and the guide's source is already known to need one more move (`replaceExample` accepts a body carrying `*/` and emits a source file that does not parse, `d7-guide-converge-report.md:396`). A release the fleet has never exercised is the opposite risk, and one pilot buys the whole of it: abort is the smallest subject (P18 read one lint diagnostic there, its own spec carries one Surface section and one Methods section, `src/core` only), so it exercises the drop-in, the seed, the pin, and the pitch against a package that is not the guide, at the cost of doing one package's work twice. Everything the pilot finds rides into `0.0.18` before it publishes rather than into `0.0.19` mid-pass.

### Decision 2 — Three units per package: a mechanical prelude, a voice pass, one Opus converge

Split by what the diff is made of, not by what the file is. `repair`, the `docs` script row, the own-specifier `paths` entry, the re-pin, the lockfile install, the version bump, and probe's manifest table are fully specified and go to `builder`; the vendored voice rule's red goes to a second `builder` unit wherever P18's real-rule reading is more than a handful of sites; the columns, the moved literals, the doc-block repairs, the class rows, the titled pair, the tagline, the pitch, and the gate cases go to one Opus `implementer` unit. The reason to keep the voice pass out of the converge diff is auditability, not cost: mcp's reading is 183 diagnostics, and folding 132 mechanical sentence rewrites into the diff an adversarial lane must read over cells buries the work that carries judgment. The ordering is load-bearing in the other direction too — a `no-malformed-summary` fix rewrites a description paragraph in `src/core/types.ts`, which is the exact text the converge unit then propagates into a `Summary` cell, so the corrected sentence must land first. The gate cases land **inside** the converge unit, uncommitted, read red on the unconverged tree before the convergence turns them green, exactly as D7.guide ruled (`d7-guide-plan.md:14`): no red gate is committed and no writer is dispatched onto a dirty tree.

### Decision 3 — Every own spec carries a `## Patterns` section, and the pinned pair is the package's primary factory

Fix one rule fleet-wide: the pinned pair is the package's primary `create*` factory's own `@example`, titled with the flattened text of the `### ` heading of the § Patterns fence that documents that factory alone. Where a spec has no `## Patterns` section — form, interpret, lsp, msg, ndjson, probe, rater, sea, sse, table, template, tool, workspace — the unit adds one and moves the guide's existing flagship fence under a `### ` heading there. A `## Patterns` section is the established shape in every other own spec, so adding it is closing a documentation gap rather than decorating a gate, and it keeps one reader-facing answer to "where is the worked example" across the whole fleet. The heading text is a plain imperative verb phrase carrying **no code span**, because `extractFences` flattens a heading's code spans and a tag written with backticks would silently fail to pair (`d7-guide-converge-report.md:392`); writing the heading plain removes the trap instead of documenting it. Before titling, the unit reads the chosen body for ``` and `*/` and takes the next candidate when either appears — those are the two bodies a three-backtick fence and a doc block respectively cannot enclose, and both were met in D7.guide.

### Decision 4 — The tagline becomes one noun phrase and the README adopts it verbatim

Rewrite each guide's H1 blockquote as a single noun phrase in plain text and code spans, carrying no link, in the form the D7.guide precedent fixed: `> <Noun phrase>: <the members it names>.` The README gains that exact blockquote under its H1, with the same line breaks. The displaced sentences fold into the guide's opening paragraph, which is where the `Source:` link and the "published through" sentence go so `links()` still finds a link. Adopting a present tagline verbatim is not available: abort's blockquote is two dense paragraphs, probe's is multi-paragraph, and codec — the one package that already carries a pitch — is still unequal because the tagline's `[src/core](../src/core)` link resolves differently at the two file depths (`codec.md:6-7` against `README.md:6-7`). That defect is the argument for the rule rather than an exception to it: **no link inside the blockquote**, on either side, in every package.

### Decision 5 — A `### Classes` table before the H3 sections, and mirrors do not move

contract, csv, html, markdown, msg, tool, and workspace gain a `### Classes` table placed **before** the H3 narratives its rows name, because `extractSurface` keeps the first symbol it meets and an H3 heading carries no summary, so a class documented only as an H3 can never satisfy the gate. The H3 narrative stays. Take the naming ruling in the same pass: the section is `### Classes` everywhere, including in packages such as abort that head the same table `### Entities` today — the `Kind` cell already reads `class` and `ExportKeyword` already fixes the word, so a second word for the same concept is drift the one-term law forbids. Mirrors of those guides in dependents stay untouched: `.claude/rules/documentation.md` § Parity calls a mirror fetched bytes and refuses a rewrite as a translation, the policy sweep excludes a mirror by catalog membership (`tests/setupPolicy.ts:1430-1444`), and no manifest row reads one, so nothing in the gate sees a mirror. Refreshing them from the registry is a single `builder` sweep after the last publish of the wave, named as intentionally excluded from D7.n on that evidence.

### Decision 6 — The voice red is its own builder unit, and an asserted fixture text is a stop

Give the vendored voice rule its own `builder` unit per package, dispatched between the prep unit and the converge unit, with the package's real-rule reading taken as its first step (P18 states the P17 proxy under-reads `no-banned-term`, so the brief supplies the command rather than the number). Its acceptance is `npm run lint:check` exit 0 over the package's own files, which makes it fully specified taste-free work despite its size. Where the reading is a handful of sites, fold it into the prep unit rather than paying for a dispatch. A banned term inside a fixture value a test asserts is not the unit's to rewrite: `.claude/rules/writing.md` § Substitutions exempts a sample string in a test fixture from every row, and `policy/no-banned-term` reads comments, so a diagnostic landing on a fixture value is an instrument defect and the unit stops and reports it under the deviation contract. A banned term in a *comment* inside a fixture file is an ordinary fix.

### Decision 7 — probe adopts the drop-in and its index becomes a table

probe's `guides/README.md` gains a `| Concept | Spec | Source | Tests |` table with one row carrying its several sources and several test directories in the `GuideModule` list form that lsp, browser, and console rows already use, and its `tests/guides.test.ts` adopts the drop-in with its existing hand-rolled cases kept beneath it. Two things force this rather than bolting the cases onto the hand-rolled harness: `scripts/docs.ts` refuses to run at all without a parseable index (`collectMissing` returns "the workspace carries no concept index to read" and exits 2, `scripts/docs.ts:185-195`), so probe cannot converge either side without the table; and a fleet-wide gate carrying one exception is where the next drift lands, because the exception is the file nobody propagates a fix into. Take the concept-cell casing fleet-wide in the same prep unit: the cell is the package's display name with canonical acronym case — `Probe`, `LSP`, `SSE`, `CSV`, `HTML`, `NDJSON`, `MSG`, `SQLite`, `IndexedDB` — which replaces probe's and lsp's `Package` and is what `describe(entry.concept)` prints in every suite run.

### Decision 8 — Order by risk, not by catalog layer; both lanes on every package, batched by slice

The convergence pass is **not** layer-ordered. Ruling 5 puts the re-pin, the bump, and the publish in phase B, so convergence needs only `@orkestrel/guide@0.0.18` and scaffold's release, and both reach every checkout at the same moment; only the release runs in catalog layer order. Order the pass by risk instead: the pilot, then the shape exceptions (probe, codec with no `## Methods` H2, lsp), then the class-row packages, then the bulk, then the giants (mcp, agent, test, process, browser, form, contract, database, terminal) last, when the convention is settled and scaffold's template exists to copy from. Run writers in disjoint checkouts at a width of three, and keep a giant alone in its slice. On the audit shape: run the subjective lane and the objective lane on **every** package, and cut the dispatch cost by giving each lane a slice of packages in one dispatch rather than one dispatch per package, numbering the slice's claims in one shared sequence, which is the shape `.agents/orchestration.md` § Context and decomposition already prescribes for disjoint slices. Add `checker` on every package, because the mechanical criteria — the column set, the row placement, the pin's presence, the pitch equality, the red-first readings — are exactly what a checker settles. Wall-clock shape: a slice is one prep round, one voice round, three parallel Opus converge units, one audit pair over the slice, one verifier per package; expect a slice to run in hours rather than minutes and the fleet to run in slices reporting as they finish, never as one block.

### Decision 9 — Scaffold gains a presence-owned drop-in template, mid-pass

Add `tests/guides.test.ts` to `ARTIFACT_TEMPLATES.tests` and emit it from `blueprintToTestArtifacts` with **presence** ownership, the same ownership `DISTRIBUTION_TEST_PATH` carries (`src/core/compilers.ts:1341-1345`): a target lacking the file receives it, and a target that wrote its own is left exactly as it is. Never vendor it through `HOST_PATHS` — the suites are not byte-identical (each carries its own `GUIDE_SPEC`, its own module map, and its own extra cases, and they run from 177 to 1464 lines), so `repair` would revert every package's own work on every scaffold release. Dispatch it as a successor unit **after the pilot and the first slice**, not before: a template written from the guide's file alone bakes in one sample's specifics, and a template written after real packages have converged becomes the copy source every later prep unit pastes from, which is what stops the fleet's copies from drifting apart.

### Decision 10 — The exit criterion

Per package, D7.n closes when each of these ends implemented, repaired, retained, or intentionally excluded on evidence: every `## Surface` and `## Methods` table heads `Summary` with only `Kind`, `Shape`, `Signature`, `Value`, and `Returns` beside it; every class documented as an H3 carries a `### Classes` row placed ahead of its H3; `tests/guides.test.ts` carries the equality case, the population pin naming both title sets, and the README pitch case, each read red before its convergence with the reading recorded; one `@example` and its § Patterns fence pair under a plain-text title; the H1 blockquote is one noun phrase carrying no link and the README's pitch is that same text; `npm run build && npm run docs` exits 0; `npm run lint:check` exits 0 with the vendored voice rule live; the whole chain `format:check → lint:check → check → build → npm test` is green under an independent `verifier`; and `version` is bumped with the lockfile. For the pass, D7.n closes when every fleet checkout under `/home/user/fleet/` has closed that list or is recorded as intentionally excluded with its reason, the guide and scaffold have published, and scaffold carries the drop-in template. Phase B carries what remains: per package, the re-pin of its `@orkestrel/*` runtime dependencies to the versions the registry then serves, a re-run of its gates against those, and the publish — in catalog layer order, on the owner's go-ahead and credential.

### What the owner must decide

- The publishes, in this order: `@orkestrel/guide@0.0.18` after the pilot returns, then scaffold's bump. Both are the owner's credential and both gate the fleet pass.
- Whether the fleet's per-package bump and publish rides now. Ruling 5 already says yes; the plan restates it because the doc-block rewrites move each package's emitted declarations, so every package's published surface moves on its own account and the cascade is real rather than optional.
- Whether the `### Entities` → `### Classes` rename and the added `## Patterns` sections are in scope. Each widens every diff and neither is forced by the gate.
- Whether the cell width the seed produces is acceptable fleet-wide. D7.guide's guide grew from 97,073 to 151,166 bytes and its widest row from 463 to 817 characters under Ruling 7; at fleet scale that is the pass's largest reversible aesthetic commitment.

## Alternatives

**Publish nothing and head-start every checkout.** Every package takes `--no-save` installs of the guide's and scaffold's packed tips, converges, then re-pins from the registry and re-runs its gates at release. It wins on one point: the owner's publish decision moves to the end, after the whole fleet has proven the readers. It loses on everything else — a per-checkout install plus a per-checkout `npm ci` restore plus a second full gate run, tarballs that must be rebuilt and repacked on every guide or scaffold source movement (and one movement is already known to be owed), and a fleet of trees that cannot prove the published artifact until the very end, which is D6 finding B repeated once per package. The design takes the one benefit — an unpublished release proven against a real second consumer — for the price of a single pilot.

**One mechanical fleet sweep, Opus only on exceptions.** A script renames every header to `Summary`, runs `repair` and `npm run docs -- --to guide` across every checkout, pastes the gate cases, and dispatches Opus only where the run reports a miss. It is by far the cheapest shape and it is the one this campaign must refuse. P16 measured what `--to guide` actually reports rather than writes — the classes, the tables carrying no `Summary` column, the Types and Constants literals, and the pitch — and every one of those is judgment: which data column a literal moves into, whether a cell carried a fact the block lacks, which sentences split into `@remarks` under Ruling 7. A sweep would leave those as reported lines and the gate would stay red on exactly the rows that needed a person; worse, the rows it *did* write would go unread, and a cell that is verb-first, equal to its block, and wrong passes every gate in the chain. It also breaks § Writing concurrency rule 7 by writing into trees live units own.

## Tensions

Each of these is my lane's judgment and is where the other lane should push.

1. **Order by risk, not by catalog layer.** The brief suggests L0 first. I claim convergence has no layer dependency at all, because Ruling 5 puts the re-pin in phase B; if the objective lane finds a convergence-time dependency on a sibling's published bytes, the order reverts to layer-first.
2. **Both lanes on every package, batched by slice.** I refuse a sampled lane. The batching is the compromise, and it rests on the claim that these units are homogeneous enough for one lane dispatch to hold four subjects without losing per-claim rigour.
3. **One head-started pilot rather than none or every checkout.** The pilot exists to de-risk an irreversible publish. Its cost is one package converged twice.
4. **Adding `## Patterns` to the specs that lack it.** The alternative — titling a block against a fence under an existing heading — makes the doc-block title read `Surface`, which is noise in the block a consumer opens. I chose a structural addition over a bad title.
5. **`### Entities` renamed to `### Classes` fleet-wide.** Pure one-term-one-concept hygiene; it widens diffs in packages that already satisfy the gate.
6. **The voice pass as its own unit.** It costs an extra dispatch per package to keep the converge diff readable.
7. **Mirror refresh excluded from D7.n.** No gate sees a mirror, and the correct source bytes do not exist until the wave publishes. If the objective lane finds a gate that does read a mirror, this reverses.
8. **probe adopts the drop-in.** The alternative keeps probe's harness and bolts the cases on; I claim the seed's refusal on a non-table index forces the manifest change regardless, so the harness change is the smaller remaining step.

## Risks

- **The propagated cells make the fleet's guides unreadable.** D7.guide's guide grew from 97,073 to 151,166 bytes with 23 cells past 400 characters, and the fleet's largest specs are far larger. Evidence to settle: run P.3's `--to guide` on one heavy L0 package (contract) and read the resulting byte growth, widest row, and a sample of written cells before the bulk slices launch. If it fails, the repair is a fleet-wide statement of what a description paragraph is under Ruling 7, written once in the brief, not per-package judgment.
- **Homogeneous-unit drift.** Near-identical units invite pattern-matching, and a cell that is verb-first, equal to its block, and factually wrong passes every gate in the chain. Evidence to settle: the subjective audit lane reads a named sample of *cells against their sources* per package rather than reading the diff, and the count of hand-rewritten blocks each unit reports is the signal that the unit actually read them.
- **The prose sweep's population after `repair`.** `repair` restores `tests/setupPolicy.ts` and `tests/policy.test.ts`, and no measurement in the evidence names `npm run test:policy` in a repaired fleet checkout. The Markdown sweep reads every authored guide, and no unit is scoped for a red there. Evidence to settle: run `npm run test:policy` in one repaired scratch clone before the first prep unit is briefed.
- **A guide or scaffold movement mid-pass.** F1 removes the one known cause. Any further movement re-pins every converged package. Evidence to settle: freeze the guide's and scaffold's source at F3 and treat any later change to either as a rescope decision for the owner.
- **Host contention at width three.** Concurrent builds and suites make a container miss deadlines it meets when idle, and a writer's own timing evidence is systematically pessimistic. Evidence to settle: the host's core count and memory, which the dispatch did not supply; the deciding re-run of any timing failure belongs to the Orchestrator after the unit exits.
- **The pilot's findings arrive after `0.0.18` has already been prepared.** If the pilot finds a reader defect the guide must fix, the guide's branch reopens and its own audit chain runs again before the release. Evidence to settle: the pilot's report names every reader miss with the exact seed line that produced it, so the decision to reopen is one reading rather than a round.
