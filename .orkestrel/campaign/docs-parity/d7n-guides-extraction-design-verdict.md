# Guide extraction design ruling

Keep Guide core-only and add a Parity composition over caller-supplied inventories.
Accept the subjective lane's shared row/rewrite entity and the objective lane's
generic inspection report. The owner requested extraction of shared guide logic,
so generic assertion computations move upstream with rewrite composition and report
formatting. Keeping the generic loops downstream would leave that request incomplete.

Use Parity.inspect(), Parity.rows(), and Parity.rewrite(direction). Keep the explicit
guide/source direction as the public destination axis that the CLI already names.
Do not introduce side-manager objects whose only method forwards the same rewrite.
Use structured readonly report groups for the existing assertion families, with
preformatted findings. Package tests retain selection, assertions, and executable
examples rather than reimplementing the computations they assert.

Make Drift.category required and emit it at the comparison's origin. Summary and
example keys can collide, so the key cannot recover this axis. Update the contract
shape, primitive callers, direct tests, and examples together. The bounded fleet
source search for computeDrift calls found Guide source/tests and scaffold's local
engine; the latter disappears on adoption. No compatibility argument is needed.

Use parsed GuideFence and SourceExample records for rewrites. Remove downstream
language/code encoding and reparsing. Keep Markdown's parser, node guards, traversal,
provenance spans, and targeted rendering authoritative. Do not render a whole guide
to replace a selected node, or replace Guide-specific section state with a generic
walk that changes its population. Add no runner dependency or server environment.

The owner's scripts-directory ruling supersedes the subjective lane's proposed
manual per-target deletion and its refusal of directory ownership. HOST_PATHS names
scripts; ordinary staging, discovery, and overwrite carry removal. No retirement
receipt subsystem, historical list, or migration step in reusable skills is needed.

Keep negative assertions that bind the owner's no-launcher and no-docs-command
contract. The predecessor generated docs, so a regression to that generation would
break the no-docs assertion. Those tests are not straggler implementation logic.
Remove actual stale docs commands from target manifests during the authorized fleet
adoption visit, while obsolete vendored files leave through scaffold overwrite.

Guide 0.0.18 and scaffold 0.0.64 remain unpublished candidates. Replace their candidate
tarballs after the revision; do not increment again merely for rebuilding an
unpublished candidate. Final registry pins and locks follow the retained layer plan.
Include the owner's toolchain changes in the accepted scaffold product commit.

gates before acceptance. Publication stays held.
