## Decisions the plan must take, each with its rationale and its cost

1. **Release first or head starts.** Either the guide and scaffold publish before D7.n (each package re-pins from the registry, `repair` lands the seed and the rule, and the drop-in imports `findDrift` from the registry) or every package takes two `--no-save` head starts (the guide's and scaffold's packed tips) and re-pins later. State the cost of each across the fleet and recommend one; the publish is the owner's, so the plan names what runs before it and what after.
2. **The per-package unit.** One unit per package or several; which parts are mechanical (`repair`, the `docs` script, the bump with the lockfile, the header renames, the seed's `--to guide`, the three gate cases pasted in the landed shape) and go to `builder`, and which carry judgment (the pitch as one noun phrase, the cells that carry information the block lacks, the titles, the class rows, the voice-rule sites in test helpers, Ruling 7 over the widest cells) and go to the Opus `implementer`; whether one Opus unit per package with a builder prelude, or a builder pass over every package followed by an Opus pass. Name the acceptance criteria per unit and the red-first proof of the three cases.
3. **The pin's population.** Every package's `@example` tags are untitled and thirteen specs have no `## Patterns` section. Decide how each package gets at least one titled pair: which fence under which heading, whether a package without `## Patterns` gains one section with one fence or titles a block against a fence under another heading, and the convention for the title text (the heading's flattened text).
4. **The pitch.** Every README but codec's lacks the blockquote; the guides' taglines are multi-sentence with links in several. Decide the convention: the guide's tagline becomes one noun phrase in plain text and code spans (the guide precedent) and the README gains it, or the README adopts the guide's present tagline verbatim where it already is one paragraph; what happens to a tagline's links.
5. **The class rows.** contract, csv, html, markdown, msg, tool, and workspace document classes as H3 headings with no row; decide the `### Classes` table placement per the guide precedent and whether mirrors of those guides in dependents (outside the concept index) move.
6. **The voice rule's red.** P18 reads 183 sites in mcp and one in abort; the sites are test helper doc blocks and banned terms in comments. Decide whether the voice convergence of test helpers is inside each package's D7.n unit or a separate builder pass per package before it, and what a unit does with a banned term in a test fixture whose text a test asserts.
7. **probe.** Its manifest is a list and its suite is hand-rolled from `@src/core`; decide whether probe adopts the drop-in or gains the three cases in its own suite, and what its manifest becomes.
8. **Batching and concurrency.** The checkouts are disjoint, so writers can run in parallel across packages (one per checkout); decide the slice size per catalog layer, the audit shape per unit (both lanes and a checker on every package, or the lanes on a sample and the checker on all — the falsification law wants per-claim verdicts on every nontrivial unit), the verifier per package, and the order (layer L0 first). State the wall-clock and token shape of the whole pass.
9. **Scaffold's own template.** Whether scaffold gains a `tests/guides.test.ts` template carrying the three cases so a new target is born with them, or the drop-in stays package-owned; this is a scaffold change and a successor unit if taken.
10. **The exit criterion.** Name it per package and for the pass: each package ends implemented, repaired, retained, or intentionally excluded on evidence; what the owner decides (the publishes); what phase B carries.
