## Findings outside the claims

**F1 — The generated command and the vendored rule assert a capability the package supplies to no target.**
`src/core/compilers.ts:351` emits `node --experimental-strip-types tests/guides.test.ts` into every guides workspace's manifest, and `:322` chains it into that workspace's `test` script. `tests/guides.test.ts` is package-owned: `guides/scaffold.md:1038` says so, `HOST_PATHS` excludes it, and scaffold generates no template for it. So the emitted command runs a file the workspace author wrote, and nothing in the package states what that file must be for the command to work. The vendored `.claude/rules/documentation.md:40-43` — which reaches every target through the host inventory — now instructs every target's reader to run `npm run test:guides -- --to guide` and `-- --to source`, directions only this package's own file implements. The released Vitest command sits in the accepted-predecessor list (`src/core/compilers.ts:457`), so `repair` replaces a target's working `test:guides` value with the node command rather than leaving it alone. Impact: a target repaired past this release receives an instruction canon describing a command it does not have and a manifest entry pointing at a file that does not implement it, and the guide gives its author no way to close the gap. Right looks like one of: state the obligation on the authored file in `guides/scaffold.md` beside `:1038` and in the vendored rule — the target's own `tests/guides.test.ts` must run the guides project when invoked directly and own the two directions — or scope the vendored rule's rewriting sentences to a workspace that implements them and leave the generated command as the Vitest invocation for the rest.

**F2 — The file carries no statement of why its local declarations live in it.**
`tests/guides.test.ts:36-51` declares module-scope constants and an interface, and `:53-342` declares module-scope functions, none exported. `.claude/rules/architecture.md` § Declaration placement permits that only in "a runtime entrypoint that must be self-contained and cannot import siblings" and requires "Explain that necessity in a comment". The retired seed carried exactly that comment (`scripts/docs.ts:1-15` in the diff), and the premise it rested on is now false: this file imports `./setupServer.js` at `:409-410`. The real authority is the owner's placement instruction, which lives only in a campaign file. Impact: the next reader or agent reads the file against the rule and either relocates the helpers into a setup module — which the accepted ruling forbids — or files the file as drift. Right looks like a header comment naming what the file is (a Vitest module and the `test:guides` entry), which branch runs on which condition, and that the local declarations sit here by the owner's placement instruction rather than by the self-contained exception.

**F3 — `readShortName` hand-narrows JSON while the declared guard is available.**
`tests/guides.test.ts:70-73` reads the manifest name through `typeof manifest !== 'object' || manifest === null` and `Object.getOwnPropertyDescriptor(manifest, 'name')?.value`. That shape was forced in the retired seed by the vendored-file import law in `.claude/rules/workspace.md` § Configuration authority. This file is not vendored, `@orkestrel/contract` is a runtime dependency (`package.json:97`), and the same file already uses `isRecord` in the worker branch (`:397`). `AGENTS.md` requires reusing a declared primitive whose semantics match, and `.claude/rules/patterns.md` § Declared ecosystem capabilities repeats it. Impact: the package carries its own narrowing for a case the ecosystem guard covers, and a reader cannot tell whether the difference is deliberate. Right looks like a static `isRecord` import used to narrow, with the descriptor read deleted.

**F4 — The guide's exit-2 sentence over-claims for the default mode.**
`guides/scaffold.md:1035-1036` reads "It exits `2` before Vitest starts for an invalid option, a missing `guides/README.md`, or an indexed spec the workspace does not carry." With no direction the entry never reads the inventory (`tests/guides.test.ts:355-358`), so a missing `guides/README.md` reaches the worker and throws at `:421-422`, which lands as a failed module and exit 1. Impact: a reader diagnosing an exit code reads the guide and expects a status the command does not produce on its most common invocation. Right looks like scoping the sentence to the explicit-direction path, the way the sentence before it scopes exit 1.

**F5 — The accepted predecessor is described as something it was not.**
`src/core/compilers.ts:429` reads "The guides entry accepts the generated command that ran Vitest without reporting." The accepted value at `:457` is `vitest run --config vite.config.ts --no-cache --reporter=dot --project guides`, which reports through the dot reporter. What it lacked is the entry's own drift reporting. Impact: the doc block describes the predecessor by a property it does not have, and a reader comparing the sentence with the literal beneath it finds them in conflict. Right looks like naming the real difference — the predecessor ran the project through Vitest alone and reported no drift.

**F6 — Prose edited in place was not rewrapped.**
`guides/scaffold.md:1030` and `:1041` run well past the wrap every neighbouring line holds, and `src/core/compilers.ts:424-431` leaves the orphan fragments "Publishing adds", "The pack hook accepts the build chain emitted before it delegated to `build`. The", and "publication hook accepts the same gate chain without". Neither the formatter nor the parity gate reflows Markdown prose or a TSDoc block, so review is the only gate these pass through. Impact: the changed passages read as patched text in files whose surrounding prose is uniform. Right looks like rewrapping both passages to the width their neighbours hold.

**F7 — `passedGuides` is a predicate in no sanctioned form.**
`tests/guides.test.ts:309` names a boolean-returning module helper `passedGuides`. `.claude/rules/names.md` fixes `is*` for a guard, `matches*` for a predicate, and `{verb}{Noun}` for a helper; a past-participle-plus-noun reads as a report of an event rather than a question about a value. The package already uses the sanctioned form in `matchesRange`, `matchesPrintWidth`, and `matchesOrchestrationPath`. Right looks like `matchesPassed`, or returning the run result and letting the caller ask.

**F8 — `recordReason` forwards to `Map.set` and adds nothing `buildReasonKey` has not already added.**
`tests/guides.test.ts:157-164` calls `buildReasonKey` and then `reasons.set`. `.claude/rules/architecture.md` § Wrapper test deletes a one-line delegate that adds no boundary, invariant, composition, translation, lifecycle, or narrower contract; the composition here is `buildReasonKey`'s, and the wrapper only re-passes it. Right looks like calling `reasons.set(buildReasonKey(row.spec, drift.key), reason)` at each site and deleting `recordReason`, or folding the key template into `recordReason` and deleting `buildReasonKey`.

**F9 — `RETIRED_HOST_PATHS` has no stated exit condition.**
`src/core/constants.ts:156-157` and `guides/scaffold.md:1049-1052` say what a retired path does and never say when it stops being one. Impact: the list is a ledger that only grows, and a maintainer adding the next retirement has no rule to apply and no reason to remove anything. Right looks like naming the condition that removes an entry in the constant's TSDoc and in the guide paragraph — or stating that entries are permanent, if that is the intent — so the question a reader has is answered where they meet it.

**F10 — `PROPOSAL.md` still names the retired `docs` script as an invocation.**
`PROPOSAL.md:421-422` says the proposed render direction "is invoked by a package `docs` script (`npm run docs`)", and `:604` has each package "runs `npm run docs` on its own schedule". This change removes that script from every generated manifest and from this package's own. Impact: an authored root document instructs a command the workspace no longer declares, and the proposal's adoption path rests on a seed that no longer exists. The writer's brief scoped this file out, so it needs its own carrier: right looks like a successor unit owning `PROPOSAL.md` that restates those steps against the `test:guides` entry and its explicit directions.

## Attacked and held

- Argument handling: `--to` alone, `--to guide extra`, `--to json`, and a bare unknown flag all reach the usage path before any inventory read, any write, and any runner start. The write path is unreachable without a valid direction.
- Self-hosting: the native branch launches the project that collects this same file, and the launched worker takes the registration branch, so the recursion terminates; the full-chain log shows it completing.
- `raiseExit` reading `process.exitCode` as a possible string looks like defensive noise, and is correct: the declared type admits a string, and the comparison never lowers a status already raised.
- The Compiler artifact case losing its totals looks like lost coverage, and is not: `Origin` is a closed union and all three of its populations are pinned by exhaustive membership, which is the form the test rules prescribe over a total.
- `writeGuide` now rewriting a titled guide fence from source looks like it contradicts the retired seed's refusal, and is the change the accepted ruling ordered, with its control updated to a full summary-and-fence replacement.
- `test:guides` no longer naming Vitest in the manifest looks like the guides project leaving the gate, and does not: `scripts.test` still chains it, and the chain log shows the project running under it.
- The retirement looks like a general deletion engine, and is not: it admits one frozen exact path, only in a selected group, through the existing foreign-file transaction, and it leaves an unrelated script in the same directory alone.
