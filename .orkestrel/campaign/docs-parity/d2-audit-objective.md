## 10. Finding 1's clause — the finding stands; the clause is sound but incomplete as worded

The finding is real and its mechanism is exactly as the ruling states: `normalizeSummary` (`src/core/helpers.ts:1673-1679`) collapses whitespace and expands `{@link}` but has no code-span awareness, while the guide side reaches it through `extractCellText` (`:972`) after the parser has already applied CommonMark's rule that a code span beginning and ending with a space, and not consisting entirely of spaces, loses one space from each end. So a doc block writing `` ` | ` `` and a guide cell writing `` ` | ` `` compare as `` ` | ` `` against `` `|` `` and never converge. The clause's "when both are present and the content is not all spaces" reproduces CommonMark exactly, and the all-spaces carve-out is required — `` ` ` `` must survive on both sides.

Cases the clause as worded misses:

- **It is worded as a source-side change and must be a change to the one shared function.** Both sides run `normalizeSummary` — the guide side through `extractRowSummary` (`:1420`), the source side through `collectSummaries` (`:1908`). A `{@link}` carve-out applied on the source side only leaves the guide side expanding a hand-written `` `{@link Widget}` `` into ``` ``Widget`` ``` at `:1676`, and the drift the clause exists to close stays permanent. State the clause as a clause of `normalizeSummary`.
- **It must fix its order against the existing clauses.** The code-span scan has to run before the `{@link}` expansion (`:1675-1676`), because the expansion inserts backticks and a later scan cannot tell an inserted delimiter from an authored one. The space strip has to run after the whitespace collapse (`:1677`), so a padded span written across a continuation marker, or padded with a tab, is judged on the same characters CommonMark judged.
- **It must name its delimiter set, and the set must be `buildCell`'s.** `buildCell` recognizes a single-backtick run with no inner backtick (`:1010`). CommonMark strips a boundary space from a multi-backtick span too, so a doubled-delimiter padded span is inside the clause as worded and outside any implementation that reuses `buildCell`'s regex. - **It changes what `buildCell` renders, and that path has never been exercised.** Today `` ` | ` `` carries boundary spaces, so `buildCell` writes it as literal text (`:1018-1019`; the case `keeps a run whose text carries a boundary space as literal text`). Whether `renderMarkdown` escapes a `|` inside a code span in a table cell is unmeasured here. Measure it before the clause lands; the corpus case `renders every doc block summary this package ships back to itself` is the guard that would catch it, and it is the case to watch turn red.
