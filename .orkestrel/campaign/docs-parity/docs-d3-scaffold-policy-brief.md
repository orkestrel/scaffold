## What is fixed

- **`policy/no-imperative-summary`** (`VOICE_RULE` in `configs/policy.ts`). Membership: every block comment whose value opens with `*` (a doc block) that is the last comment before a top-level statement whose `type` begins with `Export`, with only whitespace between the comment's end and the statement's start. The description paragraph is the block's text from its opening to its first block tag (a line whose first non-marker token starts with `@`), continuation markers (`^\s*\*\s?`) removed, whitespace collapsed. Report `voice` when the first word does not match `^[A-Z][a-z]*s$` or sits in `POLICY_VOICE_STOPWORDS` (the stop set the D3-pre brief lists, frozen and exported), and `name` when the first sentence (up to the first `. ` or the paragraph's end) contains the declared identifier as a whole word — the identifier from `declaration.id.name`, or the first `declarations[].id.name` of a variable declaration, and none for an anonymous default export. An empty paragraph reports `voice`. A tag line is never read. The diagnostic lands on the comment (`context.report({ node: comment, messageId })`, proven by P5 under oxlint 1.80.0).
- **`policy/no-banned-term`** (`TERM_RULE`). Membership: every comment, block or line, doc or not, in every linted file. The prose is the comment's value with continuation markers removed, then `stripPolicyCode` applied: fenced blocks (```` ``` ```` or `~~~` runs, across lines), inline code spans (a backtick run closed by the same run, across lines), `{@link …}`, `{@linkcode …}`, `{@inheritDoc …}` tags, and URLs (`https?://\S+`) blanked with spaces so offsets hold. Report `term` once per hit with `data: { term, replacement }`, on the comment.
- **`POLICY_BANNED_TERMS: readonly PolicyTerm[]`** in `configs/policy.ts`, frozen: `PolicyTerm { readonly term: string; readonly pattern: RegExp; readonly replacement: string }`, one entry per unconditional row of the substitution table, each pattern case-insensitive, word-bounded, and covering the inflections the D3-pre brief lists (`easy` → `eas(?:y|ier|iest|ily)`, `utilize` and `leverage` → all inflections, `robust` → `robust(?:ly|ness)?`, `dummy` → `dumm(?:y|ies)`, `sanity check` → `sanity[ -]check`, `e.g.`, `i.e.`, and `etc.` with their dots, `and/or`, `in order to`, `allows you to`; plus `should`, `simply`, `just`, `currently`, `via`, `performant`, `please`, `blacklist`, `whitelist`, `slave`). **`POLICY_JUDGED_TERMS: readonly string[]`**, frozen: `now`, `new`, `latest`, `once`, `since`, `master` — the rows a reviewer rules by sense, matched by nothing. Both live in `configs/policy.ts` because that file imports nothing and the sweep imports from it (as `tests/config.test.ts` already does from `../configs/policy.js`).
- **`PolicyContext`** gains `readonly sourceCode: PolicySourceCode`, and `PolicySourceCode { readonly text: string; getAllComments(): readonly PolicyComment[] }`, `PolicyComment { readonly type: 'Block' | 'Line'; readonly value: string; readonly range: readonly [number, number] }`, all re-declared structurally (the file imports nothing). `PolicyDiagnostic.node` widens to `PolicyNode` so a comment is reportable. Whether oxlint's context exposes `sourceCode.text` is an Unknown; probe it first (the Unknowns section), and if it is absent, read the whitespace gap between a comment's end and a statement's start from `sourceCode.getText()` or by comparing `range` values alone (a comment is attached when no other comment and no non-whitespace token lies between; the token check needs the text).
- **Exported pure helpers**, tested one by one in `tests/config.test.ts` beside the existing helper tests: `commentToPolicyParagraph(comment)`, `paragraphToPolicyOpener(paragraph)`, `isPolicyVoiced(word)`, `stripPolicyCode(text)`, `textToPolicyHits(text): readonly PolicyHit[]` (`PolicyHit { readonly term: PolicyTerm; readonly index: number }`), `programToPolicyDocs(node, sourceCode)` (each export statement paired with its doc comment and its declared name), `reportVoice(context, doc)`, `reportTerm(context, comment)`, named in the file's own `{noun}To{Noun}` and `report{Noun}` forms.
- **RuleTester controls** in `tests/config.test.ts` `describe('policy plugin')`: `tester.run('no-imperative-summary', VOICE_RULE, …)` — valid: `Creates`, `Checks whether`, `Is`, `Reports whether`, a doc block on a non-exported declaration, a doc block on a class member, a single-star block comment before an export, a stop-set word as a later word, an export with no comment; invalid, each labelled `[membership: …]`: a noun-phrase opener (`The`), an imperative opener (`Create`), a stop-set opener (`This`), a name repeat, an empty doc block, and a doc block separated from its export by a blank line (still attached: whitespace only). `tester.run('no-banned-term', TERM_RULE, …)` — valid: each exclusion (a term inside a code span, inside a fenced example, inside a `{@link}` target, inside a URL, a span crossing a line break), each judged term (`now`, `new`, `once`), a longer word containing a term (`justice`, `viable`, `pleased`?), and a clean comment; invalid: every unconditional term at least once, the inflections (`easiest`, `utilizing`, `leveraged`, `robustness`, `dummies`), the dotted forms, `and/or`, `sanity-check`, in a line comment and in a block comment, each with its `data.term`.
- **The real-binary test** (`loads every configured policy rule through the real binary`): the violations fixture gains a line comment carrying a banned term and a noun-phrase doc block before an export; the expected list gains `policy(no-banned-term) src/violations/fixture.ts` and `policy(no-imperative-summary) src/violations/fixture.ts`; the clean fixture gains a voiced doc block before its class and a clean comment, and its report stays empty.
- **The Markdown sweep** in `tests/setupPolicy.ts`: `PolicyRule` gains `'prose'`; `POLICY_PROSE_ROOTS` (excluded directory names: `node_modules`, `dist`, `tmp`, `.orkestrel`, `.git`) and `readPolicyProse(root): readonly string[]` (every `.md` path outside them, sorted); `readPolicyPackage(root): string | undefined` (the short name from `package.json`'s `name`, `@orkestrel/` stripped); `isPolicyMirror(root, path)` (a top-level `guides/<name>.md` where `<name>` is neither `README` nor the package's short name); `inspectPolicyProse(root): readonly PolicyViolation[]` — for each non-mirror prose file, `stripPolicyCode` over the text and one violation per hit with `line`, message `prose carries no banned term: <term> (<replacement>)`; for each top-level guide that is a mirror candidate with no `node_modules/@orkestrel/<name>/package.json` beside it, one violation `guide is the package's own, the map, or a vendored mirror` (so the exclusion is evidence, never silence). `inspectPolicyWorkspace` gains `...inspectPolicyProse(root)`. `PROSE_POLICY_CONTROLS` in the register: a hit in `README.md` (reports, with its line); a hit inside a fence (no report); a hit inside a code span crossing a line break (no report); a hit in `guides/other.md` with `node_modules/@orkestrel/other/package.json` written (no report); a hit in `guides/<own>.md` (reports); a top-level `guides/stray.md` with no such package (reports the guide finding); a hit under `.claude/rules/sample.md` (reports); a hit under `node_modules/sample/README.md` (no report); a hit under `tmp/notes.md` (no report).
