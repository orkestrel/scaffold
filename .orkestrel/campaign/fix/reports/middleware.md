## Deviations

Four departures from the dossier's literal text, none of them blocking.

1. s11-01, s11-02, s11-04 are deferred rather than partly applied because the vendored placement instrument makes the "move it, keep the name" half unbuildable. `tests/setupPolicy.ts` enforces `factory` ("factory functions use the create prefix") and `parser` ("parser functions use the parse prefix") on `factories.ts` and `parsers.ts`. So `restoreSession` and `resolveDefaultDirectory` have no legal home outside the leaf pair under their published names, and every remaining route renames or removes a published export. Applying the s11-04 lane amendment as written would have turned `npm run test:policy` red, which is why the whole trio went to the work order together rather than one of them being closed alone.

2. s11-19 introduces `SessionLimits` where the finding names `SessionStoreOptions`. A separate `SessionStoreOptions` would be structurally identical to the `SessionLimits` that s11-21 requires, so one public type now serves both roles and `MemorySessionStoreOptions extends SessionLimits`. This widens `ttl`/`lifetime` to `number | undefined` on that options bag, which only accepts more input.

3. s11-05 leaves `createMultipart`'s `throw new HTTPError(error.status, error.message, error.context)` re-throw in place. Now that `MultipartError` is an `HTTPError`, that line re-wraps one HTTPError as another and drops `reason`. Removing it changes the type a consumer catches, and no dossier finding names it, so it is recorded here rather than changed.

4. s11-10's sweep covered the source files the finding names. `guides/middleware.md` still carries its own `AGENTS §22`, `AGENTS §21`, `PROPOSAL §5`, and `PROPOSAL §6` citations and the "thirteen" count at line 4 — the same class of defect against the guide, outside this finding's stated scope.

One more observation, applied but worth naming: `MultipartError.name` changes from `'Error'` to `'MultipartError'`. It moves either way once the class extends `HTTPError`, because the base constructor assigns `this.name`; `'MultipartError'` is the value the sanctioned `ContentTooLargeError` pattern produces. No test or document pins the old value.
