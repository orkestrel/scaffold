**F1 — the direct case drives the daemon with a user message that has no content. Required change.**

**F2 — the page reports `null` sentinels and the guard narrows them to a type that forbids `null`.**
`tests/setupServer.ts:727-728` sends `code: failure?.code ?? null` and `status: failure?.status ?? null`. `PageOutcome` declares `readonly code?: string` and `readonly status?: number` (`:1015,:1017`), and `isPageOutcome` admits `null` for both (`:1050-1051`), so a failure carrying neither narrows to a type it does not satisfy and a consumer reading `outcome.code` receives `null` where the declaration promises `string | undefined`. `AGENTS.md` § Design laws: absence is `undefined`, and `null` only where an external format distinguishes it from omission. JSON does not distinguish here — `JSON.stringify` already omits an `undefined` member, which the guard already accepts. What right looks like: drop both `?? null` coalescences and drop the two `!== null` branches from the guard; the type then tells the truth and the guard gets shorter. Nothing in the suite currently exercises the `null` path, so no assertion changes.

**F3 — the page-error and console recorders are never shown to be able to report.**

**F4 — `Attempt.relay` is documented as the relay route's requests and holds every request the fixture served.**

**F5 — `readPath` uses the `read*` prefix for a coercion.**

# Attacked and held

- **`buildImportMap` mapping the whole installed `@orkestrel` tree rather than the proof's closure** looks like over-reach against a claim about a specific closure. It is correct: an import map resolves specifiers without fetching them, the served page imports only what the closure needs, and the proof asserts membership of the names that must resolve rather than the map's size. A hand-written map is what would drift.
- **`createPageFixture` returning `RecordingServerInterface`** instead of the `PageFixtureInterface` the design sketched looks like a type stretched past its meaning. It is the better call: the shape is `{ url, requests, stop }` either way, and a second interface would be the near-duplicate the test rules forbid.
- **`reservePort` declaring a picker `@orkestrel/test` deliberately refuses** looks like a rejected primitive smuggled back in. It is not the same job — `createLoopback` binds a server the test owns, and a launched browser binds the CDP port itself and must be handed a number before it starts. The race and why `cdp.discover: false` keeps its loss loud are named in the export's own remarks.
- **Relaunching the browser for each retry attempt**, where the design said a retry would be a fresh agent on the same document, looks like drift that buys nothing. It buys an uncontaminated request log and DOM per attempt with no reset bookkeeping, at a launch cost the authoritative run absorbed. The `list.replaceChildren()` left in the page's `run` is now unreachable in effect, which is the visible trace of that choice and is harmless.
- **The page script being a served, untypechecked string** is the design's own accepted tension and not a new defect. `PAGE_TOOL` crossing the boundary as one serialized declaration is the mitigation the design asked for and it landed.
- **`test:service` reading a stale `dist`** where `requireBuild` only proves presence: held, because `prepublishOnly` runs `build` before `test:service`, and the gate log shows the build ran ahead of the suite in the authoritative chain.
