- **The inbound-abort path leaving the response body neither closed nor errored**, because `#cancel` sets `#settled` before any `#pull` can write a terminal frame (`RelayStream.ts:59,62,66,84`). The ruled fix names exactly that behaviour, a disconnecting client's runtime cancels the body (re-entering `#cancel`, which returns early), and the package's own compositions cancel the body from the base's `finally`. A consumer that aborts the inbound signal and keeps reading without cancelling would hang; nothing in the package or its examples does. Held, and recorded here because it is undocumented.
- **`cloneJSONValue` returning deeply frozen null-prototype records** that the compiled guard and `JSON.stringify` must still accept — proven green by `RelayProvider.test.ts:51-70` and the whole-project control run (751 passed, `a2-fix-probes.md:19`). Held.
