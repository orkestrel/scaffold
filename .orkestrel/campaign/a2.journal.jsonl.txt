A\r\nversion string proves the binary is installed, and an authentication-state check reads stored\r\ncredentials, so both pass while the account is out of quota, while the routed model is unavailable to\r\nit, while the server has already revoked the credential the check read, and inside a sandbox\r\nwith the network denied. Record a bench live only on a bounded round-tripped model call that came\r\nback, and record what came back beside the routing decision. Probes are read-only, and the role file\r\nowns each bench's exact probe.\r\n\r\nThe local steps still run, because they route the recovery rather than decide the verdict: an\r\nunresolved CLI is an install problem, a failed authentication-state check starts the login ladder\r\nin Recovering a dark bench, and a bench that passes both and still cannot round-trip is dark for a\r\nreason no local check can see. Record every dark bench with its fallback and the lane substitution\r\nit forces, and never absorb one silently. A readiness script reports readiness and performs no\r\nmodel call, so the round trip belongs to the Orchestrator's own probe or to the bridge carrying\r\nthe unit, never to the hook. Liveness also expires: a dispatch that fails on quota, model access,\r\nor the network is a fresh liveness result rather than a unit-level fault, so record the bench dark\r\nfrom there and re-plan the lane instead of re-dispatching against a session-start answer that no\r\nlonger holds.\r\n\r\n1. **Absorb.** Dispatch `grok` for terrain, prior art, and the reading the decision needs. In an\r\n   Orkestrel repo dispatch `orkestrel` alongside it for live package state. Skip only when the\r\n   ground is already known.\r\n2. **Design adversarially.** Run the adversarial pass on one design brief: `planner` for\r\n   the subjective lane and `analyst` for the objective lane. Reconcile them yourself into one plan:\r\n   units, dependencies, ownership, parallel and serial order, acceptance criteria, risks.\r\n   - Surface the plan before dispatch, including a routing ledger naming each unit's role **and**\r\n     engine. Routing a unit to a Claude-native agent when its work class belongs to a bench â€”\r\n     reading-heavy to Grok, objective audit or objective implementation to Sol â€” without a recorded\r\n     bench-dark deviation is a dispatch deviation.\r\n   - State the goal's exit criterion beside the units: the enumerated capabilities whose closure\r\n     ends the campaign, each to end implemented, repaired, retained, or intentionally excluded on\r\n     evidence. A plan that names work but not its end can only be abandoned, never finished.\r\n3. **Implement.** Route each nontrivial objective unit to the Sol `implementer` and each nontrivial\r\n   subjective unit to the Opus `implementer`, in the checkout the unit writes, one writer per\r\n   checkout. Route a fully specified taste-free unit to `builder`. Never route implementation to an\r\n   engine the unit's judgment load exceeds.\r\n4. **Integrate.** Evaluate each distillate against its acceptance criteria, apply shared-file\r\n   patches serially, and route cross-cutting findings. Integration applies exact returned patches\r\n   and mechanical conflict resolution only. A new type, mechanism, behavior, or acceptance\r\n   criterion discovered at integration is a successor brief routed to a writer, never an\r\n   integration edit.\r\n5. **Audit adversarially.** Audit every nontrivial implementation with the objective lane and the\r\n   subjective lane â€” `analyst` and `reviewer`, the way the design step names its lanes â€” at least\r\n   one of them on an engine that did not write the work. Dispatch `checker` in addition when the\r\n   acceptance criteria are mechanical â€” counts, paths, parity rows, scope honesty â€” never in place\r\n   of a lane. A round that runs fewer lanes than its brief names, or omits the checker its criteria\r\n   call for, records the deviation in its verdict file with that round's own reason, never a\r\n   template sentence.\r\n   - State the audit's subject as numbered falsifiable claims and require per-claim verdicts with\r\n     evidence, per the Falsification law in `.claude/rules/quality.md` and the `orkestrel-falsify`\r\n     value set, unless the dispatch names a different skill that fixes another.\r\n   - In a fix round, give the unit to an auditor engine that did not write it.\r\n   - Run the `orkestrel-falsify` skill for multi-round audits. It owns the brief anatomy, the\r\n     successor-brief rule, the verdict shape and its single terminal line, and the reconciliation\r\n     discipline.\r\n   - Reconcile the lanes that ran. Drop, on the record, any finding no lane can substantiate.\r\n6. **Verify.** Have one independent `verifier` run the authoritative gates.\r\n7. **Re-baseline.** Reconcile the remaining plan against what the phase revealed, before dispatching\r\n   the next one.\r\n   - Rule on every remaining unit: **satisfied**, the phase closed it, strike it; **transformed**,\r\n     the intent stands and the work changed, restate it; **added**, the phase revealed a fork the\r\n     plan did not consider; **unchanged**.\r\n   - Redraw the dependency order. Strike a unit whose subject a later unit deletes. State the new\r\n     prerequisite of a unit that acquired one.\r\n   - Walk the remaining units once and ask of each whether what landed still supports it. A\r\n     decision taken inside a unit can remove a later unit's foundation, and the unit that took it\r\n     cannot see that.\r\n   - Re-baseline when a probe overturns a decision the plan rests on, not only at a phase boundary.\r\n     A measurement that falsifies your own reconciliation changes which units run.\r\n   - Record what changed and why. An unrecorded re-baseline cannot be audited, and the next one\r\n     re-derives it.\r\n8. **Accept.** Decide, then report outcomes, decisions, evidence, and remaining risk concisely.\r\n   When the design step's exit criterion is met and the gates are green, accept. The next goal is the\r\n   deliverable.\r\n\r\n### Re-baselining is not rescoping\r\n\r\n`.claude/rules/quality.md` fixes the enumerated scope when work begins and forbids reopening it. A\r\nre-baseline changes which units run. It never changes the goal's exit criterion.\r\n\r\nStrike a unit because the phase satisfied it, never because it became inconvenient. Add a unit\r\nbecause implementation revealed work the exit criterion already required, never because an engine\r\nthought of something else worth doing. A re-baseline that moves the exit criterion is a rescope, and\r\nthat needs the user.\r\n\r\n## Deviation protocol\r\n\r\nWhen reality diverges from a writing dispatch:\r\n\r\n1. The writer stops and reports: expected, found, exact evidence, done or not done, and at most one\r\n   short hypothesis. It does not investigate, improvise, or alter the plan.\r\n2. The Orchestrator triages:\r\n   - obvious correction â†’ tighten and re-dispatch;\r\n   - missing mechanical evidence â†’ dispatch `verifier`;\r\n   - unknown terrain â†’ dispatch `grok` with the report and the plan slice;\r\n   - unknown design or root cause â†’ dispatch `planner` and `analyst` on the question.\r\n3. The Orchestrator decides, updates the plan, and re-dispatches.\r\n\r\nWorkflow failures use the same ladder. Do not absorb their raw logs into the main context.\r\n\r\n## Dispatch anatomy\r\n\r\n### Native first\r\n\r\nLaunch a model through the running harness's own mechanism whenever that harness hosts it: Claude\r\nsubagents and workflows in Claude Code, Codex-native agents in a Codex session, Cursor-native\r\nsessions in Cursor. MCP and CLI transports exist only to reach a model the harness does not host.\r\nNever route a native model through its own CLI or an MCP loopback.\r\n\r\n- Use a single-agent dispatch when later control flow depends on the previous result.\r\n- Use a workflow for a known deterministic fan-out, staged pipeline, or loop. Serialize writing\r\n  nodes; never run concurrent writers in the tree.\r\n- Name a role and its engine in every node.\r\n\r\nThe harness bridge names the concrete mechanism for each of these.\r\n\r\n### Every dispatch is a file before it is a launch\r\n\r\n- Write the brief to a file under `tmp/`, named for its unit, before launching the unit, whatever\r\n  engine executes it. A brief composed only inside a launch argument cannot be corrected, resumed,\r\n  or re-run after that call ends. A native unit's pair is `tmp/units/<unit>-brief.md` and\r\n  `tmp/units/<unit>-report.md`. A bench unit's pair sits under the bench directory its role file\r\n  names, beside the journal.\r\n- Write the unit's returned report in the SAME action that commits its code, never afterwards. A\r\n  commit message states what changed; the report states what the unit measured, what it decided, what\r\n  it could not close, and which of its own claims it flagged. An auditor's subject is the report,\r\n  so a report living only in the Orchestrator's context stops the next lane on arrival.\r\n- Capture the unit's returned report to a file beside its brief under the same unit name, so a\r\n  unit's instruction and its outcome are one pair on disk.\r\n- Name, inside a report that rests on a bench lane, that lane's journal path and session id, so\r\n  the provenance survives the journal's sweep.\r\n- Amend a brief on re-run rather than restating it. A mid-campaign correction produces a successor\r\n  file recording what changed and why, and the original stays. A fix round's brief names the\r\n  findings it carries and where each came from.\r\n- Name a corrected unit's effective brief and report and the pair they supersede before that unit\r\n  integrates. A unit whose correction landed as a serial patch or a direct reconciliation, with no\r\n  successor pair on disk, cannot be re-run from what the campaign kept.\r\n- Write the round's verdict to `.orkestrel/<package>/<unit>-audit-verdict.md`. That file is where\r\n  the audit step records a lane or a checker that did not run.\r\n- Read the copy the executor will open, not the one you wrote. A brief written in the orchestrator's\r\n  repository and staged into the subject's checkout so a `-C` invocation can reach it is a second\r\n  file, and staging can rewrite a path or drop a clause. The executor rules on what it opens, so a\r\n  staged copy whose facts are false stops a unit that was correctly briefed. Verify the staged path\r\n  and its load-bearing facts before launching, and stage into a scratch directory the subject tree\r\n  ignores rather than into the checkout root.\r\n- Send a decision taken mid-campaign to every unit already in flight whose brief it invalidates. An\r\n  executor cannot see a change made after it was dispatched, so it writes the state its brief\r\n  described and the defect surfaces as its own.\r\n- Retention is uniform for every unit, whatever engine ran it, including an Orchestrator-owned\r\n  integration, fix, probe, or capture unit: copy the brief, the returned report or distillate, the\r\n  audit verdict, the exact executed script or instrument, and the acceptance evidence into\r\n  `.orkestrel/<package>/` as the unit is dispatched and as it returns, then sweep only the `tmp/`\r\n  launch copies. A capture claim's instrument is acceptance evidence; the frames may be swept once\r\n  the record transcribes them, because the committed instrument re-produces the film. The **Bench\r\n  laws** rule \"Ephemeral streams, durable records\" owns journals and points here for everything\r\n  durable.\r\n- Name a retained log with the `<unit>.log.txt` pattern, never with a bare `.log` suffix, which the\r\n  root `.gitignore` file ignores.\r\n- Promote anything that must outlive the campaign into a durable artifact before the sweep â€” a\r\n  commit message, a guide, a rule, a retrospective. What is only in a swept file did not survive,\r\n  and a debrief that must quote the record verbatim has nothing to quote.\r\n- Land a process rule stated as binding mid-campaign in the owning rule or contract file in the\r\n  same commit that states it. A campaign artifact is evidence, never a rule's home.\r\n\r\n### Where campaign artifacts live\r\n\r\n- Put every campaign artifact in the **orchestrator's** repository under `.orkestrel/<package>/`,\r\n  named for the package the campaign is about.\r\n- Give a campaign spanning several packages one shared `.orkestrel/campaign/` folder instead, so the\r\n  wave's plan, routing ledger, and verdicts sit together rather than split across the packages they\r\n  rule on.\r\n- Never put them in the package they are about. A published package's tree is its product.\r\n- Where the orchestrator's repository is itself a subject package, keep `.orkestrel/` as the\r\n  artifact home and stage every landing chain by path, never with `git add -A`. Run that\r\n  checkout's own CLI through the built `node dist/bin/main.js` entry, never through the `npx`\r\n  launcher, and record its audit reading beside the landing instead of gating the landing on it.\r\n  Commit the records before the landing's commit step, never during it.\r\n- Claim nothing outside `.orkestrel/` unless Orkestrel scaffold mandates it. Everything Orkestrel\r\n  owns in a consumer's tree lives beneath that folder, so a convention can be settled there without\r\n  colliding with a convention that is not Orkestrel's.\r\n- Keep the campaign narrative and every ruling in the durable artifact that owns it â€” the guide for\r\n  product truth, a rule or role file for process truth, the commit message for the decision itself.\r\n  Use `ROADMAP.md` only where the repository already keeps one.\r\n- Prefer a mechanism that recomputes a fact over a document that records it. A document recording\r\n  live state is stale from the moment it is written, and the next campaign reads it as current.\r\n  Where the fact can be derived, derive it: the fleet's publish order lives in the catalog table\r\n  `scaffold catalog` regenerates, not in a written order anyone has to remember to update.\r\n- Prune the campaign folder in a commit at acceptance. Git history is the archive; the working tree\r\n  is the workspace. `.agents/skills/orkestrel-debrief/references/retention.md` owns the procedure â€”\r\n  the checks that close the prune, the artifact locations it sweeps, and the promotion record\r\n  the commit message carries. Run it before deleting anything.\r\n\r\n### Required sections\r\n\r\n- **Role and engine.** The named role and its explicit engine.\r\n- **Objective.** One concrete outcome.\r\n- **Context.** The evidence slice, paths, decisions, `AGENTS.md`, applicable rules, the skill name\r\n  and its required references (or an explicit none), and the guide or spec. Include the host\r\n  environment facts the unit will hit â€” the shell, path, and network constraints its commands run\r\n  under â€” because an executor that rediscovers them pays for the discovery in round trips. State\r\n  every standing condition the same way: a file expected to be dirty, a command known to fail, a\r\n  shim the shell blocks. A condition the brief leaves unnamed comes back as a deviation report\r\n  about something you already knew.\r\n- **Unknowns.** What the Orchestrator does not yet know that the unit needs, named as unknown, with\r\n  how the unit reports back on it. A brief that cannot be fully specified says so instead of\r\n  shipping a guess the executor would have to invent an answer around.\r\n- **Scope.** Owned files, shared and off-limits files, allowed tools, permission limits.\r\n- **Execution.** State that the executor performs the assignment directly and spawns nothing. Put\r\n  it in every brief; an executor deep in a task does not re-read this contract. Write the sentence\r\n  for the reader the transport actually delivers it to, because \"directly\" names a different action\r\n  on each side of a bridge. To a native subagent or a bench engine reading the brief inside its own\r\n  CLI, it means do the work yourself. To a bridge driver, whose entire assignment is the launch, it\r\n  means carry the brief across unaltered and return the journal â€” the engine behind the CLI is not a\r\n  subagent the driver is spawning, and a driver told to work directly answers from its own engine\r\n  instead. That answer reads normal and its only tell is the missing journal, so pair this sentence\r\n  with **Bench laws** rule \"Journal first\" and refuse a bench result whose journal path and session\r\n  id are absent.\r\n- **Output.** The exact distilled return shape. No process diary.\r\n- **Deviation contract.** The required stop-and-report behaviour for writers, scoped. A conflict\r\n  with the primary objective stops the unit. An ancillary conflict â€” where a paragraph sits, which\r\n  heading a section takes â€” is the executor's to decide, record, and carry on from. An unscoped\r\n  contract stops a unit over a detail it was equipped to settle.\r\n- **Acceptance criteria.** Independently checkable completion conditions.\r\n- **Review evidence.** What the subject type requires, per the table in `orkestrel-falsify`. For a\r\n  code change that is the actual diff and the actual status output; omitting either is a dispatch\r\n  deviation. For any claim about a rendered or externally driven surface, the capture portfolio is\r\n  the review input and source is corroboration. A subject may occupy more than one row â€” a ruling\r\n  whose fixes already landed as edits is both a proposal and a code change â€” and it gets the\r\n  evidence of every row it occupies.\r\n\r\n### Check the brief before you send it\r\n\r\nFill `.agents/templates/brief.md`, which carries the named scope rows and the worked reason behind\r\neach check. Then run this checklist against what you filled.\r\n\r\n- Name the executor that will open the brief, and write the transport for that reader. A bridge\r\n  driver and the bench engine inside that driver's CLI need opposite instructions.\r\n- Paste the command and its output behind every factual claim â€” paths, counts, registrations, file\r\n  existence. Name the scope any search covered, and check a fact against the code rather than\r\n  against another artifact that states it.\r\n- Take every measurement under the conditions the unit runs in, or have the unit take it before\r\n  doing anything else.\r\n- Ask what the change does to every fact you measured, and fix each criterion to the state the unit\r\n  finishes in.\r\n- Scope the change by the files its result makes **false**, not by the files that declare the thing\r\n  changing: the test asserting the reversed behaviour, the fixture carrying the raised value, the\r\n  golden digest over generated output, the consumer script naming the removed union member.\r\n- Derive that set by running the suite. Where you cannot run it, name the search's bound in the\r\n  brief so the unit re-derives the set.\r\n- Grant a behaviour with the tests that pin it, a constant with every fixture and expectation\r\n  derived from it, and a template change with the materialized copy the package generates from it.\r\n- Read each criterion against the off-limits list, line by line. Grant the file a criterion needs or\r\n  strike that criterion. A file the change will break that appears in neither list is unscoped.\r\n- Where a scope line names the `tests/**` or `src/**` glob, name the paths the `scaffold repair`\r\n  command restores as off-limits in the same sentence. Bound a criterion wider than its Sites by\r\n  the brief's scope.\r\n- Scope a unit that changes a mechanism to own the prose describing it. Where a brief scopes that\r\n  prose out, name the carrier and dispatch it before the change ships.\r\n- Give a small unrelated obligation its own unit.\r\n- Name the property the unit must change, and stop. Record an expected consequence as an\r\n  observation, never as a second criterion.\r\n- Order the criteria cheap-first, so an unreachable one cannot hide a typecheck or a lint criterion\r\n  behind it. Where the change edits a file the repository vendors or digests, the regeneration step\r\n  precedes every gate that reads the generated artifact.\r\n- Never make a timing-sensitive or whole-suite gate result a criterion for a unit running inside its\r\n  own exec. Name it as an observation the unit reports with its own reading, and take the\r\n  authoritative run yourself after the unit exits. A scoped run over the unit's owned files stays a\r\n  legitimate criterion.\r\n- Check the brief's output mechanism and its verification method against the executor's tool\r\n  allowlist. A read-only lane writes no report file and runs no probe, so hand it the rendered\r\n  evidence instead.\r\n- Keep the brief's control identifiers inside the brief, and say in the brief that a test is named\r\n  for what it proves rather than for the control that specified it.\r\n\r\n### Carry every finding\r\n\r\nAfter reconciling findings into briefs, walk the retained finding list once. Every finding names\r\nthe brief item that carries it. A finding with no carrier is a dropped finding.\r\n\r\nEvery finding names exactly one carrier. A further brief claiming the same finding is not redundancy\r\nthat costs a little duplicated work â€” it is a conflict the executor discovers mid-unit, between\r\ndocuments you told it to obey, with no way to tell which you meant. It will either implement the row\r\ntwice or stop. Where a reconciliation table and a brief disagree about who owns a row, the brief the\r\nexecutor opens wins, and you fix the other one before the second unit launches.\r\n\r\n## Long-running commands\r\n\r\nA bench exec, a Workflow, an install, a build, and a publish chain are one class of thing: a\r\ncommand that outlives the turn that started it. Every law here binds all of them.\r\n\r\n### Launching\r\n\r\n- The Orchestrator launches every long command as a harness-tracked background command under a hard\r\n  time cap. Never detach one from inside a dispatched agent. The harness owns the lifecycle,\r\n  completion re-invokes the session, and the cap kills a wedged command loudly instead of trusting\r\n  the agent to report its own failure. A wedged bridge is silent, and silence must never read as\r\n  progress.\r\n- Never replicate git commits through a hosting provider's REST API when a file's content must ride\r\n  inside the tool-call JSON. The per-call read cap truncates it, and a lockfile is the file that\r\n  proves the point: it transits incomplete and the tree it lands in installs something else. Push\r\n  over git, or move the file another way.\r\n- Write a multi-step chain to a script file and run the file. A chain composed inside one shell\r\n  argument cannot be read back, corrected, or re-run, and the record of what actually ran is the\r\n  argument text in a transcript rather than a file on disk.\r\n- Never edit a script file while a shell is executing it. `bash` reads a script incrementally from a\r\n  byte offset rather than loading it, so an edit that shifts line numbers moves the text under that\r\n  offset and the shell resumes mid-construct. The run dies on a syntax error in a line the script\r\n  does not contain, which reads as a defect in the work rather than as the edit that caused it. Copy\r\n  the file, edit the copy, and launch the copy for the next run. A successor's header names its own\r\n  file, its own log, and what changed from the file it supersedes.\r\n- On a Windows host this binds every program-carrying command, not only long ones. Heredocs,\r\n  `node -e`, `node -p`, `&&` chaining, and any argument carrying `${...}` trip the Git Bash\r\n  approval classifier and turn an unattended run into a manual approval prompt. Write the program\r\n  to a file, invoke the file, and keep each shell call one plain command.\r\n- Detach anything that must survive its launching shell with `setsid`. A backgrounded flow the\r\n  harness reaps mid-step leaves the work half done and the exit status missing, and the reap looks\r\n  identical to the step failing.\r\n- Size the cap yourself, from the observed high mark of comparable commands, plus an\r\n  independently budgeted gate allowance, plus explicit slack. Never size it from the estimate\r\n  alone. Never delegate it: a bridge starts with a clean context, holds no record of prior runs,\r\n  and can only guess. A cap-killed exec is indistinguishable from a real failure.\r\n- Run the first use of any CLI flag, subcommand, quoting form, or stdin combination in a throwaway\r\n  probe. Never inside a dispatched unit or a publish chain.\r\n- A launch is not a launch until its record grows past its header. Confirm the log advanced beyond\r\n  the head before recording that the command started, and treat an instantly-dead log as a failed\r\n  launch whose tail is the evidence.\r\n- Keep network-dependent work out of sandboxed bench execs. Bench sandboxes deny network, so\r\n  lockfile generation, real installs, and live fetches belong to the Orchestrator's own tracked\r\n  commands or to the native `implementer` or `builder` as an ordinary dispatched writing unit. A\r\n  bench exec hanging on `npm` until its cap fires is the signature of this misroute, not of a slow\r\n  bench.\r\n- A Workflow journals identically and dies identically, so give it the same watch â€” with one\r\n  correction. A workflow journal writes only at agent start and result, so its mtime goes quiet for\r\n  minutes during healthy work, and the liveness signal is the newest subagent transcript instead. A\r\n  watch that reports only new events cannot report a death, because silence and progress look the\r\n  same; the filter must fire on absence. Recover with `resumeFromRunId`, which returns every\r\n  completed agent from cache and re-runs only what never finished.\r\n\r\n### Reading liveness\r\n\r\nRead liveness from the artifact the work produces, never from its wrapper. A subagent's transcript\r\nfile can report zero bytes while the agent is working normally, so an empty or stale wrapper proves\r\nnothing.\r\n\r\n- Judge a unit by what it has changed in the tree: modification times on the files it owns, the\r\n  counts its suite reports, the report it was told to write.\r\n- Check that before killing anything. A healthy unit killed on a false signal loses everything it\r\n  had not yet written down, and the loss is charged to the orchestrator, not the unit.\r\n- If a unit must be stopped, say plainly that it was stopped and why, then assess the tree it left\r\n  rather than assuming its partial bytes are either good or worthless.\r\n- Follow the deviation ladder for a stalled journal or a cap-killed exec, using the session id from\r\n  the journal head as the recovery handle.\r\n\r\n### Confirm dead before relaunching\r\n\r\n- Prove the previous run is gone before starting another. List the processes and read the list. A\r\n  second run started beside a live first one produces failures that read as the subject's â€” a\r\n  publish chain relaunched over a live one reports `EOTP` and `E403` that are its own processes\r\n  colliding, and both readings point at the registry.\r\n- Never ask `pgrep -f` or `ps | grep` whether a command is running from a shell whose own command line\r\n  contains that command's text. The shell matches itself, so the answer is yes whatever the truth is.\r\n  This bites in separate places and each one fails differently:\r\n  - **A liveness watcher** loops forever, reporting \"still running\" and never delivering its completion\r\n    notification, because it always finds itself.\r\n  - **An elapsed-time reading** returns the watcher's age rather than the exec's, so the number falls\r\n    instead of rising and reads as a relaunch that never happened.\r\n  - **A pre-launch \"is anything already running\" check** reports a phantom concurrent writer, which is\r\n    the worst of them: the honest response to it is to kill something, and there is nothing there.\r\n    Read liveness from the recorded process id with `kill -0 <pid>`, or enumerate by executable name and\r\n    parent with `ps -eo pid,ppid,comm` and read the rows. Both are immune; a pattern over the full command\r\n    line is not.\r\n- Kill by process id, never by pattern. `pkill -f` matches the relaunch that is already starting, so\r\n  the pattern that cleans up the old run kills the new one and the cleanup reads as a launch\r\n  failure.\r\n- A killed `codex exec` is dead only when its process tree is dead: walk the children with\r\n  `ps --ppid` and confirm the `codex-code-mode-host` child is gone. Before dispatching a substitute\r\n  writer, check the owned files' modification times against the baseline â€” a live orphan is still\r\n  writing the tree the substitute is about to own.\r\n- Read a failure against what was running when it happened, not against what you believe was\r\n  running. The check costs one command and is the only thing that separates a real failure from\r\n  self-inflicted contention.\r\n\r\n## Bench laws\r\n\r\nExternal engines widen capacity. They never inherit authority. Treat every bench output as a\r\nproposal or hypothesis until it is verified against source and accepted by the Orchestrator.\r\n\r\nA bench is cross-provider reach only. This section adds only their naming specifics:\r\n\r\n- Describe what a thing is, not its implementation.\r\n- Prefer short common English; avoid jargon, abbreviations, and non-universal acronyms.\r\n- Properties are nouns; methods are verbs.\r\n- Booleans read as assertions: `aborted`, `exhausted`, `expired`.\r\n- Accessors use bare nouns, never `get*`/`set*`.\r\n- Do not alternate `count`/`length`/`size`/`total` or `abort`/`cancel`.\r\n- Name the axis a discriminant varies: `relationship`, `command`, `category`, `operation`, `via`.\r\n- A binary switch is a boolean such as `bail`, never `'continue' | 'halt'`; genuine discriminants, multi-state lifecycles, conventional value pairs (`ascending`/`descending`, `and`/`or`), and external-spec literals remain unions.\r\n- An option key, constant, or member that transliterates an external protocol field, format field, or engine pragma keeps the external wording in this project's casing, and its TSDoc names the source it mirrors: the `foreignKeys` key mirrors the `PRAGMA foreign_keys` statement, and the `keepAlive` key mirrors the Ollama `keep_alive` field.\r\n- Outside a declared wire body, a mirrored name never uses `kind` or `type` as a member name, and never uses a word § Rejected naming lists. A Compound File Binary (CFB) directory entry's object-type byte takes a named discriminant.\r\n- A declared wire body — a type whose members transliterate an external wire format field for field — keeps the external field names, `type` and `kind` included, and its TSDoc names the format it transliterates. and are not restated here. This file adds only what TypeScript itself decides.\r\n\r\n## Syntax and imports\r\n\r\n- Tabs for indentation.\r\n- No semicolons unless ASI requires one.\r\n- Single quotes.\r\n- Named exports only, except framework-required defaults.\r\n- ESM imports use explicit `.js` extensions for local TypeScript modules.\r\n- Place `import type` declarations before value imports.\r\n- Do not place blank lines between consecutive imports of the same kind.\r\n- Narrow an accepted `unknown` with a total guard rather than a conditional access.\r\n- A parameter property is a constructor parameter carrying any accessibility or `readonly` modifier.\r\n  The ban reaches every form, `readonly` alone included; declare the `#` field and assign it in the\r\n  constructor body.\r\n\r\n## Types\r\n\r\n- Put every reusable or public interface/type alias in the nearest authoritative `*/types.ts`.\r\n- Public collection properties and return types use `readonly T[]`, `ReadonlyMap<K, V>`, or `ReadonlySet<T>`.\r\n- Optional state is `T | undefined`; an optional lookup failure returns `undefined`.\r\n- `as const` annotates a literal with its own type and never overrides the checker, so the assertion\r\n  ban does not reach it. Use it to derive a literal union from a value and to fix a tuple's arity and\r\n  element types. Do not write it on a value whose contract is already declared; annotate the\r\n  declaration instead. A class field that holds one literal keeps `as const`\r\n  (`readonly code = 'ABORT' as const`): the vendored lint gate's `prefer-as-const` rule refuses the\r\n  annotated form, and a field whose type is a union of literals is annotated as the preceding\r\n  sentence states.\r\n\r\n## Immutability\r\n\r\n- Never mutate caller-owned inputs.\r\n- Use copy-on-write for internal state.\r\n- Return copies or readonly views; never leak a mutable internal reference.\r\n- Compute derived facts instead of persisting duplicate state.\r\n\r\n## Errors and outcomes\r\n\r\n| Condition                            | Required strategy                           |\r\n| ------------------------------------ | ------------------------------------------- |\r\n| Programmer error or invalid argument | Throw an `AppError`                         |\r\n| I/O/network/external operation       | Return `Result<T, E>` or throw consistently |\r\n| Optional missing lookup              | Return `undefined`                          |\r\n| Invalid input inside a guard         | Return `false`; never throw                 |\r\n\r\nUse the existing outcome contract from a declared dependency or the owning environment; do not redeclare it at each call site. When no such contract exists and adding a dependency is not authorized, define this once in the owning `types.ts`:\r\n\r\n```ts\r\ninterface Success<T> {\r\n\treadonly success: true\r\n\treadonly value: T\r\n}\r\n\r\ninterface Failure<E> {\r\n\treadonly success: false\r\n\treadonly error: E\r\n}\r\n\r\ntype Result<T, E = Error> = Success<T> | Failure<E>\r\n```\r\n\r\n- When `@orkestrel/contract` is declared, inspect and use its exact installed `Result`, construction/narrowing helpers, and `attempt` behavior instead of duplicating them.\r\n- Otherwise construct and narrow through the owning environment's centralized helpers.\r\n- Error classes expose a machine-readable `code` and optional `context`.\r\n- Every public error class ships with a guard such as `isAppError` for safe `catch` narrowing.\r\n\r\n## Comments and API documentation\r\n\r\n- Comments explain why, never restate what self-explanatory code does. The Writing rules in `AGENTS.md` and `.claude/rules/writing.md` govern their prose.\r\n- Every public export has complete TSDoc: description, `@param`, `@returns`, and `@example` where applicable.\r\n- The first sentence states what the symbol does in the third person with an `-s` verb — `Creates`,\r\n  `Returns`, `Checks whether` — and never repeats the symbol's name.\r\n- `policy/no-malformed-summary` reads that first sentence over every doc block a top-level export\r\n  declaration follows, and refuses an opening word that is not a third-person `-s` verb and a\r\n  sentence naming the declared symbol. A word ending in `s` that the rule's stop set does not name\r\n  passes whether or not it is a verb — a plural noun such as `Files` included — so read the sentence\r\n  in review as well.\r\n- Describe a boolean parameter as \"If `true`, …; if `false`, …\", and a boolean return as\r\n  \"True if …; false otherwise\".\r\n- Write a default as \"Default: …\" and a thrown error as \"Thrown when …\".\r\n- State a prerequisite and the failure behavior wherever the symbol has either.\r\n- `@deprecated` names the replacement first, then the reason.\r\n- Document an options object as one `@param`; describe its short fields under `@remarks`.\r\n- Private methods and overload-specific notes use single-line `//` comments, not public TSDoc.\r\n- Do not document speculative future product behavior unless requested.\r\n- Never use `@internal` to hide a method; make it `#` private.\r\n---\r\npaths:\r\n  - 'src/**/*.ts'\r\n  - 'app/**/*.{ts,vue}'\r\n  - 'tests/**/*.ts'\r\n  -      | Sole location                                                |\r\n| ------------------------- | ------------------------------------------------------------ |\r\n| Interfaces/types          | `*/types.ts`                                                 |\r\n| Constants/data            | `*/constants.ts`                                             |\r\n| Template definitions      | `*/templates.ts`                                             |\r\n| Pure helpers              | `*/helpers.ts`                                               |\r\n| Guards                    | `*/validators.ts`                                            |\r\n| Guard combinators         | `*/combinators.ts`                                           |\r\n| Owned snapshots           | `*/cloners.ts`                                               |\r\n| Coercers                  | `*/parsers.ts`                                               |\r\n| Shape values              | `*/shapers.ts`                                               |\r\n| Value inferers            | `*/inferers.ts`                                              |\r\n| Shape/algorithm compilers | `*/compilers.ts`                                             |\r\n| Entity/value factories    | `*/factories.ts`                                             |\r\n| Middleware factories      | `*/middlewares.ts`                                           |\r\n| Request handlers          | `*/handlers.ts`                                              |\r\n| Route tables              | `*/routes.ts`                                                |\r\n| Seeders                   | `*/seeders.ts`                                               |\r\n| Schemas                   | `*/schemas.ts`                                               |\r\n| Compiled contracts        | `*/contracts.ts`                                             |\r\n| Relations                 | `*/relations.ts`                                             |\r\n| Error classes/guards      | `*/errors.ts`                                                |\r\n| Public exports            | `*/index.ts`                                                 |\r\n| Implementations           | `*/[domain]/[Entity].ts` — one class per file                |\r\n| Function modules          | a designated folder's `[function].ts`, one function per file |\r\n\r\nUse only the centralized files an environment needs.\r\n\r\n## Declaration placement\r\n\r\n- An implementation file contains imports and exactly one class implementation with `#` fields.\r\n- It contains no module-scope interface, type, constant, or free function—even when private to that file.\r\n- A function module contains imports and exactly one exported function named for its file. Everything else extracts by kind exactly as it does from a class module.\r\n- Extract local declarations by kind. “Only used here” and “not exported” are not exemptions.\r\n- Every declaration in a centralized file is exported. Fold away a trivial single-use declaration or export/test it; never leave it hidden.\r\n- The only permitted non-exported module-scope declarations are in a runtime entrypoint that must be self-contained and cannot import siblings, such as raw source loaded in a worker. Explain that necessity in a comment.\r\n- A runtime entry—`src/bin/main.ts`, `app/browser/main.ts`, `app/server/main.ts`—is a fixed name, not a centralized kind file. Both the data rule and the function rule reach it, so it declares no module-scope constant and no module-scope function: it imports what it needs and runs. The preceding self-contained exception covers only an entrypoint that cannot import siblings.\r\n- Perform a cleanup pass after implementation: no stray implementation-file declarations, non-exported/wrong-kind centralized declarations, prohibited nested declarations, duplicate implementations, compatibility aliases, superfluous wrappers, stale imports/barrel rows, or untested extracted functions.\r\n\r\n## Kind purity\r\n\r\n- Each centralized file contains only its named kind.\r\n- Module-scope constants live only in `constants.ts`, use UPPER_SNAKE_CASE, and freeze object/array data with `Object.freeze`.\r\n- A camelCase namespace containing functions is helper behavior, not constant data; place it in `helpers.ts`.\r\n- `helpers.ts` is exported reusable infrastructure. A reusable regex, parser, header flattener, signer, or similar fragment has one implementation used by source, tests, and fixtures.\r\n- A would-be helper has these outcomes:\r\n  - trivial and genuinely single-use → fold into its caller;\r\n  - non-trivial or reusable → extract, export, unit-test, and route every duplicate through it.\r\n- `factories.ts`, `compilers.ts`, and `parsers.ts` are centralized files, not hiding places. Factory glue extracts to `helpers.ts`; pure compiler/parser recursion remains exported in its own kind file.\r\n- Every exported function in `parsers.ts` is named `parse*`. Every exported function in\r\n  `factories.ts` is named `create*`.\r\n- Those name forms are one-directional. A name does not place a function: `createWriteDirectory`\r\n  creates a directory rather than an entity and `isVacant` is a predicate rather than a `Guard<T>`,\r\n  so both stay in `helpers.ts`. Placement follows what the function is; the name form follows\r\n  placement.\r\n- Repair a violation of those forms by deciding what the function **is** first, then moving or\r\n  renaming to match. Both repairs exist and picking the wrong one does real damage.\r\n  - Wrong file, right name → **move it**. A `scan*` in `parsers.ts` is a pure lexical leaf that\r\n    belongs in `helpers.ts`. The barrel star-exports both, so the move leaves the published surface\r\n    identical.\r\n  - Right file, wrong name → **rename it in place**. An entity is a class instance whose methods\r\n    drive its own state, as opposed to a plain value that carries data and no behaviour. A function\r\n    returning a live entity is an entity factory and belongs in `factories.ts` whatever it is\r\n    called, so `restoreThing` there is misnamed, not misplaced. Renaming moves the published\r\n    surface and earns a version bump; that cost is the correct one to pay, and it is smaller than\r\n    the alternative.\r\n  - Never let the name choose. Relocating a correctly-placed function to escape a rename drags its\r\n    dependencies with it — an entity factory moved into `helpers.ts` makes that file import an\r\n    implementation class, and a leaf file that imports a class stops being a leaf for every module\r\n    beneath it.\r\n- Keep the leaf pair class-free. `helpers.ts` and `validators.ts` sit at the bottom of a module's\r\n  graph: they import types, constants, errors, and each other, and they import no implementation\r\n  class. Every file that constructs or drives a class — `cloners.ts`, `compilers.ts`, `factories.ts`,\r\n  `shapers.ts` — sits above them, consumes them, and is never consumed by them. One cycle between\r\n  the leaves is the shape this produces and is acceptable; an edge running downward from a\r\n  class-importing file into the leaf pair is not.\r\n- `templates.ts` and `contracts.ts` hold data only — shipped template definitions and compiled\r\n  contracts. A function that builds either belongs in the kind file for what it builds.\r\n- `handlers.ts` holds request handlers, which are functions. `routes.ts` holds data only: a route is\r\n  `{ method, path, handler }`, so the table maps each path to a handler declared in `handlers.ts`\r\n  and referenced by name, never to a function expression written in place. Neither file mixes kinds and the\r\n  route set stays readable as data.\r\n\r\n### What the policy instruments prove\r\n\r\nThe `policy` Oxlint plugin (`configs/policy.ts`) enforces syntactic placement: a declaration of a\r\ngiven syntactic kind appears only in a file permitted to hold that kind. The fleet policy sweep\r\n(`tests/policy.test.ts`, `tests/setupPolicy.ts`) enforces what a path or a text reading decides.\r\nThe plugin reads declaration syntax and file name; the sweep reads paths and workspace text;\r\nneither reads meaning.\r\n\r\n- The plugin proves that a module function sits in a function-kind file, that module data sits in a\r\n  data-kind file, that every centralized declaration is exported, that a class sits in its matching\r\n  implementation or errors file, and that `constants.ts` declares only UPPER_SNAKE_CASE consts with\r\n  no bare collection literal.\r\n- The sweep proves that no source, test, config, or script file carries an `eslint-disable` or\r\n  `oxlint-disable` directive.\r\n- The sweep proves that every `.claude/rules/*.md` file has a rule-map row in `AGENTS.md` and that\r\n  every row resolves to a file.\r\n- The sweep proves the host portability rules that are path- or text-shaped over the population\r\n  `POLICY_PORTABILITY_GLOB` names: no path segment carries a Windows reserved device name, a\r\n  character Windows refuses, a trailing dot or space, or a sibling differing only by case; and no\r\n  `package.json` script names a `.sh` file.\r\n- The plugin proves, over the population `POLICY_ENDING_GLOBS` names, that no source trims a\r\n  payload before splitting it on `'\\n'`, reads `os.EOL`, or imports `EOL` from `node:os`.\r\n- The sweep cannot write a filename the host refuses. A Windows host rejects `<`, folds a case\r\n  collision into one file, and turns `:` into an alternate data stream, so those boundaries are\r\n  proven from a path population rather than from written files.\r\n- The plugin does not prove a collection is frozen. It reads the declaration, never the value a\r\n  call returns, so `Object.freeze([…])` and any other call initializer are one syntax to it. The\r\n  freeze obligation in the earlier kind-purity rules binds regardless; only the bare literal is\r\n  mechanical.\r\n- The plugin does not tell one function kind from another. Every centralized file that permits\r\n  functions reads the same to it apart from the `parse*` and `create*` name forms: `cloners.ts`,\r\n  `combinators.ts`, `compilers.ts`, `errors.ts`, `factories.ts`, `handlers.ts`, `helpers.ts`,\r\n  `inferers.ts`, `middlewares.ts`, `parsers.ts`, `relations.ts`, `schemas.ts`, `seeders.ts`,\r\n  `shapers.ts`, and `validators.ts`. That list is exhaustive, a new function kind joins it, and no\r\n  later version of the plugin claims more.\r\n- The plugin reports no `data` violation in `helpers.ts`. The kind rules place a camelCase\r\n  namespace of functions there, and a namespace of callables is not separable from a data table by\r\n  declaration syntax, so `DATA_EXEMPT_FILES` in `configs/policy.ts` excludes the file. Ordinary\r\n  module data there — `export const RETRIES = 3` — is unreported; the earlier constants rule binds\r\n  regardless.\r\n- No placement or line-ending rule inspects an ambient declaration file: `.d.ts`, `.d.mts`, and\r\n  `.d.cts` are outside their reach. The lint population reaches those files, and each of those\r\n  rules refuses the file by its name, because an ambient declaration file is not a module in the\r\n  kind table.\r\n- The plugin does not inspect class-expression members. A function assigned inside a\r\n  class-expression method is unreported; the earlier functions rule still binds, and cleanup and\r\n  review enforce it.\r\n- The cleanup pass and independent review prove kind purity across those files. A helper misfiled\r\n  as a parser, a coercer misfiled as a guard, a compiler misfiled as a factory, and a shaper\r\n  misfiled as a cloner are review findings, not instrument diagnostics.\r\n- The plugin does not decide barrel membership. It parses each file alone and resolves no module,\r\n  so it cannot tell whether a declaration is reachable from its barrel. That question belongs to\r\n  each package's `tests/guides.test.ts`, which imports the barrel and gets real resolution. Do not\r\n  add module resolution here to duplicate it.\r\n- The kind table is mandatory whether or not an instrument can see the violation.\r\n\r\n## Wrapper test\r\n\r\nA wrapper survives only when it adds a real boundary, invariant, composition, translation, lifecycle, or materially narrower contract.\r\n\r\n- Delete one-line delegates, pass-through factories, rename-only helpers/getters, compatibility aliases, and wrappers around semantically identical platform or declared-dependency primitives.\r\n- Rename or import the real symbol and update every consumer atomically. Do not preserve a wrapper to avoid downstream edits.\r\n- Do not re-export a dependency's symbol from this package.\r\n- A public class method composes real entity behavior; it never exists only to forward 1:1 to a helper.\r\n- Audit callers and callees after every extraction so the old path and duplicate implementation do not remain.\r\n\r\n## Functions and orchestration\r\n\r\n- Never declare or assign a function inside another function or method.\r\n- This bans local `function`, `function*`, and `const fn = () => ...`, regardless of caller count.\r\n- The only in-body function expressions allowed are an anonymous callback passed directly as an argument and an anonymous function returned directly as the result (the factory/combinator pattern).\r\n- Instance-bound work that reaches state or sibling methods is a method, not a free function.\r\n\r\nSeparate these roles:\r\n\r\n1. **Public method:** implements the interface and genuinely composes behavior; never forwards 1:1 to one helper.\r\n2. **`#` private method:** stateful/instance-bound orchestration or the class's defining recursive/compositional algorithm.\r\n3. **Centralized helper:** pure referentially transparent leaf, independently understandable/testable without class knowledge.\r\n\r\nApply the leaf test:\r\n\r\n1. Reaches `#` state or a sibling method → private method.\r\n2. Pure self-contained computation (key, format, compare, convert, lookup, projection, one unification) → exported helper.\r\n3. Recursive spine or composition of leaves (`solve`, `isolate`, `prove`, chaining, relational join), even if pure → private method.\r\n4. Defining engine internals remain methods when extraction would hollow the class into a thin delegate.\r\n\r\nExtract pure leaves aggressively; keep the class's actual behavior.\r\n\r\n## Class order\r\n\r\n1. `#` private fields: context, options, state/result, child managers.\r\n2. Constructor: initialize context/options and instantiate child managers.\r\n3. Public interface: getters, then methods.\r\n4. `#` private methods.\r\n\r\nStore child managers in `#` fields and expose readonly getters typed as their interfaces.\r\n\r\n## Middleware\r\n\r\n- Middleware is behavior `(context, next) => ...`, never a class with one `handle` method.\r\n- Place middleware factories in `middlewares.ts` as `createX(options): Middleware`; keep them distinct from entity/value factories.\r\n- Keep middleware-local state closure-private.\r\n- If consumers must address, share, inspect, or replace that state, extract the state to a pluggable class supplied as an option, with an in-memory default.\r\n- Extract reusable cross-middleware machinery to helpers/classes.\r\n- `MiddlewareManager` is the sole manager of the middleware composition chain; do not create one manager per middleware.\r\n\r\n## Environment/module placement\r\n\r\n- Shared cross-environment logic belongs in the central core/shared layer. Other environments import core; core imports neither browser nor server.\r\n- An environment with multiple modules keeps cross-module types/helpers at the environment root and module-specific declarations inside the module.\r\n- Promote a declaration to the environment root only when at least two modules use it.\r\n- The environment barrel re-exports root files and module barrels.\r\n- Cover cross-cutting environment-root helpers with behavioral tests; each module API receives its own guide parity.\r\n\r\n### Entity subfolders\r\n\r\n- When one entity grows a family (entity + manager or sibling implementations), nest only its class files in a lowercase plural folder.\r\n- Keep its interfaces in module-root `types.ts`, factories in module-root `factories.ts`, and exports in the module barrel.\r\n- Entity subfolders never grow their own centralized files.\r\n\r\n### Kind or folder\r\n\r\n- A word is either a centralized kind or a domain folder, never both.\r\n- A folder named for a centralized kind—`helpers/`, `validators/`, `handlers/`—is that kind's file, not a folder.\r\n- `FUNCTION_DOMAIN_FOLDERS` in the fleet-canon register (`configs/policy.ts`) registers the\r\n  folder paths whose direct modules are function modules. Registration makes a path eligible and\r\n  fixes the declaration shape checked there; it judges nothing about what a module does.\r\n- Never infer a function domain from a folder's name; a camelCase module inside an unregistered\r\n  folder is misplaced.\r\n- Register a folder only when its direct modules are camelCase single-function `.ts` modules. A\r\n  folder of PascalCase single-file components, or of entity classes, never qualifies.\r\n- Request a new domain through a fleet-canon change. There is no workspace-local registration path.\r\n\r\n### Extension categories\r\n\r\n- A designed extension point—drivers, stores, transports—gets its category folder even with one concrete class.\r\n- This applies both to consumer implementations of another domain's contract and default implementations beside the defining contract.\r\n- The contract remains in module-root `types.ts`; only concrete classes nest.\r\n- Nest because the category is a designed growth seam, not because a class name happens to end in `Store` or `Driver`.\r\n- Co-equal native-object wrappers that are core primitives stay flat.\r\n\r\n### Stores\r\n\r\nChoose the access shape:\r\n\r\n- **Point access:** `get`, `set`, `delete`.\r\n- **Bulk restore:** `save`, `load`, `remove`, `clear`.\r\n\r\nEvery shape obeys:\r\n\r\n- The stored value carries its own id; do not pass a separate id to `set`/`save`.\r\n- Every primitive is async and returns a `Promise`.\r\n- Deleting/removing a missing key is a no-op.\r\n- Concrete stores live in `stores/`; the interface stays in module-root `types.ts`; `create*Store` factories stay in `factories.ts`.\r\n\r\n## Barrel exports\r\n\r\n- `*/index.ts` is the sole public barrel.\r\n- Only an `index.ts` may re-export.\r\n- A barrel contains only `export * from './module.js'` declarations. Do not use\r\n  named, default, namespace, or type-only barrel exports.\r\n- A star-export collision is a design failure: rename the conflicting concept\r\n  at its owner and update consumers. Never hide the collision with a selective\r\n  barrel row.\r\n- Never re-export a symbol originating in another package; fix consumer imports to the originating package.\r\n- Implementation files export their own classes directly.\r\n- Expose every intentional top-level source export through its correct environment barrel.\r\n- Never let current consumer count gate later exposure. Developers receive the same supported\r\n  mechanisms the package uses, so they retain full control and customization.\r\n- If a declaration must not be public, make it a true local or runtime-private detail, or remove\r\n  the capability for a substantive reason. Never leave an intentional reusable export stranded\r\n  outside the barrel.\r\n- One-class-per-file evicts some classes from their only caller, and `export` on such a file is\r\n  structural rather than a statement of intent. Barrel that class when a consumer can construct it\r\n  from values they already hold. Intern it — out of the barrel, and named in the package's parity\r\n  `INTERNAL` list — when its constructor requires a value only its owner produces, or when the\r\n  public value is a projection of the instance rather than the instance. A class named in a public\r\n  signature is always barrelled.\r\n- Delete a barrel row whose class no consumer can construct, and delete its `@example` with it. A\r\n  row obliges a documented, runnable example, so a class kept public without one is drift that\r\n  parity cannot see.\r\n- When a symbol moves, update every import; never leave a compatibility re-export.\r\n\r\n```ts\r\nexport * from './types.js'\r\nexport * from './constants.js'\r\nexport * from './errors.js'\r\nexport * from './validators.js'\r\nexport * from './helpers.js'\r\nexport * from './factories.js'\r\nexport * from './greeters/Greeter.js'\r\n```\r\n\r\n## System constraints\r\n\r\n- Build or substantively expand a capability with its first real consumer; do not speculate. This\r\n  gate applies only when creating or expanding the capability, not to its later barrel exposure.\r\n- Keep interfaces to the smallest primitives the capability requires.\r\n- For multiple backends, implement shared querying/paging/aggregation in one engine over those primitives. A backend may override an operation only with a genuine native fast path and otherwise falls back to the engine.\r\n- Centralize any pattern repeated twice.\r\n- Keep everything generic/reusable and free of unrelated-project logic.\r\n- Do not expand the capability set without concrete need. Once that capability exists intentionally,\r\n  its reusable top-level exports follow the earlier barrel rule without a second consumer gate.\r\n- Do not remove structural files because they are empty.\r\n- Prefer the smallest complete implementation that preserves architecture.\r\n- No deprecation aliases, compatibility shims, or backward-compatibility branches; update all consumers atomically.\r\n- No polling/busy loops or recursive microtasks as architecture. Park idle work on an event/abort wakeup and yield long work in cooperative quanta.\r\n- Framework/server utilities provide mechanism—HMAC, CORS, parsing, sessions, cookies, CSRF, static serving—not product policy such as user models, login flow, or authorization.\r\n---\r\npaths:\r\n  - 'src/**/*.ts'\r\n  - 'app/**/*.{ts,vue}'\r\n  - 'tests/**/*.ts'\r\n---\r\n\r\n# API pattern rules\r\n\r\n## Declared ecosystem capabilities\r\n\r\nBefore writing a guard, parser, combinator, outcome, safe exception boundary, contract shape/compiler, schema utility, error narrower, emitter helper, or other general primitive:\r\n\r\n1. Inspect `package.json`, the lockfile, vendored dependency guides, and exact installed declarations/exports.\r\n2. Build a semantic overlap map between the proposed/local behavior and declared `@orkestrel/*` capabilities.\r\n3. Reuse the originating package directly when semantics match.\r\n4. Keep local behavior only when it adds a real domain invariant, composition, projection, translation, or intentionally different contract.\r\n5. Test the difference. Similar names are not proof of equivalent semantics.\r\n\r\nNever reimplement or rename-wrap a declared package primitive. Do not add an ecosystem dependency unless the user explicitly authorizes it.\r\n\r\n## Options\r\n\r\n- Top-level keys are single words.\r\n- Group related settings beneath the configured entity noun; every leaf is one word.\r\n- Never encode grouping through prefixes such as `serverPort` or `databasePath`.\r\n- Reserve `on` exclusively for initial `EmitterHooks`.\r\n- Explain short option keys in TSDoc `@remarks`, not through longer names.\r\n\r\n```ts\r\ninterface ServerOptions {\r\n\treadonly on?: EmitterHooks<ServerEventMap>\r\n\treadonly error?: EmitterErrorHandler\r\n\treadonly server?: { readonly port?: number; readonly timeout?: number }\r\n\treadonly database?: { readonly path?: string }\r\n}\r\n```\r\n\r\n## Managers\r\n\r\n### Accessors\r\n\r\nManagers expose one item and all items through singular/plural domain nouns:\r\n\r\n```ts\r\nentity(key): EntityInterface | undefined\r\nentities(): readonly EntityInterface[]\r\n```\r\n\r\nExamples: `timeout(id)`/`timeouts()`, `agent(id)`/`agents()`.\r\n\r\n### Batch operations\r\n\r\nOne single-word verb carries these overloads:\r\n\r\n```ts\r\nmethod(): void\r\nmethod(id: string): boolean\r\nmethod(ids: readonly string[]): boolean\r\n```\r\n\r\n- No argument applies to all.\r\n- One id applies to one.\r\n- An id list applies to those items and returns true only when all succeed.\r\n- Never split into `methodAll`, `methodOne`, or `methodMany`.\r\n- A manager that owns `clear` and a batch verb keeps both: `clear` resets the entity's state and emits one `clear`, and the no-argument batch verb applies the verb to every item and emits per item. They are different observable operations.\r\n- When a single item type can itself be a list/open record, declare the array overload first and document how callers express one list-valued item.\r\n\r\n## Stateful emitters\r\n\r\nAn entity with lifecycle transitions, constraints, or observable operations owns an emitter by composition:\r\n\r\n1. Define `{Entity}EventMap` in `types.ts`.\r\n2. Add `readonly on?: EmitterHooks<{Entity}EventMap>` and `readonly error?: EmitterErrorHandler` to options.\r\n3. Add `readonly emitter: EmitterInterface<{Entity}EventMap>` to the interface.\r\n4. Store `readonly #emitter: Emitter<{Entity}EventMap>` and expose it through `get emitter()`.\r\n5. Initialize with both hooks and error handling: `new Emitter({ on: options?.on, error: options?.error })`. Positional constructors thread both values equivalently.\r\n6. Emit directly with `this.#emitter.emit(...)`; do not add a guarded `#notify`.\r\n7. Call `this.#emitter.destroy()` last in the entity's `destroy()`.\r\n\r\nNever inherit from `Emitter`, write delegation boilerplate, or use `Omit` to reshape it.\r\n\r\n### Listener isolation\r\n\r\n- The emitter isolates each listener; one throw never prevents sibling listeners.\r\n- It reports every listener throw to its own `(error, event)` error handler.\r\n- It never rethrows a listener error.\r\n- A throwing error handler is swallowed to prevent recursion.\r\n- Never add `observerError` or another listener-failure event to a domain `EventMap`.\r\n- A genuine domain I/O/transport `error` event is distinct and remains valid.\r\n\r\n### Browser/DOM variant\r\n\r\nIn a pure browser-DOM environment where each entity already owns a host `Element`, the element may be the event host:\r\n\r\n- emit a typed bubbling `CustomEvent` through shared dispatch helpers;\r\n- subscribe with shared listener helpers;\r\n- bind `options.on` through one `bindEventMap` helper.\r\n\r\nChoose one event model per environment. `Emitter<TMap>` remains the default outside exclusively DOM-bound environments.\r\n\r\n### Event maps\r\n\r\n- Event names are single present-tense verbs or nouns: `start`, `connect`, `expire`, `exhaust`, `drain`, `chunk`.\r\n- Never publish a generic `status` event carrying a transition value; publish each transition as its own event.\r\n- Type errors as `unknown`.\r\n- Use empty tuples for signals and labeled tuple elements for IDE clarity.\r\n- Keep an entity's event map focused, normally four to eight events.\r\n\r\n## Validation and contracts\r\n\r\nUse these orthogonal contract mechanisms:\r\n\r\n| Surface          | Contract                                                                      |\r\n| ---------------- | ----------------------------------------------------------------------------- |\r\n| `validators.ts`  | Total `is*` guards: `(unknown) => value is T`; no coercion/side effects       |\r\n| `combinators.ts` | Build guards from guards: `arrayOf`, `recordOf`, `unionOf`                    |\r\n| `parsers.ts`     | Flat coercers returning `T \\| undefined`                                      |\r\n| Shape DSL        | One `ContractShape` compiled into schema, guard, parser, and seeded generator |\r\n\r\n- Use plain guards/parsers for small contracts.\r\n- Use the shape DSL only when validation, serialization, and generation parity earns its complexity.\r\n- When `@orkestrel/contract` is declared, use its exact installed guards, parsers, combinators, outcomes, `attempt` boundary, and shape DSL wherever their semantics match. Do not maintain a local copy of those primitives.\r\n- A guard never throws for adversarial input, cycles, deep nesting, or hostile prototypes; return false.\r\n- Recursive guards track ancestors and cap depth.\r\n- Recursion enters only through an explicit lazy gate.\r\n- Non-lazy structural cycles fail at build time, not runtime.\r\n- Parse/guard soundness is mandatory:\r\n  - guard-valid input is never rejected by its parser;\r\n  - every parsed result satisfies its guard.\r\n- Derive parser and guard from one source or test the round trip.\r\n\r\n### Foreign contracts\r\n\r\nA value returned by an interface another package publishes is FOREIGN data. Own it, validate what you dereference, and narrow nothing.\r\n\r\n- Enforce the published contract and no more: accept unknown members, accept any implementation the interface admits including a class instance, and check each member as its published type declares it. A member typed `number` is not checked as an integer.\r\n- Reserve the exact-record guard for a record this package owns. Over a foreign interface it refuses values the interface permits and fails closed on a valid implementation.\r\n- Narrow nothing in an ownership transform. Where the published contract is wider than the copy mechanism, seal the value in place rather than refusing it.\r\n- Own a foreign value at arrival, validate the owned copy, and read the foreign object exactly once. Read count is this package's decision, so no result may depend on it.\r\n- Validate only what the package dereferences from a union it must narrow. Own a wide foreign record it merely carries and leave it unvalidated. State that asymmetry on the option that admits the implementation.\r\n---\r\npaths:\r\n  - 'tests/**/*'\r\n  - 'vite.config.ts'\r\n  - 'configs/**/*.ts'\r\n  - 'package.json'\r\n---\r\n\r\n# Testing rules\r\n\r\n## Test contract\r\n\r\n- Mirror module/application structure:\r\n  `tests/{src,app}/[environment]/[domain]/[module].test.ts`.\r\n- The mirrored population is `src` and `app` alone. `configs/` is a source directory and is\r\n  deliberately not a mirrored root: its leaves produce the workspace's configuration rather than ship\r\n  in it, and they are proved from `tests/config.test.ts` beside the configuration they produce. Do\r\n  not add `tests/configs/`.\r\n- Resolve a mirrored module through `.ts`, `.tsx`, `.mts`, `.cts`, `.vue`, `.scss`, or `.css`.\r\n- Resolve a Sass or CSS partial through the module's leading underscore.\r\n- Resolve each root `tests/setup*.test.ts` proof against its sibling `tests/setup*.ts` module. A\r\n  root `tests/setup.test.ts` file can prove several setup modules when their helpers serve\r\n  several projects.\r\n- Prefer test filenames matching entrypoints: `index.test.ts` for `index.ts`, `main.test.ts` for `main.ts`.\r\n- Tests are deterministic: identical inputs produce identical results.\r\n- Keep default suites fast: timers normally use 10–50 ms and tests make no network calls.\r\n- Use real implementations and small scenarios. Never use mocks, behavioral fakes, module replacement, or framework spies for project-owned or integrated behavior.\r\n- Use recorders for calls/events, temporary resources for stateful boundaries, protocol-faithful fixture servers for deterministic network peers, and the real external service when its behavior is the claim.\r\n- Prefer inert customizable data and input stubs.\r\n- Allow a scripted boundary stub only when it implements the real interface or protocol minimally, to drive the system under test. It never reimplements project-owned behavior and never stands in for the integration being claimed.\r\n- Bind a test fixture server to `127.0.0.1` on an ephemeral port (`listen(0)`), never to `::1` and never to a fixed port: a host without IPv6 fails `EAFNOSUPPORT`, and a fixed port flakes on occupancy.\r\n- Cover happy paths, error paths, empty input, boundary values, `NaN`, positive/negative zero, cycles, and Map/Set order where relevant.\r\n- Test observable behavior, not implementation details.\r\n- Assert the membership a discovered or globbed set must have, not a total that a partly empty population satisfies. A glob spanning two locations passes a size check while one of them matches nothing.\r\n- Never assert an implementation against itself. Compare the answer to a declaration, a fixture, or a second mechanism that could disagree with it. Re-deriving the answer the same way the source derives it produces a test that passes for every value the source ever returns, and it reads exactly like a real one.\r\n- Probe a host-varying property at runtime, on the host the test is running on, and assert against what the probe returned. Filesystem case folding, path separators, permission bits, and rename semantics differ per host, so a fixture built on one host describes that host and silently measures something else on the next.\r\n- Assert a runtime-chosen result as the property it must have, not as the number one run produced. Compression, timing, and buffer sizing are the runtime's choice, so pin the relationship the test depends on — that the encoded form is larger, that the second call is faster — and let the assertion fail when the input drifts out of the range where that relationship holds.\r\n- Measure an elapsed interval with `performance.now()`, never `Date.now()`. `Date.now()` returns whole milliseconds, so an interval built from two of its readings truncates at both ends and can under-report by a millisecond — enough to fail a boundary assertion against a timer that behaved correctly. `performance.now()` is monotonic and sub-millisecond, and it does not move when the wall clock does.\r\n- Give a conditional skip the mechanism that makes it inapplicable, cited, not the platform name alone. A test skipped on a platform is a test nobody re-examines; a test skipped because a named API rejects a named case is one anybody can re-check.\r\n- A regression test records the exact command and its failing count before the fix, and the same command's passing count after.\r\n- The revert that proves a repair reddens exactly the test that names the defect. Keep the import and collection graph valid while reverting, and confirm the named test was collected. A revert that reddens anything beyond that test broke the harness, and its count is not evidence.\r\n- Use `it.todo()` only for explicitly out-of-scope roadmap work, never to complete the current request. Every `.skip` or conditional skip has a narrow verifiable applicability reason.\r\n- Do not create test files solely for `constants.ts`, barrels, error definitions, or `types.ts`.\r\n- Run the narrowest relevant Vitest project during development; do not run the entire suite casually.\r\n\r\n## Cross-cutting proofs\r\n\r\nA proof that covers the workspace instead of one module has a fixed location, so no package invents\r\nits own:\r\n\r\n| Path                         | Proves                                                                                                                                                                                       |\r\n| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |\r\n| `tests/policy.test.ts`       | The path- and text-shaped policy laws: mirrors, suppressions, the rule map, filenames, manifest scripts, skills, and bridges                                                                 |\r\n| `tests/config.test.ts`       | Root configuration resolves its aliases, projects, and outputs, and the `configs/` leaves behind them                                                                                        |\r\n| `tests/guides.test.ts`       | Every documented API exists, every public API is documented, every compared summary, example, and pitch equals its source, and every executable fence returns what the guide says it returns |\r\n| `tests/conformance.test.ts`  | Where this package drifts from the official tooling it tracks                                                                                                                                |\r\n| `tests/distribution.test.ts` | The packed package installs and resolves through its public exports                                                                                                                          |\r\n| `tests/integration.test.ts`  | The package's features work together end to end across environments                                                                                                                          |\r\n| `tests/setup*.test.ts`       | Reusable behavior exported from sibling `tests/setup*.ts` modules works as the workspace's suites require                                                                                    |\r\n| `tests/service/**/*.test.ts` | The live external services this package drives, driven for real                                                                                                                              |\r\n\r\n- Put each root `tests/setup*.test.ts` proof in the `setup` project. Keep its assertions on\r\n  exported test-infrastructure behavior: do not duplicate production behavior there, and do not\r\n  move setup-helper assertions into another cross-cutting proof.\r\n- `.claude/rules/workspace.md` names the Vitest project each location belongs to.\r\n- The `guides` project runs in Node with the browser disabled. Its subject is what the guide\r\n  claims: that every documented name resolves, and that every fence asserting a value returns\r\n  that value. A proof that renders a component and compares it against a definition is a\r\n  composition and belongs in an `integration.test.ts` scoped to its directory.\r\n- Transcribe each flagship fence and assert the values its comments claim. Name resolution is\r\n  not a behavioural proof, so a fence documenting a value the code contradicts passes every\r\n  parity assertion. Change a fence, change the transcription beside it.\r\n- `integration.test.ts` is a reserved filename at any level. It names a scope rather than a module,\r\n  so the mirror rule does not reach it; its scope is the directory it sits in.\r\n- An integration test is an end-to-end test: it composes the package's own features and drives them\r\n  together, through the public API, with no part of the system under test replaced.\r\n- Scope it by where the composition happens. `tests/integration.test.ts` drives features **across**\r\n  environments — core through server, core through browser, one environment's output consumed by\r\n  another. A nested `tests/src/<environment>/integration.test.ts` drives features **within** that one\r\n  environment.\r\n- Do not put a packaging, install, or distribution check in an integration test. What the tarball\r\n  contains is a different question from whether the features compose.\r\n- A test the mirror rule flags is a misplaced test until its placement is checked. Move it to the\r\n  location its scope names. Widen the rule only when that check shows the test already sits at the\r\n  location its scope names and the rule's population omits a module this ruleset mandates, and then\r\n  widen the population rather than admitting the individual case.\r\n- A nested `tests/{src,app}/<environment>/**/integration.test.ts` runs in that environment's project,\r\n  whose existing glob collects it exactly once. Give it a separate exact-path project entry only when\r\n  the proof needs different setup or a different runtime, and exclude that exact path from the\r\n  environment project when you do.\r\n\r\n## Probes\r\n\r\nA probe is a throwaway instrument that settles one question. It is not a test and never ships.\r\n\r\nRoute the question before writing a probe. When you can state the edit you believe is correct and the\r\nedit that must break with the stage it breaks at, the question is a claim for the `prove` tool the\r\n`probe` MCP server registers, and `.claude/rules/quality.md` § Instruments owns that rule. When the\r\nquestion carries no stated belief to falsify yet, when the subject lies outside the TypeScript a\r\nworkspace project judges, or when the proof needs what that tool's stages do not model — a process\r\ntree, a listening socket, an installed package, a built entry driven as a child, or a live external\r\nservice — write a probe.\r\n\r\nThe kinds split by which tool has to see the probe:\r\n\r\n- A **type probe** is read by `tsc`, whose scoped project includes only its own environment, so it\r\n  lives in the source tree beside what it measures. Delete it before the unit returns; a leaked one\r\n  fails the `policy` plugin's placement rules, because a probe filename is not a centralized kind\r\n  file.\r\n- A **runtime probe** is collected by a Vitest project, so it lives in `tmp/probe/` and runs through\r\n  the `probe` project. `tmp/` is ignored by git, so no probe enters a commit by accident, and every\r\n  test script names its project, so no gate runs the `probe` project.\r\n- A **bench** is read by Vitest's benchmark mode, so it lives inside a test file as a block behind\r\n  the `if (import.meta.env.MODE === 'benchmark')` guard. Only the `test:bench` script collects the\r\n  block, test mode fails an unguarded `bench()` call loudly, and no gate runs a bench. Call `bench`\r\n  directly inside the guard. A `describe` inside it trips `vitest/no-conditional-tests`, and a suite\r\n  the guard leaves unregistered fails test mode with `No test found in suite`.\r\n\r\nRun a probe before relying on an unverified belief about behaviour: what a function returns, what a\r\nconfiguration resolves to, whether a path is reached at all. Prefer a probe to an argument whenever\r\nthe probe is cheap.\r\n\r\nWhen the question is whether the difference between methods is a magnitude or negligible, write a\r\nguarded bench block beside the probe test and run the `test:bench` script. Declare the threshold\r\nbefore the run, read the ratio between the methods against each side's reported uncertainty, and\r\nrecord nothing below a magnitude. A settled magnitude that underwrites an implementation choice\r\npromotes with its test into the mirrored suite and keeps its guarded block there while that choice\r\nstands. A deterministic relationship promotes as an ordinary assertion, so delete the block. Never\r\ncommit baseline output.\r\n\r\nThese rules bind every probe:\r\n\r\n- **Prove the instrument can fail before trusting that it passed.** Pair it with a control drawn\r\n  from outside the population it covers.\r\n- **Promote or delete.** A probe that settles a claim becomes a test in the mirrored location that\r\n  proves the real source. Delete every other probe. A probe left in the suite reports on the harness\r\n  while reading as a test.\r\n- **Never commit a probe.** The ignore rule stops an accident, not a deliberate forced add, and a\r\n  type probe sits in tracked source with no ignore rule at all.\r\n\r\n## Live-service tests\r\n\r\nLive external services/models are the deliberate exception to fast hermetic defaults:\r\n\r\n- Put them in the `service` project, under `tests/service/`, with `tests/setupService.ts` for setup\r\n  and a longer timeout. That module's presence is what registers the project, so a live proof with\r\n  no readiness setup is a project nothing configures.\r\n- `.claude/rules/workspace.md` fixes which gate runs the `service` project, and that gate is not the\r\n  same one in a publishing and a `private: true` workspace.\r\n- Warm and verify service readiness in `tests/setupService.ts`.\r\n- Hard-require readiness: throw loudly; never silently skip.\r\n- Verify service-dependent logic through that service's project, not unrelated module tests or scattered conditional skips.\r\n- Tune each request to the smallest input/context/output that proves one behavior without becoming brittle or expensive.\r\n- Prefer semantic bounded assertions over exact generated prose.
