# Design reconciliation: the online-first fetch strategy

Lanes: `design-fetch-subjective-report.md` (Claude Opus 5) and
`design-fetch-objective-report.md` (GPT-5.6 Sol), blind, on `design-fetch-brief.md`.
Reconciled by the Orchestrator 2026-08-22. The Orchestrator's rulings follow; each names
the lane it adopts and what the other lane contributed or lost.

## The adopted strategy

The subjective lane's statement, adopted as the campaign's one sentence: **every remote
surface reads its live source first and falls back, whole, to the copy the installed
package distributes; each operation reports one baseline word per surface.** With its
corollary: a surface falls back only where the package distributes a copy; where it
distributes none, the surface refuses. The objective lane's sharp edge is folded in as a
named invariant: **authoritative absence never falls back** — a registry `404` or a
packument with no admitted version stays `missing`/`failed`, because writing a version
the registry says is absent produces an uninstallable manifest. Transport-class failures
(fault, timeout, rate refusal, byte-bound refusal, integrity refusal) select the floor.

## Ruling: the host mechanism — committed inventory, not the trees API

Adopted: the subjective lane's committed `host.json` inventory (SHA-256 digests per
vendored file, generated by `stageInventory`, fetched from the raw content host), then
raw fetches of only the paths whose live digest differs. Rejected: the objective lane's
`git/trees?recursive=1` recommendation — on that lane's own risk row. It wrote
"shared-IP REST exhaustion can cause distributed fallback in CI" while recommending the
API whose unauthenticated budget is 60 requests per hour per address; a fleet's CI
behind one address is exactly where unattended propagation must work. The committed
inventory keeps every request on the raw host with no documented REST budget, one hash
algorithm the package already uses, one endpoint group, and one branch setting. Its cost
— a generated committed file that can go stale — is closed by the conformance gate U1
must prove with a mutation probe. The objective lane's tree-consistency idea survives
transformed: the digest chain (inventory digest per file, membership digest over the
inventory) is the single-baseline consistency proof, in SHA-256.

## Ruling: the contract — the subjective shape

Adopted: `Baseline = 'live' | 'floor'`, one `Provenance` record per verb result, `Copy`,
`Host`, `MaterializerOptions.host: string | Host`, `UpstreamInterface.vendor`, the
`guides` group renamed `repository`, `ORKESTREL_SCAFFOLD_REPOSITORY` as the one new
environment variable, and `--offline`. Rejected: the objective lane's per-result
`baseline` object unions and its `HostResult`/`UpstreamBounds` groups — a per-row or
per-result baseline object under an all-or-nothing rule restates a fact the surface
already holds (the derive-state law), and the existing top-level `limit`/`budget` bounds
stand. The objective lane's endpoint-specific bounds mapping is kept as implementation
guidance: registry bounds stay `MAX_REGISTRY_BYTES`/`MAX_TOTAL_REGISTRY_BYTES`; host and
guide responses stay under the artifact bounds; every consumed byte, including from a
refused response, spends the call budget. A `--from` run omits `host` from `provenance`:
the surface was neither read live nor from the installed floor, and a surface the
operation did not read is absent.

## Ruling: versions — soften transport failures, keep authoritative refusals

Both lanes converged on softening `new` and `repair` to the floor with a loud record,
and on `catalog` staying hard (no distributed copy of membership exists). Adopted
exit-code rule (subjective): a floor baseline the network forced is drift — exit `1`
everywhere except `new`, whose exit answers "was the workspace created" and which
documents the floor as its offline product (this also makes
`guides/scaffold.md:898-901` true, which is false today). Adopted from the objective
lane: the authoritative-absence invariant above, and the rule that a row with no valid
concrete floor keeps the hard `FETCH` refusal — no mutation ever writes a dependency
without a concrete answer, which preserves the version campaign's core invariant.

## Ruling: guides — the target's mirror is the floor; nothing new ships

Adopted (subjective): no vendored fleet-guide floor. A foreign guide's floor is the
target's own existing mirror: a failed live row is skipped, the mirror is kept, the skip
is named, `provenance.guides` reads `floor`; `#assertFetched` keeps its refusal over
`entries` and drops it over `mirrors`. Rejected: the objective lane's staging of fleet
guide mirrors into `dist/host` — it grows the tarball with every fleet package's guide
and hands a new offline target guides that are stale from the moment any package
publishes documentation, silently. The objective lane's own tarball-size risk row argues
against its ruling. The per-row softening is the design's one recorded deviation from
whole-surface atomicity, justified because each mirror is an independent file with its
own local floor. Efficiency: one bounded request per package, pool 6, no conditional
requests (a stored validator is the cache the design laws forbid; both lanes agree).

## Ruling: atomicity and integrity — convergent, merged

All-or-nothing per host operation; `copiesToHost` answers `undefined` on any non-`found`
row; a row whose live digest matches the target's bytes is `found` without a request and
still belongs to the live baseline. An upstream deletion of an installed path demotes
the whole surface until the next release (both lanes' default; the resilience rival is
dropped on the one-word-baseline argument). Integrity: SHA-256 digest per fetched file
against the live inventory, membership digest via `computeManifestDigest`, stated as
integrity rather than authenticity. The objective lane's suspicious-response enumeration
is adopted as the reader's failure-note vocabulary: truncated or unparseable inventory,
missing or duplicated required path, oversized declared or actual body, digest mismatch,
redirect, invalid UTF-8, exhausted budget — each fails its row, and ruling 3 demotes the
surface. The residual is recorded, not hidden: fetched bytes govern agent behaviour in
targets with no release gate; `audit` previews, `--offline` pins,
`.claude/settings.local.json` stays untouched.

## Exit criterion

The campaign closes when: the committed inventory exists and its staleness gate has run
red then green under a mutation probe; `vendor`, the value host, `provenance`,
`--offline`, and the per-verb table are implemented and pinned by loopback runs on both
the live and dark sides; the guide states the strategy, the endpoints, the integrity
posture, and the release-note content; the cross-engine audits pass; the authoritative
gates run green. The release itself (bump, publish, fleet propagation) follows the
release-wave process and is outside this campaign.
