## Question

Which files does `scaffold overwrite` delete, replace, leave, or refuse, and which package-specific `guides/*.md`, `src/`, `tests/`, and `configs/src/*` bytes a run destroys?

## Distillate

1. **Default selection and `--groups`.** With no `--groups`, overwrite compiles and hydrates every group: `manifest`, `configs`, `source`, `tests`, `guides`, `docs`, `orchestration`. `--groups` keeps only named groups in that plan, so repair and the foreign/canon sweep see only those artifacts and those canon paths. It does not narrow `package.json` range or script writes, and it does not skip the catalog half (guide mirrors and the catalog-agent table) unless `--offline` skips catalog entirely.

2. **Deletes.** Overwrite deletes tracked `foreign` files only. A path is foreign when it appears in the deletion snapshot and the plan does not claim it. That snapshot is planned paths, files beneath any host-origin directory the plan expands, and files the target holds at `CANON_PATHS` (and beneath directory members) whose `inferGroup` is selected. `CANON_PATHS` is `AGENTS.md`, `CLAUDE.md`, `.mcp.json`, `.agents/orchestration.md`, `.agents/skills`, `.agents/templates`, `.agents/transports`, `.claude/agents`, `.claude/rules`, `.claude/skills`, `.codex/agents`, `.codex/config.toml`, `.cursor/mcp.json`, `.cursor/rules`. Planned claims inside that set (`AGENTS.md`, `CLAUDE.md`, `.claude/agents/orkestrel.md`) are not foreign. Untracked, gitignored, `.git/**`, `src`, `src/**`, `app`, and `app/**` are never removed. Compiler `HOST_PATHS` entries are files, so a normal run expands no vendored directory; package-specific files under `guides/`, `tests/`, and `configs/` that are not planned and not under `CANON_PATHS` are not deletion candidates. After deletions, emptied ancestor directories are removed.

3. **Overwrites in place; package-specific content does not survive where ownership is `content`.** Repair replaces `stale` content-owned planned files and restores `missing` content- or presence-owned planned files. Package-specific edits to those content-owned paths are reverted. That includes root `tsconfig.json` and `vite.config.ts`, selected `configs/src/*` and `configs/app/*` wrappers, `configs/helpers.ts`, `configs/policy.ts`, root toolchain dotfiles except `.gitignore`, `LICENSE`, `.claude/settings.json`, `scripts/deps.sh`, `scripts/cursor.sh`, `scripts/codex.sh`, `scripts/ollama.sh`, `tests/setupPolicy.ts`, `tests/policy.test.ts`, `tests/config.test.ts`, and the `AGENTS.md` / `CLAUDE.md` pointers. Catalog then replaces fetched `guides/<package>.md` mirrors when live (or floor) bytes differ, and replaces only the marker-bounded table inside `.claude/agents/orkestrel.md`. Presence-owned present bytes are not repaired; catalog may still replace a fetched guide mirror.

4. **Leaves alone.** Birth-owned planned files: `package.json` as a whole file, `README.md`, `guides/README.md`, `src/**` and `app/**` barrels and entries, `tests/setup.ts` and the other planned setup modules, planned entry tests, `tests/integration.test.ts` when selected, `scripts/service.sh` when vendors exist. Presence-owned present files: `.gitignore`, `tests/distribution.test.ts` if it exists, deferred guide mirrors until catalog writes them, prose around the catalog-agent markers. Paths outside the snapshot: extra `tests/**` proofs, extra `guides/*.md` other than fetched dependency mirrors, extra `configs/src/*` not in the selected matrix, `.github/**`, `.claude/settings.local.json`. Protected `src/**` and `app/**` even if reported foreign. Untracked and gitignored files, including untracked canon leftovers.

5. **Refuses to write, and the exit code.** Usage (`2`): `--help` is not this case; a bad `--groups` token, an option overwrite does not list (`--all`, `--bin`, …), or a malformed line. `TARGET` thrown as `1` before mutation: no readable `package.json`; `configs` selected while the manifest names an unregistered or ungated Vitest project; `configs` or `tests` selected while a planned tool is undeclared or a dependency section is not an object; the target is not a git repository; the worktree is dirty and `--dirty` was not passed. Compile with no plan: writes nothing, returns `1`. After repair and deletion, catalog/version failure is kept in `note` and still exits `1` (`--offline` always takes that path because catalog has no offline form). `FETCH` for a live catalog membership or version hole is collected into `note` rather than rolling back repair and deletion. A finished run with no `note` exits `0` only when the terminal audit has no blocking question and no non-`aligned` finding; a remaining foreign canon leftover, tracked or not, is still `1`.

6. **Git and `--dirty`.** Overwrite is the only verb that reads git. It requires a repository. Tracked set is `git ls-files -z`. Dirty set is `git status --porcelain=v1 --untracked-files=all -z` (untracked files dirty the tree; ignored files do not). Without `--dirty`, any dirty path refuses under `TARGET` with exit `1`. `--dirty` waives that refusal only: `remove` is given an empty dirty list, still deletes only tracked foreign eligible paths, and still skips untracked leftovers.

7. **`package.json` regions.** Every overwrite `declare`s the range region and the script region, independent of `--groups`. Ranges: in-place rewrite of already-declared names in `dependencies` and `devDependencies` that appear in the writable pin set (declared `@orkestrel/*` rows plus planned non-fleet tools already present). An undeclared requested pin throws `INVALID`. A package-specific extra dependency not in that pin set is left byte-for-byte. `peerDependencies` and `peerDependenciesMeta` are never read or written. Scripts: writable `test:<project>` lines, `test:probe`, `test:bench`, and on a publishing workspace `test:distribution`, `prepack`, and `prepublishOnly`. A declared value is replaced only when it already equals the planned command or is a recognized generated predecessor; any other string is retained; absent planned names are appended by key family. Extra scripts survive. Maintainer-owned gate chains (`test`, `check`, `build`, `dev`, `serve`, `show`, `format`, `lint`, `clean`, `copy`) are not in the writable set unless they coincide with a writable name. A non-object `scripts` field or a non-string planned key skips the script region with no script byte moving; ranges may still write. Descriptions, keywords, other keys, and key order outside the replaced ranges survive.

**Operator prediction for sibling packages.** Tracked copies under `CANON_PATHS` (harness rules, skills, MCP files, extra agents) are deleted on a default run. Edits to planned content-owned configs (`configs/src/vite.*.config.ts`, `configs/src/tsconfig.*.json`, root Vite/TS configs, `configs/helpers.ts`, `configs/policy.ts`) and to the shared policy tests are replaced. Package-specific `src/**`, extra `tests/**`, extra `guides/*.md` (including the package’s own guide), extra `configs/src/*` not in the matrix, and custom `package.json` scripts and extra dependencies survive, subject to range rewrites on declared `@orkestrel/*` and planned toolchain rows.

## Unknowns

- Whether a given sibling tracks files at `CANON_PATHS`; the command’s rule is path membership, not an inventory of those repositories.
