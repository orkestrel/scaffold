## Why a successor

The D4 ruling (`.orkestrel/campaign/plan.md` § Re-baseline 3, D4 row "Phase-in") pairs the
grandfather clause with a stage-time refusal: `stageHost` recomputes the cross-guide collision set
of the staged guides and refuses when it exceeds the set of the previously published host. D4-1b
landed the coverage refusal (a catalog row without a guide) and D4-3 read that the growth refusal
is absent (`D43-scaffold-surface-rule-report.md`, "D4-1b finding"). Without it, a name added to
two guides between scaffold releases becomes grandfathered silently at the next release.

## Objective

`stageHost` computes, over the guides it stages, the set of bare Surface names claimed by more
than one guide (the same reading `inspectPolicySurface` uses for a target — `createGuide().surface()`
column-0 names), reads the same set from the previously published host (the installed
`@orkestrel/scaffold`'s `dist/host/guides/`, resolved from this checkout's `node_modules`), and
refuses the stage when a pair (name, owner set) exists in the staged set and not in the published
set — naming each new collision. When no published host resolves (a fresh checkout), the stage
records that the baseline is absent and proceeds (the first release establishes the baseline);
state that in the guide.
