### Row 2 — TypeScript 7's plugin story

- Primary source, "Announcing TypeScript 7.0" (2026-07-08): "TypeScript 7.0 does not yet expose a stable programmatic API." https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/

- Secondary source (Elecmonkey blog, 2026-06-21): "TypeScript's team refuses to support plugin loading in tsgo, preferring instead that tools like vue-tsc build independent tsc-like CLIs. - Corroborating evidence, `Effect-TS/tsgo` ("Effect Language Service (TypeScript-Go)"), reported through search: Effect's language-service plugin works only by embedding "a pinned version of tsgo with a small patch set on top," and still requires a native `typescript`/`@typescript/native` package installed alongside for API access — indicating no first-class external-plugin extension point exists in tsgo itself as of the versions checked. https://github.com/Effect-TS/tsgo

### Row 3 — Alternatives that need no 6.x compiler

- `fi3ework/vite-plugin-checker` README: still advertises running "TypeScript, `vue-tsc`, ESLint, Biome, Stylelint in worker thread," with Vue support implemented as a `vue-tsc` wrapper. No statement about TypeScript 7 or `tsgo` compatibility was found on the README; because its Vue path is `vue-tsc` itself, it inherits row 1's blocker rather than avoiding it. https://github.com/fi3ework/vite-plugin-checker
- `KazariEX/vue-tsgo`: the closest documented "extract-and-check with `tsc`/`tsgo`" alternative — SFCs are transformed into real `.ts` files in a temporary virtual workspace and checked with `tsgo --lsp`. It is archived (read-only) as of 2026-07-19 and marked deprecated on npm, so it did not reach a maintained, adoptable state. https://github.com/KazariEX/vue-tsgo ; https://registry.npmjs.org/vue-tsgo/latest
- Elecmonkey blog names a second alternative, `golar`, which instead patches tsgo's own Go source through string replacement to forcibly expose internal APIs — described as an even more fragile technique than the current Node-side patch, with no stated stability claim. https://www.elecmonkey.com/en/blog/vue-tsc-runtime-patch-hack
- Vue's own guide (`vuejs.org/guide/typescript/overview`) still names only `vue-tsc` and `vite-plugin-checker` as the supported CLI type-checking paths; no build-time `@vue/compiler-sfc`-emitted `.ts`-shadow checking mode is documented there. https://vuejs.org/guide/typescript/overview.html
- No primary or secondary source found (searched directly) documenting an official `@vue/compiler-sfc` option that emits standalone `.ts` shadow files for checking with a stock `tsc`; the only tools attempting an equivalent transform-then-check approach are the unmaintained community projects above.
- What is lost: per the language-tools README, Volar's virtual-code transform honors `vueCompilerOptions.strictTemplates`, meaning it type-checks expressions inside `<template>` against the component's inferred types. https://github.com/vuejs/language-tools/blob/master/README.md . Neither `vite-plugin-checker` (a `vue-tsc` wrapper) nor a plain-`tsc`-over-extracted-`<script>` approach checks the template block at all, since the template text is not part of the extracted `.ts` shadow.

### Row 4 — What the fleet loses if `app/browser` drops `vue-tsc`

- `vuejs.org/guide/typescript/overview`: "`vue-tsc`... is a wrapper around `tsc`, TypeScript's own command line interface. It works largely the same as `tsc` except that it supports Vue SFCs in addition to TypeScript files." https://vuejs.org/guide/typescript/overview.html
- `vuejs/language-tools` `packages/tsc/README.md`: `vue-tsc` "transforms `.vue` files into TypeScript virtual code before passing them to `tsc`," reading `vueCompilerOptions` from `tsconfig.json`. https://github.com/vuejs/language-tools/blob/master/packages/tsc/README.md
- `vuejs/language-tools` root `README.md`: documents the `vueCompilerOptions.strictTemplates` option, which governs strict type-checking of expressions inside `<template>`. https://github.com/vuejs/language-tools/blob/master/README.md
- Inference from the two preceding sources (not itself a quoted maintainer sentence): because `vue-tsc`'s virtual code embeds the `<template>` block's expressions against the component's inferred types, and a plain `tsc` run over only the extracted `<script setup lang="ts">` text never sees the `<template>` block, dropping `vue-tsc` for `tsc`-over-extracted-script drops every check whose defect surfaces only in the template: prop/attribute binding type mismatches at the call site, `v-model` argument types, slot prop types, event-handler and directive argument types, and unresolved-component-tag references. No source directly enumerates this list; it is derived from the documented transform mechanism and is flagged as inference here.

## Distillate

- **Root cause (verified, primary):** TypeScript 7.0 (`tsgo`) ships with no stable programmatic compiler API and does not support the Strada language-service-plugin mechanism `vue-tsc`/Volar depends on. Microsoft states this directly and names Vue explicitly, in the 2026-07-08 "Announcing TypeScript 7.0" post.
- **Mechanism (verified):** `vue-tsc` works by rewriting `typescript`'s own `tsc` module source at runtime (a "patch hack") to feed it Vue-transformed virtual code; TypeScript 7's Go binary has no equivalent surface to patch, so this technique cannot be ported.
- **Fleet-relevant fact (verified):** the practical failure mode against TypeScript 7.0.2 is not a `peerDependencies` rejection — `vue-tsc@3.3.11` declares `typescript >=5.0.0` — but a hard runtime crash, because TypeScript 7 removed the `./lib/tsc` subpath `vue-tsc` imports.
- **Timeline (secondary, dated 2026-07):** TypeScript 7.1, targeted for Autumn 2026, is expected to add the stable programmatic API that would let Volar-based tooling (and therefore `vue-tsc`) adopt `tsgo`. This is a target, not a shipped fix, and no source names a committed date.
- **Alternatives (verified):** every discovered non-`vue-tsc` path either (a) still wraps `vue-tsc` and inherits its blocker (`vite-plugin-checker`), or (b) is an unmaintained community project (`vue-tsgo`, archived 2026-07-19 and marked deprecated on npm; `golar`, no stability claim found), or (c) does not exist as a documented official feature (a `@vue/compiler-sfc`-emitted `.ts`-shadow mode — searched, not found).
- **What is lost (partly inferred):** dropping `vue-tsc` for `tsc` over extracted script blocks drops template-expression type-checking entirely — the template is not part of the extracted `.ts` text at all. The exact enumerated list of template-only defect classes (prop/slot/emit/`v-model`/directive mismatches, unresolved components) is derived from the documented transform mechanism, not from a maintainer's own enumeration; flag this line as inference if it drives a decision.
- **Net honest state for a TypeScript-7-only fleet:** as of 2026-09-05 there is no option that both (a) runs under TypeScript 7 only and (b) checks `.vue` template code with the fidelity `vue-tsc` provides today. Every option trades one of those two away.
