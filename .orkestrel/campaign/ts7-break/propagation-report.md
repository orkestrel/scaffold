## Row 4 — Risks

**Declaration-path risk.** Evidence line 14 states the declaration rollup (`vite-plugin-dts` + `@microsoft/api-extractor`) runs in every package that publishes `src`. A `typescript@^7.0.2` devDependency bump is exactly the toolchain-emit case the "What a bump obliges" rule names: the rebuilt `dist/` can differ from the published tarball with no source edit at all, because the compiler that drives the declaration rollup changed. Under the versions rule that governs a development bump, that difference is decided by rebuilding and diffing `dist/` against the published tarball — material tokens/declarations/logic, sourcemaps excluded, whitespace ignored — not by inspecting the source diff. The brief supplies no such diff for any package, so which packages actually move (and therefore actually bump, beyond `probe` and `scaffold`) is unresolved; every `src`-publishing package in the catalog is a candidate until that rebuild-and-diff runs.

**`import type` risk.** A package whose published `.d.ts` imports a type directly from `typescript` re-exposes whatever that type's shape becomes under `^7.0.2` to every one of its own consumers, independent of whether its own `dist/` content changed materially. `probe` is the leading candidate: its peer dependency on `typescript` (`^6.0.3` in the catalog, moving under this plan) is the kind of edge a package takes specifically because its public surface names the dependency's types. `lsp` is a second candidate on domain grounds (a language-server package sits in the same territory), but the catalog carries no peer or runtime edge on `typescript` for `lsp` to confirm it. Neither the catalog nor the brief's evidence bullets show actual `import type ... from 'typescript'` sites, so the exact set beyond `probe` is unresolved (see Unknowns).
