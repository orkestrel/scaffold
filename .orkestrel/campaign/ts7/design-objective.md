## Evaluation criteria

Measurable criteria for ranking a plan. Each is checkable against the plan's text or by one named run.

1. **Site coverage.** The plan assigns every site in `ts7-absorb.result.md` rows 1 and 2 to a named destination — bridge, `unstable/sync`, `stripTypeScriptTypes`, oxlint plugin rule, or deleted — with no site unassigned. Count the assignment against the row, not against the plan's summary.
2. **Member coverage.** For each site assigned to a destination other than the bridge, the plan names the destination's counterpart for every member that site uses, and marks each member from `ts7-absorb.result.md:73` explicitly. A plan that assigns `tests/guides.test.ts` off the bridge without ruling on the CommonJS transform fails this criterion (C9).
3. **Ownership correctness.** Every edit is placed by its ownership class — content-owned, presence-owned, target-owned, published runtime surface — and the plan states, per class, whether a scaffold release reaches it. A plan claiming the release fixes the distribution proofs fails (C14).
4. **Order legality against `repair`.** In each target, the manifest edit and install precede `repair` wherever a planned package is added (C13), and no unit expects a scaffold verb to cross the `typescript` major (C12).
5. **Dependency legality.** No unit installs a package before the owner names it, and the plan marks `@typescript/typescript6` as awaiting that confirmation with a stated fallback if it is refused (C6). Any plan naming `oxc-parser`, `@swc/core`, or `@babel/parser` as an adopted path fails outright (C7, `AGENTS.md` § Project model).
6. **Preview exposure, stated and bounded.** The plan names every `unstable/*` use as a preview dependency, names which sites hold it, and states what a 7.1 shape change costs at each (C5). A plan without that inventory cannot be re-planned when 7.1 lands.
7. **Probe-before-unit discipline.** Each NOT-EVIDENCED item in this ruling — the bridge's member coverage and its compiler version, `stripTypeScriptTypes` over enums, namespaces, and parameter properties plus its introduction version, npm's resolution of a present out-of-range optional peer, the `matchesEngines` callers, and fleet sweep byte-identity — is either settled by a named probe before the unit that depends on it, or the unit is planned to not depend on it. `.claude/rules/quality.md` § Probes before arguments makes this binding rather than optional.
8. **Instrument continuity.** The plan states how a TypeScript-edit claim is proved in a target after that target's `typescript` moves to 7, given F2. An answer of "the receipt path is unavailable for this campaign" is acceptable and must be written down; silence is not.
9. **Product coherence for a generated workspace.** The plan rules on the `vue-tsc` seed (C18) and on the generated distribution proof template, so a workspace created from the release has a gate chain that runs.
10. **Falsifiable acceptance per unit.** Each unit's acceptance criterion is a command with an expected exit code or an expected artifact, ordered cheap-first, and no criterion depends on a file the unit's scope marks off-limits.
11. **Baseline honesty for the published surface.** Any claim that scaffold's or a target's `dist/` did not move is measured against the published tarball, not against the working tree (`.claude/rules/quality.md` § Falsification).
