# Native browser systems and elements for Veneer

This catalog ranks the browser systems and APIs, then the native elements, that Veneer can build as native modules with no Bootstrap 5.3 counterpart. It applies your order of 2026-10-07 (`records/stage-b/user-rulings-2026-10-06.md:52`): "concentrate on systems and APIs that browsers provide but also native elements that we can improve on; first what we can with the native systems and APIs of the browser and then we can look at other surfaces and elements; keep in mind the form and table packages that we have in orkestrel that would really come in handy and best to use here." Tier 1 holds the browser systems and APIs, tier 2 holds the native elements, and the three recommended first units come from tier 1.

Two earlier rulings bound every row. The native track builds only surfaces with no Bootstrap counterpart: a feature is excluded when Bootstrap 5.3 implements its concept in JavaScript or styles it as a component (`catalog:3-5`). Each module is written from scratch in its own folder `src/browser/<plural>/` and reached only by composing its plugin (`records/native-separation-verdict.md:40-52`). The elements repository (`elements/`, public as mikesaintsg/elements) is API guidance only, never a source to copy.

The catalog draws on the following sources:

- The elements repository's guides (`elements/guides/composables.md`, `surfaces.md`, `elements.md`, and `inspector.md`) and its W3C corpus (`w3c/`), read 2026-10-08.
- The `@orkestrel/form` 0.0.8 and `@orkestrel/table` 0.0.7 guides (`form.md` and `table.md`; versions from `scaffold/.claude/agents/orkestrel.md:59` and `:87`).
- The standing catalog of 2026-10-07 (`catalog:1-169`), whose support figures come from web-features 3.40.1 and whose probes ran headless Chromium 141.0.7390.37 and 153.0.8010.12 (`catalog:9`).

- The writer's reading of the veneer checkout on 2026-10-08 (`git log` and file reads), which amends two rows: Drag 1 is committed, and the copier's consumer moved with the Tailwind removal. Both amendments sit in § Deferred and § The first units.

The following notes give the reason behind each tier 1 rank.

**1. Fullscreen toggle.** It is the one small system that combines a reading under both Chromium versions, a surviving command spelling (`--fullscreen` is one of three, `catalog:101`), no package dependency, and a broad set of Bootstrap hosts (`.ratio` media and `.card` panels). The filter (`catalog:27`), the wake lock (`catalog:31`), and the landed copier (`catalog:24`) also read under 141 and 153, but the wake lock has no showcase consumer and the filter is a tier 2 element.

**2. Unsaved-changes guard.** It has the highest application value for a form-heavy Bootstrap page, it is the first consumer of the dirty state in `@orkestrel/form`, and it ships without the package. Two seams bound it: the sticky-activation precondition shapes its reading, and the router seam bounds its scope to document unload. It ranks under the fullscreen toggle because no reading exists.

**3. Relative time.** The surface fixes the refresh schedule at one timeout per host at the next unit boundary, released on hide and on disconnect, which meets the no-polling law (`scaffold/AGENTS.md:68`). Absolute formatting is host work with no module. It is small and Baseline high, and it is the display half of every table date column. It ranks under the guard because the showcase has no `time` element to consume it (`catalog:50`).

**4. Keep-screen-on toggle.** It has readings and is small, but it has no showcase consumer (`catalog:48`), so the minimal-public-API law (`scaffold/AGENTS.md:65`) holds it behind the three preceding units.

**5. Inline plain-text editing.** It ranks for real value and a table fit, and composition input with the line-break refusal makes it medium (`catalog:46`). `CloseWatcher` is ruled out for this module: Escape on a focused editor needs no dismissal stack, the free watcher slot is one per page (`w3c/interactions.md:623`), its `cancel` event is not cancelable without activation (`catalog:100`), and an Android Back press that reverts an edit would surprise the user.

**6. View transitions.** It needs two units, a two-document proof, and a wrapper that must earn its place (`catalog:44`). Its value is presentational, so it ranks last.
