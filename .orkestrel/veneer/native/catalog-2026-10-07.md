# Native platform features Bootstrap 5.3 lacks

This catalog ranks the native platform features that Bootstrap 5.3 has no counterpart for, so you can pick the native modules Veneer builds from scratch. It applies your ruling of 2026-10-07 (`records/stage-b/user-rulings-2026-10-06.md:26`): "for the native stuff, instead of looking at stuff that overlaps with what bootstrap already implements and that we already have an engine for, let's look for the native stuff that it doesn't have that we can implement from scratch instead of trying to work against bootstrap."

The overlap test decides every row. A native feature is overlap when the user-facing concept it serves is one Bootstrap 5.3 implements as a component, helper, or utility, whatever the mechanism: a modal, a dropdown, a tooltip or popover, a collapse or accordion, a carousel, a toast, tabs, an offcanvas, scrollspy, progress bars, placeholders, spinners, form validation styling, close buttons, badges, and the like. A feature passes when Bootstrap has no counterpart for its concept, or when its concept only resembles a Bootstrap family in name. Veneer's drop-in engine carries Bootstrap 5.3.8 (`bootstrap/package.json:4`) as twelve families and the Placement, Backdrop, Trap, Lock, Hold, and Swipe helpers in `veneer/src/browser/`, and no passing feature touches that engine.

Every shortlisted module follows the separation rule (`records/native-separation-verdict.md:40-52`): its own folder `src/browser/<plural entity>/`, reached only by composing its `create*Plugin` factory, root files other than `index.ts` byte-identical, CSS as a guide fence in `@layer reset` until chunk 3, and a first real consumer (`scaffold/AGENTS.md:65`). A scope that composes no native plugin gains no listener, because the scope derives its listeners from its plugin list (`veneer/src/browser/Veneer.ts:66-73`). A "Native group specimen" is the showcase group that § R13 plans (`records/native-separation-verdict.md:185`).

Support figures come from web-features 3.40.1, the version unpkg resolves for `web-features/data.json` on 2026-10-07 (see [web-features data](https://unpkg.com/web-features/data.json), read 2026-10-07). It names two Baseline tiers: low, the date the last core browser shipped the feature, and high, 30 months later. The Chromium floor is 153 (`records/stage-b/user-rulings-2026-10-06.md:13`), and Chromium 141.0.7390.37 is the reading arbiter (`records/lanes.md:47`). The judge's probes of 2026-10-07 ran headless Chromium 141.0.7390.37 and 153.0.8010.12 (`scratchpad/scripts/probe.mjs` to `probe5.mjs`, outputs in `scratchpad/wf/`). **1. Clipboard copy button.** Bootstrap 5.3 has no clipboard name in its class registry, stylesheet, or scripts (the judge's grep of 2026-10-07), and the showcase's Tailwind recipe block is the first consumer (`veneer/app/browser/sections/tailwindcss.html:31-38`). The trigger is `<button type="button" commandfor="HOST_ID" command="--copy">`, where the `HOST_ID` placeholder is the `id` of the element whose text the button copies; an `input` or `textarea` host gives its value. The plugin routes `click` on that button and resolves the host in its route's `hosts` function (`veneer/src/browser/types.ts:2042`). The host receives `copy.vn.copier` (cancelable, before the write, with `detail.text`) and `result.vn.copier` (after the write settles, with `detail.error` on a rejection), in the `toggle.vn.button` namespace form (`veneer/src/browser/constants.ts:47`). The entity is `Copier` because the DOM owns a global `Clipboard` type. The proof reads the clipboard back by a real paste, because the `readText` call in Vitest 4.1.11's tester frame is refused under 153 and never settles under 141; that frame carries `allow="clipboard-write;"` (`veneer/node_modules/@vitest/browser/dist/client/__vitest_browser__/orchestrator-jtzFEKPy.js:271-272`). Copier 1 also opens the guide's `## Native surfaces` section and an empty `### Native departures` table, and `createBootstrapPlugins()` keeps the same names in the same order.

**2. Sortable list.** Bootstrap's `list-group` styles items with no reorder behavior, and its one `dragstart` listener blocks image drags inside a carousel (`bootstrap/js/src/carousel.js:221`). The host carries `data-vn-drag`, its direct children carry the native `draggable="true"` attribute, and a focused item moves one place with Alt+ArrowUp or Alt+ArrowDown. The plugin moves nodes with `moveBefore`, which keeps an item's state, and the host receives `start.vn.drag` and `move.vn.drag` (both cancelable; `move` carries `detail.from` and `detail.to`) and `end.vn.drag`. The moved item keeps focus, and a polite live region reports its position. The fence styles the grabbed item and the drop indicator, with the transition off under `prefers-reduced-motion: reduce`. Your guidance repository carries the same capability as `createDrag` and `createDrop` (`elements/src/browser/factories/createDrag.ts:28-40`), read as guidance only. Touch drag on Android is unread.

**3. Fullscreen toggle.** You named fullscreen in the plan (`records/plan.md:22`). Bootstrap's `.modal-fullscreen` class only sizes a modal to the viewport (`veneer/src/bootstrap/components/_modal.scss:170`), and no Bootstrap script calls `requestFullscreen`. The trigger is `<button type="button" commandfor="HOST_ID" command="--fullscreen">`; the plugin toggles the host and mirrors `aria-pressed` on every trigger that names it. The host receives `enter.vn.fullscreen` and `exit.vn.fullscreen` (cancelable, before the request), `change.vn.fullscreen` (after the document's `fullscreenchange`, an Escape exit included), and `error.vn.fullscreen`. One fence rule gives `:fullscreen` the body background token and `overflow: auto`, because a host with no background shows the user agent's black backdrop. A Bootstrap tooltip, popover, or modal outside the host renders under the top layer, so its `container` option has to name the host; that reading is unread, and Fullscreen 1 owes it as a `### Native departures` row or a guide sentence.

**4. List filter.** The showcase's Contents panel lists 55 sections (`veneer/app/browser/factories.ts:652`; `ls veneer/app/browser/sections | wc -l` on 2026-10-07) and takes a filter field as the first consumer. The host is a `search` element holding an `input type="search"` whose `aria-controls` attribute names the container; the container's direct children are the items, matched case-insensitively on their text. Hiding uses the native `hidden` attribute, which Bootstrap's reboot enforces (`veneer/src/bootstrap/_reset.scss:533`). The plugin never sets `hidden` on a Bootstrap family host (`.collapse`, `.tab-pane`, `.carousel-item`), because those families own their visibility. The host receives `change.vn.filter` after each pass, with `detail.query` and `detail.count`, and a polite live region reports the count.

**5. Computed readout.** Bootstrap's reboot only sets `output { display: inline-block }` (`bootstrap/scss/_reboot.scss:582`), and the showcase's range specimens show no value (`veneer/app/browser/sections/range.html:6-7`). The host is `<output for="INPUT_ID">`, where the `INPUT_ID` placeholder is the `id` of one form control. The plugin routes `input` from that control into `output.value`, routes the form's `reset` event, and boots every `output[for]` through the plugin's boot entry (`veneer/src/browser/types.ts:2047-2048`), so the first value shows before any input. A formula over several controls takes a registered function in a later unit, never a string, so the module has no `eval` path. The readout keeps its implicit `status` role.

**6. View transitions.** Bootstrap's `.fade` and `.collapsing` classes serve one component's show and hide, never a document or a content swap. The first unit is a stylesheet fence alone: `@view-transition { navigation: auto }` inside `@media (prefers-reduced-motion: no-preference)`, with a duration for `::view-transition-group(*)`. Its proof loads two same-origin documents and reads a non-null `viewTransition` on `pagereveal`, and null under reduced-motion emulation. The second unit adds a `Transition` class with no plugin: it wraps one DOM update in `document.startViewTransition`, runs the update directly under reduced motion or a hidden document, and returns the platform's `finished` promise. That class must earn its place under the wrapper law (`scaffold/AGENTS.md:64`) by owning those two skips, and it never wraps a Bootstrap family's transition (`records/browser-stage-b-verdict.md:261`, `:357`). It waits for a consumer such as the showcase's face or theme switch, whose journeys then wait for `finished` before a capture.

**7. Inline plain-text editing.** Bootstrap's `.form-control-plaintext` class (`veneer/src/core/constants.ts:1411`) styles a read-only input as text and edits nothing. The host carries the native `contenteditable="plaintext-only"` attribute. The plugin records the text on `focusin`, commits on Enter or blur, restores the text on Escape (Enter and Escape skipped while `isComposing`), and refuses `insertParagraph` and `insertLineBreak` in `beforeinput`. The host receives `commit.vn.editor` (cancelable, with `detail.value` and `detail.previous`; prevention restores `previous`) and `revert.vn.editor`. A fence draws the focus ring from Bootstrap's focus-ring tokens on `[contenteditable="plaintext-only"]:focus-visible`. Composition input and the line-break refusal make it a medium unit, and its proof checks that pasted rich text arrives as plain text.

**8. Keep-screen-on toggle.** Bootstrap has no power or screen-state concept. The trigger is `<button type="button" commandfor="HOST_ID" command="--wake">`, where the host is the region the lock serves; the lock lasts while the host is connected, the trigger mirrors `aria-pressed`, and the class re-acquires on `visibilitychange` because the platform releases the lock when the document hides. The host receives `acquire.vn.wake` (cancelable), `release.vn.wake`, and `error.vn.wake`. Without a grant the request rejects with `NotAllowedError`; with a `wakeLockScreen` grant through CDP, which the test setup reaches (`veneer/tests/setupBrowser.ts:73`), it resolves. It ranks eighth because the showcase has no natural consumer, and its re-acquire case waits for a reading of a visibility change inside the harness.

**9. Relative time.** Bootstrap 5.3 formats no dates: `Intl` appears nowhere in `bootstrap/js/src` (grep of 2026-10-07, 0 matches). The host is a `time` element whose `datetime` attribute holds the instant and which carries `data-vn-time`. The plugin boots each host, writes `Intl.RelativeTimeFormat` text in the language of the closest `lang` attribute, and refreshes the text while the host is connected and the document is visible. The host receives `change.vn.time` after each write. It ranks ninth because no probe covers it and the showcase has no `time` element (`grep -rln '<time' veneer/app/browser`, no match on 2026-10-07); Time 1 owes a reading under 141 and 153.
