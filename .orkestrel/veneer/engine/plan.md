## Landing procedure

A unit writes in `veneer/tmp/worktrees/<unit>` on `unit/<unit>` cut from Veneer `main` (`units/unit-worktree.sh new <unit>`, E14), one writer per checkout. Before every brief and every landing, `git fetch` Veneer and scaffold, read `git log --oneline <marker>..origin/main` in both, read the styles session's `plan.md` § Intersession state, and move the marker.

1. Retain the writer's report, instrument, diff, and status under `units/` (`j-<unit>-report[-n].md`, `j-<unit>-mutations[-n].py`, `j-<unit>.diff`, `j-<unit>-status.txt`).
2. Run the Orchestrator's scoped gates (`tools/w2-gates-scoped.sh <unit> <round>`: typecheck, lint, format, the unit's test files, guides, policy).
3. Write the audit claims from the sources (`j-<unit>-audit-claims[-n].md`), then run the lanes on one claims file: `analyst` on Astra (`units/launch-codex.ps1 -Unit j-<unit>-audit[-n] -Brief <abs> -Sandbox read-only -Root C:/Users/mikes/WebstormProjects -Lane "<sentence>"`, watched by `tools/watch-codex.sh`, retained by `tools/retain-codex-last.cjs`) and the `checker` job on Grok first (`tmp/cursor/run-*.sh`, one Grok lane at a time; a native `checker` on Sonnet only after a recorded Grok darkness); `reviewer` on Opus 5.5 at the landing round or where the shape changed. Name every evidence file in a lane brief by its absolute path. `tools/generate-w2-audit-briefs.py` and `tools/patch-landing-briefs.py` draft the lane briefs; read each start to finish before launch.
4. Reconcile into `j-<unit>-audit[-n]-verdict.md`. A fix that adopts the auditor's prescription closes on the instrument probe and the Orchestrator's replay (`tools/w2-replay.sh <unit> <round> [rows]`, run only when no lane reads the worktree).
5. Land: `tools/w2-land-1.sh <unit>` (commit with the landing message, merge `origin/main`, stop on conflicts; `units/j-w2-resolve-guide-2.py` and `tools/resolve-surface-table.py` resolve guide conflicts), or `tools/w2-merge-main.sh <unit>` where the unit's commits are already on its branch; then `tools/w2-land-2d.sh <unit> [hold]` (the merge commit, a reinstall where the merge moved the lockfile, the gate chain, and, without `hold`, the fast-forward), and `tools/w2-land-3.sh <unit>` for a fast-forward an audit held. A unit whose change is Markdown no test but policy, format, and guides reads lands through `tools/land-doc.sh`. The chain runs the kickoff brief's acceptance item 5 list exactly: `format:check`, `lint:check`, `check`, `build`, `test`, and `test:service`. Its predecessor `w2-land-2c.sh` ran each project's gate but never `test` or `test:service`, so it is retired. A non-fast-forward push means the styles session landed first: merge again, re-run, push again. A conflict in `guides/veneer.md` or `ROADMAP.md` resolves in favour of the owning session.
6. Push Veneer `main`, retain the landing log, update § Intersession state, and commit the records (`tools/commit-records-2.sh <messagefile>`: stages `.orkestrel/veneer/engine` by pathspec, commits, merges `origin/main`, pushes). At the next landing boundary, prune the landed unit's records per `orkestrel-debrief` § retention.

A mutation instrument reads the failing case's error for each row. It counts a kill only when that error names an assertion failure (`AssertionError`, or the expect library's own assertion message), and it reads every other failure as refused, whatever the failure names. It reads a passed case as held only when the whole file run reports success, with no failed case and no unhandled error, because a sibling failure or an unhandled error can accompany the selected pass (the J-HOLDERS round-2 audit). A broken plant passes as a kill under a list of refused errors: the J-SAMEWAY round-2 audit found eight rows killed by a `ReferenceError` after a rename, and the J-CASCADE audit found that a denylist admits a thrown `Error`. A brief that asks for an instrument states this rule. The Orchestrator's replay lists every killed row whose message does not name an assertion before it confirms any kill (`tools/replay-*.sh`, and `tools/causes.py` for an instrument whose log does not carry the message).

Tests widen with the work: a writer runs the one file (or one case) that pins the open obligation, then the files its edit reaches, and the whole browser suite once before its report; the Orchestrator runs the landing chain once on the merge result.
