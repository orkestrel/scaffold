An additional behavior defect outside the stated name-matching cases is **lost ownership after document adoption**. `HostSnapshot` stores the original spelling (`src/browser/HostSnapshot.ts:151`) but recomputes its key using the element’s current document when releasing (`:229`). Adoption from HTML into XML can change that key. `clear()` then discards its target list without removing the original record’s holder.

Smallest witness using the typed surface:

```ts
const host = document.createElement('div')
const first = new HostSnapshot()
first.save({ category: 'attribute', element: host, name: 'DATA-STATE' })
host.setAttribute('data-state', 'changed')

const xml = document.implementation.createDocument(null, 'root')
xml.adoptNode(host)
first.clear()

const second = new HostSnapshot()
second.save({ category: 'attribute', element: host, name: 'data-state' })
host.setAttribute('data-state', 'live')
second.restore()
```

The source-derived result is `data-state="live"`; it should be `"changed"`. The abandoned uppercase save still holds the lowercase record, so the second snapshot cannot become its last holder. The retained mutations do not exercise adoption.
