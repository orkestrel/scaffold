## Design-fit defect

**D1: Tab's take-time selection read (claim 5).** The fix has these parts:
- **What is wrong.** `src/browser/Tab.ts:219-225` computes `deselection` and `selection` before the blur and before the pane writes. `Tab.test.ts:829` pins that departure from Bootstrap.
- **Why it matters.** Veneer's reference is Bootstrap's behaviour. This departure has no remaining cause and no row in the departure table. A blur listener that restructures a control's dropdown now gets a different result from Bootstrap's, and nothing records it.
- **What right looks like.** Put the reads back in Bootstrap's order:
  - Read `this.#selection(outgoing, false)` where the deselection loop runs (`Tab.ts:260`), after the previous pane's writes.
  - Read `this.#selection(host, true)` where the selection loop runs (`Tab.ts:269`), after the host's `active` write.
  - Leave the role flags where `b8c6a08` read them. That placement predates this unit.
  - Replace the case at `Tab.test.ts:829` with one that asserts Bootstrap's result: after `show()`, the wrapper a blur listener gave the `dropdown` token reads `aria-expanded="false"`.
  - Add the same after-show assertion to the destroy witness at `Tab.test.ts:805`, before `destroy()`, so the witness proves a real restoration.
  - After this change, the S4 T2 I1 mutation to run is `recordHostWrite` writing through `writeHostValue`, which must turn the destroy witness red. The "re-read after the blur restored" mutation row no longer applies.
  - The same unit carries the sentences that describe the take-time read, in the class TSDoc and in the guide's Tab section (`guides/veneer.md:1450-1452`).
- **Alternative.** Keep the take-time read, but state its cause on the record and add a departure row. The cost is a permanent departure from Bootstrap with no defect behind it. I recommend the fix.

**Optional simplification (not a defect).** Removing `#apply` also removed its `marks = []` default. `Carousel.ts:692` could take `marks` with a default of `[]`, which would remove the trailing `[]` argument from the doors at lines 481-655.
