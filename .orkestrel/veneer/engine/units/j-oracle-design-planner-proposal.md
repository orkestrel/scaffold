# J-ORACLE design round — the subjective lane's proposal (planner on Opus 5.5, native; retained from its notification, 2026-09-24)

Lane held: subjective (shape, naming, ergonomics, design fit, ownership); read-only; nothing run or dispatched. Constraints, Refusals, and Measurements are left to the objective lane.

The brief frames Button's oracle as a Node recording the ledger's Proof steps check; the source shows a second half: `tests/setupBrowser.ts:44` imports `button.json`, and the showcase journey drives Veneer's own Button over the same markup and compares step by step (`tests/app/browser/integration.test.ts:1822-1848`, read). So "the way the `btn` rows compare" is a recording plus a replay of Veneer. The design keeps that pair and tightens it to one reader.

## Design

**Vocabulary.** A *plugin oracle* is Bootstrap 5.3.8's bundle recorded while it drives fixed markup through fixed actions, keeping only the end state each action leaves; an *engine departure* is one measured difference between that end state and Veneer's on the same markup and action (reusing *oracle* from `recordButtonOracle` and *departure* from the cascade ledger's `DepartureRow`). Proposed in `tests/setupServer.ts`: types `PluginScenario` (`plugin`, `markup`, `spawned`, `setup`, `actions`), `PluginAction` (`name`, `gesture`, `target`, `key`, `point`, `call`, `completion`, `refused`), `PluginGesture` (`'click' | 'key' | 'hover' | 'focus' | 'scroll' | 'call'`), `PluginRuntime` (`'bootstrap' | 'veneer'`), `PluginState` (`elements`, `focus`, `locked`), `PluginElement` (`label`, `classes`, `attributes`, `visible`), `PluginStep`, `PluginFixture` (`version`, `plugin`, `browser`, `steps`), `EngineDeparture` (`plugin`, `subject`, `facet`, `name`, `bootstrap`, `veneer`), `EngineDepartureRow` (adds `reason`, as `Addition`/`AdditionRow`, `setupServer.ts:132-142`); discriminant `DepartureFacet` (`'class' | 'attribute' | 'element' | 'focus' | 'visible' | 'lock'`); helpers `recordPluginOracle(scenario, runtime)`, `readPluginState`, `scanPluginFixture`, `collectEngineDepartures`, `readEngineDepartures`, `describeEngineDeparture`; constants `PLUGIN_SCENARIOS`, `PLUGIN_ORACLE_TIMEOUT`, `ORACLE_OMITTED_ATTRIBUTES` (`id`, `class`, `style`); plugin keys match the `DelegateOptions` keys (`src/browser/types.ts:183-206`).

**1. What the recording captures (within E9).** After each action settles, `readPluginState` reads, in the page: every scenario element plus `html`, `body`, and every element the runtime added ("spawned": a tip, a popover, a backdrop), each labelled (a markup element by its `id`, which the scenario validator requires; a spawned element `+` its first class token and its document-order position; a removed element drops out); per element the sorted `classes`, every attribute except `ORACLE_OMITTED_ATTRIBUTES` (so `aria-*`, `role`, `tabindex`, `inert`, `popover`, `hidden`, `title`, every `data-*`), ID-reference attributes normalised to the labels they name (or `?`), and `visible` (`checkVisibility({ opacityProperty: true, visibilityProperty: true })`); `focus` (the label matching `:focus`, as `recordState` reads it, `tests/setupBrowser.ts:1206-1208`); `locked` (the viewport's used `overflow-y` after propagation is `hidden` or `clip`). It never reads event names, order, details, timing, geometry, option names, or members (E9, E11); each runtime's `setup` and `call` use its own API, never compared. Settling: each runtime's own completion event (a signal, never compared), then no running finite animation at two consecutive frames, then one task (covering Bootstrap's reduced-motion 5 ms timer, inferred); every wait uses the budget. Each scenario is recorded under `no-preference` and `reduce`, as `recordButtonOracle` does (`setupServer.ts:3354-3358`). The per-plugin actions (collapse, dropdown, tab, scrollspy, alert, carousel, modal, offcanvas, toast, tooltip, popover) and the inferred Bootstrap end states are tabulated in the proposal as sent; the recording decides them. Departures are excluded on the record: the projection boundary (`ORACLE_OMITTED_ATTRIBUTES`, and the stated out-of-scope classes: timing, event names, geometry, transient classes, autoplay, autohide, delays, hover pause, swipe) in the guide's `### Departures` introduction under `## Engine`; every other difference an `EngineDepartureRow` in a new `## Engine` › `### Departures` table (Component, Subject, Facet, Name, Bootstrap 5.3.8, Veneer, Reason), whose Reason quotes the opening sentence of the component's "departs from Bootstrap's in these ways" bullet, and the reader refuses one that does not. Likely rows: dropdown `data-popper-placement` and `popover`; tooltip and popover `data-bs-original-title`, `popover`, the Escape end state; toast `hide`; carousel `pointer-event`; modal and offcanvas sibling `inert`; offcanvas focus after hiding. Rows are keyed without a step.

**2. How it is recorded and compared.** Generalise Button's Node recorder into `recordPluginOracle(scenario, runtime)` in `tests/setupServer.ts`, moving `recordButtonOracle`'s launch, page, and teardown into one shared helper both call; `button.json` and Button's steps stay byte-identical. One Node-launched page serves both runtimes: Bootstrap from the pinned `bootstrap.css` and `bootstrap.bundle.js`; Veneer from the built `dist/src/styles/index.css` and `dist/src/browser/index.js` as a module, with an import map for `@orkestrel/contract` (the browser entry imports only `../core/index.js` and that package), the setup constructing `new Delegate()` plus the engines no data route reaches; `page.route` fulfils a synthetic origin from disk (no socket); the same trusted verbs and the same `readPluginState` for both; any page error fails the recording. Fixtures `tests/fixtures/oracle/<plugin>.json` hold Bootstrap's recording alone; `ORACLE_REFRESH=1` rewrites them; `browser` is provenance, excluded from the comparison. `conformance.test.ts` runs one case per plugin, failing on: the live Bootstrap recording no longer reproducing its fixture; a non-`refused` step leaving Bootstrap's state unchanged; a page error, missing label, or settle timeout; a Veneer difference with no row (`scanLedgerDrift(...).unrecorded`); a stale row; a Reason quoting no bullet; the `plugin` rows' plugin set differing from `PLUGIN_SCENARIOS`' keys. A `plugin` row's Proof cell names its fixture; `scanOracleObligation`'s plugin branch requires it name a `PLUGIN_SCENARIOS` key whose fixture exists; under E6 the file-existence branch and `isProofFile` are deleted with their cases; the Obligation text becomes "Bootstrap 5.3.8's end states on the recorded markup and actions, less the `<plugin>` rows of § Engine › Departures."

**3. The proofs.** Negative controls from outside the instrument's population, through Veneer's public seams (no source plant): a class control (a collapse replay under `new Delegate({ collapse: { classes: { shown: 'open' } } })` must report exactly `panel | class | show` and `panel | class | open`); a prevention control (a modal replay whose setup prevents `show.vn.modal` must report the named rows); a focus control (`focus: false` reports the `focus` row alone); a boundary control (an inline `style` reports nothing, a `data-*` attribute exactly one row); a settle control (Bootstrap's unsettled carousel `click.next` differs from settled); and pure controls in `setupServer.test.ts` (an altered fixture step, a spawned id pair against a dangling reference, an invented row reading stale, a Reason naming no bullet refused, a Proof cell naming a test file refused, a non-`refused` step changing nothing refused). Each facet distinguishes its mutation; timing, event wiring, transient classes, inline style, and geometry are stated as uncovered. The red reading: the recorder unit runs every control red first and returns the full census; the Orchestrator re-runs it after the queued engine units land and rules each row a departure, a missing bullet, or a defect; the gate unit runs the comparison with an empty table (red, listing exactly the ruled departures), fills it, reads green, and only then flips the Proof cells; no row flips while a defect is open.

## Alternatives

Button's own split (a Node recording, a replay in the browser project): two near-duplicate readers whose agreement nothing proves, an iframe that differs from a top-level page, a browser project that cannot read the guide or load Bootstrap (`conformance.test.ts:793-811` forbids it); refused. A static, independently derived inventory: a transcription that observes nothing; refused.

## Units

1. **J-ORACLE-RECORD** (`opus` on Opus 5.5, native, `tmp/worktrees/oracle-record`): owns `tests/setupServer.ts` (the types, scenarios, recorder, reader, scans, timeout, and the shared scaffold `recordButtonOracle` adopts), `tests/setupServer.test.ts` (helper cases, pure controls, the export list), `tests/conformance.test.ts` (per-plugin Bootstrap recording against its fixture, the live controls), `tests/fixtures/oracle/<plugin>.json`; every owned file is styles-owned, so each hunk is a pending shared change; off-limits `src/**`, `tests/src/**`, `guides/**`; after J-SAMEWAY and J-SNAPSHOT-SHARED land; acceptance: static gates; `button.json` byte-identical and the Button oracle green; each control red first; every non-`refused` step changes Bootstrap's state; both motion passes; the plugin cases green on Chromium 153; the census table in the report.
2. **J-ORACLE-CENSUS** (the Orchestrator's ruling): after J-ORACLE-RECORD, J-SAMEWAY-ENGINES, and J-CASCADE land; the census re-run as a tracked command, each row ruled, the styles session asked for a Chromium 141 run.
3. **J-ORACLE-FIX-<plugin>** (`opus` on Opus 5.5): one per plugin whose census holds a defect, owning that engine, its test, and its bullets, after the unit that owns the file lands; a mirrored case per defect, red first.
4. **J-ORACLE-GATE** (`opus` on Opus 5.5): owns the guide's `## Engine` › `### Departures` section and each `plugin` row's Proof, Obligation, and Status cells (taking the plugin-row half of the J-ROWS row, so each finding keeps one carrier) and a bullet the census adds; styles-owned as pending shared changes: `readEngineDepartures`, `describeEngineDeparture`, `scanOracleObligation`'s plugin branch with `isProofFile` deleted, the per-plugin Veneer comparison and membership case, the § Compatibility introduction sentence; after the census and every fix unit; acceptance: the empty table red listing exactly the ruled rows, green once filled, the controls hold, no file-proof branch, `test:guides` and `test:policy` green, every Proof cell a fixture.

Audit: `analyst` on Astra for each unit; `reviewer` on Opus 5.5 where the shape changes (RECORD, GATE); `checker` on Sonnet for membership and paths.

## Tensions

Veneer from `dist` (a stale `dist` reads green; the landing chain builds first); Node drives both runtimes, stronger than Button's split; `page.route` as transport, not module replacement; each runtime's event names used as completion signals, never compared; rows keyed without a step; Reason quoting the bullet serialises J-ROWS before the gate; fixing before the gate lengthens the critical path; Button stays out of `PLUGIN_SCENARIOS` (adding it moves E26's criterion, the user's call).

## Risks

Chromium 141 may project focus, `checkVisibility`, or popover state differently (the styles session's run settles it); passing a module-level function to `evaluate` can break under an injected helper (the first probe settles it); settle flakes under contention (size `PLUGIN_ORACLE_TIMEOUT` from a contended run); an unknown census size (Bootstrap's load-time construction may widen initial-state differences); coverage bias from the chosen markup (stated in the introduction); a future `@orkestrel/contract` entry gaining imports breaks the import map (a page error reports it).

PROPOSAL: Generalise Button's Node recorder into one page and one reader that drive Bootstrap's pinned bundle and Veneer's built engine over the same markup, commit Bootstrap's end-state recordings as per-plugin fixtures, compare Veneer against them through an `## Engine` › `### Departures` ledger whose every row quotes its departure bullet, and land it as J-ORACLE-RECORD, then a census ruling, then per-engine fixes, then J-ORACLE-GATE, which flips each plugin row's Proof cell to its fixture.
