## Claims

1. **One record per target, written back by its last holder.** For an attribute, a class token, and an inline property alike: the first `save` made while no snapshot holds the target and no restoration owns it reads the element; every later `save` joins the record without reading; a `restore` by a snapshot that is not the last holder writes nothing for the target; the last holder's `restore` writes the first saved value (and priority) back once. This holds in every release order, and a snapshot's second `save` of a target it already holds changes nothing.
2. **Takeover is a join.** A `save` made during another snapshot's restoration of that target (for example from a reaction to one of its writes) joins the pending record and clears its owner, so the restoring snapshot writes nothing more for that target, and the joiner writes the first saved value at its own last release. A `save` after the target was written back and withdrawn reads the element afresh.
3. **Re-entry completes without double writes.** A `restore` a reaction calls on the same snapshot writes each target it owns and has not yet written exactly once; the interrupted call writes nothing already written; a target a running write has marked written is not written again.
4. **A throwing write withdraws only what its snapshot owns.** When a write throws, the `finally` path withdraws only the records whose owner is the throwing snapshot and leaves every other holder's record and holdings intact; the throw reaches the caller.
5. **`clear()` relinquishes without writing.** It removes the snapshot from every record it holds, deletes a record it was the last holder of (so a later `save` reads the element), withdraws the records its interrupted restorations own (so the interrupted call writes nothing more), leaves its presence holdings, writes nothing to the DOM, and a repeated call does nothing.
6. **Presence is unchanged.** Every leaving holder whose presence record reads the attribute absent removes the `class` or `style` attribute when its own writes leave it empty, while another holder lives; the wording in `types.ts`, `HostSnapshot.ts`, and the guide states that.
7. **No owner pins a shared target.** Every class in `src/browser` that constructs a `HostSnapshot` calls `restore()` or `clear()` on every path that ends its lifetime (destruction, a completed close or dismissal, a failed construction after a save), so no ended engine stays a holder. Name any path that ends a lifetime after a `save` without either.
8. **The Tab joins and the Tooltip link hold.** A tab saves every initial attribute its list's plan names before writing, and writes only the entries that differ, so a sibling's destruction leaves a live tab's roles and states; a tooltip destroyed while a popover on the same trigger lives removes only its own id from `aria-describedby` before its restoration, and after the last engine the trigger reads its markup.
9. **The save-order machinery is gone and unreachable.** No stamp, `#order`, or earliest-recording comparison remains, and the control row shows the one case such a comparison decided cannot arise.
10. **The changed expectations are E25's and no others.** The five changed expectations in `HostSnapshot.test.ts` the report lists each follow from E25's writer-timing amendment (the last release writes the first saved value), and no other existing expectation in `tests/src/browser/**` changed.
