## Unknowns

The guides that describe a browser-side DOM mechanism as an export are `@orkestrel/test` and `@orkestrel/browser`. `waitForAnimations` is a transition wait over `getAnimations` and `finished` (`guides/test.md:1527`). `createPointerEvent` builds one `PointerEvent` (`guides/test.md:366`). `isRendered` and `isReachable` read an `[inert]` ancestor (`guides/test.md:1594`). `describeFocus` reads tab order (`guides/test.md:317`). The browser locator `focus`, `hover`, and `drag` methods, and the frame pointer `move` and `drag` methods, drive trusted input over CDP (`guides/browser.md:1533`, `guides/browser.md:1632`). `BrowserSnapshot` is a serializable CDP DOM snapshot (`guides/browser.md:70`). No Surface table exports an observer, a focus trap, a delegate, or a placement engine. `@orkestrel/supervisor` describes the platform `<dialog>` inert page, backdrop, and focus return as the browser's own behavior in unpublished application code (`guides/supervisor.md:2245`, `guides/supervisor.md:2270`). Every other guide's Surface table carries none of those mechanisms.

`@orkestrel/html` `sanitize` cannot express a general per-element attribute allowlist. `HTMLSanitizeOptions.attributes` is one list that "replaces its default rather than extending it" (`guides/html.md:40`), and `sanitizeAttributes` takes that one set (`guides/html.md:125`). The stated per-element case is only "`align` survives only on `td` and `th`" (`guides/html.md:296`). An `aria-*` keep pattern is not expressible: those names sit outside `SAFE_ATTRIBUTES` (`guides/html.md:320`), and an allowlisted `on*` name is still stripped (`guides/html.md:295`). Keeping `data:` is not expressible: "`javascript:`, `data:`, `vbscript:`, `file:` … are refused whatever `schemes` says" (`guides/html.md:297`). Removing an unlisted safe element with its content is not expressible: "a safe element merely outside the allowlist is unwrapped to its children" (`guides/html.md:298`). Whole-subtree removal is reserved for `UNSAFE_ELEMENTS`, "never unwrapped, no matter what `HTMLSanitizeOptions` allows" (`guides/html.md:294`). The result is a new `HTMLInterface`, then a string from `renderHTML`, "not a browser-native `TrustedHTML` substitute for a live DOM" (`guides/html.md:188`, `guides/html.md:303`). `@orkestrel/markdown` `renderHTML` calls that same sanitize and "exposes no options" (`guides/markdown.md:444`).

`@orkestrel/emitter` does not describe a cancelable dispatch. "`emit` returns `void`" (`guides/emitter.md:93`), listeners are `(...args) => void` (`guides/emitter.md:71`), and a throw is isolated rather than treated as a veto (`guides/emitter.md:104`). `destroy` drops every listener (`guides/emitter.md:96`). `@orkestrel/abort` does describe a signal combinator: `linkSignal` returns `AbortSignal.any([own, parent])` when a parent is given, and otherwise returns the handle's own controller signal (`guides/abort.md:44`, `guides/abort.md:89`). `abort()` returns `void`, the first reason sticks, and the child's `abort()` does not abort the parent (`guides/abort.md:81`, `guides/abort.md:89`). `@orkestrel/queue` does describe a job queue. "`enqueue` returns `Promise<TResult>`" and "`abort` returns `Promise<void>`," which "cancels active work through its signal, rejects pending work immediately," and does not retry (`guides/queue.md:149`, `guides/queue.md:156`, `guides/queue.md:179`). Its emitter cannot veto: "a listener can never change what the engine does" (`guides/queue.md:227`). It "ships no scheduler, no priorities, and no delay" (`guides/queue.md:29`), and its durable store "is a table" of `@orkestrel/database` (`guides/queue.md:19`). `@orkestrel/pool` does not describe a timer pool. "The pool has no warm floor, eviction timer, acquire timeout, or polling loop" (`guides/pool.md:7`). `acquire` returns `Promise<PoolToken<T>>`, `release` returns `void`, and an aborted acquire "preserve[s] the caller's exact `signal.reason`" (`guides/pool.md:90`, `guides/pool.md:100`, `guides/pool.md:137`). Its emitter isolates listener throws and does not state a veto (`guides/pool.md:192`).
