## Design

One rule decides all four: the engine uses a native feature when it replaces engine arithmetic without changing the consumer's Bootstrap markup or the parity cascade, and refuses one that adds a second data API or works only after a cascade change the styles session owns. No adoption adds a public API. Chromium 153 support is read from `units/j-engine-terrain-record.md`; every Chromium 141 reading is inferred from the Chrome stable release that shipped the feature; E21 counts an API available only when both gate hosts carry it, so each adoption waits on a 141 reading and no refusal depends on one.

1. **Invoker commands against the delegate's click routing.** 153 read present (`CommandEvent`, `command.attribute`, `commandForElement`, terrain `:42-44`); 141 inferred present (Chrome 135). An invoker is a `<button>`; Bootstrap's contract also routes anchors (`Collapse.test.ts:70`, `Delegate.ts:638-640`); `commandfor` names one element by id where `data-bs-target` is a selector that can name several panels (`Collapse.test.ts:163`, `readTargets` at `Delegate.ts:641`); a custom `--toggle` sets no implicit `aria-expanded`. Invokers could only sit beside the click route as a second data API, against R1's "the only data API" (`j-engine-design-verdict.md:84`) and E11's scope (`decisions.md:49`). **REFUSE:** the Bootstrap markup contract and R1's single data API.
2. **`interpolate-size` and `calc-size()` against `Collapse`'s pixel size.** 153 read true (terrain `:63-64`); 141 inferred present (Chrome 129; the baseline proof `tests/src/styles/elements/html.test.ts:6` reads the root declaration there). Adoption replaces the `scrollHeight`/`scrollWidth` read and `${size}px` write in `show` (`Collapse.ts:181-185`) and the `getBoundingClientRect()` read in `hide` (`:223-229`): the engine writes `calc-size(auto, size)` inline where it writes pixels, with `reflow(host)` before the show write. `calc-size()` over the keyword path because it interpolates with `.collapsing { height: 0 }` whatever the root declares, where the keyword path depends on `_html.scss:5`, which a consumer reset or stock Bootstrap CSS removes. It fixes the jump at completion when content grows mid-transition or a border separates the border box from `scrollHeight` (inferred). No markup change. Proof: pin the transition at its midpoint and read the rendered height; read no jump at completion; a root `interpolate-size: numeric-only` case still transitions; the horizontal case transitions width; reduced motion creates no animation; read geometry, not the serialized inline string. **MEASURE, then adopt on a green reading** (J-NATIVE-PROBE's size rows on 153 and 141; the adoption J-COLLAPSE-SIZE owns `Collapse.ts`, `Collapse.test.ts` — the "…an inline pixel size…" case and the `'40px'` and `'30px'` assertions become false — and `guides/veneer.md:1002-1009`).
3. **`hidden="until-found"` and `beforematch`.** 153 read (terrain `:70-71`); 141 inferred (Chrome 102). The parity cascade renders a collapsed panel `display: none` (`Collapse.test.ts:62-63`), which defeats until-found; the engine would have to write an inline `display` against the cascade (against "Preserve direct control through classes", `ROADMAP.md:38-39`) or the styles session depart from `.collapse:not(.show)`; and it is a Veneer addition E11 defers. Elements gets find-in-page from `<details>`, a different contract (`j-engine-terrain-distillate.md:64`). **REFUSE for this campaign:** the Bootstrap cascade's `display: none` and E11's scope; put to the user as a candidate addition needing a cascade departure.
4. **CSS `anchor()` and anchor-positioned arrows against `Placement`'s arrow offset.** 153 read (`anchor.function`, `anchor.size`, terrain `:59-60`; `anchor.containerQuery` `:149`); 141 anchor positioning read present (the `Placement` suite runs there), `anchor-center` inferred present (Chrome 125), anchored container queries inferred absent (Chrome 143+). Adoption would replace the three rectangle reads and the clamp in `update` (`Placement.ts:218-233`): the arrow takes the tip's generated anchor name as its `position-anchor`, with `justify-self: anchor-center` between `left: 0` and `right: 0` on a vertical side and `align-self: anchor-center` on a horizontal side. The arrow stays `position: absolute` in the tip; the cascade's per-side edge rules (`_tooltip.scss:93-99`) and the side measurement (`Placement.ts:191-204`) stay. Open: whether an absolutely positioned arrow accepts a reference outside its containing block as its anchor (if not, refuse); whether `anchor-center` keeps the arrow inside the tip's padding edge as the clamp does (`:228-233`). **MEASURE** (J-NATIVE-PROBE's arrow rows on both hosts; J-ARROW owns `Placement.ts`, `Placement.test.ts`, the `#### Tooltip` arrow sentence).

## Alternatives

The keyword path for `Collapse` (write `height: auto` and rely on the root `interpolate-size`): rejected, it snaps under stock Bootstrap CSS or a consumer reset. Invokers as an opt-in second route: rejected, it doubles the data API, works on buttons and one target only, and is an addition E11 defers.

## Tensions

No Chromium 141 reading exists for any feature; refusals rest on the markup contract and scope, adoptions wait on 141 readings. Choosing `calc-size()` leaves the root `interpolate-size` declaration with no engine consumer, while the guide promises "the first unit that animates a keyword length" proves it (`guides/veneer.md:10541-10543`, the styles session's). `calc-size(auto, size)` animates a horizontal panel to its container width where `scrollWidth` animated to content width, so the show mirrors the hide; record it as a departure or challenge it if Bootstrap's timing counts as parity. until-found is refused rather than measured, which pulls against Elements as the interaction reference; the choice goes to the user.

## Risks

A consumer's `hide-popover` or `toggle-popover` invoker aimed at an engine-promoted menu or tip may close it without the engine knowing (the probe's risk row settles it; carrier named after the reading). If either host does not report a `calc-size()` transition as a `CSSTransition` on `height` or `width`, `settleAnimations` settles at once and the adoption fails (the size rows settle it). Anchor acceptability and overflow alignment can differ between builds, so a green 153 reading alone must not adopt the arrow.

PROPOSAL: Refuse invoker commands and `hidden="until-found"` on the Bootstrap markup and cascade contracts and E11's scope; probe `calc-size()` for `Collapse` and the anchor-centred arrow for `Placement` on both gate hosts, then adopt `calc-size()` through J-COLLAPSE-SIZE after J-SAMEWAY-ENGINES, and adopt the arrow through J-ARROW only if both hosts accept the reference as the arrow's anchor and keep the clamp.
