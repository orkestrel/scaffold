# J-GUARDS design round — the subjective lane's proposal (planner on Opus 5.5, native; retained from its notification, 2026-09-24)

Lane held: subjective (shape, naming, ergonomics, design fit). The charter's sections were used, with the brief's answers 1 to 3 under Design and 4 under Units; every code claim is marked read or inferred.

## Design

**1. The guard family.** Fold the five null-detail guards (`isCollapseEvent`, `isAlertEvent`, `isToastEvent`, `isTooltipEvent`, `isPopoverEvent`; one body, `isInstance(value, CustomEvent) && value.detail === null`, `validators.ts:164-170, 189-195, 366-372, 420-426, 445-451`, read; each narrowing `CustomEvent<null>`) into `isBareEvent`, and the three optional-related-target guards (`isModalEvent` and `isOffcanvasEvent` byte-identical, `:337-347` and `:391-401`; `isTabEvent` accepting the same set, `:213-223`; `TabDetail`, `ModalDetail`, `OffcanvasDetail` structurally identical, `types.ts:1053-1056, 1287-1290, 1434-1437`, read) into `isRelatedEvent`. Keep `isButtonEvent`, `isDropdownEvent`, `isScrollSpyEvent` (its `relatedTarget` is required, `types.ts:1177`), `isCarouselEvent`. The family then has one rule: a guard is named for the detail it narrows, and an entity's name appears only where that entity alone owns the detail. The five and three copies are the rename-only duplication `architecture.md:159, 298` forbids, and no guard reads `event.type`, so the entity names claim a check the guards do not make (`isCollapseEvent(new CustomEvent('click'))` is `true`; `isModalEvent` accepts a `shown.vn.offcanvas` event).

Names (`names.md:177`): `isBareEvent(value: unknown): value is CustomEvent<null>` ("bare" pairs with "related"; `isPlainEvent` collides with `matchesPlainData`, `isSignalEvent` with the `signal` option, `isNullEvent` reads as "the event is null"; `isEmptyEvent` the runner-up, ambiguous); `isRelatedEvent(value: unknown): value is CustomEvent<RelatedDetail>` (Bootstrap's and the platform's `relatedTarget`).

Types: one `RelatedDetail { readonly relatedTarget: HTMLElement | undefined }` in `types.ts` beside `EventHooks` and `EventWire`; `TabDetail`, `ModalDetail`, `OffcanvasDetail` deleted; the three event maps point at `CustomEvent<RelatedDetail>`, and each entity's related-target meaning moves into its event map's summary. A consumer reads `if (isRelatedEvent(event)) event.detail.relatedTarget?.focus()`; the engines `bindEventMap(host, MODAL_EVENTS, isRelatedEvent, options?.on, signal)`.

Remove `TooltipProfile.guard`: every profile's events are `CustomEvent<null>` by the type of `TooltipProfile.events` (`types.ts:1749`), so the guard follows from another member's type (AGENTS.md "Derive state"); the engine binds `isBareEvent` directly (`Tooltip.ts:351`).

Greenfield: no alias of `isCollapseEvent`, `isAlertEvent`, `isToastEvent`, `isTooltipEvent`, `isPopoverEvent`, `isTabEvent`, `isModalEvent`, `isOffcanvasEvent`, `TabDetail`, `ModalDetail`, `OffcanvasDetail`.

Consumers (grep over the tree, `node_modules` excluded): `Collapse.ts:30,120`; `Alert.ts:15,85`; `Toast.ts:22,114`; `Tab.ts:26,111`; `Modal.ts:36,177`; `Offcanvas.ts:34,179`; `Tooltip.ts:50,137,351` and TSDoc `:107,127`; `Popover.ts:10,55` and TSDoc `:45`; `types.ts:1053-1067, 1287-1303, 1434-1450, 1750-1751`; `validators.ts:1-17, 148-451`; `validators.test.ts:147-221, 222-277, 442-570, 571-681`; `index.test.ts:169-186`; `Popover.test.ts:3-4, 68, 78`; the guide's Surface rows (`:152, 174, 189, 208, 222, 224, 238, 255, 274, 287, 301` out; `isBareEvent`, `isRelatedEvent` beside `bindEventMap`; `RelatedDetail` beside `EventHooks`), the three event-map Summary cells, and prose at `:857, 2128, 2493, 2630, 2902`. No `app/**` hit.

**2. `resolveOptions`.** Today the parser loop reads `options?.[key]` per declared key (`helpers.ts:238`) and a `for (const key in options)` loop copies and re-reads every enumerable key, own or inherited (`:251-254`). Ruling: read `options?.[key]` once for each key the parser table declares; a defined value wins, else the attribute is parsed, else the default stays; no loop over `options`. This matches `resolveVocabulary` (`helpers.ts:268-269, 283-284`) and `patterns.md:140` ("read the foreign object exactly once"), by property access as every engine's direct `options?.x` read does, so an inherited declared key still counts. Make the parser table total over `T` by dropping `TKey`: `resolveOptions<T extends object>(element, attributes: NoInfer<AttributeMap<keyof T & string>>, code, defaults: T, parsers: ParserMap<T, keyof T & string>, options: Partial<T> | undefined): T` (compiling inferred until typechecked). Behaviour changes only where the whole options object or a group is passed (Collapse, Dropdown `dismiss` and `placement`, Carousel, Toast, ScrollSpy and its `intersection`, Tooltip and Popover `settings`, `tip`, `placement`, body): an undeclared getter no longer runs, a declared getter runs once, undeclared keys leave the result. Modal and Offcanvas pass literals, unchanged.

P5 the export list names the two new guards and none of the eight, with a named search for the eleven removed names. P6 `test:guides`. Options: O1 an undeclared own getter runs 0 times; O2 `{ delay: 5, extra: 1 }` resolves to exactly `{ delay: 5 }`; O3 a declared getter runs once; O4 an inherited declared key resolves to its value (pins B against own-keys); O5 a Tooltip never runs a counting `content` getter; O6 the existing rows at `helpers.test.ts:454-591` stay green.

## Alternatives

Keep one guard per entity with honest summaries (rejected: eight duplicate exports). An `eventOf(detailGuard)` combinator (rejected: a new combinator and detail guard per shape for the same removal).

## Tensions and risks

Fold over keep reverses the offcanvas round-1 subjective lane; `isBareEvent` is a judgment call; folding the detail types and removing `TooltipProfile.guard` go past the finding's wording; the total parser table couples the options work to the engine files; property access reads inherited declared keys. Risks: fleet name collision (settle with the `surface` policy test), `bindEventMap` inference (settle with `check`), browser proofs inside an Astra sandbox (Bench law 5), guide parity drift in the event-map Summary cells.

PROPOSAL: Fold the null-detail guards into `isBareEvent` and the tab, modal, and offcanvas guards into `isRelatedEvent` over one new `RelatedDetail` type, keep the four single-entity guards, remove `TooltipProfile.guard`, leave no alias, and make `resolveOptions` read each key the parser table declares exactly once by property access over a table that the type makes total over `T`: J-GUARDS on Opus after J-INTEGRATION, then J-OPTIONS on Astra.
