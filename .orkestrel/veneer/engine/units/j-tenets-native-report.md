### Findings outside the table

1. **Takeover versus a virtual DOM (inferred, for E-VUE).** Under E22 and E24, a host whose `shown` token moves against a change has taken that change over, and the engine returns its writes. A Vue re-render that patches the host's `class` attribute through a `:class` binding is exactly that kind of foreign write. An adapter that binds the vocabulary classes would therefore stop the engine's own changes in the middle. No record names this. When E-VUE opens, its brief needs to state it and rule that the adapter drives state only through engine methods and never binds the engine's class, attribute, or selector vocabulary on a host the engine owns.
2. **E21 re-scopes a user ruling (read).** E21 "E11 restated" changes the meaning of the user's E11 floor without the user. Row 9 is the only place that change costs anything today. Any later API newer than Chromium 141 would inherit the same fallback obligation. The carrier is E21 itself, which records no user ruling, so the question in row 9 is the correction.

ALIGNMENT: 1/2; DRIFT: none; GAP: Keep framework integration outside the engine (the Vue adapter half, outside the exit criterion, carried as E-VUE)
