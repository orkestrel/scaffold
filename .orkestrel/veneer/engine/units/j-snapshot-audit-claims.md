A token `save` calls `#hold(element, 'class')` and a property `save` calls `#hold(element, 'style')`; `#hold` returns when this snapshot already joined the record in the current cycle, takes its holding back from `#leaving` when its own restoration is in flight for that record, and otherwise joins through the static `#join`, which reads `hasAttribute` only at the first holder's join and adds later holders to the set. `restore` moves `#joined` into `#leaving`; after the token writes it departs each `class` record through `#depart` → `#leave`, which removes this snapshot from the holders and returns true only when it was the last holder and the record read the attribute absent, and then removes the attribute when the class list is empty; after the property writes it does the same for `style` when the inline list is empty and the attribute is present; the `finally` departs every remaining record. So no order of restorations, overlapping or sequential, by engines of any class leaves a `class` or `style` attribute present and empty unless a write throws.
