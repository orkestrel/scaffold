## Question 1 — the override shape

**Adopted: the planner's per-entity groups, with the objective lane's resolution rules.** Each entity's options carry up to one group per kind of name, `classes?: Partial<{Entity}ClassMap>`, `attributes?: Partial<{Entity}AttributeMap>`, and `selectors?: Partial<{Entity}SelectorMap>`, each map a named, documented interface in `types.ts` whose keys name the fact the token marks or the option leaf the attribute feeds (`shown: 'show'`, `transition: 'collapsing'`, `pressed: 'active'`, `static: 'data-bs-display'`, `dismiss: 'data-bs-auto-close'`) and whose default table is a frozen `{ENTITY}_CLASSES`, `{ENTITY}_ATTRIBUTES`, or `{ENTITY}_SELECTORS` constant in `constants.ts` equal to the cascade's tokens (the parity, E9). `DelegateOptions` takes one group per routed entity keyed by the entity noun (`button`, `collapse`, `dropdown`, and the rest, each `Pick<{Entity}Options, 'classes' | 'attributes' | 'selectors'>` over the kinds that entity has), so the object a consumer passes to the delegate is the application's vocabulary and a manual construction spreads the same entity group. The objective lane's one shared `Vocabulary` type on every option is declined: it puts Tooltip's slot names on Button's options against `architecture.md` § System constraints (the smallest primitives), and the delegate's per-entity object already gives one application-wide home. A package-level default is declined on both lanes' grounds (module-level state, two embeddings overwrite each other).

Membership and resolution rules, from both lanes: a selector built only from the entity's own tokens is derived with `:is()` and `CSS.escape` and is never a member; a platform name (`aria-*`, `role`, `tabindex`, `inert`, `popover`, `href`) is never a member; an attribute key's default keeps Bootstrap's spelling; class and attribute overrides resolve before derived selectors, and an explicit selector override replaces the derived selector whole; a replacing class value is validated as one non-empty DOM token, an attribute name as a valid attribute name, a selector by parsing it, through total guards `isClassToken`, `isAttributeName`, and `isSelector` in `validators.ts`, a refused value throwing `{ENTITY}_OPTION_INVALID`; the resolved tables are snapshotted at construction; `parse{Entity}Attributes(host, attributes)` and `readTargets(trigger, attributes)` receive the effective names; a delegate routes by one name per route and never by a replaced default; a delegate drives an existing owner through `find` without reconfiguring it, so cooperating owners and their delegate use compatible groups; a click matching conflicting routes inside one delegate is refused before either runs; a document-wide scroll lock refuses a second acquisition whose effective tokens conflict with the live lock. `BackdropOptions.class` becomes `classes` (`host`, `shown`, `fade`), and the owning overlay passes its own backdrop token in. The groups are constructor-only. An override is a runtime concern with one mechanism proof per entity (R17); the style parity proofs and the `plugin` rows describe the defaults alone.

The per-entity key tables: the round-5 unit derives each entity's maps from the `CLASS_NAME_*`, `SELECTOR_*`, and data-attribute constants at the top of that entity's Bootstrap file under the rules above, checks them against both lanes' inventories (the planner's table under question 1, the objective lane's under its question 1), records the mapping in its report, and the guide's `### Vocabulary` subsection carries it (R18). A key that appears in one inventory and not the other is ruled by the rules, not by the count.

## Question 2 — wire event names

**Ruled by the user (E11): `{verb}.vn.{entity}`.** Both lanes adopt it. `EventWire<TMap, TEntity extends string>` types each value as `` `${TKey & string}.vn.${TEntity}` ``, so a table naming another suffix or entity fails to compile (both lanes). Further rulings from the planner, adopted: the own-property mirroring of detail fields goes (its only consumer was Bootstrap listener code; the detail travels in `detail` alone); a pre-change event is cancelable and a completed event is not (Button's `toggle` is no longer a special case); `hidePrevented` becomes `prevent`, the one-word event `AGENTS.md` § Design laws requires and the name Mailbox and Elements already emit for the same refusal (`mailbox/src/browser/constants.ts:174`, the terrain distillate); `DropdownDetail.clickEvent` becomes `click`; `DropdownDetail.relatedTarget` goes, because Bootstrap hydrates it with the toggle that dispatches the event (`dropdown.js:129-133`, `:164-165`), so `event.target` already carries it; every other entity's `relatedTarget` stays, because it names another element. `ButtonEventMap` and the value `toggle.vn.button` are unchanged; the `BUTTON_EVENTS` table is retyped with the entity parameter.

## Question 3 — the sanitizer port

**Adopted: both lanes' one port, the objective lane's options object, the planner's static ARIA list.** `SanitizerInterface` has one method, `write(element, html)`, which replaces the element's children with the markup the sanitizer keeps, synchronously, propagating failure and retaining neither argument; a string-returning port is declined on both lanes' grounds (a second parse and the mutation-XSS shape). `TooltipOptions.sanitizer?: SanitizerInterface` replaces `sanitize`, read from the constructor alone; its absence means the native adapter. `SanitizeOptions` and `SanitizeAllowlist` are deleted; `SanitizerConfig`, `SanitizerElementNamespaceWithAttributes`, `SetHTMLOptions`, and `SanitizeTargetInterface` stay as the native adapter's inputs, with the round-4 sentence corrections (the `attributes` default names what the dictionary path keeps, every attribute the platform does not remove as unsafe, distinct from the no-options default; `dataAttributes: false` removes the general permission and an explicitly listed `data-*` name survives; either value needs `attributes`; the "tip sanitizer sets" phrase names the mirror's subset instead). J-TYPES round 5 lands `SanitizerInterface`, `NativeSanitizerOptions { config?: SanitizerConfig }` (absence selects the engine's Bootstrap-derived configuration; an empty dictionary is an explicit platform configuration), and the option; J-TOOLTIP lands `src/browser/sanitizers/NativeSanitizer.ts` (`architecture.md` § Extension categories: a designed extension point gets its folder even with one class; the contract stays in `types.ts`), `SANITIZER_ALLOWLIST` as a `SanitizerConfig` built from Bootstrap's `DefaultAllowlist` with per-element entries, the explicit global list `class`, `dir`, `id`, `lang`, `role`, every WAI-ARIA attribute by name, and `dataAttributes: false`, plus `isSanitizeTarget`; no engine file constructs or names the `Sanitizer` global; the option's TSDoc names no class until the class exists (guide parity). Bootstrap's `sanitize: false` and `sanitizeFn` have no option: a consumer supplies its own adapter, and Veneer ships no unsafe writer (product policy); the departure is recorded in the guide's `### Content` and the Compatibility sanitizer row. A non-standard `aria-*` name Bootstrap's pattern would keep is dropped by the static list; J-TOOLTIP probes one through the adapter and the guide records the departure. `@orkestrel/html` enters later, if at all, as its own `SanitizerInterface` adapter after its own campaign, with no Veneer change and no dependency.

## Question 4 — options that survive only because Bootstrap had them

Adopted, from both lanes unless named: the `data-bs-config` JSON layer is removed (both lanes: a second channel for one option set; no engine mechanism needs it), so the merge is defaults, then the declared attributes read through the effective names, then the constructor object; `CollapseOptions.toggle` is removed (the planner: construction that flips the panel contradicts R1's explicit construction, and `toggle()` exists; the delegate constructs and then calls `toggle()`); `TooltipOptions.animation` and `ToastOptions.animation` become `animated` (the planner: the boolean-as-assertion rule and `BackdropOptions.animated`); `ButtonOptions` gains `signal` (the objective lane: R11 promised it to every entity); Popper's `boundary` and `popperConfig` are neither options nor declared attributes and the guide records the exclusion (both); ScrollSpy's deprecated `data-bs-offset` conversion is removed (both); `data-bs-original-title` and Toast's `hide` token are never written (both; `HostSnapshot` restores `title`). Every other option key stands as round 4 left it. Default attribute values such as `hover`, `static`, and `inside` stay input syntax the parsers project into the boolean groups.
