## The shape rulings

1. **The public static `profile`, `TooltipProfile`, and `TooltipDefaults`: CONFIRMED.** R12 requires a static read through `new.target`; a `#` static cannot be read through a subclass constructor and `protected` is banned, so public is the only working form; every member is one word; `TooltipDefaults` follows `DropdownDefaults` (`types.ts` ~936). Optional tightening (about two lines, no behaviour change): declare `TooltipProfile.attributes` and `.selectors` as `TooltipAttributeMap & Partial<Pick<PopoverAttributeMap, 'content'>>` (and the selector twin), and type `popover` as `NonNullable<PlacementInput['popover']>`.
2. **The generic `Tooltip<TOptions>` with `NoInfer`: CONFIRMED as the least-cost shape.** A pass-through constructor is refused by lint and the wrapper law; widening the `Tooltip` parameter to `PopoverOptions` would let a tooltip accept a `content` it ignores. Remaining cost: `TOptions` is a phantom on the instance type, so an explicit `new Tooltip<PopoverOptions>(h, { content })` compiles and the content is ignored; the `@typeParam` TSDoc bounds it.
3. **`PlacementOptions.owned`: CONFIRMED on its home; the name is acceptable.** A lifetime read like `signal`, not an element `PlacementInput` names. Alternative `hold?: () => boolean` (matching the `@param` and `#holds`), touching `types.ts`, `Placement.ts`, one key in `Tooltip.ts`, the Placement case, one guide sentence, and three instrument rows; not a law violation, the Orchestrator's choice. `.bind(this, change, false)` avoids the nested-function ban.
4. **Profile records as class statics: CONFIRMED.** A static member is not module-scope data; R12 requires it; a `TOOLTIP_PROFILE` row would add a second public name, put a guard function in a data table, and give `constants.ts` an import from `validators.ts`.

## Referrals to the objective lane

- **`Placement.ts` ~126: a throwing `owned` leaks the promotion.** The read sits outside the `try`; a throwing `owned` leaves `popover` written and the element open, and no instance escapes to restore it unless a `signal` aborts later. The `showPopover` throw path (~116–121) restores before throwing; `owned` is public, so rule whether it gets the same restore-then-throw.
- **`Tooltip.ts` ~234: the widening to `PopoverOptions` is sound only for the declared instantiations.** A subclass `extends Tooltip<TooltipOptions & { content: number }>` whose profile names a body slot would pass a number into `fillSlot`.
