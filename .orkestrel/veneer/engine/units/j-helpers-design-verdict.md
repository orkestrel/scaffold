## The rule the rulings apply

The leaf test: a pure self-contained lookup or projection is an exported helper; a member that reaches `#` state or a sibling method, or is the class's defining composition, stays a method. `helpers.ts` is exported reusable infrastructure: a would-be helper that is trivial and single-use folds into its caller; one that is non-trivial or reusable is extracted, exported, tested, and every duplicate routes through it. A wrapper survives only where it adds a boundary, invariant, composition, translation, lifecycle, or a materially narrower contract. A public API grows with its first real consumer, never on speculation. From these, the Orchestrator's dividing line: **a pure DOM reading with two or more consuming classes, or one whose contract the classes' own suites cannot pin without it, is extracted; a pure reading one class uses stays that class's private method, because exporting it adds a public capability nobody else consumes.** The objective lane extracted every pure member; the subjective lane extracted three. The line falls between them.

## 2. The shapes, their names, and their contracts

Every live-DOM read in `helpers.ts` takes the `read*` prefix, the registered meaning "obtains a value from a live host object", which the existing `readTargets`, `readTarget`, and `readControls` already use for single values and lists alike; `scan*` and `collect*` would give one concept a second term. `find*` is not a registered prefix. The fleet-name check (both lanes, over `scaffold/guides`, `elements/guides`, `mailbox/guides`, `veneer/guides`, and the installed `@orkestrel/*` declarations) found none of these names claimed; `elements` claims `findClosest`, `findNextSibling`, and `findPreviousSibling`, none of which this design uses.

```ts
export function readClosest(element: Element, selector: string, root?: ParentNode): HTMLElement | undefined
export function readSiblings(element: Element, selector: string, forward: boolean): readonly Element[]
export function readOutermost(root: ParentNode, selector: string): readonly HTMLElement[]
export function readScrollbarWidth(document: Document): number
export function readTarget(trigger: Element, attributes: AttributeMap<'target'>, root?: ParentNode): HTMLElement | undefined
export function matchesDisabled(element: Element, token: string): boolean
```

- **`readClosest`.** The platform `closest` (which includes the element itself), then the `isInstance(…, HTMLElement)` guard on that first match, then, where `root` is given, `root.contains(element)` (the root itself is contained); `undefined` on any rejection, never continuing past a rejected match. Sites: every former `Delegate.#closest` call with `this.#root`; `Tab.#list`'s callers and `Tab.#wrapper` unbounded; the `#routeTabKey` list read unbounded (its control keeps its later root check). A selector error propagates.
- **`readSiblings`.** The element's siblings on one side that match the selector, nearest first, the element excluded, no HTML guard and no root bound; `forward` true reads the following siblings, false the preceding ones, the meaning `computeNeighbor` gives the word. Returns `Element` so a route's later guard keeps its semantics (a matching non-HTML sibling ends the search as today). Sites: `Dropdown.#locate` (`[...readSiblings(host, menu, true), ...readSiblings(host, menu, false), ...parent descendants].find(instanceOf(HTMLElement))`), `Delegate.#locateToggle` (the same spread in the order false, true, parent, then `.find(not disabled)`, then one `readClosest(found, trigger, this.#root)`), `ScrollSpy.#parents` (`readSiblings(holder, parent, false)[0]`). A composite both-sides-then-parent helper is rejected: `forward` would carry two meanings, and the order is each entity's policy.
- **`readOutermost`.** The HTML elements inside the root matching the selector that sit inside no other match within the root, in document order, the root excluded; nesting judged against every match through `:scope :is(S) :is(S)`, the `:is()` wrapper written by the helper so a selector list nests correctly. Sites: `Carousel.#items` (the body), `Collapse.#siblings` (`readOutermost(parent, host + ', ' + transition).filter(not this.#host and matches(host.shown, transition))`, which equals today's candidates minus the nested set).
- **`readScrollbarWidth`.** `Math.abs(view.innerWidth - documentElement.clientWidth)`, `0` for a document with no view, read afresh on each call. Sites: `Modal.#adjust` (`host.ownerDocument`), the `ScrollLock` constructor at both measurement points, their positions around the writes unchanged.
- **Bounded `readTarget`.** The existing read, then, where `root` is given, containment of the first HTML result; an out-of-root first result returns `undefined` even where another named element lies inside. Sites: `Delegate.#routeModal` (in place of `#readModal`), `Delegate.#slideHost`. The unbounded callers stay unbounded, and `Delegate.#locate` stays unbounded so an explicit outside target never falls back to the closest host (the analyst's invariant, kept).
- **Rejected as platform wrappers (both lanes agree):** a first-match `querySelector` plus guard, a `checkVisibility` read, a `contains` read, `readAncestors` (one site), `readFragment` (one site).

## 3. The disabled reading

- `ScrollSpy.#section` routes through the shared predicate (both lanes). Nothing changes: `:disabled` matches no anchor or area, and the attribute's `false` value is already honoured by hand.
- `Dropdown.#refused` routes through the shared predicate (the planner's finding, over the analyst's "documented exception"). Bootstrap's `Dropdown.show` and `hide` read `isDisabled(this._element)`, which admits an `<a disabled>` toggle as disabled; Veneer's method reads only the token and `:disabled`, so a directly constructed `<a disabled>` toggle shows while the delegate refuses it. E16 fixes one reading for the delegate routes, and the same reading belongs to the engine's own show and hide; the guide sentence that documents the narrower reading changes with it. Red first.
- The delegate's dropdown-entry keyboard filter keeps its declared entry selector (both lanes): it follows the cascade and Bootstrap's visible-items selector, and an `<a class="dropdown-item" disabled>` is painted and clickable, so the keys still reach it.
- The button, collapse, carousel, and modal toggle routes read no disabled state, as Bootstrap's data API does (both lanes).
- **Rename `isDisabled` to `matchesDisabled`** (the planner's naming finding; the Orchestrator rules for it). `.claude/rules/names.md` § Fixed derivation/construction forms binds a new `is*` name to a total `Guard<T>`, and names `isVacant` as a *retained* name that keeps its form outside its file, not as a licence for new two-argument `is*` predicates; `isDisabled(element, token)` is new, narrows nothing, and takes a token. `matches*` is the registered predicate prefix its sibling `matchesReducedMotion` already uses. The rules outrank E16's amended wording, whose placement ruling (`helpers.ts`) stands; E16 is amended in `decisions.md` in the same commit that dispatches the unit. The guide's "Bootstrap's `isDisabled`" comparison is reworded so every backticked name resolves.

## 4. The cross-package position

**Ruling: (a) Veneer's own `helpers.ts`, with no new dependency** (both lanes). The prior art is not adoptable: the `elements` and `mailbox` checkouts are unscoped local projects at `0.0.1` (`elements/package.json`, `mailbox/package.json`), not `@orkestrel` packages, and the catalog lists neither; `elements` carries a runtime `@vue/reactivity` dependency; its traversals take predicates and return `null`, against the absence law; neither has a counterpart to `readTargets`, `readControls`, or the `:scope` exclusion, and their scrollbar expressions live inside stateful lock operations. Option (c), a small fleet DOM package, becomes worth its release sequence only when a second `@orkestrel` package grows a sibling walk, an outermost read, or a closest-with-root read with the same selector-based `undefined`-returning contracts; it then runs under the align-packages skill with the user's ruling. Nothing here needs a dependency change, so nothing here waits on the user.

## 5. The test-side ledger

Every `tests/setupBrowser.ts` export stays, each with its stated difference from the installed `@orkestrel/test` 0.0.22 export (both lanes, read against the installed implementation): the fixture lookups (`readButton`, `readSpecimen`, `readSubject`, `readOracleButton`) select by Veneer fixture policy and admit unreachable hosts where the installed resolvers refuse them; `pressOracleKeys` composes the installed `pressKeys` after a root-scoped lookup; `SceneManager`, `scene`, and the `mount*` fixtures own the mounted nodes and their cleanup, which `mount`, `render`, and `build` do not; `visitBreakpoint` restores the viewport around an action, where `stagePane` is capture staging; the cascade collectors (`readCascadeSheet`, `collectLayer`, `collectLayerRules`, `collectNestedRules`, `collectSheetRules`, and their siblings) read a supplied sheet depth-first where `readRules` reads the document breadth-first; `recordCalls`, `recordListeners`, `recordEvents`, `recordState`, and `collectPainted` compose `createRecorder` and `readStates` rather than repeat them; `measureVariation` and `readRegion` compute regional variation where `readFrame` reports dimensions. One substantive overlap: `holdOraclePointer` repeats the pointer-driving sequence the installed `driveHold` owns and adds release on a failed frame wait; the analyst rules "move the cleanup difference upstream, then reuse". That is an `@orkestrel/test` change with a release, so it is carried for the user's ruling rather than done here, and `holdOraclePointer` stays until then. On the production side every leaf stays separate from the test package (`settleAnimations` from `waitForAnimations`, the disabled predicate from `isReachable` and `readStates`, the section visibility read from `isRendered`, `readControls` from `readRows` and `FOCUSABLE_SELECTOR`), because `src/` never imports `@orkestrel/test` and each pair differs in contract.

## 6. The unit plan

One writing unit, **J-HELPERS**, on `opus` on Opus 5.5 in `tmp/worktrees/helpers` cut from Veneer `main` after the J-TOAST landing (`e8251cf`), because the refactor's proofs run in the browser, which the Codex sandbox cannot host; the objective audit lane runs on Astra. The unit owns `src/browser/helpers.ts`, `Delegate.ts`, `Tab.ts`, `Dropdown.ts`, `Collapse.ts`, `Carousel.ts`, `ScrollSpy.ts`, `Modal.ts`, `ScrollLock.ts`, `tests/src/browser/helpers.test.ts`, the class tests where a case is added (`Delegate.test.ts`, `Dropdown.test.ts`, `ScrollSpy.test.ts`), and `guides/veneer.md` (the § Surface rows of the new and renamed helpers, the § Delegation, `#### Dropdown`, and `#### ScrollSpy` sentences, and the duplicate `computeNeighbor` § Surface row the planner found). `types.ts` is report-only (no contract changes; the optional `root` parameter is a helper signature). Serialized after J-TOAST; J-TOOLTIP may run beside it in its own worktree because their owned sets are disjoint except the append-only `helpers.ts`, `constants.ts`, and the guide, which the later landing reconciles.

Acceptance (falsifiable): the six signatures above are exported with doc blocks and titled `@example` fences and their § Surface rows; `helpers.test.ts` pins for `readClosest` self inclusion, the guard on the first match (an SVG match returns `undefined`), root containment including root equality, and an unbounded read; for `readSiblings` each direction nearest first, self excluded, a matching non-HTML sibling returned, and no parent returning `[]`; for `readOutermost` a nested match excluded, the root excluded, a selector list `'.a, .b'` with `.b` inside `.a`, and nesting through a non-HTML match; for `readScrollbarWidth` a viewless document returning `0`; for the bounded `readTarget` an outside first result returning `undefined` with an inside second result present; for `matchesDisabled` the token, `:disabled`, the attribute, `disabled="false"`, and the renamed cases. Under `src/browser`, no `previousElementSibling`, `nextElementSibling`, `:scope `, or `innerWidth - documentElement.clientWidth` remains outside `helpers.ts`, and `getAttribute('disabled')` and `, :disabled` remain only in `helpers.ts` and the entry selector; no `isDisabled` identifier remains anywhere in `src`, `tests`, or the guide. Red first: a directly constructed `<a href="#" data-bs-toggle="dropdown" disabled>` toggle's `show()` resolves `false` (the failing command and count recorded before the fix). Site proof in `Delegate.test.ts`: a menu whose preceding toggle is disabled and whose following toggle is enabled takes the following one. The Dropdown, ScrollSpy, Collapse, Carousel, Modal, ScrollLock, Tab, and Delegate suites stay green without other edits; the mutation instrument turns each named mutation red (direction reversed, farthest-first order, the `:is()` wrapper dropped, the nested set not excluded, the null-view guard removed, the containment applied before the guard, the guard widened to `Element`); `test:guides` green.

Risks named: a `readSiblings` filtered to HTML elements would change the toggle route; a root bound inside `Delegate.#locate`'s target read would make an outside target fall back to the closest host; the widened `Dropdown.#refused` also refuses `hide()` and `toggle()` on an `<a disabled>` toggle, which matches Bootstrap; headless Chromium may draw no classic scrollbar, so the `readScrollbarWidth` proof pins the viewless `0` and records the host's live width as an observation.
