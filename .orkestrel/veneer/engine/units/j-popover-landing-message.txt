Add the Popover over the tooltip engine's profile, and stop a placement whose owner lost the element

`Popover` extends `Tooltip` and supplies its profile through a static `profile` member the tooltip constructor reads through `new.target` (R12): the popover name for its `.vn.popover` events, error codes, and `vn-popover-` tip ids, its own registry so a trigger carries a tooltip and a popover at once, the `POPOVER_*` tables and defaults (a click toggles the tip, which sits right of its trigger at offset [0, 8], built from the header-and-body template), and the `manual` popover value. A profile whose tables name `content` gives the tip a body slot the `content` option and the `data-bs-content` attribute fill; an empty header or body is removed. `Tooltip` is generic over its options so `new Popover(trigger, { content })` type-checks while a tooltip refuses `content`, and a delegating engine constructs each descendant from the class being constructed.

`Placement` reads a new `owned` option once, after the promotion and before its first positioning write, and restores what it wrote when the owner no longer holds the element: a listener to the opening `beforetoggle` event that moves a tip now leaves no promoted, positioned tip behind, which closes the one interval E18 left to this unit. The tooltip passes its door as `owned`; a placement given none, such as the dropdown's, is unchanged. The tooltip's build returns moved elements from one release site, and `#occupy` takes the change first. The Popover `plugin` row reads `shipped`.
