Give every saved target one record across snapshots, written back by its last holder

Two tabs of one list, or a carousel and a swipe on one host, each recorded a shared target at its own first write, so a destruction wrote another engine's value back: a list left showing the tab another tab had selected, and a live swipe losing its `pointer-event` token. Every snapshot that saves one attribute, class token, or inline property of one element now shares one record of it: the first save made while no snapshot holds it and no restoration has it pending reads the element, each later save joins, a restoration that is not the last holder writes nothing for it, and the last holder's restoration writes the first saved value back (E25). A save during a restoration joins the pending record, so takeover needs no separate path, and the save-order stamp is gone. `HostSnapshotInterface.clear()` relinquishes a snapshot's holdings without writing, and an alert's completed close calls it. A tab joins every initial attribute its list's plan names, so a destroyed sibling cannot strip a live tab's roles, and a tooltip destroyed beside a live popover takes its own id out of `aria-describedby`. Each reproducer and each mechanism read red first.
