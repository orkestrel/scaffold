
## Amendments (2026-09-23, the J-ENGINE-SHAPE round under E8 to E11)

Each entry names the ruling it amends and gives the replacement text; a sentence not named stands. The reconciliation and its evidence are `units/j-engine-shape-verdict.md`.

- **R1 The styles are Bootstrap's; the engine is Veneer's.** The cascade's class tokens and the attributes it selects on are the parity, and the engine's default vocabulary equals them. Every class token, attribute name, and selector the engine reads or writes is a default a consumer replaces per entity (R19). Wire event names, option paths, members, and event details follow Veneer's naming law. Explicit construction, a side-effect-free import, `Delegate` as the only data API, one owner per host per class, restore on destroy, one `AbortController` per entity, and no mutation after `destroy()` stand.
- **R2 Wire events.** Each entity dispatches `{verb}.vn.{entity}` (`show.vn.collapse`, `slid.vn.carousel`, `toggle.vn.button`), bubbling, on its host, so a page running Bootstrap's scripts beside the engine never crosses events (E11). A pre-change event (`show`, `hide`, `close`, `slide`) is cancelable and `preventDefault()` refuses the change; a completed event is not cancelable. The detail travels in `detail` alone, with no mirrored own property. A handler's return value refuses nothing. `emitEvent` takes the cancelable flag and returns `!defaultPrevented`. `DropdownDetail` carries `click` (Bootstrap's `clickEvent`) and no `relatedTarget`, because the toggle that dispatches the event is `event.target`; every other `relatedTarget` names another element and stays.
- **R3 Event-map keys are the entity's verbs.** `{Entity}EventMap` keys are `show`, `shown`, `hide`, `hidden`, `prevent` (Bootstrap's `hidePrevented`, the one-word event the design laws require and the name Mailbox and Elements emit), `inserted`, `close`, `closed`, `slide`, `slid`, `activate`, and `toggle`, and each key's TSDoc names the `.vn.` wire event it carries. The frozen `{ENTITY}_EVENTS` table is typed `EventWire<{Entity}EventMap, '{entity}'>` (`COLLAPSE_EVENTS.shown === 'shown.vn.collapse'`), so a table naming another suffix or entity fails to compile. The translated vocabulary stays refused on its original ground.
- **R5 Delegate routing.** `Delegate` routes by the `selectors` of the entities it serves, resolved from its per-entity groups (`DelegateOptions.button`, `.collapse`, and the rest) over each entity's default table, constructs each engine with that entity's groups, and drives one a consumer constructed through `find` without reconfiguring it. A delegate routes by one name per route: a replaced default is not an alias and routes nothing; a click matching conflicting routes inside one delegate is refused before either runs; a host under nested roots is driven once per click. The observer release and the per-component route landings stand.
- **R6 Timers.** Tooltip delays, Toast lifetimes, and Carousel intervals use native `setTimeout` and `clearTimeout`, cleared on destruction or lifetime abort; no timeout package and no transition fallback timer is introduced (E8).
- **R8 Light dismiss.** Light dismiss is Bootstrap's own check (`mousedown` then `click` on the host itself); with a backdrop present, `dismiss.backdrop: false` emits `prevent.vn.modal` and applies the effective static token, whose default is `modal-static`. The literal tokens and selectors in the rest of R8 are defaults under R1.
- **R9 Placement.** `Placement` promotes menus and popover tips with `popover="manual"` and tooltip tips with `popover="hint"`, keeps the anchor-positioning and restoration mechanism, and reads and writes the effective names for its placement attributes (`attributes.popper`, `attributes.side`) and direction tokens; `static` stays the boolean, and `--bs-position` stays the cascade property. A hint tooltip bridges platform dismissal through cancelable `beforetoggle` into `hide.vn.tooltip`. `boundary` and `popperConfig` are neither options nor declared attributes, and the guide records both as excluded. The computed-style proof against UA defaults stands.
- **R10 Content.** `html: false` writes `textContent`. `html: true` writes string content and the template through `TooltipOptions.sanitizer`, a `SanitizerInterface` whose `write(element, html)` replaces the element's children synchronously, propagating failure and retaining neither argument; the option is constructor-only, and its absence means `NativeSanitizer` (`src/browser/sanitizers/NativeSanitizer.ts`, `NativeSanitizerOptions { config? }`) over `SANITIZER_ALLOWLIST`, a `SanitizerConfig` built from Bootstrap's `DefaultAllowlist` (`util/sanitizer.js:11-46`) with per-element attribute entries, the explicit global list `class`, `dir`, `id`, `lang`, and `role`, every WAI-ARIA attribute by name, and `dataAttributes: false`, written through the guarded `setHTML`; no engine file constructs or names the `Sanitizer` global (E7). `sanitize: false` and `sanitizeFn` have no option: a consumer supplies its own `SanitizerInterface`, Veneer ships no unsafe writer, and the guide's `### Content` and the Compatibility sanitizer row record the departure, including the non-standard `aria-*` names the static list drops. The template, slot, `destroy`, and `tip.class` clauses stand; templates use the effective vocabulary. `@orkestrel/html` enters later, if at all, as its own adapter after its own campaign (E9).
- **R11 Options and attributes.** Each class merges `{ENTITY}_DEFAULTS`, then the attributes its resolved `attributes` table names (`parse{Entity}Attributes` takes that table), then the constructor object; explicit `false` and `0` survive; a declared attribute that fails coercion throws `AppError` `{ENTITY}_OPTION_INVALID`; an undeclared attribute is ignored; no `data-bs-config` is read. Hooks, `signal`, the vocabulary groups, and `sanitizer` are read from the constructor alone. Every entity, Button included, accepts `on` and `signal`. In the option-path list: `toggle` is struck (construction flips nothing; `toggle()` exists); `animation` becomes `animated` on Tooltip and Toast; `sanitize: { enabled, allow, filter }` becomes `sanitizer`; ScrollSpy's `data-bs-offset` conversion is struck. Attribute tables in the guide name Bootstrap's spellings as defaults mapped to option paths.
- **R12 Members.** The member names stand. `Popover extends Tooltip` selects its profile through `new.target`; the profile supplies its name, event table, behavioural defaults, and template, and the effective vocabulary supplies the class tokens, attributes, and slot selectors (`selectors.title`, `selectors.content`), so the shared engine needs no protected member.
- **R13 Placement of files.** The flat placement stands. `constants.ts` also owns the `{ENTITY}_CLASSES`, `{ENTITY}_ATTRIBUTES`, and `{ENTITY}_SELECTORS` default tables and `SANITIZER_ALLOWLIST`; `validators.ts` gains `isClassToken`, `isAttributeName`, `isSelector`, and `isSanitizeTarget`; `parsers.ts` is created by the first entity whose attribute coercion no `@orkestrel/contract` reader performs, the option merge being `resolveOptions` in `helpers.ts` (E10); `NativeSanitizer.ts` sits in `src/browser/sanitizers/` under `architecture.md` § Extension categories, the one category folder; `Snapshot` is `HostSnapshot` with `HostSnapshotInterface`, `HostSnapshotTarget`, and `HostSnapshotCategory` (E10); `isHost` is deleted for `isInstance(value, HTMLElement)` (E10).
- **R14 The `@orkestrel/*` matrix.** `contract` stays the sole runtime dependency; `emitter`, `abort`, `queue`, and `template` stay excluded; `timeout` is excluded by E8; `html` is not a dependency, because its `sanitize` cannot express Bootstrap's allowlist (the E7 addendum: unlisted safe elements unwrap, `data:` is refused, attributes are global), and it enters later, if at all, as a `SanitizerInterface` adapter after its own campaign. No `package.json` change.

The Status and Proof resolver rule stands.

The native sanitizer's proofs distinguish an omitted configuration from an empty dictionary and prove the per-element restrictions, the ARIA list, and the data-attribute behaviour.
