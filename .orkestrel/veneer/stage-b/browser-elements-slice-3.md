### Tabs

The `createTabs` factory takes a trigger, a pane, and a group (`src/browser/types.ts:2077`). The header says the trigger is a button or any `[role="tab"]` element, the pane is a tabpanel, and the group is a tablist (`src/browser/factories/createTabs.ts:28`). When `role` is absent the factory writes `tablist`, `tab`, and `tabpanel` (`src/browser/factories/createTabs.ts:39`). The header says `[aria-selected]` on the trigger is the source of truth for which sibling is active (`src/browser/factories/createTabs.ts:11`). The catalog names `aria-selected` toggling and lazy panel mounting (`guides/composables.md:410`).

The `initial` option forces the tab active (`src/browser/types.ts:2085`). The `on` option is a partial tabs event map (`src/browser/types.ts:2084`). Active state starts true when `initial` is true or the trigger already has `aria-selected="true"` (`src/browser/factories/createTabs.ts:47`).

The instance returns the `active` ref and the `show`, `hide`, `toggle`, and `destroy` methods (`src/browser/types.ts:2095`).

The event names are `elements:tabs:show`, `elements:tabs:open`, `elements:tabs:hide`, `elements:tabs:close`, and `elements:tabs:deactivate` (`src/browser/constants.ts:504`).

Each trigger carries `aria-controls` pointing at the pane id (`src/browser/factories/createTabs.ts:12`). The factory writes `aria-controls` only when it is absent, and it assigns a pane id when the pane has none (`src/browser/factories/createTabs.ts:140`). The inactive pane receives the `hidden` attribute. The header says that attribute removes the pane from layout and from the accessibility tree, and that the factory does not write `aria-hidden` for the pane (`src/browser/factories/createTabs.ts:16`). `show` sets the previous trigger's `aria-selected` to `false`, emits `deactivate` on that trigger, sets this trigger's `aria-selected` to `true`, sets `hidden` on the previous pane, removes `hidden` from this pane, and emits `open` (`src/browser/factories/createTabs.ts:87`, `src/browser/factories/createTabs.ts:97`, `src/browser/factories/createTabs.ts:104`). `hide` sets `aria-selected` to `false`, sets `hidden` on the pane, and emits `close` (`src/browser/factories/createTabs.ts:112`).

`paintIndicator` writes `--set-tabs-indicator-x`, `--set-tabs-indicator-y`, `--set-tabs-indicator-width`, and `--set-tabs-indicator-height` on the group from the trigger rect relative to the group rect (`src/browser/factories/createTabs.ts:52`). `show` calls it before the swap, and an initially active tab calls it at setup (`src/browser/factories/createTabs.ts:82`, `src/browser/factories/createTabs.ts:133`). The header says the factory does not wait for a transition, because an earlier wait listened for a `transitionend` the tab chrome does not declare and that wait was the `TRANSITION_FALLBACK_MS` timeout of 400 on every switch (`src/browser/factories/createTabs.ts:21`).

### Toast

The `createToast` factory binds a `<div>` host and throws when the tag differs (`src/browser/factories/createToast.ts:62`). That popover call is what sets `popover="manual"` on the host (`src/browser/factories/createPopover.ts:261`).

The `autohide` option is false or `{ delay }` (`src/browser/types.ts:1819`). False keeps the timer off. Otherwise the delay is `autohide.delay` or the `DEFAULT_TOAST_DELAY_MS` constant, which is 5000 (`src/browser/factories/createToast.ts:69`, `src/browser/constants.ts:38`). The instance returns the popover `visible` ref and the `show`, `hide`, `pause`, `resume`, and `destroy` methods (`src/browser/types.ts:1834`, `src/browser/factories/createToast.ts:455`).

A `paused` flag drops a repeated pause or resume (`src/browser/factories/createToast.ts:269`).

The parent opts into a deck with `data-toast-stack` (`src/browser/constants.ts:96`, `src/browser/factories/createToast.ts:126`). `stack` collects open `div` children with `role="status"` and `popover`. In a deck, each toast receives `--set-toast-stack-index`. An index at or past the depth receives `data-toast-stack-hidden` and `aria-hidden="true"`.
