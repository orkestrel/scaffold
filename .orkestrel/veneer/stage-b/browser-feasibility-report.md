# Browser feasibility

Chromium 153.0.8010.12 supports the requested native primitives, but Bootstrap integration needs explicit handling of dialog defaults, popover visibility, arrow placement, and top-layer order. The measurements also distinguish `inert` exclusion from focus wrapping.

## Recipe

Measured on Windows with Playwright 1.63.0 and Bootstrap 5.3.8, in Vitest's 414 × 896 Chromium test iframe. The trivial `sheetProject` probe ran without changing its root or aliases. Bootstrap's bundled CSS was loaded through `import 'bootstrap/dist/css/bootstrap.css'`. Real nodes, keyboard input, browser clocks, computed styles, geometry, and events supplied the readings. Constructed stylesheets supplied the requested experimental declarations.

The command was `npx vitest run --config tmp/probes/vite.chromium.config.ts tmp/probes/<family>.test.ts`. Bootstrap source imports initially triggered Vite dependency-optimizer reloads; explicitly including Modal, Dropdown, Tooltip, FocusTrap, and ScrollBarHelper stabilized subsequent runs. Removing Playwright's `--hide-scrollbars` default exposed a classic scrollbar. The exact config, probe sources, inputs, controls, and readings are preserved in [browser-feasibility-measurements.json](C:/Users/mikes/WebstormProjects/veneer/tmp/units/browser-feasibility-measurements.json). Entry names in the following paragraphs identify the corresponding measurements. Every control audit passed. The probes directory is empty, and `git status --porcelain` was empty before and after the run.

**Feature census — `feature-census`.** All requested CSS declarations and selectors returned true. The requested API members were present, including `commandForElement`, `interestForElement`, `closedBy`, `CloseWatcher`, and view transitions. `showPopover({ source })` opened successfully, `popover="hint"` was accepted, and `closedby="any"` reflected as `any`. Popovers emitted `beforetoggle`; details emitted `toggle`, but no `beforetoggle`, during programmatic opening and a real summary click. The made-up property and selector both returned false.

**Modal dialog — `dialog-modal`.** An unmodified `dialog.modal` remains `display:none` after `showModal()`. Enabling display exposes a 3 px UA border, 16 px padding, constrained dimensions, and centered margins. The adopted rules `dialog.modal { margin:0; border:0; padding:0; max-width:none; max-height:none; color:inherit; background:transparent; }` and `dialog.modal[open] { display:block; }` matched every sampled computed property and both bounding boxes of the ordinary-div control. The modal became 414 × 896, and its inner dialog began at (8, 8). The native backdrop resolved to `rgba(0, 0, 0, 0.1)` and intercepted the sampled point ahead of a sibling with z-index 2147483647. Opening focused the first inner button; Escape emitted cancel and close, closed the dialog, and restored opener focus. The outside opener could not receive focus while modal. Tab reached the surrounding Vitest frame, so these readings do not establish standalone focus wrapping.

**Dropdown — `dropdown-anchor-popover`.** The literal absolute-positioned anchor recipe did not match the static control: menu y was 182 px instead of 212 px. Adding `position:fixed` matched the control's (70, 212) position and 160 × 82 box. After scrolling the toggle to y=856, fallback placed the menu at y=772, ending 2 px before the toggle. Top-layer popover placement also matched the static box. Bootstrap overrides the UA position, margin, border, padding, color, background, and display; UA inset and overflow remain 0 and auto, while Bootstrap's minimum width constrains the content-sized box. The menu preceded a z-index 2000 sibling in hit testing. A modal opened afterward intercepted it; reparenting the menu inside that modal and showing it placed the menu first. Auto popovers closed on outside click and Escape; manual controls stayed open. Opening `beforetoggle` was cancelable, closing `beforetoggle` was not. Crucially, dismissal left `.dropdown-menu.show` displayed as a 160 × 82 box: native open state and Bootstrap's visibility class require synchronization.

**Tooltip arrows — `tooltip-arrows`.** Anchor positioning placed the tooltip, but its unmodified arrow remained in normal flow. Adding `position:absolute` and `left:calc(50% - var(--bs-tooltip-arrow-width) / 2)` to the top arrow, plus a 6 px bottom margin on the tip, matched Bootstrap/Popper within 1 px. Right placement used the corresponding `top` calculation and a 6 px left margin, also matching within 1 px. The JSON retains Popper's exact inline transforms and offsets. At the viewport edge the tip flipped left, while `data-popper-placement="right"` and the arrow remained oriented for right placement. Removing `position-anchor` sent the tip to (0, 0).

**Fade — `fade-discrete`.** Bootstrap's reflow idiom and the `@starting-style` alternative both produced opacity animations with a 150 ms CSS duration. Their recorded transitionend arrivals were approximately 156 ms and 167 ms. The alternative toggled display and `.show` together, with `transition-behavior:allow-discrete` and starting opacity zero. Emulated reduced motion matched the media query and produced no animation or transitionend. The `transition:none` control likewise produced neither.

**Collapse — `collapse-intrinsic`.** Pixel-height and `interpolate-size:allow-keywords` paths both animated to a 120 px content height. Their transitionend arrivals were approximately 368 ms and 349 ms, with a 350 ms CSS duration. The numeric-only control snapped to auto without animation. The requested `details::details-content` rules produced a 120 px content box but no animation or transitionend during the approximately 466 ms observation. A shared details `name` closed the first item when the second opened.

**Focus exclusion — `focus-inert`.** Without either mechanism, Tab reached the outside button. Applying `inert` excluded the outside controls from keyboard focus and Chromium's accessibility tree while preserving their layout rectangles and leaving `aria-hidden` absent. The accessibility control contained both outside buttons; the inert reading contained only the inner buttons. However, Tab from the last inner button left the test iframe and reached Vitest's controls. Bootstrap's FocusTrap instead cycled between the inner buttons. These measurements do not support replacing focus wrapping with `inert` alone in an embedded document.

**Scroll lock — `scroll-lock`.** With the scrollbar-hiding flag removed, the scrollbar measured 15 px. Uncompensated overflow hiding widened the body and fixed navbar from 399 px to 414 px. Bootstrap's helper also widened their border boxes but applied 15 px right padding to both. A stable gutter preserved both widths at 399 px with zero padding. The document's clientWidth still changed from 399 px to 414 px, so clientWidth alone does not describe the preserved layout.

**Bootstrap oracle — `bootstrap-oracle`.** Modal and Dropdown ESM imports resolved and ran. The retained transcript records show, scroll locking, body class changes, backdrop insertion, modal display and accessibility writes, shown, hide, reversed writes, backdrop removal, cleanup, and hidden, with old attribute values and reconstructed new values. Shown arrived at approximately 467 ms and hidden at 792 ms from the opening call. Captured transitionend events distinguish trusted opacity events from Bootstrap's untrusted fallback events; a lifecycle wait does not prove a native transition completed. Dropdown showed, acquired Popper's bottom-start placement, and hid. The `opened.bs.modal` control recorded nothing.

**Top layer — `top-layer`.** With dialog, dropdown, and tooltip opened in that order, the sampled order was tooltip, dropdown, toast, dialog. Reopening the dropdown moved it ahead of the tooltip despite its lower Bootstrap z-index. The sampled variables were modal 1055, dropdown 1000, tooltip 1080, toast 1090, and backdrop 1050. The document-layer z-index 1 control was excluded from modal hit testing. Hiding the popovers restored the toast to the leading position; retained Bootstrap display classes left the former popovers present in ordinary layout.

**Invoker commands — `invoker-commands`.** `show-modal` opened the dialog and `toggle-popover` opened the menu. Both dispatched cancelable command events carrying the command value, and preventing those events stopped the action. The `--custom` control dispatched its event without opening the dialog.

## Limits

Standalone Tab wrapping was not measured: the prescribed Vitest browser project embeds the test document, and real Tab input reached its parent interface. Dialog and inert results therefore establish exclusion within the test document, with the recorded frame-boundary limitation.

Pixel compositing was not measured. Stacking readings use the requested `elementsFromPoint` instrument and computed backdrop color. In particular, an outside popover reopened over a modal remained absent from hit testing because it was outside the modal's interactive subtree; that reading cannot settle whether its pixels paint over the modal. The descendant-popover ordering was measured.

Chromium refused command-line introspection with `Command line not returned because --enable-automation not set.` The retained launch configuration and measured 15 px scrollbar establish the scrollbar conditions independently.

MutationObserver timestamps identify delivery, not the instant of each synchronous write. Attribute order and intermediate values were reconstructed from old-value records, with pending mutations drained before lifecycle events. Node labels reflect their state at observer delivery. No probe remained unable to run after the recorded adaptations.
