### Popover

The `createPopover` factory takes an anchor element and a panel element, plus an optional arrow element (`src/browser/types.ts:1352`). The header says the panel is set to `popover="manual"`, top-layer visibility stays with the popover API, and placement stays with CSS anchor positioning (`src/browser/factories/createPopover.ts:22`). The catalog calls it the backbone for menu, tooltip, and select (`guides/composables.md:422`). The anchor-position surface covers `[popover]` except `aside`, `dialog`, `nav`, and `output` (`guides/surfaces.md:129`).

The `placement` option is a placement or false, and the factory defaults it to `bottom` (`src/browser/types.ts:1362`, `src/browser/factories/createPopover.ts:72`). The `strategy` option defaults to `absolute`, and the `offset` option defaults to the `DEFAULT_FLOATING_OFFSET` constant, which is 8 (`src/browser/factories/createPopover.ts:64`, `src/browser/constants.ts:42`). The `trigger` object carries `hover`, `focus`, and `click` (`src/browser/types.ts:1367`). The `delay` object carries `show` and `hide` (`src/browser/types.ts:1372`). The `dismiss` object carries `outside` and `escape` (`src/browser/types.ts:1376`). The `on` option is a partial popover event map (`src/browser/types.ts:1380`). Construction defaults `outside` and `escape` to true, and both delays to 0 (`src/browser/factories/createPopover.ts:67`). An omitted `trigger` object becomes `{ click: true }` (`src/browser/factories/createPopover.ts:66`).

The instance returns the `visible` ref, the `placement` ref, a `styles` computed, and the `show`, `hide`, `toggle`, `update`, and `destroy` methods (`src/browser/types.ts:1383`, `src/browser/factories/createPopover.ts:354`). The `styles` computed returns empty `panel` and `arrow` records (`src/browser/factories/createPopover.ts:94`).

The event names are `elements:popover:show`, `elements:popover:open`, `elements:popover:hide`, `elements:popover:close`, and `elements:popover:place` (`src/browser/constants.ts:482`). The factory dispatches and emits them on the anchor (`src/browser/factories/createPopover.ts:192`, `src/browser/factories/createPopover.ts:220`).

Setup assigns `panel.popover` the value `manual` (`src/browser/factories/createPopover.ts:261`). The `show` path calls `panel.showPopover({ source: anchor })` (`src/browser/factories/createPopover.ts:197`). The factory also writes an explicit pair: `anchor.style.anchorName` and `panel.style.positionAnchor` share one `--elements-anchor-…` name (`src/browser/factories/createPopover.ts:269`). The comment states why both exist: `showPopover({ source })` establishes the implicit anchor that `position-area` uses, and an `anchor()` read needs the explicit binding (`src/browser/factories/createPopover.ts:262`). The surface guide states the other invoker path: a `popovertarget` button gets that implicit anchor from the browser, and the surface declares `position-area` (`guides/surfaces.md:131`). The `destroy` method writes the saved `anchorName` and `positionAnchor` back (`src/browser/factories/createPopover.ts:338`).

When placement is on, `applyPlacement` writes `panel.style.positionArea` from `PLACEMENT_AREAS`, and `alignSelf` plus `justifySelf` from `PLACEMENT_SELFS` (`src/browser/factories/createPopover.ts:124`, `src/browser/constants.ts:662`, `src/browser/constants.ts:686`). The constants comment says the surface default `align-self: start` and `justify-self: anchor-center` fits the `bottom` placement, and every aligned placement needs the inline pair (`src/browser/constants.ts:677`). The same comment claims Chromium's `position-area` parser accepts physical `left` and `right` keywords, so logical `start` and `end` map to those physical words; the comment records no version (`src/browser/constants.ts:661`). The factory comment says the inline `position-area` overrides the surface token, and the browser's `position-try-fallbacks` on the surface rule flips an overflowing side (`src/browser/factories/createPopover.ts:120`). The surface guide lists that fallback as `flip-block`, `flip-inline`, then `flip-block flip-inline` (`guides/surfaces.md:135`).

`applyPlacement` first writes `data-popover-side` from the requested side (`src/browser/factories/createPopover.ts:135`). `scheduleResolvedSide` waits one animation frame, and `syncResolvedSide` then replaces `data-popover-side` with `resolvePopoverSide` (`src/browser/factories/createPopover.ts:140`, `src/browser/factories/createPopover.ts:146`). The helper comment says native popover plus `position-try-fallbacks` can flip the requested side, so chrome needs the resolved side (`src/browser/helpers.ts:2125`). Scroll with capture, and `resize`, call the same scheduler (`src/browser/factories/createPopover.ts:258`, `src/browser/factories/createPopover.ts:309`). The `update` method emits `place` when placement is on (`src/browser/factories/createPopover.ts:211`).

Hover listens for `mouseenter` and `mouseleave`. Focus listens for `focusin` and `focusout`. Click listens for `click` (`src/browser/factories/createPopover.ts:296`). Enter and leave call `show` and `hide`. Click calls `toggle` (`src/browser/factories/createPopover.ts:238`). A positive `delay.show` or `delay.hide` waits on a timeout before `doShow` or `doHide` (`src/browser/factories/createPopover.ts:223`).

A document `pointerdown` hides the popover when `dismiss.outside` is true, the target is outside the anchor and the panel, and `event.timeStamp - openedAt` is at least the `POPOVER_TOUCH_GUARD_MS` constant (`src/browser/factories/createPopover.ts:242`). That constant is 50 (`src/browser/constants.ts:59`). `openedAt` is `performance.now()`, or `Date.now()` when `performance` is absent, recorded in `doShow` (`src/browser/factories/createPopover.ts:195`). A document `keydown` of Escape calls `preventDefault` and `hide` when `dismiss.escape` is true (`src/browser/factories/createPopover.ts:251`).

When `aria-haspopup` was absent, the factory sets it to `dialog` (`src/browser/factories/createPopover.ts:288`). It sets `aria-controls` to the panel id, creating `elements-popover-…` when the panel has no id, and it sets `aria-expanded` to `false` (`src/browser/factories/createPopover.ts:287`). `doShow` sets `aria-expanded` to `true`. `doHide` sets it to `false` (`src/browser/factories/createPopover.ts:194`, `src/browser/factories/createPopover.ts:206`). The comment says `aria-haspopup` and `aria-controls` are written once, and `aria-expanded` tracks `visible` (`src/browser/factories/createPopover.ts:275`). The `destroy` method removes each of those three attributes when the saved value was null, and otherwise writes the saved value back; an empty saved panel id is removed (`src/browser/factories/createPopover.ts:340`).

### Tooltip

The `createTooltip` factory takes an anchor and a panel (`src/browser/types.ts:1567`). The header says hover and focus triggers are always on, the panel uses `popover="manual"`, and inline `position-area` plus the surface `position-try-fallbacks` place it (`src/browser/factories/createTooltip.ts:23`). The catalog names the panel as any element plus a `[popover=hint]` target, with hover and focus triggers and `role="tooltip"` wiring (`guides/composables.md:423`). The surfaces guide pairs `[popover='hint']` with `[role='tooltip']` as the tooltip shape (`guides/surfaces.md:97`). The component pairing names hover and focus triggers plus a `[popover=hint]` panel (`guides/components.md:225`).

The options are `placement`, `strategy`, `offset`, a `delay` object of `show` and `hide`, a `dismiss` object of `escape`, and `on` (`src/browser/types.ts:1573`). There is no `trigger` object. Construction defaults `strategy` to `absolute`, `offset` to `DEFAULT_FLOATING_OFFSET`, `escape` to true, and both delays to 0 (`src/browser/factories/createTooltip.ts:44`).

The instance returns the `visible` ref, the `placement` ref, and the `show`, `hide`, `toggle`, `update`, and `destroy` methods (`src/browser/types.ts:1582`). The event names match the popover set with source `tooltip`, including `place` (`src/browser/constants.ts:553`).

The factory always listens for `mouseenter`, `mouseleave`, `focusin`, and `focusout` on the anchor (`src/browser/factories/createTooltip.ts:240`). A `pointerdown` whose `pointerType` is `touch` or `pen` calls `toggle` (`src/browser/factories/createTooltip.ts:206`). The comment claims that on a coarse pointer `mouseenter` and `mouseleave` do not fire, or they fire beside a synthesized click that blurs the anchor, and that the touch path toggles without waiting for hover; the comment records no measurement (`src/browser/factories/createTooltip.ts:200`). A document `pointerdown` in the capture phase, again for `touch` or `pen`, calls `hide` when the target is outside the anchor and the panel (`src/browser/factories/createTooltip.ts:214`). The comment says that outside tap is what dismisses a touch-opened tooltip (`src/browser/factories/createTooltip.ts:211`). Setup sets `panel.popover` to `manual` and sets `role` to `tooltip` (`src/browser/factories/createTooltip.ts:230`, `src/browser/factories/createTooltip.ts:236`). Escape dismiss follows `dismiss.escape`, defaulting true (`src/browser/factories/createTooltip.ts:222`).

### Menu

The `createMenu` factory takes a toggle element and a `<menu>` panel, and it throws when the panel is not a `<menu>` (`src/browser/types.ts:1627`, `src/browser/factories/createMenu.ts:48`). It composes the `createPopover` factory for top-layer visibility (`src/browser/factories/createMenu.ts:26`, `src/browser/factories/createMenu.ts:83`). The catalog names arrow-key roving, Home, End, click-outside dismiss, and anchor positioning (`guides/composables.md:407`). The component pairing names a `<menu popover>` panel, arrow-key roving, and anchor positioning (`guides/components.md:224`).

The `placement` option defaults to `bottom-start` in the `createPopover` call (`src/browser/factories/createMenu.ts:86`). The `offset` option defaults to the `DEFAULT_MENU_OFFSET` constant, which is 2 (`src/browser/factories/createMenu.ts:54`, `src/browser/constants.ts:43`). The `flip` option defaults through the `DEFAULT_MENU_FLIP` constant, which is 5 (`src/browser/factories/createMenu.ts:55`, `src/browser/constants.ts:51`). The `dismiss` object carries `outside`, `escape`, and `inside`, each defaulting to true (`src/browser/types.ts:1639`, `src/browser/factories/createMenu.ts:50`). The composed popover receives `trigger: {}` and the outside and escape flags (`src/browser/factories/createMenu.ts:89`). The `on` option is a partial menu event map (`src/browser/types.ts:1644`).

The instance returns the popover `visible` ref and the `show`, `hide`, `toggle`, `update`, and `destroy` methods, each forwarded to that popover (`src/browser/types.ts:1647`, `src/browser/factories/createMenu.ts:196`).

The event names are `elements:menu:show`, `elements:menu:open`, `elements:menu:hide`, `elements:menu:close`, and `elements:menu:select` (`src/browser/constants.ts:445`). The composed popover's `show` and `hide` handlers re-dispatch those menu verbs and call `preventDefault` on the popover event when the menu event is cancelled; `open` and `close` are re-emitted (`src/browser/factories/createMenu.ts:92`).

Setup sets `aria-expanded` to `false` and `aria-haspopup` to `menu` on the toggle (`src/browser/factories/createMenu.ts:162`). The `show` handler sets `aria-expanded` to `true` after the menu `show` event is allowed. The `hide` handler sets it to `false` (`src/browser/factories/createMenu.ts:100`, `src/browser/factories/createMenu.ts:111`). The `destroy` method removes both attributes (`src/browser/factories/createMenu.ts:188`).

The toggle's click calls `preventDefault` and `popover.toggle` (`src/browser/factories/createMenu.ts:118`). A click inside the menu, on a target matching `MENU_ITEM_SELECTOR`, emits `select` with the item and a value, then calls `popover.hide` when `dismiss.inside` is true (`src/browser/factories/createMenu.ts:123`). The value is `data-value` when that attribute is set, otherwise the trimmed text (`src/browser/factories/createMenu.ts:132`). The selector is `:where(li, a, button)` excluding `[disabled]` and `[aria-disabled="true"]` (`src/browser/constants.ts:115`).

ArrowUp and ArrowDown, on the toggle or inside the menu, call `preventDefault`, call `show` when the menu is closed, and focus the item `rove` returns (`src/browser/factories/createMenu.ts:137`). Home and End do that focus only while the menu is visible (`src/browser/factories/createMenu.ts:153`). The `rove` function maps Home to the first index, End to the last index, and ArrowDown and ArrowUp to a wrapped step (`src/browser/helpers.ts:2266`). The candidates are `focusableItems` of the menu (`src/browser/factories/createMenu.ts:146`).

The flip threshold is written as inline style. The comment says the surface layer's `max-block-size` is `var(--set-anchor-max-block-size)`, stated there as 18 rem, and a component-layer override would lose (`src/browser/factories/createMenu.ts:57`). The surface guide states that same default as 18rem and says the browser uses the cap as demanded size for `position-try-fallbacks` (`guides/surfaces.md:137`). A threshold of 0 sets `max-block-size` to `none` and `position-try-fallbacks` to `flip-inline` (`src/browser/factories/createMenu.ts:75`). Any other threshold sets `--set-menu-flip` to that count and `max-block-size` to the count times the `ROW_HEIGHT_REM` constant, which is 2.25, in rem (`src/browser/factories/createMenu.ts:71`, `src/browser/factories/createMenu.ts:78`). The constants comment says `flip: 0` removes the cap and the `flip-block` fallback so surplus rows scroll inside the panel (`src/browser/constants.ts:44`).

### Select

The `createSelect` factory takes a toggle, a `<menu>` panel, an optional native `<select>` or `<input>`, and an optional combobox `<input>` (`src/browser/types.ts:1713`). It asserts the panel is a `<menu>`, and the header says the wrapped `createMenu` factory gates that tag as well (`src/browser/factories/createSelect.ts:47`, `src/browser/factories/createSelect.ts:57`). The header says the factory composes `createMenu` for popover visibility, dismiss, and position (`src/browser/factories/createSelect.ts:29`). The catalog says it wraps `createMenu` (`guides/composables.md:408`). The component pairing names a `<menu>` listbox (`guides/components.md:226`).

The options include `multiple`, `autocomplete`, `value`, `placement`, `strategy`, `offset`, `flip`, a `dismiss` object of `outside`, `escape`, and `inside`, and `on` (`src/browser/types.ts:1720`). The `flip` comment says 0 opts out and the default is 5 (`src/browser/types.ts:1731`). The `inside` comment says single-select defaults to true and multi-select defaults to false (`src/browser/types.ts:1737`).

The instance returns the `visible`, `value`, `values`, and `query` refs, and the `show`, `hide`, `toggle`, `select`, `clear`, `update`, and `destroy` methods (`src/browser/types.ts:1745`). The event names are `elements:select:show`, `elements:select:open`, `elements:select:hide`, `elements:select:close`, `elements:select:select`, `elements:select:clear`, and `elements:select:input` (`src/browser/constants.ts:493`).

The factory calls `createMenu` with the toggle and the menu (`src/browser/factories/createSelect.ts:180`). That call defaults `placement` to `bottom-start` and `flip` to the `DEFAULT_SELECT_FLIP` constant, which is 5 (`src/browser/factories/createSelect.ts:183`, `src/browser/constants.ts:58`). It passes `dismiss.inside` as false, so the menu factory's item-click hide stays off (`src/browser/factories/createSelect.ts:191`). Before that call, the factory gives the menu an id and sets `role` to `listbox` (`src/browser/factories/createSelect.ts:84`). After that call, it sets `aria-controls`, `aria-haspopup` to `listbox`, and `aria-expanded` to `false`; when an input exists it also sets `role` to `combobox` and `aria-autocomplete` to `list` (`src/browser/factories/createSelect.ts:227`). The comment says those listbox values overwrite the `aria-haspopup="menu"` value `createMenu` wrote (`src/browser/factories/createSelect.ts:91`). The `show`, `hide`, and `toggle` methods forward to the menu instance (`src/browser/factories/createSelect.ts:238`).

The header says a `native` `<select>` or `<input>` receives the current value so the selection joins form data and constraint validation (`src/browser/factories/createSelect.ts:43`, `src/browser/types.ts:1710`). `writeNative` returns when `native` is absent. For an `HTMLSelectElement` in multiple mode it sets each option's `selected` from the value set. Otherwise it assigns `native.value` from the scalar, using an empty string when the scalar is null. It then dispatches a bubbling `change` event (`src/browser/factories/createSelect.ts:135`). `sync` calls `writeNative`, and so does construction (`src/browser/factories/createSelect.ts:150`, `src/browser/factories/createSelect.ts:439`). The autocomplete input path calls `writeNative` as well (`src/browser/factories/createSelect.ts:382`). The catalog states the same mirror: the native control is written on every commit and a `change` event is dispatched (`guides/composables.md:408`).
