# Browser engine design: analyst proposal

Build a DOM-owned engine that preserves Bootstrap's elements, classes, data attributes, and lifecycle events. Use native anchor positioning, CSS transitions, and observers where the measurements support them. Retain ordinary document stacking, explicit dismissal, focus containment, and backdrop nodes where native top-layer behavior changes Bootstrap's contract. This is a design proposal, not a claim that an implementation passes the oracle. [D-shared] [F-layers] [M-veto] [R]

## Contract

Write `src/browser/types.ts` before implementations. Keep plain readonly getters and imperative methods; import no Vue runtime. The `elements` factories inform the factory/host/state/method pattern, but their tag requirements, reactive refs, attributes, and event names do not define this engine. In particular, `createMenu` requires a `menu` element, `createDialog` requires a `dialog`, and `createTabs` uses `hidden`; those choices cannot replace Bootstrap's markup and state selectors unchanged. [L] [E-pattern] [E-menu] [E-dialog] [E-tabs] [D-tab]

The proposed entity surface follows this table. Every entity has `readonly element: HTMLElement`, `readonly destroyed: boolean`, and `destroy(): void`. `visible` means the accepted open state, not a claim about occlusion or pixels. `phase` distinguishes `hidden | showing | shown | hiding`; derive `visible` from the plugin's authoritative state, never maintain a second independently writable flag. Use a phase only where the plugin has an asynchronous transition. All collections are readonly. Visibility verbs are domain operations; resource lifecycle uses `destroy`, and carousel scheduling uses `start`, `pause`, and `resume`. [L] [N] [D-shared]

Use `void` returns for these operations. Preserve synchronous event gates and plugin-specific no-op guards; completion is observable through the host events. A prevented operation changes no owned state. `destroy()` is idempotent, releases ownership, and makes later mutating calls no-ops; getters remain readable. Do not impose a universal transition queue on plugins whose Bootstrap guards differ. [D-shared] [D-offcanvas] [D-carousel]

Expose `createVeneer(root?: Document | HTMLElement)` as the explicit data-API boot entry, returning `VeneerInterface` with readonly `root`, readonly `destroyed`, and `destroy()`. It installs delegated behavior and schedules Bootstrap's load initialization, or initializes immediately after document load. Also expose `createAlert`, `createButton`, `createToast`, `createCollapse`, `createTab`, `createModal`, `createOffcanvas`, `createDropdown`, `createTooltip`, `createPopover`, `createCarousel`, and `createScrollspy`, each taking the Bootstrap host and its typed options. Factories perform registry lookup, config translation, ownership, and hook binding; they are not constructor aliases. Importing the barrel installs nothing. The product-qualified boot name avoids `createBrowser` and `BrowserInterface`, which the published browser package already owns. [D-shared] [D-cross] [A] [Fleet-browser]

Use a document-owned registry, keyed by host and plugin, for factory/data-API identity. Repeated boot of the same root must not double-handle a click. Nested roots choose one responsible scope per event. A scope destroys only instances it owns; an explicitly created instance survives another scope's disposal. Preserve author element identity and existing listeners. Do not reproduce Bootstrap's single-plugin-per-element registry restriction: the registry is part of the excluded JavaScript API, and an element can legitimately be a button toggle and a tooltip trigger. Prove this choice as an API difference. [D-shared] [B:48]

Define named discriminants such as `BrowserPlugin`, `VisibilityPhase`, `FloatingSide`, `FloatingPlacement`, and `CarouselRide`; never add a generic `type` or `kind` member. `FloatingPlacement` retains physical sides and start/end alignment as external values. Preserve raw external compound keys only in explicitly documented Bootstrap input records and legacy event properties. [N] [L]

Keep Bootstrap event strings as the sole wire names for Bootstrap lifecycle events. Emit a typed bubbling `CustomEvent`, add typed `detail`, and retain the legacy event properties on that same object. `detail` uses single-word fields: `related`, `click`, `direction`, `from`, and `to`, as applicable. Legacy properties remain `relatedTarget`, `clickEvent`, `direction`, `from`, and `to`. Match Bootstrap's null/undefined values at that external boundary. Do not create a second event solely to offer a Veneer spelling. The probe preserved bubbling, cancellation, and `relatedTarget` delivery with one event; emitting both names required another dispatch. It measured dispatch/listener counts, not latency or allocation size. [M-events] [P] [D-shared]

Bind hooks through one shared `bindEventMap` to these wire events. Hook `show` maps to `show.bs.<plugin>`, `open` to `shown`, `hide` to `hide`, `close` to `hidden`, `insert` to `inserted`, and `prevent` to `hidePrevented`. Alert uses `close` and `remove` for `close.bs.alert` and `closed.bs.alert`; Carousel uses `slide` and `change` for `slide.bs.carousel` and `slid.bs.carousel`; Scrollspy uses `activate`. Preserve `cancelable:true` even on Bootstrap completion events whose prevention has no effect. Only the source-defined before-event gates stop work. Bootstrap Button emits no event; add the explicitly documented `toggle.vn.button` notification, with hook `toggle` and `detail.active`, after its synchronous write so a Vue adapter can observe data-API activation. ## Shared mechanics

**Data API.** Delegate the selectors and capture/bubble phases recorded in the distillate. Resolve `data-bs-target`, then eligible `href` fragments, with escaped IDs and multi-target collapse support. Dismissal resolves an explicit target before the closest component. Keep each plugin's disabled, form-control, right-click, and navigation rules. Initialize ride carousels, scroll spies, shown offcanvas elements, and active tab toggles at load. Tooltips and popovers remain explicit factory opt-ins because Bootstrap supplies no automatic initialization for them. Native invoker commands do not replace this routing: they require different attributes and do not carry the plugin-specific gates. [D-shared] [D-cross] [F-commands]

Use `CLASS_NAMES.bootstrap` for sheet-declared class names, and pin the engine's writes against `tests/fixtures/bootstrap/engine.json` as well as the CSS inventory. Keep engine-only spellings such as `modal-open` in browser constants rather than fabricating a core registry entry for a name absent from the sheet. The registry is a class-name contract, not a source of behavioral defaults. [Registry] [Engine-census] [Registry-law]

**Config.** Parse the external shape before projecting grouped options. For ordinary plugins, preserve defaults → `data-bs-config` → individual attributes → explicit options. Merge precedence applies to supplied leaves; an omitted grouped leaf cannot overwrite an attribute default. Tooltip and Popover deliberately ignore `data-bs-config` and strip `sanitize`, `allowList`, and `sanitizeFn` from attributes, matching their actual source. Preserve Bootstrap's string/number/null normalization and per-plugin post-merge transformations. A blanket `JSON.parse` or generic numeric coercer does not reproduce that behavior. [D-shared] [D-tooltip] [T-config]

Reuse the installed contract guards, `parseJSON`, and `attempt`. `parseNumber` accepts nonblank numeric strings more broadly than Bootstrap's round-trip equality check, so a Bootstrap-specific coercer earns its existence; reuse primitives within that translation rather than renaming a generic parser. `@orkestrel/contract` is declared under devDependencies, so the implementation unit must move it to runtime dependencies before shipping imports from it. No package installation is needed for this proposal. [C-json] [C-number] [C-attempt] [Package]

**Transitions.** Preserve the target element, animation flag, class-write order, and synchronous/asynchronous boundary per plugin. Keep Bootstrap's first duration/delay pair plus its 5 ms fallback for compatibility, including its fallback `transitionend` dispatch unless an explicit departure is accepted. Observe `transitioncancel` and abort owned waits during disposal so stale completion cannot mutate a later operation. Use `getAnimations()` as a proof instrument and to diagnose actual interpolation; do not replace the lifecycle wait with an unfiltered wait on every animation, which could include an unrelated infinite animation. [D-shared] [F-oracle]

Retain the reflow-based Bootstrap fade path in this chunk. The measured `@starting-style` alternative animates, but requires additional CSS and does not establish all plugin sequencing. Likewise, `allow-discrete` alone is not a completion signal. The reduced-motion path must complete without waiting for an event that never arrives. Use intrinsic height interpolation only in the proven intrinsic vertical-collapse case, with a numeric sizing path for incompatible sizing constraints; horizontal collapse retains measured width. Both paths retain Bootstrap's class phases. [F-fade] [F-collapse] [M-width]

**Focus and modality.** Keep focus containment through native keyboard/focus events and DOM focusability checks. Preserve the source's trap activation condition and initial focus target. Do not replace an ordinary `.modal` element with a dialog or put its children into a wrapper: selectors, parent relationships, event paths, and element identity are part of the drop-in surface. Borrowing `showModal()` on a div throws; a real modal dialog prevents outside focus even when the desired Bootstrap option is `focus:false`. A generic `showModal()` backend therefore fails this contract. [M-dialog] [D-modal] [D-offcanvas]

Do not apply `inert` globally as a replacement for the trap. The recorded iframe experiment excluded outside controls but failed to reproduce focus wrapping, and adding inertness would change Bootstrap's accessibility and interaction behavior. Keep `inert` as a measured, rejected default, not an unproved extra. No standalone Tab-wrapping claim follows from the iframe probe. [F-focus]

**Backdrop and scroll lock.** Retain appended `.modal-backdrop` and `.offcanvas-backdrop` elements, including their distinct parents, classes, mouse actions, and transition sequencing. `::backdrop` needs a top-layer host and different styling; it does not select Bootstrap's existing class rules. Keep measured scrollbar compensation, saved inline values, fixed/sticky adjustments, and modal overflow padding. `scrollbar-gutter:stable` preserved content widths in its fixture but changed border-box geometry relative to Bootstrap's padding approach, so it is not an equivalent default. Share ownership of body writes and restore only after their final owner releases them; record overlapping-owner behavior separately from Bootstrap's single-overlay assumptions. [D-shared] [D-modal] [D-offcanvas] [F-dialog] [F-scroll]

**Placement.** Keep floating elements in Bootstrap's document/container hierarchy. For dynamic placement, use unique, restored `anchor-name`/`position-anchor` bindings and native `position-area`; select positioning coordinates from the actual containing block. The measured ordinary fixed-position case tracks and flips. It does not authorize converting every Popper absolute-positioned element to fixed positioning. Static/navbar dropdowns retain their stylesheet positioning and `data-bs-popper="static"`. [M-anchor] [F-dropdown] [D-dropdown]

Compile the requested fallback order into `position-try-fallbacks`, using a document-owned constructed stylesheet for scoped named `@position-try` rules where keyword flips cannot express that order. Preserve offsets and responsive `--bs-position` resolution. After layout, Chromium's computed `position-area` reports the applied side in the measured flip, and `@container anchored(fallback: flip-block)` reports it to descendants. Read the resolved side and write `data-popper-placement` before exposing placement-dependent state; do not retain the requested side after a flip. The CSS query is also a possible arrow-rendering aid, but its production declarations still need the floating unit's proof. [M-anchor] [F-arrows] [D-dropdown] [D-tooltip]

Write arrow positioning inline, as Popper did: absolute position, the appropriate cross-axis coordinate, and the resolved side attribute. Centering suffices only for the centered fixtures; clipped/shifted tips require an anchor-relative, edge-clamped arrow coordinate. Preserve the Bootstrap arrow tokens and pseudo-element borders. Add no theme or component chrome to the engine. Name every constructed rule and inline correction in the guide; release generated rules and restore prior styles on disposal. The existing guide's “ships no sheet” wording must be revised if constructed positioning rules ship, under the brief's explicit stylesheet ruling. [F-arrows] [D-tooltip] [D-popover] [G-browser] [B:50]

Viewport fallback is not clipping-boundary or tether parity. The placement unit must independently implement the finite geometry corrections that the browser does not supply, using native DOM measurements and a bounded candidate pass, while retaining native anchoring for attachment where compatible. Wake placement on opening, explicit update, captured ancestor scroll, viewport changes, and resize observation of relevant boxes. Coalesce work into a requested frame; run no idle frame loop. Bootstrap/Popper also has behavior beyond `position-try`: boundary, root boundary, alternate boundary, padding, axis choices, variation flips, and tethering are real inputs. [Popper-flip] [Popper-overflow] [L]

Treat declarative `data-bs-popper-config` as markup input, not as permission to discard it because the JavaScript API is excluded. Translate serializable built-in placement/modifier options and prove them against the oracle. The implementation must either cover those options or report a blocking incompatibility; it cannot silently ignore them or admit them through an unreviewed departure. Arbitrary JavaScript modifier callbacks belong to the excluded Popper/Bootstrap API, and no public Veneer option exposes that executable protocol. [D-dropdown] [D-tooltip] [B:48]

**Disposal.** Own listeners with abort signals, disconnect observers, clear actual timer handles, abort transition completions, remove generated nodes/rules, and release scroll/registry ownership. Restore author attributes and styles only where the engine owns the write; preserve application edits made afterward. A removed alert remains removed. A destroy operation is resource teardown rather than a cancellable hide request, so an event veto cannot retain a body lock or timer. Prove destroy during entry, exit, delayed hover, autoplay, and observer delivery. [L] [D-shared] [D-toast] [D-carousel] [D-spy]

## Proof model

Run Bootstrap's installed engine as a test-only oracle on identical markup and CSS. Run each engine in a separate document/context, or fully isolated sequential browser fixture, so Bootstrap's document listeners and registry cannot drive the Veneer half. Use the same user actions and comparable factory initialization; do not claim constructor/API parity. The recorded Modal/Dropdown transcript proves these imports run in the Chromium recipe, not that all plugins have already been compared. [F-oracle] [V]

Capture baseline, before-event, synchronous return, transition, completion, and disposal checkpoints. Compare class sets; attribute presence and values; owned inline style properties; created/removed nodes and parentage; focus; event host, order, bubbling, cancelability, default prevention, legacy payload, and completion guards. Normalize generated IDs by their referenced relationships, not by deleting IDs from the comparison. Drain pending mutation records at event checkpoints; MutationObserver delivery timestamps are not synchronous-write timestamps. [D-shared] [F-oracle]

Compare rendered boxes, resolved visibility, arrows, and hit-test order as well as DOM state. Exclude Popper's exact transform/matrix serialization and engine bookkeeping from equality, but never use that exclusion to hide a placement or clipping error. Exclude exact wall-clock timestamps; retain synchronous versus deferred behavior, the correct waited element, ordering, and completion bounds derived from the actual sheet. Distinguish trusted transition events from synthetic fallback events. A lifecycle completion alone is not proof of a rendered animation. [F-arrows] [F-fade] [F-oracle] [F-layers]

Create `guides/veneer.md` → Browser entry → Engine departures as the authoritative departure table. Each row identifies a scenario, observable path/property, exact upstream value/behavior, exact Veneer value/behavior, rationale, and proof. The comparator reads it in both directions: every observed difference needs its exact row, and every row needs a reproduced difference and passing proof. A planted row, deleted row, wrong expected value, and an extra undeclared mutation must fail. No broad “ignore styles/events/native differences” exemption is admissible. This follows the sheet's existing bidirectional departure model. [R] [Guide-departure]

Proposed departures are limited to typed `CustomEvent.detail` while preserving legacy properties; the Button notification; temporary intrinsic vertical-height/anchor/arrow writes replacing measured engine writes; and explicitly specified teardown/overlapping-ownership improvements. Data-API events and Bootstrap markup behavior remain mandatory. Admit a row only after its oracle mismatch and replacement invariant are demonstrated. A row that violates the fixed markup ruling is a blocker, not a documentary escape. [M-events] [F-collapse] [F-arrows] [B:48]

Centralize browser builders, event recorders, action scripts, and snapshot readers in `tests/setupBrowser.ts`, with setup proofs; use `@orkestrel/test` waits/recorders and `@orkestrel/test/browser` builders, frame waits, and journeys. Keep style readers in `tests/setupStyles.ts`. The browser project already collects `tests/src/browser/**/*.test.ts`; render acceptance additionally needs real keyboard/pointer journeys. Every instrument gets a negative control outside its positive population. [Test-surface] [Test-browser] [V] [Q]

## Risks

- **Native placement is only partly measured.** The fresh probe establishes an ordinary fixed box, a block-axis flip, computed resolved side, and an anchored query. It does not prove transformed containing blocks, clipping-parent equivalence, alternate boundaries, all writing modes, or tethering. The Placement unit closes those obligations before floating plugins can be accepted. [M-anchor] [Popper-flip] [Popper-overflow]
- **Intrinsic width is disproved for general collapse.** In the measured fixture, auto width is 300 px and Bootstrap's scroll-width target is 120 px. Keep measured horizontal sizing. Vertical intrinsic sizing remains gated by constraint-specific oracle proofs. This contradicts a universal no-measurement collapse strategy, not the user's conditional preference for native mechanisms. [M-width] [F-collapse]
- **Top-layer promotion changes observable behavior.** Do not treat it as a styling-only difference: measured popover insertion order outranks Bootstrap z-index, automatic closing is not vetoable, and a native dialog imposes focus exclusion. The default design refuses those substitutions. The retained dialog neutralization recipe belongs to future explicit native-host work, not an unrequested second backend. [F-layers] [M-veto] [M-dialog] [F-dialog]
- **Elements is guidance, not an oracle.** Its factory contracts differ from Bootstrap, and its documentation includes platform claims the feasibility record does not establish. Reuse vocabulary and composition ideas only. No `elements:` event or `@vue/reactivity` import enters this face. [E-pattern] [E-dialog] [E-menu] [E-tabs] [B:48]
- **External config is broader than the obvious defaults.** Preserve the tooltip config exception and sanitized attribute boundary. Arbitrary executable Popper extensions are excluded JavaScript API; serializable built-in options in markup are not. Silently dropping either distinction would misstate compatibility. [T-config] [D-dropdown] [D-tooltip]
- **The browser baseline is measured, not inferred from syntax alone.** The retained run uses Chromium 153.0.8010.12. Anchored fallback queries are specified in CSS Anchor Positioning Level 2; this proposal's support claim comes from rendered readings with a disabled-fallback control. Pin that tested baseline or establish a lower one through equivalent probes before advertising it. [M-anchor] [CSS-anchor]
- **Lifecycle cleanup improves on upstream resource ownership.** Restoring shared body styles and aborting stale work must not erase newer application writes or introduce completion events after destroy. These are deliberate API/resource differences with dedicated oracle and ownership tests, not permission to change ordinary show/hide behavior. [D-shared] [Q]
- **Scope of these measurements is bounded.** They run in Vitest's Chromium iframe. They establish no standalone focus wrapping, pixel compositing, assistive-technology announcement sequence, wall-clock performance advantage, or finished-engine compatibility. The probe's initial failed outside click was repaired by moving the fixture control out from under the menu, without a forced click. [F-limits] [M-validation]
