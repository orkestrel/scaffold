### Dialog

The `createDialog` factory binds a `<dialog>` host and throws when the tag differs (`src/browser/factories/createDialog.ts:36`). The header comment assigns top-layer rendering, initial focus, the modal Tab trap, and the `::backdrop` pseudo to the browser, and assigns the cancellable lifecycle events, the dismiss policy, the optional non-modal scroll lock, and the post-transition notifications to the factory (`src/browser/factories/createDialog.ts:20`, `src/browser/factories/createDialog.ts:25`). The component pairing names native `showModal` and `close` with cancellable show and hide events (`guides/components.md:221`). The open-state selectors in the pattern table are `dialog:modal` and `dialog.scrollable[open]`: `:modal` covers the centered modal, `[open]` covers the non-modal dialog, and a `.scrollable` size modifier gates `display` on `[open]` (`guides/composables.md:243`). The surface-family table places `showModal` in the top-layer modal family and `show` with `[open]` in the in-flow family (`guides/components.md:156`, `guides/components.md:157`, `guides/components.md:163`). The backdrop surface paints `dialog:modal::backdrop` (`guides/surfaces.md:166`).

The `modal` option defaults to true and selects `dialog.show()` when false (`src/browser/types.ts:1442`, `src/browser/factories/createDialog.ts:40`). The `dismiss` object carries `backdrop` (`true`, `false`, or `'static'`) and `escape` (`src/browser/types.ts:1444`). The `scroll` object carries `lock` (`src/browser/types.ts:1449`). The `on` option is a partial dialog event map (`src/browser/types.ts:1453`). Construction defaults `backdrop` to true, `escape` to true, and `scroll.lock` to false (`src/browser/factories/createDialog.ts:37`).

The instance returns the `visible` ref and the `show`, `hide`, `toggle`, and `destroy` methods (`src/browser/types.ts:1456`, `src/browser/factories/createDialog.ts:187`). The `visible` ref starts from `element.open` (`src/browser/factories/createDialog.ts:43`). The `toggle` method calls `hide` when `visible` is true and `show` otherwise (`src/browser/factories/createDialog.ts:102`).

The event names are `elements:dialog:show`, `elements:dialog:open`, `elements:dialog:hide`, `elements:dialog:close`, and `elements:dialog:prevent` (`src/browser/constants.ts:466`). The catalog lists the same five verbs (`guides/composables.md:404`). The `prevent` hook fires when a dismiss attempt is blocked by `dismiss.backdrop: 'static'` (`src/browser/types.ts:1438`).

The `show` method returns when `visible` is already true, and it returns when the `show` event is cancelled (`src/browser/factories/createDialog.ts:56`). A modal host then calls `showModal`; a non-modal host calls `show` (`src/browser/factories/createDialog.ts:62`). The `hide` method returns when `visible` is false, and it returns when the `hide` event is cancelled, then calls `close` (`src/browser/factories/createDialog.ts:79`, `src/browser/factories/createDialog.ts:87`). After `show`, `runTransition` emits `open`. After `hide`, `runTransition` emits `close` (`src/browser/factories/createDialog.ts:73`, `src/browser/factories/createDialog.ts:96`).

The factory listens for `cancel`, `close`, and `click` (`src/browser/factories/createDialog.ts:160`). The `cancel` comment states that `cancel` fires on Escape for a modal dialog and on a form `method="dialog"` cancellation (`src/browser/factories/createDialog.ts:106`). When `escape` is false the handler calls `preventDefault`, and on that same path it emits `prevent` when `backdrop` is `'static'` (`src/browser/factories/createDialog.ts:111`). The `close` handler returns while `suppressNativeClose` is true, and it returns when `visible` is already false; otherwise it sets `visible` false, unlocks a held scroll lock, and emits `close` in that turn (`src/browser/factories/createDialog.ts:117`, `src/browser/factories/createDialog.ts:120`). The `hide` method sets `suppressNativeClose` around its own `close` call so that native `close` listener does not emit a second `close` (`src/browser/factories/createDialog.ts:84`). The `destroy` method sets the same flag around `close` when the dialog is open (`src/browser/factories/createDialog.ts:179`).

A click is a backdrop hit when `event.target` is the dialog; an inner click has a deeper target (`src/browser/factories/createDialog.ts:131`). The handler returns unless the dialog is visible, the target is the dialog, and the event is a `MouseEvent` (`src/browser/factories/createDialog.ts:145`). It then compares `clientX` and `clientY` with `getBoundingClientRect` and returns when the point lies inside the rect, edges included (`src/browser/factories/createDialog.ts:148`). The comment claims a phone padding band of ~1rem still has `event.target === dialog` and would dismiss as a backdrop hit; the comment records no measurement (`src/browser/factories/createDialog.ts:136`). Outside the rect, `backdrop` true calls `hide`, and `backdrop` `'static'` emits `prevent` (`src/browser/factories/createDialog.ts:155`, `src/browser/types.ts:1445`). The false value matches neither branch (`src/browser/factories/createDialog.ts:133`).

The `show` comment states that `showModal` locks document scroll, and that the factory locks manually for a non-modal dialog that opts in through `scroll.lock` (`src/browser/factories/createDialog.ts:60`). That opt-in calls `lockBodyScroll` and sets `locked` (`src/browser/factories/createDialog.ts:66`). The `hide` method, the native `close` handler, and the `destroy` method each call `unlockBodyScroll` when `locked` is true (`src/browser/factories/createDialog.ts:90`, `src/browser/factories/createDialog.ts:124`, `src/browser/factories/createDialog.ts:175`). The type comment states the same native lock for a modal dialog (`src/browser/types.ts:1450`).

### Aside

The `createAside` factory binds an `<aside>` host and throws when the tag differs (`src/browser/factories/createAside.ts:59`). It is a programmatic shim over the Popover API (`src/browser/factories/createAside.ts:7`, `guides/composables.md:405`). The header assigns the platform top-layer rendering, light-dismiss for `popover="auto"`, the `::backdrop` pseudo, the slide through `:popover-open` plus `@starting-style` plus `transition-behavior: allow-discrete`, and the `beforetoggle` and `toggle` events (`src/browser/factories/createAside.ts:10`). The pattern table names the open selector `aside[popover]:popover-open` and says the slide and the scrim are platform-driven (`guides/composables.md:241`). The backdrop surface paints `:is(aside, nav)[popover]:popover-open::backdrop` (`guides/surfaces.md:167`). The surface-family table places `<aside popover>` in the top-layer modal family, with `popover="auto"` as platform light-dismiss (`guides/components.md:157`).

The `popover` option is `'auto'`, `'manual'`, or false (`src/browser/types.ts:1534`). The type comment states that `'auto'` opts into native light-dismiss, `'manual'` closes through programmatic `hide` or an inner `popovertargetaction="hide"` button, and false leaves the author's attribute (`src/browser/types.ts:1527`). Construction stores `element.popover` and, when the option is not false, sets `element.popover` to the option or to `'auto'` (`src/browser/factories/createAside.ts:65`). The `on` option is a partial aside event map (`src/browser/types.ts:1535`).

The instance returns the `visible` ref and the `show`, `hide`, `toggle`, and `destroy` methods (`src/browser/types.ts:1538`, `src/browser/factories/createAside.ts:144`). The `visible` ref is seeded false and then set from `element.matches(':popover-open')` (`src/browser/factories/createAside.ts:62`, `src/browser/factories/createAside.ts:70`).

The event names are `elements:aside:show`, `elements:aside:open`, `elements:aside:hide`, and `elements:aside:close` (`src/browser/constants.ts:475`). The catalog lists those four verbs (`guides/composables.md:405`).

The factory listens for `beforetoggle` and `toggle` (`src/browser/factories/createAside.ts:104`). A `beforetoggle` event that carries `newState` sets `visible` from that state and emits `show` or `hide` (`src/browser/factories/createAside.ts:81`). The header states those two verbs are informational because the native event is not cancellable (`src/browser/factories/createAside.ts:25`). A `toggle` event that carries `newState` sets `visible` and emits `open` or `close` (`src/browser/factories/createAside.ts:92`). Two counters, `suppressBeforeToggle` and `suppressToggle`, start at 0 (`src/browser/factories/createAside.ts:78`). The `show` method and the `hide` method increment both counters, call `showPopover` or `hidePopover`, set `visible`, and emit the matching pair in that turn (`src/browser/factories/createAside.ts:109`, `src/browser/factories/createAside.ts:118`). A suppressed native event decrements its counter and returns (`src/browser/factories/createAside.ts:83`). The comment states that an external change, Escape, an outside click, or an inner `popovertargetaction` button leaves the counters at 0 so the bridge emits (`src/browser/factories/createAside.ts:73`). The header comment maps programmatic `toggle` onto `togglePopover` (`src/browser/factories/createAside.ts:30`). The `toggle` method calls `hide` when the popover is open and `show` otherwise (`src/browser/factories/createAside.ts:127`). The catalog also names `togglePopover` (`guides/composables.md:405`). The `destroy` method hides an open popover and writes the saved `popover` value back (`src/browser/factories/createAside.ts:139`).

The header records the strip (`src/browser/factories/createAside.ts:35`). It removes `[data-aside-open]` and `[data-aside-closing]` writes because the CSS does not key on them and the slide is `:popover-open` plus `@starting-style` plus `allow-discrete` (`src/browser/factories/createAside.ts:37`). It removes the `runTransition` wait before `hidePopover` and claims that wait was ~400 ms of dead time, because `hidePopover` is what starts the transition (`src/browser/factories/createAside.ts:40`). It removes `aria-modal`, `role="dialog"`, and `inert` auto-wiring, and says the static chrome handles accessibility (`src/browser/factories/createAside.ts:43`). The gotcha sentence still says the `createAside` factory uses `inert` (`guides/composables.md:252`). It removes body scroll lock because the popover is already top-layer, and says a caller who wants the lock composes `lockBodyScroll` or uses `<dialog>` (`src/browser/factories/createAside.ts:46`). It removes custom Escape and backdrop-click dismiss: `popover="auto"` is the light-dismiss contract and `popover="manual"` is the sticky-panel contract (`src/browser/factories/createAside.ts:49`). The redundancy section claims the attribute writes had no matching rule in `components/_aside.scss` or `composables/_aside.scss`, and claims the strip dropped close latency from ~400 ms to ~73 ms (`guides/composables.md:389`). Those timings are the comment's claim and the guide's claim. The component pairing describes the drawer as popover top-layer plus slide-in through dual-attribute gating (`guides/components.md:222`).

### Focus

The `createFocus` factory accepts any `HTMLElement` and confines Tab to focusable descendants while active (`src/browser/factories/createFocus.ts:7`, `src/browser/factories/createFocus.ts:31`). The catalog calls it a tab trap for a drawer-like surface that has no native focus management (`guides/composables.md:429`). The component pairing names the same `activate` and `deactivate` primitive (`guides/components.md:236`). The header remark says the dialog factory and the aside factory keep their own ARIA and scroll-lock concerns (`src/browser/factories/createFocus.ts:28`). The dialog header assigns the modal Tab trap to the browser (`src/browser/factories/createDialog.ts:20`).

The `initial` option is an element or a function of the host, and the comment says it defaults to the first focusable descendant (`src/browser/types.ts:1977`). The `restore` option defaults to true (`src/browser/types.ts:1980`, `src/browser/factories/createFocus.ts:35`). The options interface carries no `on` map (`src/browser/types.ts:1976`).

The instance returns the `active` ref and the `activate`, `deactivate`, and `destroy` methods (`src/browser/types.ts:1985`, `src/browser/factories/createFocus.ts:97`). The `active` ref starts false (`src/browser/factories/createFocus.ts:39`).

The event names are `elements:focus:activate` and `elements:focus:deactivate` (`src/browser/constants.ts:439`). The constants comment says `activate` fires when the trap engages and `deactivate` fires when it releases (`src/browser/constants.ts:434`).

The candidate list is `FOCUSABLE_SELECTOR`: `[autofocus]`, an `input`, `button`, `select`, or `textarea` that is not `[disabled]`, an `a[href]`, and a `[tabindex]` other than `-1` (`src/browser/constants.ts:154`). The factory queries that selector inside the host and drops any element that has a `disabled` attribute (`src/browser/factories/createFocus.ts:44`). A `keydown` listener on `document` runs only while `active` is true and `event.key` is `Tab` (`src/browser/factories/createFocus.ts:49`, `src/browser/factories/createFocus.ts:66`). Shift+Tab on the first item calls `preventDefault` and focuses the last item; Tab on the last item calls `preventDefault` and focuses the first item (`src/browser/factories/createFocus.ts:57`). The header says other keys pass through (`src/browser/factories/createFocus.ts:19`). The `activate` method returns when the trap is already active, stores `document.activeElement`, focuses `initial` when it is an element, or the function's result, or the first candidate, and emits `activate` (`src/browser/factories/createFocus.ts:68`). The header comment states that `activate` is a no-op when the host has no focusable descendant (`src/browser/factories/createFocus.ts:24`). The `deactivate` method returns when the trap is inactive, sets `active` false, focuses the stored element when `restore` is true and that element is an `HTMLElement`, clears the stored element, and emits `deactivate` (`src/browser/factories/createFocus.ts:79`). The `destroy` method removes the document listener once and then calls `deactivate` (`src/browser/factories/createFocus.ts:88`).
