# Instrument readings

Each row records a browser-side capability the plan depends on, the instrument that measured it,
the browser and date, and the reading. A reading here settles what an instrument can see; it
accepts no Veneer behavior.

| Does `CSSStyleDeclaration` enumerate custom properties declared in a `:root` rule read through `document.styleSheets`, inside a `@layer` block, and under a scoped selector? | [`instruments/cssom-probe.mjs`](instruments/cssom-probe.mjs) | Playwright `chromium-1234` (Chromium `151.0.7922.34`) and Edge `153.0.4234.48`, 2026-09-20 | Yes on both. `Array.from(rule.style)` lists `--vn-a` on the bare `:root` rule, `--vn-b` on the `:root` rule inside `@layer base` (reached through `CSSLayerBlockRule.cssRules`), and `--vn-c` on `[data-bs-theme="dark"]`. The control rule `.control { color: blue }` lists no custom property. |

| Does `userEvent.hover` from `vitest/browser` match `:hover` on a resolved control and change a used property? | [`units/u5-probe.test.ts`](../units/u5-probe.test.ts), run through [`units/u5-probe.sh`](../units/u5-probe.sh) in Veneer's `src:browser` project | Vitest Playwright provider, `HeadlessChrome/153.0.8010.12` (managed Chromium) and `Edg/153.0.0.0`, 2026-09-20 | Yes on both. `.u5-hover:hover { padding: 32px }` reads `16px` before, `32px` during `userEvent.hover`, `16px` after `userEvent.unhover`. |
| Does a pointer hold reachable through `cdp()` produce `:active`, and does the release clear it? | same | same | Yes on both, through `Input.dispatchMouseEvent` (`mouseMoved`, `mousePressed`, `mouseReleased`, `button: 'left'`), once the tester iframe's scale is applied: the orchestrator page paints the 414 × 896 tester iframe at 157 × 340 on Chromium (scale 0.379) and 152 × 328 on Edge (scale 0.366), so the target point is `frame.left + local.x * scale`, `frame.top + local.y * scale`. The press fires `pointerdown`, `mousedown`, focuses the button, reads `32px` while held and `16px` after release; the unscaled and iframe-local coordinates miss the element. |
| Do `getComputedStyle(element, '::after')`, `'::backdrop'`, and `'::details-content'` return used values inside the tester document? | same | same | Yes on both: `::after` `padding-top` reads `7px`, an open modal `<dialog>`'s `::backdrop` `background-color` reads `rgb(1, 2, 3)`, and an open `<details>`'s `::details-content` `padding-top` reads `9px`. |
| Does `cdp()` `Emulation.setEmulatedMedia` switch `prefers-reduced-motion` and `print` for the tester document, and does the switch restore? | same | same | Yes on both: `1px` at base, `2px` under `features: [{ name: 'prefers-reduced-motion', value: 'reduce' }]` with `matchMedia` agreeing, `3px` under `media: 'print'`, `1px` after `{ media: '', features: [] }`. |
| Which token and theme syntax capabilities do the tester engines expose? | same | same | All true on both: `CSS.registerProperty`, and an `@property` rule's `initial-value` reaches a consumer (`5px`); `light-dark()`, `color-mix()`, `oklch()`, `@layer` (`CSSLayerBlockRule`), `:has()`, `@starting-style` (`CSSStartingStyleRule`), `transition-behavior: allow-discrete`, `overlay`, `::details-content`, the `popover` attribute, `anchor-name`, `position-anchor`, `position-try-fallbacks`, `@container`, `round()`, `inset-inline`, and the `forced-colors` media query. |

| What sRGB triplet does each calibrated `oklch()` colour resolve to, and what does the engine paint for one outside the sRGB gamut? | [`instruments/srgb-probe.mjs`](instruments/srgb-probe.mjs) (`color-mix(in srgb, …)` serialization) and [`instruments/paint-probe.mjs`](instruments/paint-probe.mjs) (the painted pixel of a screenshotted swatch, read back through a canvas) | Chromium `153.0.8010.12` and Edge `153.0.4234.48`, 2026-09-20 | Identical on both. `color-mix` serializes an in-gamut colour as `color(srgb r g b)` whose channels × 255 equal the painted pixel: primary light `8, 65, 234`; text `15, 23, 43` light and `226, 232, 240` dark; border `202, 213, 226` light and `64, 72, 84` dark; raised surface `248, 250, 252` light and `26, 30, 36` dark. The dark primary `oklch(0.7 0.15 233)` is outside sRGB: `color-mix` serializes a negative red channel (`color(srgb -0.108087 0.675236 0.924272)`) while both engines paint `0, 172, 236`, so a `-rgb` triplet for it must come from the painted reading, not from the mix. `rgb(18, 18, 18)` paints itself. |

| Does `matchMedia('print')` follow `Emulation.setEmulatedMedia`, and which pseudo-element selectors does `CSS.supports` accept? | [`instruments/media-probe.mjs`](instruments/media-probe.mjs) | Chromium `153.0.8010.12` and Edge `153.0.4234.48`, 2026-09-20 | Identical on both. Staging `media: 'print'` flips `matchMedia('print')` to true and `screen` to false while the print rule paints (`3px`); the `prefers-reduced-motion: reduce` feature flips its query and paints `2px`; `{ media: '', features: [] }` restores every reading. `CSS.supports('selector(::before)')`, `::after`, `::backdrop`, `::details-content`, `::marker`, `::placeholder`, and `::selection` read true in the bare and the `*`-prefixed form; an invented `::journey-absent` reads false; the pseudo-class `:hover` also reads true, so a pseudo-element guard must check the `::` prefix before `CSS.supports`. |

The U5 rows settle the plan's § U5 questions: every instrument the provider reaches answered positively, so U6 owes no substitute instrument for them; the `:active` reading names the scale mapping a press helper must perform.

Run an instrument from the scaffold checkout with `node .orkestrel/veneer/research/instruments/<name>.mjs`.
Each imports Playwright from scaffold's `node_modules` through a `file:///` URL, because Node on
Windows refuses a bare drive-letter path as an ESM specifier. Playwright `1.63` pins Chromium
revision `1243`, which is not installed on this host; the instruments launch the installed `1234`
build by executable path and Edge by channel. Install the pinned revision in a workspace with
`npx playwright install chromium` after `npm ci`.

Open questions U5 in [the plan](../plan.md) answers the same way: hover through the provider,
pseudo-element used values, media emulation through `cdp()`, and a pointer hold for `:active`.
