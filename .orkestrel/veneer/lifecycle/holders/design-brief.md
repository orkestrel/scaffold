## Settle each question, with a ruling and the reasoning

1. **Who a holder is.** From `clients.md`, name the consumers that deliver concurrent independent work to one `browse` server: subagents that reuse the parent's configured server, parallel tool calls in one turn, a replay beside interactive work, several sessions on a multi-session transport, and library consumers such as service tests. MCP carries no caller identity inside a session (`clients.md` facts 9 and 12), so rule how a call names its holder: a handle in tool arguments, one session per holder on a transport that carries sessions, a replay-only second holder, or another shape. Rule which consumers item 14 serves and which it leaves, each with its reasoning.
2. **Holder lifecycle.** How a holder begins, how later calls address it, and how it ends (an explicit end, the session's end, the server's end). What a holder its caller abandons costs, and how the server reclaims it without polling. How a session that never names a holder keeps today's behavior.
3. **Lease per holder.** Each holder takes its own token from `pool.acquire()`. Rule whether an ended holder releases its browser to the next holder or destroys it for a clean page, from the state a reused browser carries (cookies, storage, tabs, the retained reading, a recording, downloads, the profile) and the measured refill cost in `eager/readings.md`. If reuse wins, name the reset that makes the browser clean and the test that proves it.
4. **Capacity and waiting.** Holders stay within the size. Rule what a holder beyond capacity receives (it waits under its signal, or it is refused with a code), in what order, and whether one holder can starve another. Rule failover when every browser is leased and no idle spare exists: what a holder whose browser dies receives, and when.
5. **The pool under several tokens.** Rule each with `@orkestrel/pool`, as a pool change (named, with its version, tests, guide, and release order) or as `browse` policy: the `cleanup` refusal of a waiter while another holder's live lease could still be released (`Pool.ts:351-366`, `guides/pool.md:159-160`); the strike reset on every grant (`Pool.ts:671`), under which a browser that always fails would relaunch on every demand, against D7 (reassessment D-5); the waiter order at `#waiters[0]`. Name which ruling binds probe item 1, whose concurrent proves already hold several tokens per stage pool (`eager/probe-design.md:167-212`).
6. **State that is one per server.** Rule what becomes per holder and what stays shared: the mirrored tool list when holders' toolsets add different tools (`BrowserMCPServer.ts:396-400`, `:704-731`); `#notice` and the `CRASH` note (which holder hears which loss); the `#references` counter behind `isolate`; the journey and run stores on one root with one lock per journey name, when two holders record or replay the same name; the replay refusal on each toolset.
7. **Placement and names.** What belongs in the library (`src/server`, reusable by tests) and what in the `browse` server and its `BROWSE_*` variables; the public type changes in `src/server/types.ts` with single-word names; tool-argument or transport changes; guide parity.
8. **Measurement.** The contention measurement that rules the default size: the workload kinds (interactive holders, replays, journeys) and the load each represents, the host's other load, the readings (per-holder call latency, memory, CPU, failover time with every browser leased), the instrument, and the decision rule. State properties; fix no figure in advance.
9. **Proof.** How each claim is proved with a real Chromium and no mocks: holders isolated from each other (one holder's navigation and storage invisible to another), a loss on one holder leaving the others serving, waiting and refusal at capacity, the release or destroy contract, and a teardown that leaves nothing behind with several leases live.
10. **Carry-over.** Which parts carry to probe item 1 and to service tests sharing warm browsers (`scaffold/.orkestrel/veneer/lifecycle/status.md`, the shared-browser question). Note them; design nothing there.
