Reconciled 2026-10-05 by the Orchestrator from `contexts-proposal-analyst.md` (GPT-6 Astra, objective) and `contexts-proposal-planner.md` (Opus 5.5, subjective), blind to each other over `contexts-design-brief.md`.

- Q2: the shared holder counts against it (0.0.24's behavior; `contexts=1` reproduces 0.0.24).

## Where the lanes agree

- A holder becomes an isolated CDP browser context with its page and started toolset on one pooled browser; browsers stay the pool's records; the shared holder is a context with a server-long lifetime.
- `BROWSE_POOL` and `pool.size` keep meaning the number of browsers; a second bound governs holders.
- Assignment: the live browser with the fewest occupied places (pending constructions and disposals counted), ties by warm order, reserved synchronously; no rebalancing of healthy contexts.
- A browser loss invalidates every context on it with one owner-side disposal and one refill credit; each holder keeps its id and receives its own `BROWSER_SERVER_CRASH` note with its own last URL; holders on other browsers see nothing; interrupted calls answer `BROWSER_SERVER_UNRESOLVED` and are never repeated; recovery lands on another live browser's capacity or waits for the refill, never past the bounds.
- An active-page renderer crash costs only that holder's context; a background-page crash is not a holder loss.
- `destroy` runs toolset teardown, then `context.close()` (which sends `Target.disposeBrowserContext`), then removes the context's downloads folder; never `context.destroy()`, which skips disposal (`BrowserContext.ts:160-176`).
- Downloads go to a folder per context under the browser's profile, set per context through `isolate({ downloads })`.
- Liveness: a browser watch (disconnect, the root ping at hand-out and after a failed call) and a context watch (page events), no timer; a successful root ping keeps a page-level timeout a page failure.
- The isolation matrix (cookies, local and session storage, IndexedDB, Cache Storage, service workers, HTTP cache, permissions, downloads, references and catalogs) is a release gate proved with real Chromium, not inferred; contexts are automation isolation, not a hostile-tenant boundary.
- Tabs inside one holder keep today's sequential `tabs` and `switch`; no concurrent lanes inside a holder.
- Measurement first (M1) at library level with spread, then the implementation, then a binary-level confirmation; defaults come from the measurement; no MCP change; the wire contract is unchanged.

## Orchestrator rulings where the lanes differ (revised after `contexts-attack.md`)

1. **The pool gains shared leases** (analyst), so browse never holds a lease without a holder behind it. Under the planner's shape every browser stays leased, so every loss owes a refill and never strikes (`Pool.ts:478`, `:489-492`, `:410-411`) and the next grant resets the strikes (`:678`): a browser that launches and then crashes would relaunch with no caller at all. `@orkestrel/pool` gains an optional per-record `capacity` (exclusive by default): leases bounded per record, least-occupied selection with stable ties, FIFO waiters and cancellation, exact-lease `release()`, one disposal and one refill credit per lost record (`#owing` is a set of records), a record with no live lease idle again so its loss strikes, and the idle-loss repair (a released, previously used record's loss strikes). Under sharing one lease's `PoolToken.destroy()` disposes the record for every co-holder; P1 pins that and the guide states it, browse uses `release()` for a failure local to one context, and P1 rules whether hand-out validation runs on a record that already has live leases. The `idle` and `active` counts are documented under sharing. Ships as pool 0.0.16 before the browser re-pin.
2. **A call-paced relaunch loop remains, in 0.0.24 today and under contexts** (a recorded limit, put to the user as Q3): a browser lost while a holder leases it owes a refill, never strikes, and the refilled record's grant resets the strikes, so a browser that crashes under every holder's use relaunches once per call without bound (0.0.24's renderer-crash-as-browser-loss, `BrowserMCPServer.ts:739-743`, makes a page that crashes its renderer do this today). Contexts narrow it: a renderer crash costs only the context. Bounding the remainder changes the user's Q3 grant rule.
3. **Each browser warms with one prepared blank context held in the record `create` builds, with no lease before assignment** (analyst), so a broken page or toolset shows at the onset (D4) and no browser is leased without a holder; further contexts are built at `acquire`. At size 1 the shared holder consumes the first prepared context at setup, so D4 covers the first context there.
4. **Disposal outcomes are classified through the context seam** (analyst's context-ownership unit, restored): `BrowserContext.close()` rejects when any page close fails even after `Target.disposeBrowserContext` succeeds (`BrowserContext.ts:371-383`), so browse confirms disposal with `Target.getBrowserContexts` (or a typed outcome from the seam). A confirmed disposal with a failed page close is a page-close fault reported at teardown; an unconfirmed disposal retires the host browser through the pool and charges a strike, so a Chromium that always fails disposal cannot relaunch without bound; the destroyed holder's place stays occupied until the retirement settles. A failed download-folder removal keeps that folder's ownership and its place until teardown reports it; `destroy` answers success (the H2 review's F3 rule).
5. **Recovery happens at the holder's next call, single-flight** (analyst), with no background reconstruction; it inherits the call-paced limit of ruling 2.
6. **Each context generation gets its own folder under the browser's per-launch profile** (`ROOT/.profiles/PID-UUID/contexts/GENERATION-UUID/downloads/`, the profile named by `formatBrowserLockEntry`, `BrowserMCPServer.ts:787`).
7. **Visibility is measured, not promised** (analyst); a remedy M1 demands (bringing a page forward, focus emulation, a launch flag) lands in C1.
8. **A browser that answers its ping but fails `Target.createBrowserContext` repeatedly** is retired through the pool with a strike after a creation failure, so `acquire` cannot fail forever on a browser nothing retires.
9. **A hung active renderer stays a page failure while the root ping answers**; the holder recovers through `destroy` or the next renderer event (a recorded limit).
10. **A clean slate means fresh context-scoped web state, fresh automation state, and removal of owned downloads,** not a fresh process or freed memory; the guide states it, and C2 proves each store in the isolation matrix.

## Questions for the user

- **Q1, the shape of the holder bound.** (a) Per browser, `BROWSE_CONTEXTS` (`pool.contexts`), total admission `size × contexts` (analyst): `contexts=1` reproduces 0.0.24 exactly (a size of 3 admits 3 with the shared holder), so no existing configuration changes; `BROWSE_POOL` then also multiplies admission, and holders displaced by a browser loss wait for the refill when the survivors are full rather than failing over at once. (b) A total bound, `BROWSE_HOLDERS` (`pool.holders`) (planner): one number for admission, holders can fail over onto survivors at once, but a browser can concentrate holders after a loss and an existing `BROWSE_POOL=3` configuration changes capacity. Recommendation: (a), for the unchanged configurations and the bounded per-browser memory and crash domain.
- **Q2, whether the shared holder counts against the bound.** (a) It counts (analyst; 0.0.24's behavior). (b) It does not (planner). Recommendation: (a).
- **Q3, the call-paced relaunch loop (ruling 2).** (a) Record it as a limit and keep the Q3 grant rule (recommended for this campaign; contexts already remove the renderer-crash path). (b) Bound it: a leased loss strikes and the reset moves from a bare grant to a proven-healthy event such as the first release, a change to the grant rule ruled 2026-10-04.
- **Q4, the default topology after measurement.** (a) One browser with the measured context capacity if it passes the rule (expected). (b) A hybrid of two browsers if the measured failover gain is worth the idle cost. Decided from M1.
