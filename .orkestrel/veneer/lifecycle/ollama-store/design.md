## Measurement plan

Lane: objective (what the contracts and the oracles permit).

Design: eight changes in three owners. The browser changes are ranks 1, 2, 6, 7, and 8, released as one browser version after measurement. The harness changes are ranks 3, 4, and 5. Alternatives considered, at most two:
- (a) Seed the view as an assistant look call plus its tool result (G-7), instead of rank 5. Rejected: it fabricates an assistant turn, needs history injection that `converseStore` may not support, and would show the seed in a different encoding from later results (G-8).
- (b) Route fact-finding through a system-prompt sentence instead of look's footer (rank 2), avoiding a browser release. Rejected: 0 of 16 read attempts called read first despite 'To learn a fact, call read', while look's footer was followed in 18 attempts.

Comparison rule (derived from the baseline's own n, no borrowed figure):
- Each configuration runs the unchanged proof: the same model, temperature 0, context 16384, predict 256, iteration limit 8, and 3 attempts. Run it 8 times, filtered to the tasks the change touches. 8 matches the n of the 2026-10-04 baseline.
- Compare each task's per-run pass count with the immediately preceding configuration, using a one-sided Fisher exact test at 5%. With 8 runs per arm the settling counts follow from the hypergeometric distribution:
  - From 0/8, 4/8 settles (p = C(8,4)/C(16,4) = 70/1820 ≈ 0.038); 3/8 does not (56/560 = 0.10).
  - From 1/8, 6/8 settles (≈ 0.020); 5/8 does not (≈ 0.059).
  - From 3/8 (the b4a18c3 shipping, click, and paging level), only 8/8 settles (56/4368 ≈ 0.013); 7/8 gives ≈ 0.059.
  - From 4/8, 8/8 settles (70/1820 ≈ 0.038).
  - For harm at a ceiling (search, form), a fall from 8/8 to 3/8 or lower settles (≈ 0.013).
- When a count lands between these thresholds, run both arms another 8 times and recompute; never accept an unsettled difference.
- Keep a change when its target class count falls and no task's pass count falls by a margin the same rule settles. Otherwise revert it. Pass rates cannot separate a class with 1 or 2 baseline instances (rank 8, F-15 alone), so attribute those from the classified transcripts.
- Primary reading for every configuration: per-attempt failure-class counts, using the F-1 to F-18 classes and the bisect classifier over every transcript. Pass counts are secondary.
- Also record whether attempts 2 and 3 repeat attempt 1's calls. At temperature 0 with isolated contexts (since 90901da), the attempts may be near-identical. If they are, 3 attempts add little, and the per-attempt rate is the reliability, so a change must make the modal path pass rather than raise the odds.

Order, chosen so that each effect is separable:
- S0: a head baseline, 8 full runs including journey. The b4a18c3 baseline predates per-attempt isolation (90901da) and browser 0.0.23, so it cannot be the comparison arm.
- S1: rank 3 (paging only).
- S2: rank 1 (read, paging, click).
- S3: rank 2 (read, paging, search). It goes after rank 3 so that it cannot turn look failures into match-block failures.
- S4: ranks 6, 7, and 8 (paging, search).
- S5 is not used. Keep the label free for a rerun.
- S6: rank 5 (all five page tasks, because the first message changes everywhere).
- S7: rank 4 (click, form, journey).
- S8: the acceptance series, all six tasks.

Measure the browser changes from a local pack of the browser branch installed in a measurement worktree of ollama, one commit per configuration. Publish one browser release holding only the kept changes, then re-pin ollama.

The acceptance claim needs more runs than the screens. A run passes only when all six tasks pass, and n runs with no failure bound the per-run failure rate below 1 − 0.05^(1/n) at 95%. The orchestrator picks the target rate, and n ≥ ln(0.05)/ln(1 − target) follows: 8 clean runs bound it below about 31%, and a bound below 10% needs 29.

## Rejected

- Raise predict above 256 to stop the F-6 echo, or raise the attempt count or the iteration limit to absorb the F-1 and F-16 loops.: The user's constraint: 'never raise a budget, attempt count, iteration limit, or temperature'.
- Accept look continuations, or reads at a match-row offset, in `findContinuedRead`, or drop its read requirement.: That weakens the paging oracle, which the user forbids.
- Click task prompt that names the path ('Open the Cedar Tea Tray's page and add it to the cart.'), G-6's alternative.: It answers the step the click task measures, the first choice of a link, for this product specifically. Rank 4 states a product-agnostic strategy instead.

- Handled-submission status 'do not submit again; call wait for the text you expect, such as a confirmation' (G-10).: It fixes a duplicate order for every agent, but it removes the second submission that `matchesRemovedSubmission` requires, so the journey could never pass. - System prompt 'When a result tells you to call wait, call it once with the text you expect.' - Refusal copy for a stale reference ('call look for current references', G-14), the idle save (G-12), and a save after saving (G-13).: None turns a failing attempt into a pass. - Refuse or translate a read offset that came from look (instead of rank 6's note).: All 3 baseline paging passes rely on the restart at 0 (F-17, F-22(2)). Refusing or mapping the offset would change the only measured passing path.

Use "an attempt's calls reach STORE_FACT" as the shipping guard. Before the series, the orchestrator rules whether rank 1's look line may name read on a page where read's search reaches only a heading.
- Two primary readings are met by the change's own text, so they cannot fail. Evidence: Rank 1's reading counts attempts with 2 or more look calls whose bodies are identical. The F-1 loops vary the search ("shipping cutoff time", "shipping", "delivery", "delivery time" in run-1, run-5, and run-7 read-*.json), and the zero line quotes the search. Every changed search therefore produces a distinct body, even when the model keeps looping with no read. For rank 3, record where the former F-15 attempts go next (read at the footer offset, a look continuation, or a stop) instead of a count fixed at 0.
- The guard rule has almost no power to detect harm. A change can drop click or paging to 0/8 and still be kept. Evidence: The plan keeps a change when no task 'falls by a margin the same rule settles'. With 8 runs per arm and a start at 3/8 (click and paging), a fall to 0/8 gives one-sided p = C(8,3)/C(16,3) = 56/560 ≈ 0.10, which does not settle. From 4/8 (shipping), only 0/8 settles; 4/8 to 1/8 gives p ≈ 0.14. Rank 2's guard ('all 4 shipping passes used look continuation') can therefore keep a change that takes shipping to 1/8. Fix: Use a non-inferiority rule for guards: any fall in a guarded task's pass count triggers a pre-set extension or a revert. Back the pass counts with attempt-level class counts and the fact-reached count, which carry about 3 times the n.
- The harm thresholds are misstated, and search is not at a ceiling. Evidence: The plan says a fall from 8/8 'to 3/8 or lower settles'. A fall from 8/8 to 4/8 also settles: p = C(12,4)/C(16,8) = 495/12870 ≈ 0.038, the mirror of the 4/8→8/8 case the plan computes. Search is 7/8 at b4a18c3, and from 7/8 only 2/8 settles (261/12870 ≈ 0.020); 3/8 gives ≈ 0.16. Fix: Correct the table: a fall from 8/8 to 4/8 or lower settles, and a fall from 7/8 to 2/8 or lower settles. Derive each guard's threshold from that task's S0 count, not from b4a18c3.
- Open-ended sequential extension and many comparisons push the false-positive rate above the stated 5%. Evidence: The plan says: 'When a count lands between these thresholds, run both arms another 8 times and recompute; never accept an unsettled difference.' Each extra look is another test at 5%, and each configuration tests 3 to 6 tasks across 7 configurations, with no correction. Fix: Fix the maximum n per arm in advance (for example 8, extended once to 16) with a stated alpha split across the looks, or test once at a pre-registered n. Name one target task per configuration as the confirmatory test and treat the other tasks as guards.
- Several comparisons name an arm that did not run the task, and rank 2's configuration omits tasks whose first message it changes.
