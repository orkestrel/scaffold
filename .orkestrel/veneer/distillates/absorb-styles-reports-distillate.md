## Token proof mechanism

The reader is a computed style on a shipped consumer. Round 5's nested cases call `readStyle` for `color`, `border-top-color`, and the feedback `color` (.orkestrel/veneer/units/token-proofs-report-5.md:137). Round 6's scope cross-check calls `getComputedStyle` on the root, a light island, and a dark island (.orkestrel/veneer/units/token-proofs-report-6.md:37). Every asserted literal in the first round was a reading taken in that worktree (.orkestrel/veneer/units/token-proofs-report.md:41). The form assertions read `border-top-color` and feedback `color` (.orkestrel/veneer/units/token-proofs-report.md:56).

The override site is an ancestor, and the site decides which declarations move. A plain ancestor moves a rule or a component alias that reads the token inside it, which is how the link colors, the link decoration, the button mixes, the disabled opacity, the heading weight, and the easing move (.orkestrel/veneer/units/token-proofs-report-5.md:88). A `[data-bs-theme]` ancestor moves the tiers and aliases that mode scope re-declares (.orkestrel/veneer/units/token-proofs-report-2.md:12). The form tokens are in that second set: `--bs-form-valid-color` moved to `rgb(7, 8, 9)` from a light scope, while `--bs-success`, `--bs-border-radius`, `--bs-body-font-weight`, and `--bs-link-decoration` stayed on their root values (.orkestrel/veneer/units/token-proofs-report-2.md:8). The root is a special site. An inline `--vn-radius-base` of `20px` on a root that carries `data-bs-theme="light"` makes a child read `--bs-border-radius` as `20px`, because the `:root` rule matches that element (.orkestrel/veneer/units/token-proofs-report-6.md:62). The same root-with-mode pattern carries an alias override: `--bs-form-valid-color: rgb(9, 8, 7)` on that root is what the child reads (.orkestrel/veneer/units/token-proofs-report-6.md:153).

The control is a twin outside the override, read first (.orkestrel/veneer/units/token-proofs-report.md:41). The nested cases add a mode twin outside the override and a consumer inside a nested `[data-bs-theme]`, and they refuse the equality when the mode twin already equals the override (.orkestrel/veneer/units/token-proofs-report-5.md:142). The alias case sets `--bs-form-valid-border-color` and `--bs-form-valid-color` to different colors so a consumer on the wrong alias fails (.orkestrel/veneer/units/token-proofs-report-2.md:61). The scope instruments use the same shape of control: a perturbed `:root` value leaves the text-equal list (.orkestrel/veneer/units/token-proofs-report-6.md:31), a dark `--vn-state-hover` of `13%` leaves the resolved-equal list (.orkestrel/veneer/units/token-proofs-report-6.md:35), and `--bs-primary` differs when the root carries the dark scope while root-only names do not (.orkestrel/veneer/units/token-proofs-report-6.md:44).

The plant replaces the load-bearing declaration with the resolved rest literal, rebuilds `src:styles`, and runs that case (.orkestrel/veneer/units/token-proofs-report.md:44). The link and the link button, and the control border and its feedback, are planted separately (.orkestrel/veneer/units/token-proofs-report.md:46). The round-2 plain-ancestor plants do the opposite for placement: they point the validation rule at the canonical token, which is the edit those assertions exist to catch (.orkestrel/veneer/units/token-proofs-report-2.md:52). The nested plants write `inherit` on the mode-scope declaration so the nested consumer follows the outer override while the outer mode twin still reads the rest value (.orkestrel/veneer/units/token-proofs-report-5.md:183). The root-with-mode plant adds `:root[data-bs-theme] { --bs-border-radius: calc(0.375rem * var(--vn-factor-radius)); }` and the child stays at `calc(.375rem * 1)` (.orkestrel/veneer/units/token-proofs-report-6.md:109).

A mode scope that wants a descendant to keep the mode value has to declare that name again. The measured same-valued re-declarations are `--vn-state-hover`, `--vn-state-active`, `--vn-state-stripe`, `--vn-focus-highlight`, `--vn-focus-reset`, and `--bs-heading-color` (.orkestrel/veneer/units/token-proofs-report-6.md:19). ## Ledger mechanism

Additions are measured from the built cascade, not by reading the partials. (.orkestrel/veneer/units/ledger-additions-report.md:56) `attributeSelector` attributes a rule by its classes. A `:where()` or other functional argument hides those classes, which is why `.caption-bottom` and the button reboot rules were unattributed until a recorded selector row owned them. (.orkestrel/veneer/units/ledger-additions-report.md:38) Ownership order is: a component key from `attributeSelector`; otherwise a recorded selector row when the inventory has no selector row and the layer names no component; otherwise the rule is unattributed. The owner has to ship and have a vocabulary. (.orkestrel/veneer/units/ledger-additions-report.md:79) Each declaration under an added selector is its own row, named `selector { property }`, with the emitted value in the required `Veneer` column. Registry names are exempt. (.orkestrel/veneer/units/ledger-additions-report.md:76) The blockquote plant is the red additions gate: `97px solid currentColor` is unrecorded, and the shipped `var(--vn-space-2) solid currentColor` becomes the stale row. (.orkestrel/veneer/units/ledger-additions-report.md:148)

Departures compare the Bootstrap release sheet with the built cascade in Chromium. Canonical tokens compare the built cascade with itself, site against the Reference map cell. (.orkestrel/veneer/units/ledger-retune-report.md:76) The neutral host is `font-size: 16px` and `width: 1000px`, with `color-scheme` taken from the mode. (.orkestrel/veneer/units/ledger-retune-report.md:41) Round 2 also computes `font`, `block`, `color`, `direction`, `root`, and `viewport`, plus a parent value for regular properties. (.orkestrel/veneer/units/ledger-retune-report-3.md:61) A pair is alike only when every setting agrees. The stored reading is the first one whose sides differ, otherwise the `base` reading. Identical text after substitution stays on `base`. (.orkestrel/veneer/units/ledger-retune-report-3.md:66)

Priority of written values is the last value Chromium parses at that site. `written` keeps the earlier values, which is how a `-webkit-sticky` fallback, a caret written twice, and the `pre` and `kbd` `font-size` rows stay visible. (.orkestrel/veneer/units/ledger-retune-report.md:44) Priority of members is `dropped`, then unresolved, then `retuned` when the resolved values differ, then the text-only member `fallback`, `tokenized`, `aliased`, or `restated`. The `Source` column is not an input. (.orkestrel/veneer/units/ledger-retune-report.md:103) A keyword on a regular property against a concrete value is `retuned` when a parent value varies the property, which is why `.col-form-label` font-size moved. (.orkestrel/veneer/units/ledger-retune-report-3.md:82) `attr`, `counter`, `counters`, and `env` leave the pair unresolved. (.orkestrel/veneer/units/ledger-retune-report-3.md:69)

Custom properties are typed by the first probe both sides parse. Round 2 keeps `<number>#`, `<length-percentage>+`, `<time>`, `<angle>`, and `<color>`, then the property rungs. `<image>` was dropped because it left gradient colors unresolved. (.orkestrel/veneer/units/ledger-retune-report-3.md:75) Legacy sRGB is compared at 8-bit, and `color(srgb 0 0 0 / 0.175)` is the drift from `rgba(0, 0, 0, 0.176)`. (.orkestrel/veneer/units/ledger-retune-report-3.md:190) `oklch()` and `color(display-p3 …)` compare as written. (.orkestrel/veneer/units/ledger-retune-report-3.md:282)

The canonical scan uses the light cell for a site outside every mode scope and the dark cell for a site under `[data-bs-theme=dark]`. Empty against empty compares the written text and prints `(empty)`. (.orkestrel/veneer/units/ledger-retune-report-3.md:90) A witness is `var(<token>)` alone resolving to the release value. A factor or other arithmetic on the token witnesses nothing. (.orkestrel/veneer/units/ledger-retune-report-3.md:300) The red canonical plant is `--vn-radius-base` doubled to `calc(0.75rem * var(--vn-factor-radius))`, read as `12px` against the cell's `6px` at `:root` and in the dark scope. (.orkestrel/veneer/units/ledger-retune-report.md:197) The red witness plant is `--vn-radius-pill: 40rem` in the sheet and in the cell. (.orkestrel/veneer/units/ledger-retune-report.md:198) The red unresolved plant is `1px` against `red` on `--bs-btn-padding-x`. (.orkestrel/veneer/units/ledger-retune-report.md:199)
