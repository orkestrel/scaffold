## Engine mechanisms as documented

- An engine dispatches its wire events on its host as bubbling `CustomEvent` instances through `emitEvent`: a pre-change event is cancelable and the function returns `false` when a listener's `preventDefault` prevented it, a completed event is not cancelable, a listener's return value refuses nothing, and the detail travels in `event.detail` alone. The wire table maps each event-map key to the wire name, the `on` option's hooks are bound to those names until destruction, and an event whose payload fails the engine's event guard reaches no hook. `tmp/mikesaintsg-veneer/guides/veneer.md:878` `tmp/mikesaintsg-veneer/guides/veneer.md:886`
- The `Delegate` is the only data API: it listens for clicks and keys on its root, routes each click by the selectors it resolves for each entity, acquires a host the static `find` method does not already own, and while it owns an engine it restores and releases every acquired host the root no longer contains at the observer delivery after a removal. A host removed and reinserted before that delivery keeps its engine; destruction removes the listeners and the observer and restores every host the delegate still owns. A trigger names its target by `data-bs-target` or by the `href` fragment, and `readTarget` returns only an HTML element the optional root contains. `tmp/mikesaintsg-veneer/guides/veneer.md:894` `tmp/mikesaintsg-veneer/guides/veneer.md:922` `tmp/mikesaintsg-veneer/guides/veneer.md:936`
- Each engine keeps a `HostSnapshot`. The first save of a target, while no snapshot holds it and no restoration still has it to write back, records the value the target carried before any engine wrote it, and later saves join that record without reading. The last engine holding a target writes the record back at its destruction, and a value the record reads as absent is removed. Restoration writes class tokens first, then removes a `class` attribute the presence record reads as absent when the list is empty, then writes inline properties, then removes an empty `style` attribute the same way, and writes attributes last. `tmp/mikesaintsg-veneer/guides/veneer.md:961` `tmp/mikesaintsg-veneer/guides/veneer.md:973` `tmp/mikesaintsg-veneer/guides/veneer.md:1000`
- `settleAnimations` reads the element's own animations, leaves infinite and paused animations out, and resolves when each running animation finishes, is cancelled, or leaves with its element, re-reading the list after each round. No timer and no emulated `transitionend` stand in for the animation. A transition of zero length creates no animation, so under reduced motion the wait resolves in a microtask, and aborting the signal resolves the wait at once. `reflow` forces a style computation so the write that follows it in the same task transitions from the element's present state. `tmp/mikesaintsg-veneer/guides/veneer.md:1074` `tmp/mikesaintsg-veneer/guides/veneer.md:1083`
