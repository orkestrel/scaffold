## Lessons

- The shell paints `color-scheme` because a document arrives with no theme attribute, and those rules carry the scheme through the state before the color-mode engine has applied a mode (`tmp/mikesaintsg-veneer/app/browser/styles/_shell.scss:4-8`).
- A showcase constructed on a root that already has `data-bs-theme="dark"` announces the mode button pressed, and `destroy` leaves that attribute in place (`tmp/mikesaintsg-veneer/tests/app/browser/Showcase.test.ts:353-361`).
- The mode control's affordance is read through the keyboard, because a reading taken while the pointer rests on it would include the published button hover fill (`tmp/mikesaintsg-veneer/tests/app/browser/Showcase.test.ts:319-322`). The compared properties omit `border-color` because the border token retunes with the mode, and the test requires a non-zero width and a style other than `none` before it requires the dark reading to equal the light reading (`tmp/mikesaintsg-veneer/tests/app/browser/Showcase.test.ts:326-347`).
- The theme-switch case shoots no frame. The comment says a frame shot under that click would carry the hover mix, and a reader comparing the two modes would read that mark as a mode difference (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:284-288`).
- A hover or active capture has to survive pane staging: staging repositions the document under a pointer that does not move, and each frame's state is read again after the shot because a frame labelled hover has to be shown to have been taken while the pointer was still on the host (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:541-556`).
- A specimen that contains a `.viewport` child gets bottom padding on the specimen, because a capture of the specimen would otherwise end on a row no specimen paints (`tmp/mikesaintsg-veneer/app/browser/styles/_shell.scss:58-65`).
- The Color modes specimen is a theme-island reading: one set of controls on a light surface, in a dark island inside it, and in a light island nested in the dark one, each mode set by `data-bs-theme` in markup (`tmp/mikesaintsg-veneer/app/browser/constants.ts:4087-4090`). The navbar remarks record a second island: the class bar opens a light island with its own `data-bs-theme` because the card's dark scope paints a plain bar's brand white (`tmp/mikesaintsg-veneer/app/browser/constants.ts:4022-4025`).
- A refused teardown sets `unclean` and never clears it, so a later case cannot report a staged emulation's paint as a defect of the surface (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:205-216`). The teardown still releases the pointer, the media, and the pane when a case fails between staging and its own release (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:224-231`).
- Reaching Anchor before Toggle is required by traversal cost: each traversal walks forward and wraps once, and the comment records 30816 ms for the reversed order against 5546 ms for this order at the wide variant (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:347-352`).
- The Engine unit mounts the section and then a `Delegate` rooted at the same host, in the page's order, so the delegate's construction scan finds the scrollspy host (`tmp/mikesaintsg-veneer/tests/app/browser/sections/EngineSection.test.ts:42-53`). The published cascade and the shell styles are imported before any click (`tmp/mikesaintsg-veneer/tests/app/browser/sections/EngineSection.test.ts:35-40`).
- A specimen class that no loaded rule declares and no engine reads renders as nothing. The carousel `slide` class is the behaviour token the engine reads (`tmp/mikesaintsg-veneer/tests/app/browser/sections/EngineSection.test.ts:86-96`). With that token, the move is still sliding immediately after the Next click (`tmp/mikesaintsg-veneer/tests/app/browser/sections/EngineSection.test.ts:388-392`).
- Modal waits are armed before the click, because the completed event follows the motion, the focus move, and, on hide, the page release (`tmp/mikesaintsg-veneer/tests/app/browser/sections/EngineSection.test.ts:228-236`). The toast case waits on `TOAST_EVENTS.shown` and `TOAST_EVENTS.hidden`, and after the delegate dismisses it `Toast.find` is still the section's engine (`tmp/mikesaintsg-veneer/tests/app/browser/sections/EngineSection.test.ts:311-333`).
- Engine destruction order is the tooltip element removed, then the toast class restored, then the region removed, and both hosts then accept a fresh engine (`tmp/mikesaintsg-veneer/tests/app/browser/sections/EngineSection.test.ts:470-502`).
- The accessibility artifact is taken at rest on arrival, and it says so, because the Button scenarios drive focus, the pointer, and a press for their own frames (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:3399-3407`). A reading taken on the Primary button alone calls that specimen unreachable while the page inventory lists the same control (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:3419-3422`). The pressed Toggle moment has to be a second record beside the arrival tree (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:3446-3454`).
- Frame files are guarded from disk even when this run's capture flag is unset, and the region used for the variation check is the one recorded at placement (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:3467-3471`). A frame whose region variation is 0 fails as a blank frame region (`tmp/mikesaintsg-veneer/tests/app/browser/integration.test.ts:3510`).
