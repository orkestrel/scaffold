## Findings

8. **`tests/setupStyles.ts:1053` declares a hidden module-scope constant.** `const MEDIA_WIDTH_CONDITION` is not exported and is read only by `parseMediaWidth` at `:1070`. `AGENTS.md` § Design laws: "No hidden module helpers or declarations. Fold trivial one-use logic into its caller, or export it from the correct centralized module and test it." `.claude/rules/tests.md` § Shared test infrastructure repeats it for this file class: "Export every reusable helper, fixture type, factory, constant, and guard from setup files." A `^const|^function|^type|^interface` sweep over `tests/setup*.ts` returns this declaration and nothing else, so the module set carries no precedent for it. Failure scenario: a later helper needing the same two spellings re-declares the pattern, because nothing exports the one that exists and no case pins it. Right looks like: move the regex literal into `parseMediaWidth`'s body (the smaller closure, inventory unchanged), or export it and add it to the `tests/setupStyles.test.ts` inventory with a case. **Forces a fix round.**

9. **`tests/setupBrowser.test.ts:641-643` cannot fail for a per-gate attribution defect.** The fixture's two gates carry the same width (`(width >= 576px)` and `(width < 576px)`), and the assertion maps the returned `conditionText` through `parseMediaWidth`, so `[576, 576]` holds whatever order the reader returns and holds if it reports one matched rule's condition twice. Failure scenario: `collectMediaConditions` starts returning the first matching media rule's condition once per match and this case stays green while `tests/src/styles/mixins.test.ts:147-148` reads the wrong gate. Right looks like: give the two fixture gates different widths — `(width >= 576px)` and `(width < 768px)` — so the parsed array `[576, 768]` binds both the order and the gate-to-selector correspondence while staying serialization-agnostic. Does not force a round on its own; fold it into the round finding 8 forces.

10. **`tests/setupBrowser.test.ts:648-650` is an assertion that cannot fail.** `readRules()` over every `CSSMediaRule` on the page is asserted `.not.toEqual([])`, and the shipped cascade plus the fixture already guarantee media rules, so the assertion holds for every possible behaviour of the function under case. `.claude/rules/tests.md` § Discovery and adequacy audit requires each assertion to fail for the defect it claims to catch. Right looks like: assert what the flat walk cannot do — that the flat list carries the two fixture conditions while `collectMediaConditions(rules, '.vn-probe-open')` is empty — or drop the assertion. Does not force a round.

11. **`tests/src/styles/tokens.test.ts:288` does not bind the stripe's theme-closure placement.** The case reads `--vn-state-stripe` on `[data-bs-theme]` scoped divs, and a custom property declared at `:root` alone inherits into those divs, so the reading is `5%` whether or not the token sits inside `theme-tokens`. Claim 1's placement is therefore true of the source and unbound by a proof. Failure scenario: a later edit moves the declaration out of the closure, and the whole suite stays green until a mode-varying value makes a light island inside a dark island read the wrong tint. Right looks like: assert the placement where it is observable — `collectScopeProperties(rules, "[data-bs-theme='dark']")` contains `--vn-state-stripe` — or record in the test that the placement is unproven while the value is mode-invariant. Does not force a round.
