## 1. The split

**Ruling: the Orchestrator's working split is right about the files and wrong about the order. Validation runs FIRST, not last, and no unit closes a key until every partial that key's selector closure needs has landed.**

The split cannot be derived from the release's file list, because an inventory key is not a file. The `form-control` key opens at `tests/fixtures/oracle/inventory.json:26124` and contains `.form-control-sm` (`inventory.json:26632`), `.form-floating > .form-control` (`inventory.json:26930`), `.input-group > .form-control` (`inventory.json:27222`), `.was-validated .form-control:valid` (`inventory.json:27360`), and `.form-control.is-valid` (`inventory.json:27394`). Four of Bootstrap's files emit one key. `scanCompatibilityPresence` demands every selector of a `shipped` key in the built cascade (`tests/conformance.test.ts:117`), so a unit owning `_form-control.scss` alone cannot mark `form-control` shipped.

Run the closure the other way and the order falls out. Every selector of `was-validated`, `is-valid`, and `is-invalid` carries one of those classes, and `_validation.scss` emits all of them, including the input-group ones (`node_modules/bootstrap/scss/mixins/_forms.scss:149`) — so validation's own keys close on validation alone. The feedback and tooltip keys need one further rule, the input-group `:not(:first-child)` selector (terrain § A, `inventory.json:45084`, `inventory.json:45285`), so they close with input group. `form-floating` closes on floating plus input group plus validation. `form-control` and `form-select` then close with nothing left outstanding. `form-check` needs only its own file plus validation. `form-range` is the one self-contained key (terrain § A: `form-range` carries no validation, floating, or input-group selector).

**The rule to state once and apply everywhere: a key's compatibility row, its shipped-list entry, and its ledger rows belong to the LAST unit in the landing order whose partial the key's closure needs — not to the unit whose file the key is named after.** That is what buys zero bridging deferral rows. The reverse order (validation last) forces a bridging deferral row for every validation, floating, and input-group selector of `form-control`, `form-select`, `form-check`, and `input-group`, each written by one unit and struck by another, with `scanShippedDeferrals` thrashing in between.

Two further consequences of the accounting machinery, which also argue against the working split:

- `attributeSelector` stops on a membership hit under a **withheld** key (`b-passive-baseline.md` § The ledger), so a rule an early unit emits into a not-yet-shipped key needs no departure row yet. The departure rows for a key therefore land in one act, with the unit that ships it. Units sized smaller than a key's closure do not reduce that act; they only move it.
- The `form` key is the union of the whole compiled forms cascade (`inventory.json:19239` through `inventory.json:23245`, 195 selectors per `inventory.json:114385`). It closes last, by construction.

**Where the 195-selector `form` key's rows go.** Nowhere new, except the label family. `.form-control-plaintext` (`inventory.json:26536`), `textarea.form-control` (`inventory.json:26788`), `.form-control-color` (`inventory.json:26830`), and the size rows all sit inside the `form-control` key and go to the CONTROL unit. Only `.form-label` (`inventory.json:19241`) and `.form-text` (`inventory.json:19255`) appear in the `form` key and in no other key; with the three `.col-form-label*` rows the `col` key records (`inventory.json:11430`, deferred to Forms at `guides/veneer.md:457`) they are the whole of what the CLOSE unit authors. The `form` key's compatibility and ledger rows are CLOSE's accounting act over the family's integrated cascade.

**Shared-file contention.** Terrain § B's shipped pattern touches `src/styles/index.scss`, `app/browser/constants.ts`, `app/browser/Showcase.ts`, `app/browser/index.ts`, `tests/setup.ts`, `tests/setupStyles.ts`, the `listed` literal (`tests/conformance.test.ts:83`), and the guide and ledger files. Every one is an append at a named anchor, so authorship parallelises in worktrees and integration serialises — the B-PASSIVE ruling 13 discipline, unchanged. The family adds one contention B-PASSIVE did not have: `src/styles/_tokens.scss` and `src/styles/_theme.scss` need a rewrite, not an append (question 3). One unit owns both, and they are off-limits to every other unit of the family.

**Standing condition the design rests on.** This checkout carries no ledger reader (`tests/setupServer.ts` exports `readDeferrals` and `collectShippedComponents` and no `collectLedger`) and no B-PASSIVE partial (`src/styles/components/` holds button, table, type, list, quote, image, link, container, grid, icon-link, ratio, vr). Every ruling here assumes F5b, F5c, F7, F8a, and B-PASSIVE have landed first, as `ROADMAP.md:263` through `ROADMAP.md:272` sequences them. Where they land differently, the tree wins and the affected unit stops.

## 2. Naming

**Partials, one per class family, named for the class it emits rather than for Bootstrap's file:** `_validation.scss`, `_input-group.scss`, `_form-floating.scss`, `_form-check.scss`, `_form-range.scss`, `_form-control.scss`, `_form-select.scss`, `_form-label.scss`. Bootstrap's `_floating-labels.scss` and `_labels.scss` are named for a topic; Veneer's partials are named for the selector root a reader greps (`src/styles/components/_icon-link.scss`, `_button.scss`, `_table.scss`). `_form-label.scss` carries `.form-text` and `.col-form-label*` as well, because the label, the column label, and the helper text are one subject: the text around a control.

**No `@use` alias for any of them.** The aliases at `src/styles/index.scss:43` and `index.scss:51` exist because `elements/button` and `elements/table` already hold those namespaces. No forms stem collides with a namespace the barrel loads (`index.scss:1` through `index.scss:55`): `label`, `input`, and `select` are taken by element partials, and `form-label`, `form-control`, and `form-select` are not. Adding an alias where no collision exists is a second name for one thing (D7).

**Barrel order follows Bootstrap's own import order** (`node_modules/bootstrap/scss/_forms.scss:1`): form-label, form-control, form-select, form-check, form-range, form-floating, input-group, validation, each appended after `@use 'components/vr'` at the position that order gives it against the lines already present. No validation rule ties on specificity with a control rule, so order is a readability decision rather than a cascade one; matching the release keeps a diff against the oracle readable.

**Proofs mirror the partials:** `tests/src/styles/components/validation.test.ts`, `input-group.test.ts`, `form-floating.test.ts`, `form-check.test.ts`, `form-range.test.ts`, `form-control.test.ts`, `form-select.test.ts`, `form-label.test.ts`.

**Sections and constants:** `ValidationSection.ts`, `InputGroupSection.ts`, `FormFloatingSection.ts`, `FormCheckSection.ts`, `FormRangeSection.ts`, `FormControlSection.ts`, `FormSelectSection.ts`, `FormLabelSection.ts`, each fed by `VALIDATION_COPY`/`VALIDATION_SPECIMENS`, `INPUT_GROUP_*`, `FORM_FLOATING_*`, `FORM_CHECK_*`, `FORM_RANGE_*`, `FORM_CONTROL_*`, `FORM_SELECT_*`, `FORM_LABEL_*` in `app/browser/constants.ts`, each `Object.freeze`d in the `TABLE_SPECIMENS` shape (`app/browser/constants.ts:590`).

**Region names are the inventory key in sentence case:** `Form control`, `Form select`, `Form check`, `Form range`, `Form floating`, `Form label`, `Input group`, `Validation`. This is the one naming decision with a mechanical payoff: `buildStem` (`tests/setup.ts:43`) reduces each to the key's own spelling, so a frame's stem is the key it proves and the portfolio sorts by key against a counterpart portfolio.

**Specimen names open with their key's noun** — `Control plaintext`, `Select multiple`, `Check switch`, `Range disabled`, `Group prepended`, `Valid control`, `Invalid select`. `CaptureSubject` is a union of declared names (`tests/setup.ts:81`) and `TABLE_SPECIMENS` already declares `Base` (`app/browser/constants.ts:592`), so a bare `Base` under Form control would collide with a stem that is already claimed.

## 3. The icons

**Ruling: every forms SVG data URI lands in `src/styles/_tokens.scss`, and no data URI is authored inside a component partial.**

`.claude/rules/styles.md` § Prohibitions permits a literal colour in `_tokens.scss` alone, and every one of these URIs bakes one: the check and radio glyphs bake their stroke, the switch knob bakes `rgba(255,255,255,0.25)`, and the feedback marks bake Bootstrap's success and danger hexes (terrain § A). The tree already settles this: `src/styles/_tokens.scss:104` through `_tokens.scss:112` hold the caret, the knob, the toggler, and the accordion glyphs as Sass values, and `guides/veneer.md:888` names them assets because "a data URI cannot read a custom property".

**Mechanism: one `$icons` map in `_tokens.scss` for the mode-independent glyphs** — check, radio, indeterminate, switch off, switch focus, switch on, the light caret, the valid mark, the invalid mark — read by the partial with `map.get`, interpolated into the `--bs-form-check-bg-image`, `--bs-form-switch-bg`, `--bs-form-select-bg-img`, and `--bs-form-select-bg-icon` declarations Bootstrap writes (terrain § A). The mode-varying pair keeps its home in `$dark`.

**A Sass map entry is not a token.** It carries no `--vn-*` name, so the tokenizing ceiling (family ruling 4), the § Reference map rows, and `UNMAPPED_TOKENS` are all untouched. The ceiling bans adding a published token; it does not ban a Sass value.

**Ruling: the theme-scope emission of `--bs-form-select-bg-img` and `--bs-form-switch-bg` is removed, and the dark rules land where Bootstrap writes them.** `_theme.scss:21` walks `tokens.$assets` (`_tokens.scss:123`) and declares both on `[data-bs-theme='dark']`. Bootstrap declares the light value on the element itself — `forms/_form-check.scss:128` on `.form-switch .form-check-input`, `forms/_form-select.scss:7` on `.form-select` — and a declaration on the element beats an inherited one, so shipping Bootstrap's set exactly makes the theme-scope value unreachable. Bootstrap's own answer is a dark rule re-declared on the input at `forms/_form-check.scss:185` with `:not(:checked):not(:focus)`, and on the select at `forms/_form-select.scss:75`; the inventory records both under the `theme` key (`inventory.json:2648`, `inventory.json:2662`). `guides/veneer.md:895` already assigns this closure to "the component unit that owns each one", which is this family. The VALIDATION unit performs the relocation and corrects that guide sentence; `$assets` keeps the toggler and accordion entries, so the `@error` proof at `_theme.scss:23` and its override in `tests/setupStyles.test.ts` keep their subject.

**Colour source per URI:** baked at compile time from Bootstrap's own variable (terrain § A's table names each). Dark changes the caret and the unchecked, unfocused knob and nothing else; the check, radio, indeterminate, and feedback glyphs are identical in both modes, which is why they belong in `$icons` rather than in `$light` and `$dark`.

**No escaped-SVG idiom is added to `_mixins.scss`, and none is needed.** Bootstrap's `escape-svg` exists to escape an authored SVG at compile time; Veneer authors the already-escaped compiled URI, so the function has no work. A mixin wrapping `map.get` would be a mixin for one caller, which `.claude/rules/styles.md:46` refuses.

## 4. The elements layer

**Must not be restated by any component partial** (terrain § C): `label { display: inline-block }`; the `control-text` treatment on `input`, `select`, `textarea`, and `optgroup`; `select`'s `text-transform`, `word-wrap`, and disabled opacity; `textarea { resize: vertical }`; the `fieldset` and `legend` resets; the `button` appearance and focus repairs; and the Reboot rules for the calendar picker, the search decorations, the spin button, the datetime-edit padding, the colour-swatch wrapper, and the bare `::file-selector-button`.

**The distinction that keeps the two layers apart: the elements layer owns the rule keyed to a bare element or a bare pseudo; the component partial owns the rule keyed to `.form-control`.** So `.form-control::file-selector-button` (`inventory.json:19562`), `.form-control::-webkit-date-and-time-value` (`inventory.json:19420`), `.form-control::-webkit-datetime-edit` (`inventory.json:19442`), `.form-control::placeholder` (`inventory.json:19460`), and `.form-control-color::-moz-color-swatch` (`inventory.json:20016`) are Forms' rules and are authored in `_form-control.scss`, beside rather than instead of the Reboot rules at `src/styles/elements/_input.scss:5` through `_input.scss:41`.

**`[type=range]` needs nothing from the elements layer, and the range partial authors no bare-tag rule.** Terrain § C records that no `[type=range]` rule exists under `src/styles`, and Bootstrap supplies width, height, padding, `appearance`, and a transparent background on `.form-range` itself. A bare `[type=range]` rule would infer a component from a tag, which `ROADMAP.md:136` refuses.

**Proving the pseudos.** `readStyle` takes a pseudo argument (`node_modules/@orkestrel/test/dist/src/browser/index.d.ts:2456`), so `::placeholder` and `::file-selector-button` are read resolved on the rendered control. For the `-webkit-` and `-moz-` slider and swatch pseudos, the resolved path is not dependable across engines: each unit takes the resolved reading first, falls back to the authored declaration through `findRule` (`index.d.ts:1205`) and `readRules` (`index.d.ts:2413`) where the engine returns the originating element's style, corroborates with the capture frame, and **records in its report which path each pseudo took**. `findRule` is a substring lookup and proves no completeness (family ruling 11), so it is never the only reading for a value.

**Exclusions, ruled by cause rather than by prefix.** `.form-control::-webkit-file-upload-button` and its hover and reduced-motion twins follow `guides/veneer.md:395` — the standard `::file-selector-button` ships the same control part. `.form-select:-moz-focusring` and `.form-range::-moz-focus-outer` follow `guides/veneer.md:394` — each exists to suppress a default the managed Chromium and Edge receipts do not render. `::-moz-range-thumb`, `::-moz-range-track`, and `::-moz-color-swatch` **ship**: each paints a part that has no standard twin, and excluding them leaves Gecko with an unpainted control. The rule to state: exclude a vendor pseudo that suppresses a default; ship a vendor pseudo that paints a part.

## 5. The showcase

**One section per partial**, so a section, a proof, a partial, and a unit's owned set are one boundary.

**Specimens, by key,** each exercising the selectors its key records: Form label — label, column label small and large, helper text. Form control — base, focused-by-journey, disabled, readonly, plaintext, plaintext sized, small, large, textarea, colour, file, file disabled. Form select — base, multiple, sized `[size]`, disabled, small, large. Form check — checkbox, radio, checked checkbox, checked radio, indeterminate-by-journey, disabled, disabled label, switch, switch checked, reverse, switch reverse, inline. Form range — base, disabled. Form floating — control, filled control, select, plaintext, textarea, disabled. Input group — prepended text, appended text, button, sized small and large, floating inside a group, with validation. Validation — valid control, invalid control, valid select, invalid select, valid check, invalid check, valid feedback, invalid feedback, valid tooltip, invalid tooltip, a `.was-validated` form.

**Which states are driven and which render at rest.** A state the markup can declare renders at rest and takes no scenario: `[readonly]`, `:disabled`, `:checked`, `.is-valid`, `.is-invalid`, and `.was-validated` over a required empty control, which is `:invalid` on arrival. A state only a journey can produce takes a scenario: `focus`, which `CaptureState` already carries (`tests/setup.ts:98`), and `indeterminate`, which no HTML attribute expresses and which a journey must set on the element.

**So this family extends `CaptureState` with `indeterminate` and nothing else.** Every other forms state is a specimen, and a specimen is cheaper than a scenario: it renders in the arrival frame, the accessibility artifact covers it, and it cannot drift from what a journey drove.

**Frame scope follows the Button ruling** (`tests/setup.ts:201`): a focus scenario is a **page** frame, because the ring paints outside the border box and an element frame crops it; every other scenario is an element frame over the lifted specimen. The coverage obligation is family ruling 9's: every selector the inventory records for a key is exercised by a proof and rendered by a specimen at least once, and the unit's report carries the matrix.

## 7. Departures and additions

Every candidate from terrain § D, ruled:

- **Elements' element-level validation** — `:user-invalid` and `:invalid:not(:placeholder-shown):not(:focus)` (`/home/user/elements/src/styles/elements/_input.scss:155`). **Refused** under D2: Bootstrap carries no such rule, and painting a bare input from its validity infers a component from a tag state, which `ROADMAP.md:136` refuses.
- **Mailbox's `:user-valid` and `:user-invalid` beside the classes** (`/home/user/mailbox/src/styles/_forms.scss:893`). **Refused**, same cause.
- **Elements' `form[data-form-validated]` in place of `.was-validated`** (`/home/user/elements/src/styles/components/_form.scss:96`). **Refused** under D7: it is a second name for a Bootstrap class.
- **Elements' `stroke='currentColor'` chevron** (`/home/user/elements/src/styles/_tokens.scss:342`). **Refused as a defect, not as a taste call.** Terrain § D records that a data URI does not retint, so the idiom ships a black caret in dark mode. It would also delete the dark caret asset the tree already carries correctly.
- **Elements' range-thumb and glyph tokens** (`--set-range-thumb-background-color`, `--set-icon-*`). **Adopted only as role routing.** The forms partials bind role-bearing colours to the `--vn-*` tokens the shipped partials already use (`src/styles/components/_button.scss:135`, `_table.scss:108`) and record each as a `tokenized` departure. No `--set-*` name is imported and no `--vn-*` token is added.
- **Mailbox's paired light and dark glyph URIs** (`/home/user/mailbox/src/styles/_tokens.scss:86`). **Adopted only where Bootstrap itself pairs them** — the caret and the unchecked knob. **Refused** for the check, dash, and radio glyphs, which Bootstrap leaves unchanged across modes; pairing them is a Veneer appearance change and belongs to E-IDENTITY, after APPEARANCE-RULING.
- **Mailbox's `.select` listbox and `.range-slider` widget** (`/home/user/mailbox/src/styles/_select.scss:3`, `_range-slider.scss:5`). **Refused**: outside Bootstrap's set, and each is a component with its own engine obligations.

**The family's one pervasive departure class, stated once so no unit re-derives it:** where Bootstrap compiles a role colour, a space, a size, a radius, a border width, or a motion value to a literal, the partial writes the existing `--vn-*` token the shipped partials bind and the comparison reports a `tokenized` departure. Where Bootstrap's own value already references a `--bs-*` global the tree declares, the partial writes it byte for byte and records nothing (family ruling 4). **A unit that meets a value with no existing token stops and reports rather than adding one**, and this family expects to add none.

## 9. Risks

Named per unit in the table; the family-wide ones:

- **`attributeSelector` may collapse every forms rule onto the `form` key** once `form` ships, since `form` is a membership hit for every selector in the family. If it does, CLOSE's landing makes every per-key ledger row stale at once. **This is the single reading the Orchestrator must take before CLOSE's brief is written** — read `attributeSelector` in the F5b tree and record which key it returns for a selector that two shipped keys both contain.
- **The build's treatment of vendor pseudos is unmeasured here.** `guides/veneer.md:395` states that the build's targets remove `::-webkit-file-upload-button` from the cascade. Whether the same happens to `:-moz-focusring`, `::-moz-focus-outer`, `::-moz-range-thumb`, `::-moz-range-track`, and `::-moz-color-swatch` decides whether CONTROL, SELECT, and RANGE author those rules or file exclusion rows. Take the reading with a throwaway compile before those three units launch.
- **The relocation of the caret and knob assets touches `_tokens.scss`, `_theme.scss`, the guide's retained-variables sentence, the § Reference map coverage floor, and the theme proofs.** It is the only rewrite in the family and it has one owner.
- **A unit authored in a worktree cut before its dependency landed cannot run its own presence gate.** Each brief names the commit it is cut from and the landing position it integrates at, and a unit whose scoped conformance run reddens on a sibling's absent file reports it as an observation rather than repairing it.
