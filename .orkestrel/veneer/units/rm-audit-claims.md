1. **The fix.** In `src/core/templates.ts` (the `vite` template's `mergeOverride`) and in scaffold's own
   `vite.config.ts`, the invocation record (an object carrying `command` and `mode`) returns the base with `mode` set to
   the record's `mode` and carries none of `command`, `isPreview`, `isSsrBuild`, or any other record field; a record
   whose `mode` is not a string throws; every other path of the merge is unchanged; the two spans are byte-identical.
2. **The vendored contract.** In `tests/config.test.ts`, the case `runs every project in the mode Vitest was invoked
   with` drives every factory the configuration registers with a sentinel record and asserts each result carries the
   record's `mode` and none of its other fields; its controls (a factory that ignores the record, one that spreads it
   whole, an inline entry) each fail the same predicate; it asserts the throw on a record with no string `mode`; the file
   imports only `node:` modules and `vitest`; and it replaces the two cases the design verdict names as false.
3. **The end-to-end pin.** The case in `tests/distribution.test.ts` materializes a generated consumer, serves a
   `127.0.0.1` fixture that refuses `npm ping` for the whole of each child run, and asserts the release run exits 1 with
   the proof failing on the registry diagnostic and no case collected, and the ordinary run exits 0 with skips; the
   rival runs (a configuration that cannot load, a collection failure, an unrelated failed assertion, a timeout) each
   read differently from the release failure, so none of them satisfies the case.
4. **Failing first, then green.** `rm-red-config.log.txt` and `rm-red-distribution.log.txt` read each new case red on
   the `392aa1e0` bytes of the two fix sites, and `rm-green-config.log.txt` and `rm-green-distribution.log.txt` read
   them green on the fixed bytes.
5. **Mutation.** Replacing the forwarding return with `return base` at both sites (`rm-mutation.diff.txt`) reddens the
   vendored case and the end-to-end case, each with an assertion failure that distinguishes the mutation
   (`rm-mutation-config.log.txt`, `rm-mutation-distribution.log.txt`); the third red, the pinned template text in
   `tests/src/core/compilers.test.ts` (`rm-mutation-src-core.log.txt`), is a byte pin of the changed span, not a proof of
   the behaviour.
6. **Host log.** With the registry at a closed local port, `npm run test:distribution -- --mode release` exits 1 with
   the release gate's registry message and the same command in ordinary mode exits 0 with skips

7. **Prose.** `guides/scaffold.md`'s release paragraph states that the root project factories carry the invocation mode
   into each project, the template comments state what the code does, and no guide, TSDoc, or comment in the owned files
