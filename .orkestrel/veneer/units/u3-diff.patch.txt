+/**
+ * Reads the sRGB channels a browser paints for one CSS color expression.
+ *
+ * @param value - Any fully substituted color expression the CSSOM accepts, such as the computed
+ *   value of a custom property or of a resolved color property.
+ * @returns The painted channels on the 0-255 scale with the alpha on the 0-1 scale, or `undefined`
+ *   when the CSSOM refuses the expression or the canvas is unavailable.

+ * @remarks
+ * A modern color function computes to itself, so `getComputedStyle` hands back `oklch(...)` rather
+ * than channels, and a `color-mix()` outside the sRGB gamut serializes with a negative channel.
+ * Painting the expression onto a one-pixel canvas and reading the pixel back answers what the
+ * engine actually renders in either case, which is what a `-rgb` triplet has to equal. The read
+ * goes through the same engine the treatment paints with, so it needs no conversion of its own.

+ * A `var()` reference resolves nowhere here, because a canvas has no cascade. Read the token
+ * first, then pass what the cascade computed for it.

+export function readPaintedColor(
+	value: string,

+	const probe = document.createElement('span')
+	probe.style.color = value

+	const canvas = document.createElement('canvas')
+	canvas.width = 1
+	canvas.height = 1
+	const context = canvas.getContext('2d')
+	if (context === null) return undefined
+	context.fillStyle = value

+	const [red, green, blue, alpha] = context.getImageData(0, 0, 1, 1).data
+	if (red === undefined || green === undefined || blue === undefined || alpha === undefined) {
+		return undefined
+	}

+# Tokens
+
+> The custom-property contract Veneer ships, and the Bootstrap 5.3 aliases it answers.
+
+Veneer declares one canonical token per value and one `--bs-*` alias per Bootstrap root variable.
+The canonical names live in `src/styles/_tokens.scss`, the theme retunes in `src/styles/_theme.scss`,
+and the same names are published as the frozen `TOKEN_NAMES` registry in `src/core`. A registry path
+is its name: `TOKEN_NAMES.color.primary.subtle` is `--vn-color-primary-subtle`.
+
+Every value traces to one of three sources, named in the `Source` column of each table that follows.
+
+| Source      | Meaning                                                                                       |
+| ----------- | --------------------------------------------------------------------------------------------- |
+| `elements`  | Read from Elements' built showcase on 2026-09-20; the cell names the reading                  |
+| `bootstrap` | Bootstrap 5.3.8's own value, retained because no Elements specimen measures it                |
+| `derived`   | An expression over other Veneer tokens; the cell gives the expression or the value it targets |
+
+## Reference map
+
+### Factors
+
+Each factor is a registered `<number>` that inherits, so an invalid value falls back to `1` rather
+than dropping every length built on it.
+
+| Token                   | Value | Source                                                 | Alias |
+| ----------------------- | ----- | ------------------------------------------------------ | ----- |
+| `--vn-factor-density`   | `1`   | `derived` — the neutral multiplier of the space scale  | none  |
+| `--vn-factor-radius`    | `1`   | `derived` — the neutral multiplier of the radius scale | none  |
+| `--vn-factor-elevation` | `1`   | `derived` — the neutral multiplier of the shadow scale | none  |
+| `--vn-factor-motion`    | `1`   | `derived` — the neutral multiplier of the durations    | none  |
+
+A factor takes effect where the scale it multiplies is declared. Veneer declares the scales at
+`:root`, so a factor set on the root element rescales the document. A subtree that sets a factor
+alone keeps the root's lengths, because a custom property carries its `var()` references already
+substituted; to rescale a subtree, declare the factor and the scale together on that subtree.
+

+## Bootstrap variables Veneer retains
+
+Four root variables paint a component Veneer does not own yet, and each keeps Bootstrap's value in
+the alias scope until the component that paints it lands its canonical token: `--bs-btn-close-filter`,
+`--bs-carousel-indicator-active-bg`, `--bs-carousel-caption-color`, and
+`--bs-carousel-control-icon-filter`. A data URI cannot read a custom property, so the forward path
+for each is a `mask-image` treatment in the unit that owns the component.
+
+Bootstrap also retunes five image-valued variables under a dark component selector and declares no
+light counterpart at theme scope: `--bs-form-select-bg-img`, `--bs-form-switch-bg`,
+`--bs-navbar-toggler-icon-bg`, `--bs-accordion-btn-icon`, and `--bs-accordion-btn-active-icon`.
+Veneer declares each in its dark scope with Bootstrap's own value. A light island nested inside a
+dark one therefore inherits the dark asset, and the component unit that owns each one closes that.

+## Customization
+
+Override a canonical token in your own unlayered `:root` rule. Veneer declares its tokens inside
+`@layer theme`, so an unlayered rule wins, and every derived tier and alias follows the override
+because each one is an expression over the token you changed.
+
+```css
+:root {
+	--vn-factor-density: 1.25;
+	--vn-color-primary-base: oklch(0.55 0.2 150);
+}
+```
+
+That rule rescales the space scale from 6 px to 7.5 px at `--vn-space-3`, repaints `--bs-primary`
+in the color you named, and carries that color through `--bs-primary-bg-subtle`,
+`--bs-primary-text-emphasis`, and `--bs-primary-border-subtle`. It carries into the dark scope too:
+a `[data-bs-theme='dark']` island keeps the dark primary and mixes its own tiers from it.
+`tests/src/styles/integration.test.ts` transcribes the rule and reads each of those results.
+
+## Departures from Bootstrap
+
+Veneer takes Elements' identity wherever a specimen measures it, so these values differ from the
+Bootstrap release they alias.

+import { readPaintedColor } from '../../../setupStyles.js'

+/**
+ * Determines whether two color expressions paint the same color.
+ *
+ * @param first - A fully substituted color expression.
+ * @param second - A fully substituted color expression.
+ * @returns `true` when both paint channels that agree within a browser's own rounding; `false`
+ *   otherwise, including when either expression paints nothing readable.
+ *
+ * @remarks
+ * This is `matchesColor` over the pair `readPaintedColor` returns, which is what a calibration
+ * comparison needs: a recorded reading is an `oklch()` or `oklab()` string, a derived tier resolves
+ * to a `color-mix()`, and a computed color function hands back itself rather than channels, so
+ * neither side can be read as channels without painting it first.
+ *
+ * It sits beside the style proofs rather than in `tests/setupStyles.ts`, because that module is
+ * also imported by the Node project that proves it, and `@orkestrel/test/browser` refuses to load
+ * outside browser mode.
+ */
+export function matchesPaintedColor(first: string, second: string): boolean {
+	const left = readPaintedColor(first)
+	const right = readPaintedColor(second)
+	if (left === undefined || right === undefined) return false
+	return matchesColor(left, right)
+}
