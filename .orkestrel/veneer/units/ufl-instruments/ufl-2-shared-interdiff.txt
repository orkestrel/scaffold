> ### Overflow utilities
> 
> The overflow key ships whole in the utilities layer from the `src/styles/utilities/_overflow.scss`
> partial. The `.overflow-*` classes set the `overflow` shorthand, and the `.overflow-x-*` and
> `.overflow-y-*` classes set the `overflow-x` and `overflow-y` properties, each to the `auto`,
> `hidden`, `visible`, and `scroll` values. The release's overflow entries are not responsive, so no
> overflow class writes a breakpoint infix.
> 
> The partial writes the shorthand entry, then the `overflow-x` entry, then the `overflow-y` entry, in
> the release's map order, so an axis class beats the shorthand on its own axis whatever order the
> classes are written in: an element carrying the `.overflow-x-auto` and `.overflow-hidden` classes
> scrolls across and clips down. Each axis keeps its own value, with one rule the browser applies: an
> axis at the `visible` value beside an axis at another value computes as the `auto` value, so an
> element carrying the `.overflow-x-visible` and `.overflow-y-scroll` classes scrolls on the x and the
> y axis. Every declaration carries the `!important` flag the release writes, and none reads a token.
> 
> The `tests/src/styles/utilities/overflow.test.ts` proof reads every value of the shorthand on the x
> and the y axis, the content spilling past its box under the `visible` value alone, each pair of axis
> classes as the browser computes it with a wheel scrolling each axis apart from the other, the axis
> entries over the shorthand, the absence of an infixed class, a dark island and the density factor,
> the priority over a later unlayered rule, and the escape inside the utilities layer. The overflow
> key carries no recorded departure.
