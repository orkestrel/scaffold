# CL11 audit round 1 — subjective lane report

## Rulings

Claims 1 through 7, 10 through 12, 14 through 18, and 21 through 22 CONFIRMED against the tree, each
with a named mutation. The load-bearing exceptions follow.

- **Claim 1, the seam — CONFIRMED as a sanctioned boundary stub.** The injected collaborator is reached
  through a module global, which is exactly what the seam rule calls a missing injection point rather
  than an untestable truth. The resizer the case supplies is real, not inert: its accepted call awaits
  the installed verb and the case asserts the visit landed before the refusal is armed. On the
  kindness-or-coupling question, the default is the correct call, not a convenience — the visitor is
  called from four files this unit does not own, so a required parameter would have forced edits outside
  the owned set to buy nothing. The parameter is typed, named by an exported type, documented at its own
  tag, and passed by one case; it is visible rather than hidden.
- **Claim 2 — CONFIRMED with one wording correction.** The installed verb posts its message and settles
  on a done or fail event, and the orchestrator's handler posts the failure in one branch only, for an
  unknown frame id. So no reachable refusal, and the seam rests on a reading that holds. The correction:
  the verb does not *ignore* the dimensions — it applies them — it **validates** neither, which is the
  operative point the claim needed.
- **Claim 8 — CONFIRMED as to the reading; the sufficiency claim REFUTED.** The copy-against-specimen
  comparison compares one declared property per key, so a copy differing in anything else photographs
  unchallenged, and **it cannot see the failure the lift exists for at all**: a blank frame resolves the
  same computed value as a painted one. It also runs after every placement call, so in a capture run the
  frames are on disk before it is evaluated; the protection is that the run goes red, not that the file
  is withheld.
- **Claim 9 — CONFIRMED for two keys; REFUTED as a general property.** The table and link keys carry a
  cross-mode difference assertion. For the container and row the case asserts the opposite — that the
  reading is identical in both modes — so nothing would catch a dark twin identical to its light frame.
  The twins are distinct today, and that distinctness rests on a paint no assertion reads.
- **Claim 26 — registering rather than striking was right; the byte-identity measurement is REFUTED.**
  The ruling holds and the duplication was confirmed by eye. The measurement does not: the two files
  differ in pixel height, and PNGs of different height are not byte-identical.
- **Claim 27 — the shipped design does NOT hold the blank-frame failure off. REFUTED.** The
  copy-against-specimen comparison detects a copy whose cascade differs, which is a different failure.
  The frames are good today; the suite would not say so if they stopped being.

## Findings

**29. Two registered dark twins have no reading that distinguishes them.** The registry's own test —
that a pair of frames whose paint never moved would be one frame registered twice — is applied to two
keys and to nothing else. Those two twins are registered, photographed, and placed on the strength of a
mode change nothing in the suite reads. Does not force a round: the twins are distinct today.

**30. The cascade state assertion forbids a second key in the same family, which is not the rule it
states.** It enforces uniqueness of the first name segment, so a legitimate second key in a family
collides though it is a different specimen. Per-key uniqueness is already enforced correctly one case
earlier. The next maintainer meets a red assertion whose stated reason does not describe what stopped
them, and the cheapest way out is to loosen the check rather than understand it.

**31. "Specimen" names two different things on one module's public surface** — the fixture registry that
records ad-hoc mounted nodes, and the showcase's declared labelled specimens, which is the sense the
application already owns. One term, two concepts, one barrel. CL11 did not create the collision; it added
the export that makes it visible, and chose the sense the application already fixed, which is the right
side of the ambiguity to be on. Cannot be closed inside this unit's scope.

**32. The reason recorded for shipping no blank-frame guard is wrong, and the guard is reachable
today.** The unit's report says a successor "needs the base the frame reader resolves against". **No base
is needed.** The installed portfolio's place method returns the written absolute path, the portfolio
records that same path, and the installed frame reader explicitly accepts it — the unit passed the
relative directory string, which that reader's own doc block names as the wrong input. The gap was
recorded as irreducible on a mis-read of an installed contract, and the seam rule asks for the seam to be
looked for before the gap is accepted. **A successor reading the record will spend its round chasing a
base path that does not exist.**

## Referral

The cascade case places every frame before its comparison is evaluated, so in a capture run a frame shot
on a copy that paints differently is written to disk and the run then goes red. Whether a red capture run
leaving files on disk matters downstream is a correctness question this lane does not rule on.

**Verdict: accept**
