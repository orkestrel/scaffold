**F1 — `scanPositional`'s `mandated` exclusion is proved by nothing; its removal leaves the suite green.**

Right looks like one case in `tests/setupBrowser.test.ts` beside the inventory row, using the same `scene.load` plant: load `@layer elements { details summary { margin: 0 } }`, expect `scanPositional(rules, ['details','summary'], MANDATED_TAG_PAIRS)` to equal `[]` and the same call with `[]` for `mandated` to equal `['details > summary']`. **F2 — the reader cannot see a same-tag positional rule, and the retired grammar could.**
`tests/setupBrowser.ts:1049` skips `outer === inner`, so `li + li`, `tr + tr`, `option + option`, and `p + p` are never mounted and never compared. `matchesLooseTagPair` flagged any selector joining two tag-naming compounds, same tag included (`f5a.diff:5938-5957`). Why it matters: the case title at `index.test.ts:36` and the guide sentence at `guides/veneer.md:205` both state the policy without that exception, so the proof is narrower than the claim it carries, and adjacent-sibling rules between same-tag elements are the most ordinary positional rule a stylesheet acquires. Right looks like moving the guard so it bounds only the nesting comparison, or removing it entirely — mounting a tag inside itself is harmless here because nothing parses markup — which adds one mount per tag to a cross product that already runs 1039 ms.

**F3 — `FORBIDDEN_SIGNATURES` says "identifiers" and the pass is a raw substring test.**
`tests/setupConformance.ts:227-242` documents the list as "the identifiers a forbidden runtime leaves in bundled output", but `@popperjs` is a package scope and `tailwind` is a bare word, and `scanForbiddenBuild` matches them with `built.includes(signature)` at line 534 — no word boundary, comments and string literals included. Why it matters: one concept, one term. The name, the doc, and the mechanism disagree, so a reader cannot tell from the constant whether adding a member is safe, and the two non-identifier members are exactly the ones that will match Veneer's own future text. Right looks like either matching identifiers with a word-boundary pattern and keeping the doc's word, or renaming the doc's "identifiers" to "text markers" and saying in the `@remarks` that a member is matched anywhere in the file including a comment. The false-positive exposure itself is the objective lane's call — see the referrals.

**F4 — only half of `ELEMENT_TAGS` is bound to the layer.**
`tests/setupCases.test.ts:558-581` binds the partial column to `readdirSync('src/styles/elements')` exactly, and binds the tags column to nothing but its own shape (non-empty, lowercase-tag-shaped, mandated parents present). ## Attacked and held

- **The `mandated` third parameter rather than an import.** Attacked as a needless argument; held. `tests/setupBrowser.ts` gains no dependency on `tests/setupCases.ts`, which keeps the browser reader free of the data module, and the parameter is what lets a case vary the exclusion list — which is exactly what F1's missing case needs.
- **The `rules: readonly CSSStyleRule[]` parameter as a design choice.** Attacked as coupling to the CSSOM for a body that only reads `selectorText`; held as a design intent (the caller cannot hand-write selector text) but overturned on the testability ground in claim 15(a), where the narrower parameter buys the proof.
- **`MANDATED_TAG_PAIRS` placed in `setupCases.ts` rather than `setupCalibration.ts`.** Attacked: the pairs are copied from a source outside this workspace (the HTML content model), which is `setupCalibration.ts`'s own stated admission criterion at lines 1-6. Held: `setupCases.test.ts:572-581` binds the two tables to each other, and splitting them would put a table and the case that validates it in different modules for a gain no reader collects.
- **Case ordering contamination in `index.test.ts`.** Attacked: the planted sheet enters `document.head` and could move the shipped-layer reading. Held in both directions — `collectLayer` resolves through `readCascadeSheet` (`setupBrowser.ts:980`) and never sees the planted sheet, and `scanPositional` matches only the selectors passed to it, so neither case can contaminate the other whatever order they run in.
- **`ELEMENT_TAGS` including `html` and `body`, which the retained probe omitted.** Attacked as an unvalidated widening; held — `test:src:styles exit=0` on the tree that includes them (gate log:4196).
- **The `@popperjs` plant proving the wrong pass.** Attacked; held — the assertion at `setupConformance.test.ts:1161` expects the full specifier `@popperjs/core`, which only the specifier pass can produce, so the plant pins which pass answered rather than merely that one did.
