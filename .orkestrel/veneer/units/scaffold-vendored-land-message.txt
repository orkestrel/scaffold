Account for a guide the directory index maps, and permit a literal color in the token file

The vendored prose policy admitted a top-level guide only when it was
the package's own, the map, or a catalog row, so a package with a
second published face (Veneer's stylesheet, with its token reference)
reported its own guide as a stray. A guide is now also accounted for
when a directory-index row of `guides/README.md` maps a workspace
directory to it. A row is the workspace's statement that the guide
documents that directory; a mirror is linked in prose and mapped by
no row, so a mirror the catalog stops registering still reports.

`readPolicyIndex` reads those rows after blanking fenced code; the link
cell admits the ordinary CommonMark forms (a `./` prefix, a title in
any quote form, angle brackets, a fragment) and rejects the nested,
absolute, and parent forms; its two capture groups carry distinct
names because a duplicate name is a syntax error before Node 23, the
package's floor. Every control row names its expected path, and the
accounting case reads nothing particular to one checkout: the change
was run in Veneer and Test before landing.

The styles rule now says the one file a literal color may appear in is
`_tokens.scss`, where the token itself is declared.

Both files are vendored, so `host.json` is restaged and this lands as
a vendored-only release; every target re-pins and repairs after it.
