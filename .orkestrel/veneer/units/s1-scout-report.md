`--src` is one comma-separated string on `new` only. The closed set is `Environment` / `ENVIRONMENTS` / `SRC_MATRIX` (`core`, `browser`, `server`). Parsing keeps the raw string; `selectionToEnvironments` maps it onto that set in declared order and throws on any other token, including `styles`. `createBlueprint` defaults `src` to none. The compile gate requires at least one env on `src` or `app`, forbids duplicates, and advisories a multi-`src` selection that omits `core`. Reading verbs ignore `--src` and recover the axis from physical `src/<environment>` directories via `targetToEnvironments`.

Generation is `SRC_MATRIX`-driven, not a styles-capable loop. Root `tsconfig.json` (content) gets `@src/<env>` and published `@orkestrel/<name>…` paths. Root `vite.config.ts` (content) inlines `CONFIG_TEMPLATES.factories.src.<env>` and lists `srcCore`/`srcBrowser`/`srcServer`. Each selected env also gets content-owned `configs/src/vite.<env>.config.ts` and `configs/src/tsconfig.<env>.json`. Scripts and `exports` come from `blueprintToScripts` / `srcToExports` inside a birth-owned `package.json`. Barrels `src/<env>/index.ts` are birth and empty. Shared setup is birth `tests/setup.ts` plus `setupBrowser.ts` / `setupServer.ts` only when those hosts are selected. Entry tests `tests/src/<env>/index.test.ts` are birth and import `@src/<env>`. `dist/src/<env>` is the Vite/tsconfig outDir, not a generated source tree. There is no styles factory, alias, wrapper, script, or seed.

`tests/config.test.ts` pins live workspace shape from directories on disk: aliases, Vitest include/setup per `src:<env>`, wrapper paths, `dist/<axis>/<env>` outDir, and scoped `lib`/`types`. It does not compile a blueprint; it does not assert `build:src:*` / `exports`. It does pin `src/styles/index.scss` as a stylesheet path helper and `@src/core` vs `@src/server` boundary, without requiring a styles environment to exist.

"Reading a target" is directory-fact inference for `src`/`app` plus exact-case files for structural flags.
