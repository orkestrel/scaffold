+## Tokens
+
+Veneer publishes the token registry through the `@orkestrel/veneer` specifier and the cascade that
+declares those tokens through `@orkestrel/veneer/styles`. `src/core/constants.ts` holds the names,
+`src/styles/_tokens.scss` holds the light and dark value maps, and `src/styles/_theme.scss` holds the
+scopes that apply them.
+
+Veneer declares one canonical token per value and one `--bs-*` alias per Bootstrap root variable. A
+registry path is its name: `TOKEN_NAMES.color.primary.subtle` is `--vn-color-primary-subtle`. A
+registry member is a group exactly where the cascade declares more than one property for it, so
+`TOKEN_NAMES.border.color` is a leaf while `TOKEN_NAMES.color.primary` carries `base`, `rgb`, and
+the tiers. A group's own value takes the `base` member and the `-base` suffix with it, which is why
+`--vn-text-body-base` sits beside `--vn-text-body-rgb` and the tierless `--vn-text-secondary` takes
+no suffix at all. Read a channel triplet through the alpha form it exists for:
+`rgba(var(--vn-color-primary-rgb), 0.5)`.
+
+A table with a `Source` column names in each cell where that row's value comes from. The factor
+table, the tier table, and the departures table carry no such column: the factor table's values are
+Veneer's own neutral multipliers, the tier table gives each tier's expression in the row, and the
+departures table sets Veneer's value beside Bootstrap's.
+
+| Source      | Meaning                                                                                       |
+| ----------- | --------------------------------------------------------------------------------------------- |
+| `elements`  | Read from Elements' built showcase on 2026-09-20; the cell names the reading                  |
+| `bootstrap` | Bootstrap 5.3.8's own value, retained because no Elements specimen measures it                |
+| `derived`   | An expression over other Veneer tokens; the cell gives the expression or the value it targets |
+
+### Reference map
+
+#### Factors
+
+Each factor is a registered `<number>` that inherits, so an invalid value falls back to `1` rather
+than dropping every length built on it. Each value here is the neutral multiplier of the scale the
+token's own name gives: `density` multiplies the space scale, `radius` the radius scale,
+`elevation` the shadow scale, and `motion` the durations. A factor is Veneer's own, so it carries
+no `Source` column.
+
+| Token                   | Value | Alias |
+| ----------------------- | ----- | ----- |
+| `--vn-factor-density`   | `1`   | none  |
+| `--vn-factor-radius`    | `1`   | none  |
+| `--vn-factor-elevation` | `1`   | none  |
+| `--vn-factor-motion`    | `1`   | none  |
+
+A factor takes effect where the scale it multiplies is declared. Veneer declares the scales at
+`:root`, so a factor set on the root element rescales the document. A subtree that sets a factor
+alone keeps the root's lengths, because a custom property carries its `var()` references already
+substituted; to rescale a subtree, declare the factor and the scale together on that subtree.
+
+#### Palette and gray ramp
+
+No Elements specimen measures a hue outside the semantic roles, so every value here is Bootstrap's.
+

+### Bootstrap variables Veneer retains
+
+`--bs-btn-close-filter`, `--bs-carousel-indicator-active-bg`, `--bs-carousel-caption-color`, and
+`--bs-carousel-control-icon-filter` paint a component Veneer does not own yet. Each keeps
+Bootstrap's value in the alias scope until the component that paints it lands its canonical token. A
+data URI cannot read a custom property, so the forward path for each is a `mask-image` treatment in
+the unit that owns the component.
+
+Bootstrap also retunes `--bs-form-select-bg-img`, `--bs-form-switch-bg`,
+`--bs-navbar-toggler-icon-bg`, `--bs-accordion-btn-icon`, and `--bs-accordion-btn-active-icon` under
+a dark component selector, and declares no light counterpart at theme scope. Veneer declares each in
+its dark scope with Bootstrap's own value. A light island nested inside a dark one therefore
+inherits the dark asset, and the component unit that owns each one closes that.
+
+### Customization
+
+Override a canonical token in your own unlayered rule. Veneer declares its tokens inside
+`@layer theme`, so an unlayered rule wins, and every derived tier and every `--bs-*` alias follows
+the override because each one is an expression over the token you changed.
+
+```css
+:root {
+	--vn-factor-density: 1.25;
+	--vn-color-primary-base: #2e7d32;
+	--vn-color-primary-rgb: 46, 125, 50;
+}
+
+[data-bs-theme='dark'] {
+	--vn-color-primary-base: #66bb6a;
+	--vn-color-primary-rgb: 102, 187, 106;
+}
+
+.brand-veil {
+	background-color: rgba(var(--vn-color-primary-rgb), 0.5);
+}
+```
+
+That rule rescales the space scale from 6 px to 7.5 px at `--vn-space-3`, repaints `--bs-primary` in
+the color you named, and carries that color through `--bs-primary-bg-subtle`,
+`--bs-primary-text-emphasis`, and `--bs-primary-border-subtle`. The channel triplet is a literal
+rather than an expression, so override `--vn-color-primary-rgb` alongside the fill; the
+`.brand-veil` rule, and any other rule of yours reading the triplet, otherwise keeps painting the
+old brand. That rule is also the alpha form itself: a triplet is comma-separated, so it takes
+`rgba(triplet, alpha)` and not the slash syntax a modern `rgb()` accepts. The
+`[data-bs-theme='dark']` rule is what carries the brand into a dark island, which keeps its own fill
+and mixes its own tiers from it. `tests/src/styles/integration.test.ts` executes this recipe and
+reads the rescaled spacing, the fill, the subtle, emphasis, and border tiers, the triplet, the
+translucent fill the alpha form paints, what a fill override without the triplet leaves that
+translucent fill painting, and the dark island's own fill and tiers.

+import { isRecord } from '@orkestrel/contract'
+
+/** Names the prefix every canonical custom property the token registry carries begins with. */
+export const TOKEN_PREFIX = '--vn-'
+
+/**
+ * Collects every node of a token registry, each paired with the path it sits at.
+ *
+ * @param value - The registry node to walk: a group, or the custom-property name at a leaf.
+ * @param path - The group keys already walked, outermost first. Default: the empty path.
+ * @returns The node itself, then every node beneath it, each paired with its own path, in registry
+ *   order. A group yields its own entry before its members, so a caller that wants the groups and a
+ *   caller that wants the leaves both read one walk.
+ *
+ * @remarks
+ * This module is loaded by every project, which is what puts the walk here: the Node core proof
+ * reads the registry's shape from it, and `tests/setupStyles.ts` reduces the same walk to the
+ * canonical names the shipped cascade must declare.
+ */
+export function collectTokenNodes(
+	value: unknown,
+	path: readonly string[] = [],
+): ReadonlyArray<readonly [readonly string[], unknown]> {
+	if (!isRecord(value)) return [[path, value]]
+	return [
+		[path, value],
+		...Object.entries(value).flatMap(([key, member]) => collectTokenNodes(member, [...path, key])),
+	]
+}
+
+/**
+ * Normalizes one selector's text for comparison.
+ *
+ * @param selector - The selector text to normalize.
+ * @returns The text with every whitespace run collapsed to one space, the surrounding whitespace
+ *   trimmed, and every quotation mark removed.
+ *
+ * @remarks
+ * This module is loaded by every project, which is what puts the normalizer here: the Node oracle
+ * in `tests/setupStyles.ts` matches a postcss selector with it, and the browser scope reader in
+ * `tests/setupBrowser.ts` matches a CSSOM `selectorText` with the same rule. An engine writes
+ * `[data-bs-theme=dark]` where an author wrote `[data-bs-theme='dark']`, and a minifier moves the
+ * whitespace in a selector list, so an authored spelling and an engine's spelling compare equal
+ * only after each goes through this.
+ */
+export function normalizeSelectorText(selector: string): string {
+	return selector.replace(/["']/gu, '').replace(/\s+/gu, ' ').trim()
+}

+/**
+ * Reads the sRGB channels a browser paints for one CSS color expression.
+ *
+ * @param value - Any fully substituted color expression the CSSOM accepts, such as the computed
+ *   value of a custom property or of a resolved color property.
+ * @returns The painted channels on the 0-255 scale with the alpha on the 0-1 scale, or `undefined`
+ *   when the CSSOM refuses the expression or the canvas is unavailable.
+ *
+ * @remarks
+ * The installed `parseCSSColor` export resolves a color expression by reading a probe element's
+ * computed `color`, and a modern color function computes to itself, so an `oklch()` or `oklab()`
+ * recording comes back unread and the answer is absence. That is the one reading this adds: a
+ * `color-mix()` outside the sRGB gamut also serializes with a negative channel there. Painting the
+ * expression onto a one-pixel canvas and reading the pixel back answers what the engine actually
+ * renders in either case, which is what a `-rgb` triplet has to equal. The read goes through the
+ * same engine the treatment paints with, so it needs no conversion of its own.
+ *
+ * A `var()` reference resolves nowhere here, because a canvas has no cascade. Read the token
+ * first, then pass what the cascade computed for it.
+ */
+export function readPaintedColor(
+	value: string,
+): readonly [number, number, number, number] | undefined {
+	const probe = document.createElement('span')
+	probe.style.color = value
+	if (probe.style.color === '') return undefined
+	const canvas = document.createElement('canvas')
+	canvas.width = 1
+	canvas.height = 1
+	const context = canvas.getContext('2d')
+	if (context === null) return undefined
+	context.fillStyle = value
+	context.fillRect(0, 0, 1, 1)
+	const [red, green, blue, alpha] = context.getImageData(0, 0, 1, 1).data
+	if (red === undefined || green === undefined || blue === undefined || alpha === undefined) {
+		return undefined
+	}
+	return [red, green, blue, alpha / 255]
+}

+/** Carries one `box-shadow` layer as the browser resolved it. */

+	/** Holds the layer's offsets, blur, and spread in order, each in pixels. */

+	/** Holds whether the layer paints inside the box. */

+/**
+ * Extracts the layers one resolved `box-shadow` value carries.
+ *
+ * @param value - The resolved `box-shadow` value, such as the one `readStyle` returns.
+ * @returns One entry per layer, in paint order. A layer's first token is its color, the `inset`
+ *   keyword is taken out wherever it appears, and every remaining token is read as a pixel length
+ *   through `Number.parseFloat`. A layer carrying no token at all is dropped.
+ *
+ * @remarks
+ * A browser resolves `box-shadow` with the color first and every length in pixels, whatever the
+ * author wrote, so comparing the parts is what lets a proof assert the lengths as numbers and the
+ * color through {@link matchesPaintedColor} rather than against one engine's serialization of the
+ * whole value.

+export function extractShadowLayers(value: string): readonly ShadowLayer[] {
+	return splitTopLevelList(value).flatMap((layer) => {
+		const tokens = splitTopLevelValues(layer)
+		const parts = tokens.filter((token) => token !== 'inset')

+		if (color === undefined) return []

+		return [{ color, lengths, inset: tokens.length !== parts.length }]
+	})

+/** Names the combinators CSS joins two compound selectors with. */
+export type SelectorCombinator = ' ' | '>' | '+' | '~'
+
+/**
+ * Carries the bare tags one compound selector names and the combinator reaching that compound.
+ */
+export interface SelectorCompound {
+	/**
+	 * Holds every bare tag the compound names, lowercased, in the order the compound writes them. A
+	 * compound naming one tag holds one; an `:is()` or `:where()` list holds one per bare-tag
+	 * alternative, a nested list's alternatives included, because the compound matches whichever of
+	 * them the element carries.
+	 */
+	readonly tags: readonly string[]
+	/** Holds the combinator reaching this compound, or `undefined` where it is the first. */
+	readonly combinator: SelectorCombinator | undefined
+}
+
+/** Carries one character of walked selector text with the state the walk read it under. */
+export interface SelectorStep {
+	/** Holds the character itself, as the one UTF-16 unit the walked text writes at `index`. */
+	readonly char: string
+	/** Holds the character's position in the walked text, so `text[step.index]` is `step.char`. */
+	readonly index: number
+	/**
+	 * Holds how many groups enclose the character. A group's own opener and its matching closer
+	 * carry the depth the group sits at rather than the depth inside it, so a whole group reads at
+	 * the depth its caller wrote it at and its contents read one deeper.
+	 */
+	readonly depth: number
+	/**
+	 * Holds whether the character is text rather than selector syntax: a quotation mark, every
+	 * character between one and its match, a backslash, and the character a backslash escapes. A
+	 * literal character opens no group, closes none, and separates nothing.
+	 */
+	readonly literal: boolean
+}
+
+/**
+ * Walks selector text once, reporting each character with the nesting and quotation it sits in.
+ *
+ * @param text - The selector text to walk. A declaration value carries the same grammar for the
+ *   part of it this walk reads, which is why {@link splitTopLevelList} serves both.
+ * @returns One step per UTF-16 unit of `text`, in written order and at the same index.
+ *
+ * @remarks
+ * This is the grammar every selector reader in this module reads through — {@link findGroupEnd},
+ * {@link splitTopLevelList}, {@link splitTopLevelCompounds}, {@link normalizeComplexSelector}, and
+ * {@link extractCompoundTags} — so a form one reader must not misread cannot be misread by one
+ * reader alone.
+ *
+ * The grammar covers strings, escapes, and groups. A `"` or a `'` opens a string that the same
+ * mark closes, and every character of it, the marks included, is literal. A `\` and the character
+ * after it are literal wherever they appear, so an escaped quotation mark leaves its string open
+ * and an escaped `+` belongs to the identifier around it rather than joining two compounds. A `(`
+ * or a `[` opens a group that a `)` or a `]` closes, groups nest, and `depth` counts the ones
+ * still open; a closer with no opener leaves `depth` at zero.
+ *
+ * Text outside that grammar is walked rather than refused. An unterminated string leaves every
+ * character after its opening mark literal to the end of the text, and an unclosed group leaves
+ * every character after it one deeper to the end, which is what makes {@link findGroupEnd} answer
+ * `text.length` for a group that never closes.
+ */
+export function walkSelector(text: string): readonly SelectorStep[] {
+	const steps: SelectorStep[] = []
+	let depth = 0
+	let quote: '"' | "'" | undefined
+	let escaped = false
+	for (const [index, char] of text.split('').entries()) {
+		const quoted = quote !== undefined
+		const literal = escaped || quoted || char === '\\' || char === '"' || char === "'"
+		if (escaped) escaped = false
+		else if (char === '\\') escaped = true
+		else if (quoted) quote = char === quote ? undefined : quote
+		else if (char === '"' || char === "'") quote = char
+		else if (char === ')' || char === ']') depth = Math.max(0, depth - 1)
+		steps.push({ char, index, depth, literal })
+		if (!literal && (char === '(' || char === '[')) depth += 1
+	}
+	return steps
+}
+
+/**
+ * Splits text on the commas that separate its top-level items.
+ *
+ * @param text - The selector or declaration value to split.
+ * @returns Each item, trimmed, with an empty item dropped. A comma the grammar
+ *   {@link walkSelector} states puts inside a group or a string belongs to the item around it and
+ *   is not a split point, so `:is(h1, h2) + p` stays one selector, `[title="a,b"] p` stays one,
+ *   and `rgba(0, 0, 0, 0.5) 0 1px 2px` stays one shadow layer.
+ */
+export function splitTopLevelList(text: string): readonly string[] {
+	const parts: string[] = []
+	let current = ''
+	for (const step of walkSelector(text)) {
+		if (step.char === ',' && step.depth === 0 && !step.literal) {
+			parts.push(current)
+			current = ''
+			continue
+		}
+		current += step.char
+	}
+	parts.push(current)
+	return parts.map((part) => part.trim()).filter((part) => part.length > 0)
+}
+
+/**
+ * Normalizes one complex selector so every combinator stands alone between its compounds.
+ *
+ * @param complex - The complex selector text to normalize.
+ * @returns The text with each `>`, `+`, and `~` the grammar {@link walkSelector} states reads as a
+ *   combinator surrounded by one space, every other top-level whitespace run collapsed to one
+ *   space, and the result trimmed, so `h1+p` and `h1 + p` read the same. Every other character is
+ *   copied through byte for byte, so `[title="a  b"]` and `[title="a b"]` stay the different
+ *   selectors they are, `:is(h1,  p)` keeps its own spacing, and the escaped `+` in `h1\+p` stays
+ *   part of the one identifier it belongs to.
+ */
+export function normalizeComplexSelector(complex: string): string {
+	let normalized = ''
+	let spaced = false
+	for (const step of walkSelector(complex)) {
+		const top = step.depth === 0 && !step.literal
+		if (top && /\s/u.test(step.char)) {
+			spaced = true
+			continue
+		}
+		if (top && (step.char === '>' || step.char === '+' || step.char === '~')) {
+			if (normalized.length > 0) normalized += ' '
+			normalized += step.char
+			spaced = true
+			continue
+		}
+		if (spaced && normalized.length > 0) normalized += ' '
+		spaced = false
+		normalized += step.char
+	}
+	return normalized
+}
+
+/**
+ * Splits one normalized complex selector into the compounds and combinators it writes.
+ *
+ * @param complex - The complex selector's text, as {@link normalizeComplexSelector} returns it.
+ * @returns Each compound in selector order, with a `>`, `+`, or `~` written between two of them
+ *   returned in its own place between them. Whitespace the grammar {@link walkSelector} states
+ *   puts inside a group or a string belongs to the compound around it and is never a split point,
+ *   so `:is(h1, p)` stays one compound, `[title='a b']` stays part of the compound carrying it,
+ *   the escaped quotation mark in `[title="a\" b"]` leaves the string open so the space after it
+ *   still belongs to that attribute value, and `h1\ p` is the one identifier it escapes to.
+ *
+ * @remarks
+ * {@link splitTopLevelValues} answers the same question for a declaration value and cannot be used
+ * here: it emits a bare `/` as a token of its own, which a declaration value needs and a selector
+ * never writes, and it tracks no bracket depth, which an attribute selector needs.
+ */
+export function splitTopLevelCompounds(complex: string): readonly string[] {
+	const compounds: string[] = []
+	let current = ''
+	for (const step of walkSelector(complex)) {
+		if (step.depth === 0 && !step.literal && /\s/u.test(step.char)) {
+			if (current.length > 0) compounds.push(current)
+			current = ''
+			continue
+		}
+		current += step.char
+	}
+	if (current.length > 0) compounds.push(current)
+	return compounds
+}
+
+/**
+ * Locates the character closing the parenthesis or bracket that opens at one position.
+ *
+ * @param text - The selector text to walk.
+ * @param open - The index of the `(` or `[` the group opens with.
+ * @returns The index of the `)` or `]` closing that group: the first closer the grammar
+ *   {@link walkSelector} states reads back at the opener's own depth, so a nested group counts as
+ *   part of this one and a closer inside quotation or behind a backslash closes nothing. An
+ *   unclosed group returns `text.length`, so a caller slicing to it takes the rest of the text.
+ */
+export function findGroupEnd(text: string, open: number): number {
+	const steps = walkSelector(text)
+	const opener = steps[open]
+	if (opener === undefined) return text.length
+	for (const step of steps) {
+		if (step.index <= open || step.literal || step.depth !== opener.depth) continue
+		if (step.char === ')' || step.char === ']') return step.index
+	}
+	return text.length
+}
+
+/**
+ * Extracts every bare tag one compound selector names.
+ *
+ * @param compound - The compound selector text to read.
+ * @returns Each tag the compound names, lowercased, in written order and without a repeat. A
+ *   compound beginning with an identifier names that identifier. An `:is()` or `:where()` list
+ *   names every tag its alternatives name, because the compound matches an element carrying any
+ *   one of them, so `:is(h1, p)` names `h1` and `p`, `:is(.title, h1)` names `h1`, and the nested
+ *   list in `:is(h1, :where(p, .title))` names `p`. A compound naming no tag returns an empty
+ *   list.
+ *
+ * @remarks
+ * Only an `:is()` or a `:where()` argument is read, and only where the grammar
+ * {@link walkSelector} states puts its `(` at the compound's own depth outside quotation. Every
+ * other group — an attribute selector's quoted value, a `:not()` argument, any other functional
+ * pseudo-class — holds its contents one deeper and is passed over whole, so `[title=':is(h1)']`
+ * names no tag and `:not(:is(h1))` names none either: the text inside an attribute string is a
+ * value rather than a selector, and a negated tag is the one tag the compound refuses.
+ *
+ * The leading identifier is read by an anchored match rather than by the walk, because it is the
+ * one thing a compound writes before any grammar applies.
+ */
+export function extractCompoundTags(compound: string): readonly string[] {
+	const tags: string[] = []
+	const bare = compound.match(/^([a-zA-Z][a-zA-Z0-9]*)/u)?.[1]
+	if (bare !== undefined) tags.push(bare.toLowerCase())
+	for (const step of walkSelector(compound)) {
+		if (step.char !== '(' || step.depth !== 0 || step.literal) continue
+		if (!/:(?:is|where)$/u.test(compound.slice(0, step.index))) continue
+		const inside = compound.slice(step.index + 1, findGroupEnd(compound, step.index))
+		for (const alternative of splitTopLevelList(inside))
+			for (const tag of extractCompoundTags(alternative)) if (!tags.includes(tag)) tags.push(tag)
+	}
+	return tags
+}
+
+/**
+ * Extracts the tag-naming compounds one complex selector carries, each with the combinator that
+ * reaches it.
+ *
+ * @param complex - One complex selector's text, without a comma list around it.
+ * @returns Each compound that names at least one tag, in selector order. The first carries
+ *   `undefined`; every later one carries the combinator written before it, and a descendant
+ *   combinator where none was written. A compound naming no tag is dropped, so the compounds on
+ *   either side of it read as joined by the combinator that reaches the later one.
+ *
+ * @remarks
+ * A compound stays one entry however many tags it names, because an alternative list inside one
+ * compound selects one element rather than joining two.
+ */
+export function extractSelectorCompounds(complex: string): readonly SelectorCompound[] {
+	const compounds: SelectorCompound[] = []
+	let join: SelectorCombinator | undefined
+	for (const part of splitTopLevelCompounds(normalizeComplexSelector(complex))) {
+		if (part === '>' || part === '+' || part === '~') {
+			join = part
+			continue
+		}
+		const tags = extractCompoundTags(part)
+		if (tags.length > 0) {
+			compounds.push({ tags, combinator: compounds.length > 0 ? (join ?? ' ') : undefined })
+		}
+		join = undefined
+	}
+	return compounds
+}

+/**
+ * Matches a selector joining two bare tags the HTML content model does not mandate.
+ *
+ * @param selector - The selector text to judge, a comma list included.
+ * @returns `true` when any complex selector in the list joins two tag-naming compounds by a
+ *   sibling combinator, or joins them by a descendant or child combinator outside
+ *   {@link MANDATED_TAG_PAIRS}; `false` otherwise. A comma separates complex selectors rather
+ *   than joining compounds, so `h1, p` is a list and never a pair, and an alternative list inside
+ *   one compound is a list too, so `:is(h1, p)` is not a pair either. A selector carrying one
+ *   tag-naming compound or none is never a pair.
+ *
+ * @remarks
+ * A mandated pair states that the descendant has no other legal parent, which is a containment
+ * claim. A sibling combinator makes no such claim, so `details + summary` is a loose pair while
+ * `details summary` is not.
+ *
+ * Where either compound names more than one tag, the pair is loose as soon as one combination of
+ * them is, because the selector reaches every combination it admits.
+ */
+export function matchesLooseTagPair(selector: string): boolean {
+	return splitTopLevelList(selector).some((complex) => {
+		const compounds = extractSelectorCompounds(complex)
+		return compounds.some((compound, index) => {
+			const previous = compounds[index - 1]
+			if (previous === undefined || compound.combinator === undefined) return false
+			if (compound.combinator !== ' ' && compound.combinator !== '>') return true
+			return compound.tags.some((descendant) =>
+				previous.tags.some(
+					(ancestor) =>
+						!MANDATED_TAG_PAIRS.some(
+							([mandated, held]) => mandated === ancestor && held === descendant,
+						),
+				),
+			)
+		})
+	})
+}

+/**
+ * Reduces a group of custom-property names to the union of the names at its leaves.

+ * @typeParam TNode - A custom-property name, or a group whose members are names or groups.

+	? TNode
+	: { readonly [TKey in keyof TNode]: TokenLeaf<TNode[TKey]> }[keyof TNode]
