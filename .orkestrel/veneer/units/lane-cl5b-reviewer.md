## Findings

**10. The declaration reader drops every interpolated property name, so a duplicated block of such declarations is invisible to the gate.** `tests/setupConformance.ts:313` — `/^\s*(--[\w-]+|[a-z-]+)\s*:\s*(\S[\s\S]*)$/u`. Neither alternative admits `#` or `{`, so `--vn-color-#{$role}-subtle: color-mix(...)` at `src/styles/_mixins.scss:171` never enters a block; the whole `role-each` body and the `@each $role in $aliased` body at `:243-247` are recorded as zero-declaration blocks and dropped at `:321`. Failure scenario: a future unit writes the same interpolated-property block in `src/styles/_tokens.scss` and in `src/styles/_theme.scss`, and `scanStyleBlocks().shared` stays `[]` while the rule at `.claude/rules/styles.md` § Prohibitions is broken. Right: admit `#{...}` inside the property group, or report a block whose brace-block text contains an interpolated property as unreadable rather than as empty. **Does not force a fix round** — it narrows a gate that is new coverage either way, and no such duplicate exists in the tree today.

**11. The ≥2 threshold hides a cross-partial repeat that exists in the tree right now.** `tests/setupConformance.ts:340` requires `declarations.length >= 2`. `src/styles/elements/_heading.scss:12-16` and `src/styles/components/_type.scss:12-16` each hold a `@for $level from 1 through 6` body whose sole declaration is `font-size: var(--vn-size-#{9 - $level})` — byte-identical across the two partials, one declaration, therefore no hit. Failure scenario: a reader treats a green `carries no shared written declaration block across style partials` as "no pattern repeats across partials" and the single-declaration class accumulates unchecked. Right: keep the threshold and state the bound in the function's contract, or make the threshold a parameter the tree-is-clean case can tighten. **Does not force a fix round** — the threshold is the one both pre-dispatch instruments used, claim 3 discloses it, and brief 1 item 1 explicitly retained the loops.

**12. Whitespace inside `#{...}` is not folded while whitespace outside it is, so two spellings of one interpolation compare unequal.** `tests/setupConformance.ts:301-303` appends interpolation tokens raw; `:326` folds every other whitespace run to a single space. `var(--vn-size-#{9 - $level})` and `var(--vn-size-#{9-$level})` therefore produce different declaration strings. Failure scenario: a duplicated block is written in the second partial with different spacing inside an interpolation and the gate stays green; no SCSS formatter runs in this repository's gate chain (`format:check` is `oxfmt` over 184 JS/TS files), so nothing normalizes the difference. Right: fold whitespace inside interpolation the same way, or record the bound. **Does not force a fix round.**

**13. `parentheses` has no floor, so a single unmatched `)` would silently disable block detection for the rest of that file.** `tests/setupConformance.ts:306` — `if (token === ')') parentheses -= 1`. Once the counter goes negative, every `parentheses === 0` guard at `:307` and `:312` fails for the remainder of the file and that partial contributes no blocks at all — a silent whole-file under-report with no diagnostic. I found no valid-SCSS construct that triggers it: strings, both comment forms, and interpolation are each consumed as whole tokens before the counter is read. Right: clamp with `Math.max(0, parentheses - 1)`. **Does not force a fix round** — no demonstrated trigger.

**14. Same-file duplication is outside the sweep by construction, and a case pins that as expected.** `tests/setupConformance.ts:333` (`members.slice(index + 1)`) and `tests/setupConformance.test.ts:190-194`, which rewrites `_split.scss` to two identical sibling blocks and asserts `shared` is `[]`. This is faithful to `.claude/rules/styles.md` § Prohibitions, which says "appears in at least two partials", so it is an observation rather than a defect. Recording it so a later unit does not read it as a bug.
