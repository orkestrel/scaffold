`/home/user/veneer-ba/tests/setupStyles.ts`, the `BADGE_GEOMETRY_CASES` doc block (near the file's end, after `FILL_ONLY_RECIPE`): "the recorded padding is `0.65em` and `0.35em` of the badge's own computed size rather than the host's, so the two multiply. No host size separates the two references, because the host is the only free variable. A second host row therefore buys nothing for the reason stated. (It does buy something real and unstated: it catches a rewrite to absolute pixels, which passes at 16 and fails at 24.)
Why it matters: this is a false rationale sitting on the case table the family names as the pattern every sibling unit copies (`<KEY>_*_CASES` in `tests/setupStyles.ts`, family ruling 11), and `.claude/rules/documentation.md` requires a prose claim to be falsified the way a code claim is. What right looks like: state the rival the second host actually excludes — a padding rewritten as an absolute length — and add the case that does separate the two references: mount at a 16px host, `scene.load('.badge { --bs-badge-font-size: 2em; }')`, and assert `padding-left` is `32 × 0.65 = 20.8` rather than `16 × 0.4875 = 7.8`.
