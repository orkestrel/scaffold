Close the shared-block class and make the rule enforce itself (CL5b)

The heading treatment and the image sizing block were each written in two
partials, one in the element folder and one in the component folder. Both are
now mixins, and each consumer keeps its own selector, its layer, and its own
remaining declarations. The built stylesheet is byte-identical before and
after, by size and by digest, and the comparison that establishes it reports
its own changed-byte control as different, so the identity reading means
something.

That duplication had come back in four consecutive units, and every sweep sent
after it was scoped to one folder while the rule is not. So the sweep now
ships. `scanStyleBlocks` reads each partial's written SCSS, groups
declarations by brace block, and reports every cross-file block two partials
share. A case asserts the tree carries none, and the case is proved to fail:
a duplicated block planted in two partials the extractions never touched
reddened exactly that case, named both files, and removing it restored them
byte for byte.

The sweep sweeps every partial under the styles source recursively rather than
the two folders the duplication happened to sit in, so a future subfolder is
covered without anyone remembering to widen it.

It needs no package. The precise instrument this began as used a source-map
library that reaches this tree only as another package's dependency, and
reading the written source instead returns the same answer using nothing
beyond Node's own file reading.

The image fixture has one home, exported from the styles setup module and read
by both image proofs.

Every gate exits 0 on managed Chromium and Edge. The audit is recorded in
scaffold's `.orkestrel/veneer/cl5b-audit-verdict.md` file.
