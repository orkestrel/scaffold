Split the styles setup module and prove position independence in the browser (F5a)

tests/setupStyles.ts splits into tests/setupCases.ts (the case tables,
MANDATED_TAG_PAIRS, and the ELEMENT_TAGS table whose partial column the
setup proof reads back from src/styles/elements/), tests/setupCalibration.ts
(the oracle value lists and calibration readings), and the remaining
tests/setupStyles.ts (the cascade readers, compile helpers, direction
scanners, shadow reader, and selector normalizer). Every export moved
once, unrenamed; each module has its own inventory case.

The tag-pair selector grammar (matchesLooseTagPair, scanUnreadForm,
extractSelectorCompounds, extractCompoundTags, and the pieces only they
used) is gone. scanPositionalPairs in tests/setupBrowser.ts mounts each
styled tag alone, inside each tag, and after each tag through scene and
compares the rules Element.matches reports, so the browser's own engine
answers the question; the shipped elements layer reports no positional
pair, a planted p:not(h1 + p) reports h1 + p, a planted details summary
is excluded only by the mandated table, li + li is read, and a namespaced
audit|p is refused by name (the host probe shows Element.matches throws
on it in Chromium 141).

SpecifierReader holds the specifier walk's readings as its own state and
extractSpecifiers reads on a reader of its own. scanForbiddenBuild sweeps
the built entries by specifier and by whole-word signature
(matchesSignature); tailwind is not a signature, because no distribution
measures it. The duplicate ::file-selector-button text assertion is gone.
