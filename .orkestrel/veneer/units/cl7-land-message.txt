Ship the container classes and their width scale (CL7)

The published cascade carries the container classes: the fluid shell for
every variant, the breakpoint-scoped maximum widths, and the navigation
combinators. No selector the pinned inventory records under the container key
is excluded, so the key reads `shipped` and joins the listed set with a
variable row behind each of its gutter properties.

The caps are emitted from a loop over the breakpoint ramp rather than written
out, so each named variant starts capping at its own boundary and then takes
the larger caps, and a ramp retune reaches every cap without an edit per cap.
The fluid variant never receives one. No ramp member changed: every media
condition the key carries already matched a named breakpoint mixin at the same
width, with only the spelling differing.

The payload widths and the gutter values take tokens of their own with
registry leaves, because the styles rule bars a literal length outside the
token file and these are a published scale a consumer retunes. They are
independent of the density-scaled space ramp, whose twelfth member happens to
carry the same gutter value. That member's consumers, its registry entry and
the density assertion, read identically before and after at both density
factors.

The navigation combinators ship rather than being excluded. Their declarations
are self-contained layout on the container, and the rule matches nothing until
a consumer brings their own navigation markup, at which point it is correct.
Excluding them would have meant explaining why a container-key selector is
absent from a cascade that ships the container. The navigation class is
referenced and never defined here, which is recorded for the guide.

Independent controls guard the result. Omitting one navigation combinator from
the built cascade reddens the presence scan with the component and selector
named. Changing one container token by a single pixel reddens the boundary
reading with the expected and received widths named, which is what establishes
that the widths are read from the browser rather than asserted from the token.

The loop that emits the caps is now bound to its tokens in both directions.
The styles setup proof compiles the real ramp, drops the zero boundary, and
compares the remaining names against the container token keys as sets, so a
ramp boundary added without its token reddens instead of emitting a cap whose
variable names nothing and silently capping nothing. Adding a boundary to the
ramp without its token reddened that assertion with the unmatched member
named, and removing that exact addition returned it green.

The container proof lost its direction axis. Every property it asserts is
symmetric under the writing mode — logical sizing, and the padding and margin
sides asserted equal to each other — so the axis could not fail, and it
doubled the real viewport round-trips for no reading.

Every gate exits 0 on managed Chromium and Edge. The audit is recorded in
scaffold's `.orkestrel/veneer/cl7-audit-verdict.md` file.
