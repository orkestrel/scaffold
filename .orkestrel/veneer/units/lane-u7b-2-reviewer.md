8. `veneer/src/browser/Delegate.ts:53` — the prune key `button.host.isConnected` is document connectivity, not membership of the delegate's own root, so a delegate over a `DocumentFragment` or a detached element destroys and rebuilds every engine on every click and the host can never release. Failure scenario: `const delegate = new Delegate({ root: fragment })` over a `[data-bs-toggle="button"]` host, then two clicks — the first presses (`aria-pressed="true"`), the second prunes engine A (restoring the original absent attribute), constructs engine B from that restored state, and toggles on again, so the host reports `aria-pressed="true"` where Bootstrap's oracle reports `"false"` (`veneer/tests/fixtures/oracle/button.json:117-126`). Why it matters: `DelegateOptions.root` is typed `ParentNode` (`veneer/src/browser/types.ts:352-355`) and a fragment root is an asserted supported case (`veneer/tests/src/browser/Delegate.test.ts:283-297`), so this is declared support that the shipped class now breaks. The suite cannot see it: the fragment case makes exactly one engine-creating click (`:295`), the two remaining detached-root cases each make exactly one (`:121-138`, `:154-169`), and the fix round converted the three round-1 cases whose second click would have reddened to mounted roots (`:9`, `:141`, `:172`; disclosed at `u7b-report-3.md:61`). What right looks like: prune on root-relative membership — replace the condition with `if (this.#root.contains(button.host)) continue` — which is equivalent to `isConnected` for a `document` root and correct for fragment and detached roots; add a case that clicks a fragment-rooted host twice and requires `aria-pressed="false"` and one engine reused. The `isConnected` wording came from the brief (`.orkestrel/veneer/units/u7b-brief-3.md:35-39`), so the Orchestrator must restate that ruling in the successor brief rather than leaving the writer to contradict it.
