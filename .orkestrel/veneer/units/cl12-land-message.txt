Make the guide true (CL12)

Nine tokens shipped with no guide row: the five container widths, the two gutters, and the
mark pair. Each now carries a row naming one token literally, with the value read from the
built cascade and the source read from what declares it. Nothing gated their absence, which is
why it survived the units that landed them.

A compatibility row was asserting a false reading. It claimed the mark class paints from the
highlight aliases; the cascade gives it two Veneer tokens. That row is the published contract a
consumer reads, and only its obligation text changed, so the conformance reader sees the same
obligation it did before.

Two sentences claimed readings the tree does not produce, and both were found by measuring
rather than by reading. One said each container width caps its own family from its own boundary
upward. The cascade appends on every pass, so each rule names its own name and every narrower
one, and a capped container takes the width of the widest boundary the viewport has crossed: the
narrow container reads its own width only between the first two boundaries and reads the widest
width above the last. A consumer sizing a layout from the old sentence would have expected one
number and measured another. The other justified keeping two deferral table shapes on the
grounds that the deferred names are Veneer's own; the first row is a standard CSS property. The
true reason is stronger, and now stated: none of those names is in the pinned inventory the
presence scanner checks against, which is exactly why the other table's reader would refuse
them.

The deferral shapes stay different and each subsection now says why. Unifying them is blocked in
the directions that matter: relocating the rows fails the scanner's inventory check, and
reshaping the read table removes the owner column its reader requires.

A sentence promising that component surfaces would consume the raised-surface token is gone,
replaced by what the cascade actually does — three element rules read it and nothing else. The
files table gained the rows its own enumerating sentence claimed, and the tests section gained
the links that make a corrected sentence about it true.

Left to a successor with its trap named: a gate over the token table's completeness. The obvious
form cannot fail, because a token deleted from its row survives in the prose beside it, so the
gate must read the table's name cells and compare them against the registered set, with a
negative control that deletes a row and leaves its prose intact.
