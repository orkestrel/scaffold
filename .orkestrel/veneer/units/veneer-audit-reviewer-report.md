**5. Colour-mode islands — BROKEN.**
Input: any root that is not `document.documentElement`. `probe-engine.log.txt` CLAIM5 reads `--bs-body-bg` on a nested root under a dark ancestor: `explicitLight={"bg":"#fff","scheme":"light"}` against `applyLight={"bg":"oklch(21% .013 256)","scheme":"dark","attr":null}`, so `applyLightEqualsExplicitLight=false`. The root stays dark and reports `color-scheme: dark` after `apply('light')`.

Cause: `src/browser/ColorMode.ts:35-40` — `apply` writes the attribute for `dark` and calls `removeAttribute` for `light`, which expresses light only where absence means light. `src/browser/types.ts:5-10` invites any `HTMLElement` as `root`, and `src/browser/types.ts:2` names the type for "the color modes Bootstrap's color-mode attribute accepts" — so the API offers a mode the writer cannot write on the root the API offers.

This is the sharpest finding in the round because the cascade already ships the target. `src/styles/_theme.scss:10-13` declares a full `[data-bs-theme='light']` island scope, unqualified by `:root`, and its own comment at `:6-9` states that any element opens an island. The styles axis built light islands and the engine made them unreachable.

Smallest correct fix: in `src/browser/ColorMode.ts`, write `this.#root.setAttribute(COLOR_MODE_ATTRIBUTE, mode)` for both modes; capture `readonly #attribute = root.getAttribute(COLOR_MODE_ATTRIBUTE)` in the constructor the way `src/browser/Button.ts:53` captures its own; restore that captured value in `destroy` (`removeAttribute` when `null`, `setAttribute` otherwise); delete `#written`, which is a stored flag over a fact the captured attribute already derives. Constraint against over-correcting: writing `data-bs-theme="light"` on `document.documentElement` changes no resolved value, because `:root` already carries the light closure (`src/styles/_theme.scss:8`), so the fix costs nothing at the document root and only gains the island case. Update `guides/veneer.md:42-44`, which states the removal as the mechanism, and the `destroy` summary at `src/browser/types.ts:22` and `guides/veneer.md:57`, which become "Restores the attribute the root carried when this controller was constructed."
