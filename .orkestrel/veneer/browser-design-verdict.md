# Browser engine design verdict

Reconciled on 2026-10-02 from the design round of chunk 4 (`src/browser`): the planner proposal (Claude Opus 5.5, `veneer/tmp/units/browser-design-planner-proposal.md`, 1077 s) and the analyst proposal (GPT-6 Astra, `veneer/tmp/units/browser-design-analyst-proposal.md`, 1613 s, with five fresh Chromium measurements in `browser-design-analyst-measurements.json`), both on `veneer/tmp/units/browser-design-brief.md`, blind to each other, over the engine contract `browser-engine-distillate.md` (1401 citations), the elements guidance `browser-elements-distillate.md` (598 citations), and the feasibility measurements `browser-feasibility-measurements.json` (11 probes, Chromium 153.0.8010.12, Playwright 1.63.0). ## Where the lanes agree

- Types first; plain readonly state and imperative methods; no Vue runtime, no `@vue/reactivity`, no `elements:` event names.
- Bootstrap's own event names (`show.bs.modal`, `slid.bs.carousel`, and the rest) are the sole wire names, dispatched as bubbling `CustomEvent`s from the element Bootstrap dispatches from, cancelable where Bootstrap's are; the legacy own properties (`relatedTarget`, `clickEvent`, `direction`, `from`, `to`) stay on the event for drop-in listeners. A second event per fact is refused (the analyst's `event-contract` probe: one dispatch against two).
- A document-owned registry with the data API: capture-phase delegated `document` listeners, Bootstrap's selectors and target resolution, load-time initialisation (`data-bs-ride`, `data-bs-spy`, `.offcanvas.show`, active tab toggles); one explicit boot call, because a library barrel installs nothing.
- The proof model: Bootstrap's own engine runs as the test-only oracle on identical markup and CSS in an isolated document, driven through the same actions; transcripts of DOM writes and events are compared; every deliberate difference is a row of a bidirectional departure table in the guide.
- Anchor positioning replaces Popper for the dropdown menu, the tooltip, and the popover.
- Refused as substitutions, each with its measurement: `<details>` for `div.collapse` and `[hidden]` for tab panes (the markup is fixed; `::details-content` as written did not animate, `collapse-intrinsic`); `popover="auto"` light dismiss for dropdowns (closing `beforetoggle` is not cancelable while `hide.bs.dropdown` is, `close-veto`; `inside` and `outside` cannot be expressed); invoker commands as the data API (different attributes, no plugin gates); `interestfor` for tooltips (no `delay` and no hover-state semantics); `inert` as the focus trap (excludes but does not wrap, `focus-inert`); View Transitions and scroll snap for the carousel (Bootstrap's classes drive the slide); `@starting-style` with `allow-discrete` for the fade (equal motion, `fade-discrete`, and it needs rules Bootstrap's sheet does not carry); top-layer promotion of the toast (it leaves `.toast-container` layout).
- `IntersectionObserver` scrollspy and pointer-event swipe are Bootstrap's own mechanisms and stay.

## Rulings

1. **Two stages.** Stage A is this chunk's acceptance: the twelve plugins on Bootstrap's own markup, classes, and data attributes, proven equal to the oracle under the departure table. Stage B is a successor set of units after stage A is green: author-opted native hosts the engine accepts beside Bootstrap's markup, each with its own departure rows: `<dialog class="modal">` (the measured neutralisation recipe of `dialog-modal`, `closedby="none"` with Bootstrap's keydown path, the `div` backdrop kept, the Tab limit named), and the measured options deferred from stage A (`scrollbar-gutter: stable` scroll lock, `interpolate-size` vertical collapse, `popover="manual"` floating parts). The user rules whether stage B belongs to this chunk or a later one; stage A does not wait on that ruling.
2. **Contract.** `createEngine(root?: Document | HTMLElement): EngineInterface` is the boot entry (the data API scope and the registry; `root`, `destroyed`, `destroy()`); one factory per plugin (`createAlert`, `createButton`, `createCarousel`, `createCollapse`, `createDropdown`, `createModal`, `createOffcanvas`, `createPopover`, `createScrollspy`, `createTab`, `createToast`, `createTooltip`), each taking Bootstrap's host element and the typed options, performing registry lookup, input translation, ownership, and hook binding. Implementation classes take an owner-created context, stay out of the barrel, and sit in the parity `INTERNAL` list. The fleet owns `Overlay`, `Template`, `createScope`, `ScopeInterface`, `createBrowser`, and `BrowserInterface`; `Engine`, `Placement`, `Backdrop`, `Trap`, `Lock`, and `Registry` are free (the hosted guides' `## Surface` tables, read 2026-10-02), and the template renderer takes a name the fleet does not own.
3. **State.** Every entity exposes `element`, `destroyed`, and `destroy()`; `visible` (the accepted open state, derived from the plugin's authoritative DOM state, never a second flag) and `phase: 'hidden' | 'showing' | 'shown' | 'hiding'` where a transition exists; `active` on the button and the tab; `index`, `cycling`, and `sliding` on the carousel; `current: HTMLAnchorElement | undefined` on the scrollspy; `menu` on the dropdown; `panel` on the tab, the tooltip, and the popover; `placement` on the floating entities, read from the resolved side; `enabled` on the tooltip and the popover. Methods use the fixed vocabulary: `show`, `hide`, `toggle`; `close` on the alert; `next`, `previous`, `select(index)`, `start`, `pause`, `resume` on the carousel; `update()` recomputes placement or overflow compensation and `write(content)` replaces a tip's content, because one method selecting two actions is refused; `enable` and `disable` on the tip; `refresh` on the scrollspy.
4. **Options.** Grouped one-word keys, the analyst's table: `dismiss.{backdrop, escape}` (modal, offcanvas), `dismiss.{inside, outside}` (dropdown, from `autoClose`), `dismiss.{automatic, delay}` (toast), `scroll` (offcanvas), `focus` (modal), `parent` and `toggle` (collapse), `position.{boundary, reference, display, offset}` (dropdown), `position.{side, fallback, boundary, offset}`, `trigger.{click, hover, focus}`, `delay.{show, hide}`, `content.{title, body, html, template, class}`, `container`, `selector`, and the programmatic `sanitize.{enabled, allowlist, transform}` (tooltip and popover), `autoplay.{interval, ride, hover}`, `keyboard`, `touch`, `wrap` (carousel; `ride` is `false | 'interaction' | 'load'`), `target`, `intersection.{margin, threshold, offset}`, `scroll.{smooth}` (scrollspy), `animation` where Bootstrap has it, and `on` for the hook map. Bootstrap's markup input is parsed before projection: `data-bs-*` attributes and `data-bs-config` with Bootstrap's merge order and value normalisation, the tooltip's exception (no `data-bs-config`; `allowList`, `sanitize`, `sanitizeFn` stripped), and `data-bs-popper-config` admitted for the serializable built-in options the placement unit covers (placement, offset, flip, preventOverflow); a function-valued option and a Popper modifier callback are refused as JavaScript API, named in the guide. A mistyped markup value resolves to the default; Bootstrap's `TypeError` is a documented departure.
5. **Hooks and detail.** Hook keys are one word, mapped to the wire names: `show`, `open` (shown), `hide`, `close` (hidden), `insert` (inserted), `prevent` (hidePrevented); the alert's `close` and `remove` (closed); the carousel's `slide` and `change` (slid); the scrollspy's `activate`; the button's `toggle`. `detail` carries one-word fields (`related`, `click`, `direction`, `from`, `to`). The button gains `toggle.vn.button`, a Veneer-namespaced notification after its synchronous write, because Bootstrap emits none and the Vue surface must observe data-API toggles; it is the only `.vn.` event of stage A.
6. **Registry.** Keyed by host element and plugin; an element may host several plugins (Bootstrap's one-instance-per-element refusal is JavaScript API and is not reproduced; the guide names the difference). Repeated boot of one root does not double-handle an event; nested roots select one responsible scope per event; a scope destroys only the instances it owns.
7. **Shared mechanics of stage A.** Bootstrap's writes in Bootstrap's order per plugin (the distillate is the specification), including `reflow` at every site Bootstrap reflows. Transition completion waits on the element's own `CSSTransition`s from `getAnimations()`, bounded by the computed first `transition-duration` plus `transition-delay` plus 5 ms, resolving at once under reduced motion or `transition: none`; the engine dispatches no synthetic `transitionend` (a departure row), and a wait aborts on `destroy`. The focus trap, the `div.modal-backdrop` and `div.offcanvas-backdrop` nodes, and Bootstrap's scrollbar compensation (`overflow`, `padding-right`, the saved `data-bs-*` values, the fixed and sticky adjustments, the modal overflow padding) are kept, with one owner for the body writes across overlapping overlays.
8. **Placement.** A `Placement` mechanism replaces Popper for the dropdown's dynamic path, the tooltip, and the popover, in the ordinary layer (no `popover` attribute: insertion order outranks Bootstrap's z-index model, `top-layer`): a unique, restored `anchor-name` and `position-anchor` pair, `position-area` from the requested placement in logical keywords, `position-try-fallbacks` compiled from the fallback order (a constructed per-document stylesheet carrying named `@position-try` rules is admissible only where keyword flips cannot express an order, and the unit proves the need), the offset as a margin, the resolved side read back after layout (Chromium reports the applied `position-area`, `anchor-resolution`) and written to `data-popper-placement` before placement-dependent state is exposed, the arrow positioned inline as Popper did (absolute, the cross-axis coordinate anchor-relative and edge-clamped, `tooltip-arrows`), and a bounded correction pass for the boundary, tether, and clipping behavior anchor positioning does not supply, run on open, `update`, captured ancestor scroll, resize, and a `ResizeObserver` of the relevant boxes, coalesced into one requested frame, never an idle loop. The static path (`.navbar`, `display: 'static'`) keeps `data-bs-popper="static"` and the sheet's positioning. Geometry is proven against Popper's boxes within 1 px over the configuration population; an uncovered declarative option blocks the floating units rather than passing through silently.
9. **Auto-start.** `createEngine` initialises `[data-bs-toggle="tooltip"]` and `[data-bs-toggle="popover"]` present at boot, a departure row (Bootstrap needs page script), because a markup-only page must work under a drop-in that drops the JavaScript API; the factories serve elements added later.
10. **Dependencies.** No runtime dependency is added: guards and coercers are local to `src/browser` (`validators.ts`, `parsers.ts`), the Bootstrap-specific `normalizeData` mirror included; `@orkestrel/contract` stays a devDependency; the browser graph packs without Bootstrap, Popper, or Vue. The Chromium baseline is 153.0.8010.12 through Playwright 1.63.0, named in the guide. Amended by the user on 2026-10-02: `@orkestrel/contract` is a runtime dependency and is used throughout the package (its guards, parsers, `isInstance`, and `Result` forms replace every local primitive whose semantics they match); the browser graph still packs without Bootstrap, Popper, or Vue. The convention design round names which local validators, parsers, and helpers fold into contract's.
11. **Proof model.** The oracle is `bootstrap.bundle.js` loaded by a `<script>` into a same-origin child iframe with the Bootstrap sheet and the fixture markup, so its document listeners and registry never see the engine's document; the engine runs on the same markup in the test document. One scenario drives both through the same steps. The transcript per step records the class set, attribute values, owned inline style properties, created and removed nodes with parentage, `activeElement`, and the ordered `*.bs.*` events with host, `cancelable`, `defaultPrevented`, and legacy payload; generated ids are normalised by their referenced relationship; pending mutation records are drained at each checkpoint. Floating entities add rendered boxes, arrow boxes, and hit-test order. Excluded: timestamps, `isTrusted`, `transitionend` events, Popper's transform serialisation, and the engine's own anchor properties. The departure table is `guides/veneer.md` § Browser entry → `### Engine departures` (scenario, path or property, Bootstrap's value, the engine's value, reason, proof), read in both directions by `readDepartures` with a section argument (the sheet's reader refuses a second table today); the harness's controls are a planted row, a deleted row, a wrong value, and an extra undeclared mutation. Proven departures of stage A: typed `detail` beside the legacy properties; `toggle.vn.button`; no synthetic `transitionend`; mistyped markup to the default; several plugins per element; tooltip and popover auto-start; the engine's anchor and arrow writes in place of Popper's; teardown that aborts stale work.
