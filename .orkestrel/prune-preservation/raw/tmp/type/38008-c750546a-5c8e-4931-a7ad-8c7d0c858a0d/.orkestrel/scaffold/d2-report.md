## The findings

### 1. The `published` predicate is wrong in substance — CLOSED

`tests/config.test.ts:80` now reads:

```ts
const publishes = ['core', 'browser', 'server'].some(
	(environment) =>
		lstatSync(resolve(root, 'src', environment), { throwIfNoEntry: false })?.isDirectory() === true,
)
```

This is the derivation `targetToEnvironments` uses at `src/bin/helpers.ts:899-903`: the environment
names filtered by a physical directory. `lstatSync` reports a symbolic link as a link rather than as
its target, which is what `isPhysicalDirectory` at `src/server/helpers.ts:412-415` does, so a
symlinked `src/core` is excluded the same way. A regular file named `src`, an empty `src` directory,
and an `src` directory holding no recognized environment are all excluded, which is what the audit's
F-1 required.

`SRC/CORE` still resolves on this case-insensitive host, and that is deliberate. The repository's own
axis derivation folds case the same way, so a workspace with `SRC/CORE` is one `targetToEnvironments`
calls a source axis and one the compiler vendors a wrapper for. Making the test case-exact would put
it in disagreement with the mechanism the brief told it to agree with. The verdict dropped
case-folding as a separate finding for the matching reason, and what F-1 actually reached — a bare
`SRC` entry with nothing recognized inside — no longer enters the case.

**The throw stays reachable.** A workspace carrying `src/core` and no
`configs/src/tsconfig.core.json` still fails with `The workspace declares no face project`. Proven by
run, not by reading — see criterion 6.

## Choices settled inside the unit

The deviation contract scoped these to this unit. Each is recorded rather than escalated.

- **The predicate's exact expression.** `lstatSync(..., { throwIfNoEntry: false })?.isDirectory() === true` over `['core', 'browser', 'server']`. `lstatSync` rather than `statSync` to match `isPhysicalDirectory`, which excludes a symbolic link. `throwIfNoEntry: false` rather than a `try` block, so the expression stays one anonymous callback passed directly as an argument and adds no module helper.
- **The case-local rename.** `manifestPublishes`, qualified for the source that decides it, rather than a second word for the same concept.
- **`NPM_LAUNCHER` as a grouped constant** rather than two flat constants. The launcher's command and its shell are two facts about one thing and neither is usable alone, so they group under the entity noun with one-word leaves.
- **`relative as relativePath` in `tests/setupServer.ts`.** Two exported functions there take a parameter named `relative`, and the bare `node:path` import made both a `no-shadow` warning under `--deny-warnings`. Aliasing the import touches no exported signature; the file already aliases `createServer as createSocketServer` for the same reason. Renaming those parameters is the alternative and it moves two unrelated doc blocks.
- **`readManifestVersion` moved with the helpers.** `installGeneratedWorkspace` calls it, so leaving it in the test file would have meant a second copy in the setup module.
- **Throws rather than assertions inside the helpers**, carrying the same text the assertion messages carried, because a `setup*.ts` module holds no `expect`. Value comparisons stayed in the cases.
- **The blocked-plan message names the blueprint expression** rather than restoring the literal word `proof`, which would be false for any other blueprint the general helper is given.
- **The `here` sweep covers both owned test files entirely**, not only D1's added lines, because criterion 3 is written that way.
