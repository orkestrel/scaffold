## Lane

I held the **subjective lane** — design acceptance, API and vocabulary, architecture fit, simplification, guide voice and product coherence. My engine wrote this unit; every ruling below rests on source I read myself, not on the report.

## Numbered verdicts

**1. The announced state is true at every frame a settle can read — CONFIRMED.**
Attacks that failed: (a) the open animation — `offcanvas.js:101-110` adds `show` and fires `shown.bs.offcanvas` inside one `completeCallBack`, so `opened` flips at the frame the menu finishes opening and `waitForState('button', 'Menu', 'expanded')` cannot settle early; (b) the navigation hide — `App.vue:70-79` calls `instance.hide()`, and `offcanvas.js:126-134` fires `hidden.bs.offcanvas` from the hide completion, so `onMenuClosed` runs and the ref resets; (c) a second open after that hide — `_isShown` is false by then, so `show()` runs its full path again; (d) the wide viewport — `#site-menu` and the `d-lg-none` trigger both stay in the document, so `menu.value` is never null and the attribute stays consistent with a trigger nobody can reach; (e) `:aria-expanded="false"` rendering as an absent attribute — `aria-expanded` is not a special boolean attribute in Vue's attribute patch, so it renders the string, which is what R-A-C1's green `collapsed` reading shows. Adjacent behaviour that looks like the defect and is correct: `menu.value?.addEventListener` at `App.vue:87-88` swallows a null ref silently, but `#site-menu` at `App.vue:212-219` is unconditional, so the ref is always bound.

**2. The measurement is the one the brief asked for — CONFIRMED.**
I re-took the source half myself rather than trusting the report's grep: `node_modules/bootstrap/js/dist/offcanvas.js` carries `setAttribute` only at `:98` (`aria-modal`) and `:99` (`role`), both on `this._element`, and nothing in the file touches a trigger's attributes. The invited attack — was the menu open by Bootstrap's own account when the `after` frame was read — fails: `offcanvas.js:105-108` adds `show` immediately before triggering `shown.bs.offcanvas` in the same callback, so a reading gated on the `show` class is at or after `shown`. No other Bootstrap component claims this trigger: it declares `data-bs-toggle="offcanvas"`, and `collapse.js` and `dropdown.js` bind their own toggle values.

**3. The naming rule is one rule and the product's vocabulary — BROKEN.**
Input that falsifies it: `app/browser/components/HomeView.vue:255-268`. The rule is "the region carrying the control". The section at `:255` is `aria-labelledby="join-heading"`, and `:259` makes that heading `Get Rough Notes delivered — free to licensed agents`. The announced name at `:268` is `Get started, Join the community`, taken from the decorative eyebrow paragraph at `:258`. The suffix names no region; it names a line of display copy that carries no accessible-name role at all. A screen-reader user hears the section as "Get Rough Notes delivered — free to licensed agents" and the control as "Get started, Join the community", and nothing connects them.
Second input, same claim: the compact menu's destinations. `App.vue:212-219` names that region `Menu`; `App.vue:237` announces `Site` for every destination inside it. So the shipped rule is not one rule — the utility bar and footer announce their carrying region, the compact menu's destinations announce a region that is not theirs, and the compact menu's own action announces the region it sits in. A reader given the guide's sentence can predict none of the three.
What right looks like: state the rule the code follows — "a shell destination announces the navigation it belongs to, and the compact menu's copy of an action announces `Menu` because the masthead's copy stays in the accessible-name population" — or change the code to follow the stated one. For the invite, either label the section `aria-label="Join the community"` so the suffix and the region agree, or suffix the control with the section's own accessible name.

**4. The exception is measured, not assumed — BROKEN.**
The measurement is real; its stated reason is false. The claim says both actions "are reachable" at 390 with the menu open. They are reachable only to `isReachable`. Bootstrap makes the covered masthead action unreachable to a person in every modality at once: `offcanvas.js:98` sets `aria-modal="true"`, which takes everything outside `#site-menu` out of a screen reader's virtual cursor; `offcanvas.js:101-104` activates a `FocusTrap` over the dialog, and `focustrap.js:86-101` returns focus into the dialog on any outside `focusin`, so Tab never rests on the masthead action; `offcanvas.js:144-161` builds a visible backdrop whose click closes the menu, so a pointer aimed at the masthead action never reaches it. The installed contract confirms the gap is the measurement's: `node_modules/@orkestrel/test/dist/src/browser/index.d.ts:1131-1161` documents `isReachable` as reading connectedness, visibility, box, focus order, disabled state, and `[inert]` ancestry — `aria-modal`, a focus trap, and an overlaying backdrop are all outside it.
My ruling on the mechanism, since the claim asks for one: **retain the two-name split, strike its stated reason.** I tested the obvious alternatives and each fails. Scoping the census to the open dialog fixes the census but not the journeys, because `resolveRendered` applies the same `isReachable`, so `Get started, Site` would resolve ambiguously at run time inside the menu. Marking the shell `[inert]` while the dialog is open — which `isReachable` does honour — puts the trigger itself inside the inert subtree (`App.vue:134-162` holds the trigger in the masthead), so `resolveAccessible('button', COPY.menu)` would refuse it and R-A's own state proof would break; carving the trigger out of the inert set is machinery bent to the measurement in the other direction. The durable carrier is upstream, in `@orkestrel/test` — see referral R1.
Consequence for R-B: R-B pins `Get started, Menu` as the menu's target today, and that target changes again if the layer later models the modal. Record it as a known-provisional name in R-B's brief rather than as settled product vocabulary.
Required change here: `app/browser/App.vue:53-55` and `guides/README.md:142-144` both state the reason as "the compact masthead keeps its own action beside the open menu". Replace it with the true one — the journey layer's reachability filter counts a control the dialog covers, so the name is split to keep resolution unambiguous.

**10. Would you ship the interface? — BROKEN.**
Input: the claim's own narrative fails at its first step. "A person using a screen reader at 390 opens the menu, hears the trigger's state, and reaches `Get started, Menu`." They do not hear the trigger's expanded state. `offcanvas.js:101-107` activates the focus trap — which calls `trapElement.focus()` — *before* it adds `show` and fires `shown`, and `App.vue:87` flips `opened` only on `shown`. So focus has already left the trigger when the attribute becomes `true`, and `aria-modal="true"` has already removed the trigger from the dialog user's reachable subtree. The expanded value is observable to `waitForState` and to nobody else. Authoring the attribute is still right — a disclosure trigger owes it — but the guide presents it as an interface improvement it is not.
The first announced name that misleads, since the claim asks for it: `Get started, Menu`. One destination, `#/subscribe`, carries a different accessible name depending on whether a dialog is open, and the qualifier distinguishes it from a control the person cannot reach in any modality. A returning user who learned the action as `Get started, Site` finds it renamed inside the menu, with no product reason behind the rename.
Would I ship the rest? Yes, with the guide corrected. The listing, footer, and utility collisions are genuinely resolved, the visible label leads every composed name, and the icon-only controls were left alone. The unrecorded cost is redundancy: `App.vue:108-113` names each utility list after its cluster and `App.vue:118` then repeats that cluster inside every link's name, so a screen reader announces "Contact" on entering the list and "800-428-4384, Contact" on the link inside it; the footer echoes each column heading in every link under it. That is the known cost of `aria-label`-per-link disambiguation, it was taken in place of the region-scoped resolver this diff removes from the journeys, and neither the guide nor the report records it as a tradeoff.

The criterion is not closed, and R-B will build journeys on the belief that it is.
What right looks like: extend the census, or add a companion proof, to drive the states the data-state table declares, starting with the Absent rows. Then name the colliding controls apart — the notice recovery and the continuation are different acts and can read differently.
