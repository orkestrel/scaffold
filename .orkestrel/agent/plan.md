# The context and selection campaign for `@orkestrel/agent`

Plan of record for the live campaign under `.orkestrel/agent/`, written 2026-10-07 against agent 0.0.28 (release commit `7784837`, fix commit `c8ab2c5`) on the branch `claude/confident-maxwell-6nd0f3` of every checkout it names. This file is the one home of unit order and status. [context.md](context.md) is the verdict of the refactor seam and [refine.md](refine.md) is the verdict of the judge, judgments, selection, and scope seams; each carries its design and points here for order, acceptance, and status, so no second plan table can drift. The folder is deleted in the acceptance commit; git history is the archive.

Two kinds of sentence appear, as in the records: a measured fact names the file, test, command, or run it came from; a ruling is a decision for this codebase.

## Goal

Build the agent's context machinery in place, in `@orkestrel/agent`, as three layers that compose in one direction and never weaken the dispatch contract agent 0.0.28 fixed.

- **Scope** is the static, synchronous, evidence-free mode. It filters instructions, tools, and active workspace files with no model call, and through the tool allow-list it decides what a turn may advertise and call.
- **Selection** is the dynamic inclusion. It chooses the conversation messages `build()` folds for the request the loop is serving, its judgments are recorded on the conversation, and it never decides what a turn may call.
- **Dispatch admission** stays in the loop and reads the allow-list snapshot the turn advertised.

The work has two parts. First the refactor the context ruling ordered: `hygiene`, `framing`, `correlate`, `carve`, and `consolidate`. Then the selection round on that layout: `judgments`, the `seam` with the scope-held handler, the stock `selection`, and the merged `guide`, followed by the consumers against packed builds, one falsification round, the agent release, and the re-pin wave.

## Rulings of 2026-10-07

The planning round of 2026-10-07 (two blind lanes and a distillate over the records, the hand-off, and the agent source at 0.0.28) found the contradictions listed here. Each is ruled once; the user can overturn a ruling before the unit it binds dispatches.

- **Release numbers.** Agent 0.0.27 (`gitHead` `6ea0451`) is the judge release and 0.0.28 (`7784837`) is the judge plus the scope-dispatch fix; both tarballs list 9 files. The row "release 0.0.28" that refine.md § The plan carried and the row "release 0.0.27" that context.md § The plan carried named versions the registry serves with other content, so both tables are struck and this file's `release` row names one release above 0.0.28, proposed as 0.0.29, after the selection round. One release after the round costs one re-pin wave; a release after the refactor and another after the round would cost two, because a caret on a `0.0.x` version admits that one patch.
- **Order.** The refactor units run first and the selection round lands on the carved layout, because refine.md places the seam's types in `contexts/types.ts` and the judgments in the conversations module, and the stock selection's never-split-a-tool-group clause needs `correlate`. The row order in refine.md § The plan, which put `judgments`, `seam`, and `selection` ahead of the carve, is superseded.
- **Handler home.** Two homes, scope first, ruled on 2026-10-07 after a design round of three blind lanes, six refuters, and a judge over agent 0.0.28. `AgentOptions.select`, forwarded as `AgentContextOptions.select` beside the six members the constructor forwards today, is the agent default; the active scope's `select` (`ScopeInput.select`, `ScopeInterface.select`) overrides it while that scope is active. `AgentContextInterface.select(request, signal)` resolves `scope?.select ?? default` once at each select site and returns `Promise<Selection> | undefined`, `undefined` when neither holds a handler, so the loop awaits only a returned promise and the default path stays synchronous. The precedent is the conversation manager, which resolves `input?.summarize ?? this.#summarize` for the sibling policy that also decides which messages fold. The scope-only shape this file carried before was withdrawn for two measured reasons: an agent whose only need is a policy would pay a `createScope` call and a required `name`, and every tool-only switch the fleet uses, the ollama store harness's `apply(undefined)` before each turn and its answer-only cap scope with no handler, and the guide's `apply(undefined)` idiom, would silently switch selection off. The agent-only shape was withdrawn because one `apply` could no longer switch mode and policy together, which is the user's recorded intent, and because the post-build `apply` hook is what reaches a sub-agent built from a job. A mode that must run with no selection while a default exists carries a pass-through handler that returns `view()`; the framework exports no such constant until a consumer asks. A precedence keyed on whether a scope is present was rejected because the answer-only scope would still switch selection off under it.
- **`description`.** A scope gains `description` in the `seam` unit, as the user ruled. `build()` never reads it, so it changes no request byte, and `narrow` keeps it with `name`. Its first reader is the desk reply page in `desk-select`, which shows the active mode's description beside the `select` receipt; a role catalog that lists modes to a model is deferred with the spawning layer. `AgentOptions` gets no description, and the `select` event carries no scope.
- **Role registry.** A role for a subagent is a scope plus agent options (provider, budget, authority). The registry that creates an agent from a named role belongs to the layer that spawns subagents and is built when that layer names its consumer; it is not a unit here, and the framework ships no file-format loader. Answer-only carries over to it with no code.
- **`correlate`'s member.** The member is advisory: one optional single-word member on a tool-role message holding the `ToolCall.id` it answers, with position staying the join the loop and the merge use. Minting a unique id per call was rejected because it changes the wire bytes on every provider and the ids the `deny` and `tool` events carry. The member's name is ruled by the unit's implementer and reviewer; the rival to `call` is a name that cannot be mistaken for the `ToolCall` object.
- **Mid-run scope timing.** A scope change has two application points: the tool half applies at the next turn (the snapshot rule), and the prompt half (instructions, files, and `select`) applies at the next build, that is, the next run or a compaction rebuild. The `guide` unit adds the executed assertion for the prompt half and corrects the `AgentOptions.scope` TSDoc sentence before it writes the rule. Rebuilding the system block every turn was rejected: it changes bytes and work on every multi-turn run.
- **`desk-select`.** The desk integration waits until the agent and ollama work is settled and the desk is re-pinned, as the user instructed on 2026-10-07, so it is the last unit. It stays the first consumer of `AgentOptions.select`, built as refine.md designed it: the per-ticket reply agent is created once per ticket with `select` set at creation and runs under a named scope that carries the mode's description. The trade-off is recorded: the agent release ships the seam before its first consumer has run against it, so a seam defect the desk finds becomes a patch release rather than a pre-release fix. If the user rules the desk out, the stock selection waits for another consumer under the first-consumer law.
- **Records.** This file carries order, acceptance, status, invariants, measurement discipline, deferred work, risks, and open questions. refine.md and context.md keep their design sections as the verdicts of their seams and point here from their § The plan. The seven records that described more than one package or that landed as code (`README.md`, `agent.md`, `mica.md`, `system-one.md`, `provider.md`, `packages.md`, `desk.md`) are deleted in the sweep commit, their surviving sentences folded into § Folded guidance and into refine.md.
- **Sub-agent route.** No job or registry member is added this campaign. A sub-agent built from a serializable job, a runner child, or a toolbox delegation takes a mode or a policy through a wrapping `AgentRegistryInterface` whose `build` calls the stock build and then applies the mode or attaches listeners before the handler generates; `createAgentQueue`, `createAgentRunner`, and the toolbox agent tool each accept any registry and generate only after `build` returns. The route depends on the post-build `apply` the scope home keeps. A per-job mode name, a `scopes` pool and its accessor, a registry-wide default `select`, and job `instructions` wait for the spawning layer's consumer; that change rules the pool kind (a name-keyed record or a `ScopeManager` with caller-supplied stable ids, because minted ids do not survive a restore), an accessor name that does not collide with `ScopeManagerInterface.scope(id)`, which returns `undefined` on a miss, and whether one registry-level default policy is enough.
- **Per-run scope or select.** Rejected. `AgentRunOptions` members are resolved once at run entry and never mutate the agent; a one-run mode is `apply`, `generate`, and a restore in `finally` after the result settles. Overlapping runs share the scope and the default, so runs that need different modes at the same moment need separate agents.
- **`strict` and the `select` event.** One agent-wide `strict` covers the three selection faults (a thrown handler, a returned `fault`, a changed tail), with no per-mode switch; the `select` event carries `[selection]` alone and fires after `build(selection)`, twice before turn 0 when the pre-first-turn trim folds, and not at all when the run aborts during selection.
- **Option surfaces otherwise unchanged.** `AgentOptions` grows by one member and `AgentContextOptions` by one; `ScopeInput` and `ScopeInterface` gain `select` and `description`; `AgentContextInterface` gains `select` and `build(selection?)`; `AgentEventMap` gains `select`. `AgentRunOptions`, `AgentJobInput`, `AgentRegistryOptions`, `AgentRegistryInterface`, `ScopeFilter`, and `ScopeManagerInterface` stay as 0.0.28 declares them. Rejected without a consumer: `AgentOptions extends AgentContextOptions`, a `context` regroup of the six forwarded members, a whole-context option, authority on the scope, the judge on `AgentOptions`, job `workspaces`, `conversations`, `select`, or `on`, a per-mode `strict`, a boolean selection switch, and an exported pass-through handler.
- **Agent checkout gate.** Cleared on 2026-10-07 by the small-model campaign's hand-off: its agent work ended at 0.0.28 (`7784837`), nothing of this plan's was touched, and no agent change is pending in the other session. The agent units start in order from `hygiene`. The agent release follows the selection round.
- **Prose is not a gate.** The user ruled on 2026-10-07 that implementation comes first and that comment and prose hygiene must not hold the campaign's pace, because any line can move at any time. After `hygiene`'s two passes no further comment-only unit runs; a unit that rewrites a file fixes the comments it touches under the writing rules, the reviewer reads them with the diff, and a residual elsewhere is recorded, not chased.
- **Baseline re-pin.** The desk consumes the published packages before the campaign starts: agent `^0.0.28`, ollama `^0.0.21`, browser `^0.0.27`, scaffold `^0.0.94`, and probe `^0.0.21`, installed with one agent copy (ollama's deduped), every desk gate green at the same counts as before (type check 0, lint's 29 pre-existing findings only, 101 app tests, 119 policy, 225 config, the journey 6 with 66 captures). The post-release re-pin in unit 14 moves the desk again when the agent release lands.

## Measurement discipline

The small-model campaign of 2026-10-07 (`.orkestrel/veneer/lifecycle/reading/small/matrix.md`) measured that a 2B model is byte-sensitive to what it is sent. Every brief in this campaign states these properties and no figure of its own.

- **Classify each unit by the bytes it can change.** The bytes a provider receives are the system block, the tool definitions and descriptions, the tool and assistant message shape on a wire, and which messages are included. `hygiene`, `carve`, `consolidate`, `judgments`, and the default paths of `seam` and `selection` must leave them unchanged. `framing` (for a provider that set a format), `correlate` (where a wire forwards the member), a configured selection, and a new tool (`recall`) change them.
- **Measure the cheap way first.** The recorded-request control in `framing` captures the request bodies the scripted provider receives before and after a change; an empty diff closes the question with no live run, and the control stays green through unit 9. Ollama's hermetic wire fixtures do the same for its wire.
- **Measure live only where the bytes change and reach a small model.** The live harness is ollama's store harness (`tests/setupStore.ts`) with `qwen3.5:2b-q4_K_M` on the Ollama 0.40.0 daemon, on the fixed port set behind the 16-port rows of the matrix and never the 8-port set: the 8-port reading passed a configuration the 16-port reading failed. Run every task (search, read, paging, click, form, and the journeys), not only the task the change targets: making `read`'s `from` optional left read working and took search from 16 of 16 to 6 of 16 and paging to 0 of 16 on the same ports, and rewording the click and type copy turned every search into a read. Run a baseline arm and a change arm on the same ports and the same pack.
- **Read first attempts and per-class counts.** One first attempt per port per task; a retried pass does not count. Read per-class counts first (the ollama 500 `tool call parsing failed: XML syntax error`, which is the model emitting malformed tool-call XML, deterministic per context, its own failure class, never retried; refused-unlisted; loops and repeated refusals; budget exhaustion; `ended` scope withdrawals) and pass counts second. Report follow-up turns separately. A regression is any task's first-attempt pass count falling below the baseline or any failure-class count rising, with one exception: a rise in `ended` beside an equal or higher pass count is the cap working. A regression on any task rejects the change, however the target task moved.
- **The baseline.** The ollama store harness at 0.0.21 installs agent `^0.0.28`; the recorded reference is matrix row F3, `confirm.ts 2b-final3`: every one of the six store tasks passed in 16 runs of 16 with thinking on, after the fixes the reflexive run exposed. Earlier rows (JENL 15 of 16) were read on a checkout that installed agent 0.0.26 under `^0.0.26`, where the harness's answer-only cap was inert, and are not the baseline.
- **Copy is search-critical.** A unit that edits a tool description, a schema, a deny reason, or refusal text states the exact before and after bytes in its report. A refusal names the refused tool and points at no other tool: two refusals pointing at each other produced a 36-call alternation.
- **Budgets are properties.** A turn's call budget is its shortest correct sequence plus one correction per call, stated in the task definition and never as a figure in a rule or a brief; raising a limit lengthens a loop and fixes nothing. The loop-ending policy stays in the harness (the refusal cap that applies the answer-only scope) and the stop stays in the agent (the answer-only path); the agent gains no refusal counter and no switch.
- **Where and when.** Measurements run in the ollama checkout, now this session's, with the harness re-pinned to the packed agent, and never beside a live writer there. The model is `qwen3.5:2b-q4_K_M`, the fleet's small model, and this campaign measures it with `think` false (the user, 2026-10-07): the reflexive run is the instrument that exposed the harness and package defects a reasoning model walks around, so a unit reads it first and turns thinking on only when a reading needs the model's reasoning (then as the harness does, `think: true` set by the harness itself with `num_predict 1024`, because thinking counts toward the cap); the provider's `think` default stays `false`; keep the model card's sampling penalties, because plain greedy sent the thinking 2B back to reading the page before it searched (search 4 of 8 against 16 of 16); dump one attempt (`tmp/probes/wire-dump.test.ts`), replay the decision turn with `tmp/codex/wire-replay.ts --think true`, read the reasoning, change the fixture, the prompt, or the tool, screen 8 ports, confirm 16 runs (`tmp/codex/confirm.ts`); a description change is the last lever. The instruments are listed in [small-models.md](small-models.md).

## Folded guidance

Sentences that survive the deleted records and bind a unit here; each names the unit that carries it.

- For `guide`: a judge is frozen at inference. Record corrections, change thresholds and criteria in code, and train another model only offline as a batch on rows collected for that purpose, refitting temperature on rows the training run did not see. Thresholds are the application's; no default sits in the framework.
- For `guide` and for any unit that builds a tool over a judge: a handler that judges on a model's tool call must use the argument the model passed, or its description must say it judges a fixed input. The desk's first experiment showed the hazard: the handler judged a fixed ticket when the model shortened the argument.
- For `selection` and `guide`, the jev-1.13 failure modes TypeSafe's jaggedness page named (reviewed 2026-10-02), which bear on criteria wording: the model reads literally, scoping words and negations included; it counts and orders dates weakly, so arithmetic and date comparison stay in code; indirection (a double negative, a property of a property) costs accuracy; irrelevant state distracts, so filter first; an adversarial note inside the state can move the answer, because state is data the model does not treat as hostile; a `noul` whose true criterion means no performs worse; the model can lean toward the first option, so reorder and check; it is not a generator.
- For `selection`: question ids are caller keys the model never sees, so the whole question lives in `instructions`; a later judgment that needs an earlier answer is a second request.
- For `ollama`: the Ollama logprob wire's behavior at Mica's 8,192-token limit is unmeasured; the official server rejects a longer input with HTTP 400.
- For `recall` and every tool a small model calls: the model opens a call's arguments with what it read last, so a key argument that competes with a large pasted structure is dropped; put the key before the structure in the instruction and the schema, or give the tool an unambiguous default (the hand-off's `edit` defaulting `journey` to the only saved journey). A result that names a field is typed literally by a reflexive model and read as advice by a thinking one; keep the naming and measure with thinking on.
- For `guide` and for every refusal text a unit writes: a refusal that addresses the user reads as a user turn to a reasoning model mid-task; a refusal names the one next call and says nothing about who asked. The deny reasons stay frozen (§ Invariants).
- For `seam` and `selection`: measure, never infer, a small model's reading; the transcript's thinking is the evidence, and a reflexive run's shape is a symptom.
